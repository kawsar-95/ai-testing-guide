Page: `content/getting-started/permission-modes.mdx`. I did not write this page.

Method: I read the 7 `<Voices>` blocks. For each claim in a `<Layman>` or `<Bangla>` panel, I found the `<Technical>` sentence of the same `##` section that it restates. A claim that is not in the Technical panel, or that changes a number, a version, a flag, a command, a path, a scope, or a condition, is a FAIL. An omission is not a FAIL. For each `<Cite n>` in a voice panel, I checked that the Technical panel of the same section cites the same `n` and that the same source supports the same claim (see `getting-started-permission-modes.factcheck.md`). I read the Bangla text for meaning, for the polite form (আপনি), for technical terms in English, and for the hyphen between an English word and a Bangla suffix. The page has no "Key words" section, so no section is skipped.

Notes from the check:

- In "The six modes", `acceptEdits`: the Technical text puts "only for paths inside the working directory" on the filesystem commands. The Layman and Bangla panels put it on file edits and commands. The next Technical paragraph says that paths outside that scope still prompt, so this is not a change. PASS.
