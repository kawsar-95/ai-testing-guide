# Voice fact-check: MCP Servers (round 1, 2026-10-20)

Page: `content/extend/mcp.mdx`. I did not write this page.

Method: I read the 7 `<Voices>` blocks. For each claim in a `<Layman>` or `<Bangla>` panel, I found the `<Technical>` sentence of the same `##` section that it restates. A claim that is not in the Technical panel, or that changes a number, a version, a flag, a command, a path, a product name, a scope, or a condition, is a FAIL. An omission is not a FAIL. For each `<Cite n>` in a voice panel, I checked that the Technical panel of the same section cites the same `n` for the same claim. The source claims themselves are in the Technical fact-check of the page and are not checked again here. I read the Bangla text for meaning and natural use (polite আপনি, technical terms in English, a hyphen between an English word and a Bangla suffix). The tip callout "See it in practice" (Keep it safe) and the Technical-only code blocks have no restatement in the voices. This is an omission, not a FAIL.

Notes on borderline items:

- Add a server, Layman and Bangla: "put one more option ... between `--env` and the server name" (Layman) and "অন্তত আরেকটি option" (Bangla). The Technical text says "at least one other option". The Bangla text keeps "at least". The Layman text says "one more option", which is the minimum that works and does not give a wrong instruction. PASS, with a language note on row 40.
- Add a server, Layman: "For a remote server, use HTTP." The Technical text says "HTTP is the recommended transport for remote servers" and "Use HTTP where the server supports it". The Layman text keeps "recommended". PASS (row 35).
- Find servers, Bangla: "শুধু package-এর দিকে নির্দেশ করা metadata রাখে". "শুধু" (only) matches "stores metadata that points to packages. It does not host the server code". PASS (row 27).
- Servers for testing work, Layman and Bangla (Jira): the voices cite only [7]. The Technical text cites [7] and [8] for "run `/mcp` to sign in". The same claim has [7], so the cite is valid. PASS.
