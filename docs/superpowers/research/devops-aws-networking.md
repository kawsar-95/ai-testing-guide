# Research notes: AWS Networking and Delivery

Page: `content/devops/aws-networking.mdx`. Module: DevOps & Cloud. Date: 2026-11-18 (first version: 2026-11-05).

The page is a full lesson for a tester (`docs/superpowers/specs/2026-11-15-devops-full-lessons-design.md`): the VPC (subnets, CIDR blocks and the five reserved subnet addresses, route tables, internet gateways, NAT gateways, security groups, network ACLs, flow logs, Reachability Analyzer), Elastic Load Balancing (the Application Load Balancer parts and health checks), Route 53 (routing policies and health checks), and CloudFront (caching, expiry, invalidation), with a practice run of IP range checks in Python and AWS CLI templates on a laptop, and a read-along of AWS's own pages. The first version (2026-11-05) had four sources and one section. The page needs no AWS account: nothing on it runs against AWS. It gives no price, because prices change; it cites the AWS pages that say what is billed.

The practice run of `## Try it` (steps 1 to 3) was run on 2026-11-18 at 12:30:35 (+06) on Linux 7.0.0-43-generic with the system Python 3.14.4 (`/usr/bin/python3`), aws-cli/2.41.0 (Python 3.14.8, installed that day for one user, as the page AWS Compute and Storage describes), and bash 5.3.9. The runner `practice/nw.sh` ran in a fresh temp folder with a copy of `net.py` (the tutorial's own code, not from a source), and stopped at once if `~/.aws` existed. It ran the three step files (`practice/nw/steps/step1.sh` to `step3.sh`) in one shell and saved the output of each step in `practice/nw/out/`. The date, the versions, the names of the `AWS_` variables that were set before the steps (none), and whether `~/.aws` existed after the run (it did not) are in `practice/nw/out/env.txt`.

- Step 1: `python3 net.py` printed ten lines. The /16 range has 65536 addresses and splits into 256 /24 subnets. The first four addresses and the last address of `10.0.0.0/24` are `10.0.0.0`, `10.0.0.1`, `10.0.0.2`, `10.0.0.3`, and `10.0.0.255`: the same five that S5 lists as reserved. `10.0.0.128/25` is inside `10.0.0.0/24`, `10.0.0.0/24` overlaps `10.0.0.128/25` and does not overlap `10.0.1.0/24`, `10.0.0.37` is in `10.0.0.0/25` and `10.0.0.200` is not, and `10.0.0.5/24` raised `ValueError: 10.0.0.5/24 has host bits set`.
- Step 2: `aws ec2 create-security-group --generate-cli-skeleton` printed the template (17 lines). It shows `"ResourceType": "capacity-reservation"` and `"DryRun": true` as placeholders.
- Step 3: the filter printed eleven top-level names of `aws ec2 authorize-security-group-ingress --generate-cli-skeleton`.

The run did not watch the network, so the page does not say that the commands send nothing to AWS. It says that they needed no account and no credentials in the tutorial's run. The tutorial matched the template names `CidrIp`, `IpProtocol`, `FromPort`, and `ToPort` to the rule parts by their names only (the page says so).

Steps 4 to 6 are a read-along of S26 and S3, S17, and S25. The tutorial did not run them. The cost warnings come from S1 (VPC charges), S26 (NAT gateways), S30 (the hourly charge of an Application Load Balancer), and S25 (delete the distribution first). S17 (Create an Application Load Balancer) is the page that `application-load-balancer-getting-started.html` redirects to. S30 is the Elastic Load Balancing pricing page (`https://aws.amazon.com/elasticloadbalancing/pricing/`); the page cites only its sentence about the hourly charge, not any price.

Some quotes are written as `scripts/devops_claimcheck.py` reads them (case, white space, and curly quotes do not count as differences).
