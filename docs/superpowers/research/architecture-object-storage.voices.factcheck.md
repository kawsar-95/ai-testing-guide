Method: I read the 5 `<Voices>` blocks. For each claim in a `<Layman>` or `<Bangla>` panel, I found the `<Technical>` sentence of the same `##` section that it restates. A claim that is not in the Technical panel, or that changes a number, a condition, a product name, or a scope, is a FAIL. An omission is not a FAIL. For each `<Cite n>` in a voice panel, I checked that the Technical panel of the same section cites the same `n` for the same claim, and that source n supports it. I read the Bangla text for meaning, for the polite form (আপনি), for technical terms in English, and for the hyphen between an English word and a Bangla suffix. The "Key words" section has no voices.

Judgment calls:

- Bangla "বাঁচে" (saves) in the Valet Key bullet (row 30): the Technical text says that a file transfer through the app server uses its compute, memory, and bandwidth [8], and the next sentence says that the Valet Key client talks to the storage directly [8]. - The Layman text of the multipart bullet (row 58) has the "100 MB" claim with no cite on its own sentence. The `[7]` on the next sentence is the same cite that the Technical text puts on both sentences. PASS.
- The Layman and Bangla panels of "What a tester can check" have no Callout box. They start with "the tutorial's own advice" and repeat the 6 ideas with no cites. PASS, rows 67 to 80.
