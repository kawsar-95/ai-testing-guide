Local checks (Ubuntu, kernel 7.0.0-38, util-linux, GNU coreutils 9.7; `stat` on PATH is uutils 0.10 and also accepts the page options). Only read-only commands and one sandbox demo ran. No `sudo`, no `mount`, `mkfs`, `fdisk`, `swapon`, `lvcreate`, `dd`, or `wipefs`. `pvs`, `vgs`, `lvs` are not installed, so LVM is checked from the manuals only.
- `lsblk -f` lists `nvme0n1p2 ext4 /` and `nvme0n1p1 vfat /boot/efi`. A whole disk with partitions has empty `FSTYPE` and `MOUNTPOINTS` columns.
- `lsblk -N -o NAME,TYPE` prints `nvme0n1` and `nvme1n1` only. `lsblk -v` prints nothing (no virtio disk here).
- `df -hT /` prints `/dev/nvme0n1p2 ext4 233G 150G 72G 68% /`. `du -xsh /var/log` prints `1.7G /var/log` plus one `Permission denied` line.
- `cat /proc/filesystems` has `nodev` marks (`sysfs`, `tmpfs`, `proc`, `overlay`) and plain `ext2`, `ext3`, `ext4`, `vfat`.
- `findmnt -no FSTYPE /` prints `ext4`. `stat -f -c %T /` prints `ext2/ext3`. `stat -f -c 'block=%S free=%f inodes=%c' /` prints `block=4096 free=21731801 inodes=15564800`.
- `echo x > /dev/full` prints `No space left on device`, exit status 1.
- Inode demo of the page (run with `TMPDIR` set to the sandbox): `ls -i a.txt b.txt` printed `10233210` twice, `stat -c '%i inode, %h links' a.txt` printed `10233210 inode, 2 links`, `df -i .` printed the table, the cleanup removed everything (`rmdir` status 0). The sandbox was empty after the run.
- `swapon --show` prints `/swap.img file 8G 0B -1`. `cat /proc/swaps` has the same area. `cat /proc/sys/vm/swappiness` prints `60`. `cat /proc/self/oom_score` prints a number (733). `free -h` prints the `Swap:` line.
- `findmnt --target /tmp -o TARGET,SOURCE,FSTYPE,OPTIONS` prints `/tmp tmpfs tmpfs rw,nosuid,nodev,nr_inodes=1048576,...`. `findmnt --verify` as a normal user prints `0 parse errors, 0 errors, 4 warnings` (warnings: "cannot detect on-disk filesystem type (Permission denied)"), exit status 0.
- `npm test` in the worktree: 145 tests, 145 pass, 0 fail.

Overlap check: `python3 scripts/linux_overlap.py content/linux/disks-filesystems.mdx <dir>` against the raw dir (243 `*.txt` files read) and against my official dir (48 `*.txt` files read): no output, exit 0. No copied run of 8 or more words.

Weak points of the writer (checked first)
- NVMe/virtio: the page says only that `lsblk -N` and `lsblk -v` filter them. lsblk(8) supports this (rows 5 and 17). No naming pattern is claimed.
- LVM: all claims checked against the Debian pages of lvm(8), lvcreate(8), lvextend(8), lvreduce(8). One cite problem (row 93). The code block is not fully covered by its danger callout (row 115). The page does not claim online extension of an LV.
- "A wrong fstab line can stop the boot": not marked as tutorial advice, not cited. FAIL (row 75). systemd.mount(5) (fetched) supports a corrected sentence.
- `findmnt --verify` instead of `mount -a`: PASS (mount(8): "it is a bad practice to use mount -a for fstab checking").
- `dd` for the swap file, no `fallocate`, no `mkswap --file`: PASS. The page makes no claim about `fallocate`, `--file`, `nocow`, or swap file permissions (grep of the page found none).
