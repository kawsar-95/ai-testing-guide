## Claims

| # | Claim (plain words) | Source | Exact quote (under 40 words, verbatim) |
|---|---|---|---|
| 1 | In an agent, working memory holds the information that is active for the current step. | S1 | "Working memory maintains active and readily available information as symbolic variables for the current decision cycle" |
| 2 | It holds inputs, knowledge from reasoning or from long-term memory, and data from the last step. | S1 | "This includes perceptual inputs, active knowledge (generated by reasoning or retrieved from long-term memory), and other core information carried over from the previous decision cycle" |
| 3 | Working memory connects the other parts of the agent. | S1 | "It thus serves as the central hub connecting different components of a language agent." |
| 4 | In the older Soar architecture, working memory holds the current input, goals, and reasoning results. | S1 | "reflects the agent’s current circumstances: it stores the agent’s recent perceptual input, goals, and results from intermediate, internal reasoning." |
| 5 | Psychology origin: working memory keeps information for a short time, ready to use. | S2 | "any of various hypothetical systems involved in the brief retention of information in a highly accessible state." |
| 6 | The common model (Baddeley and Hitch, 1974) is short-term storage and processing for tasks such as reasoning. | S2 | "the short-term maintenance and manipulation of information necessary for performing complex cognitive tasks such as learning, reasoning, and comprehension." |
| 7 | Human working memory has a limited capacity. | S2 | "Both are supervised by a limited capacity central executive" |
| 8 | For an LLM, Anthropic calls the context window the model's "working memory". It is not the training data. | S3 | "This is different from the large corpus of data the language model was trained on, and instead represents a “working memory” for the model." |
| 9 | Everything in a request uses space in the context window: system prompt, messages, tool results, tool definitions. | S3 | "Everything in the request counts toward the context window: the system prompt, every message in `messages` (including tool results, images, and documents), and your tool definitions." |
| 10 | More context is not always better: accuracy and recall go down as the token count grows ("context rot"). | S3 | "As token count grows, accuracy and recall degrade, a phenomenon known as context rot." |
| 11 | When the output reaches the context window limit, generation stops with a specific stop reason (Claude 4.5 models and newer). | S3 | "If generation then reaches the context window limit, it stops with `stop_reason: "model_context_window_exceeded"`." |
| 12 | Models use information at the start or end of a long input best, and worse in the middle ("lost in the middle"). | S4 | "performance is often highest when relevant information occurs at the beginning or end of the input context, and significantly degrades when models must access relevant information in the middle of long contexts" |
| 13 | Testable: each response reports the tokens that the request used. | S3 | "Every response reports what the request consumed in its `usage` field." |
| 14 | Testable: you can count the tokens of a request before you send it. | S3 | "To estimate a request before you send it, use the token counting API." |
| 15 | CoALA has short-term working memory and three long-term memories. (Added by the fact check, 2026-10-28.) | S1 | "These include short-term working memory and several long-term memories: episodic, semantic, and procedural." |

## Notes

- CoALA (S1) defines working memory as a module of the agent, not as the context window. It holds "symbolic variables" for the current decision cycle. The Anthropic docs (S3) are the source for "the context window is the model's working memory". A page can give both views, but it must not say that CoALA equates working memory with the context window.
- Claim 8: the quote marks around "working memory" are in the source page (curly quotes).
- Claim 10: in the source, "context rot" is in italics.
- Claim 11: the stop-reason rule applies to Claude 4.5 models and newer. On earlier models, the API returns a validation error (same page, S3). Context window sizes change by model (S3 lists 1M tokens for the newest models and 200k for others). Do not put a fixed number on the page without a date.
- Claim 14: in the source, "token counting API" is a link.
- S4 is from 2023 and tested the models of that time. Say "studies found", not "all models do this".
- MemGPT (arXiv 2310.08560) also manages a limited context window ("main context"). It is a source of the Retrieval Memory topic. Its "working context" is a part of the prompt, which is a different meaning of "working".
- Test ideas for the page (tutorial's own advice, no cite): send a long conversation and check that an early instruction is still followed; put a key fact in the middle of a long input and check that the answer uses it; check the `usage` numbers against the token counting API; check how the app reacts to `model_context_window_exceeded`.
