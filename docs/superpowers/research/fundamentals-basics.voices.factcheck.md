Method: I read the 7 `<Voices>` blocks. Each block has a `<Technical>`, a `<Layman>`, and a `<Bangla>` panel, and each panel has one `notes` and one `istqb` `<Version>` block. I checked this structure with a script: all 21 panels have exactly one block of each version, and no `notes` block has a `<Cite>`. For each claim in a `<Layman>` or `<Bangla>` block, I found the sentence of the `<Technical>` block of the same `##` section and the same version that it restates. A `notes` voice block was compared only with the Technical `notes` block, and an `istqb` voice block only with the Technical `istqb` block. A claim that is not in that Technical block, or that changes a number, a term, a definition, a list, a step order, a scope, or a condition, is a FAIL. An omission is not a FAIL. For each `<Cite n>` in a voice panel, I checked that the same Technical block cites the same `n` for the same claim. The cites used are 1 to 8 (ISTQB syllabus and glossary entries). I did not open the sources again, because the claims are the Technical claims and the page has its own fact-check report (`fundamentals-basics.factcheck.md`). I read the Bangla text for meaning and for natural use, and I checked that testing terms stay in English with a hyphen before a Bangla suffix. The "Key words" rule does not apply: this page has no such section.
