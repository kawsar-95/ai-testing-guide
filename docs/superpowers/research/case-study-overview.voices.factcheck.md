# Voice fact-check: The Practice Project (round 1, 2026-10-20)

Page: `content/case-study/overview.mdx`. I did not write this page.

Method: I read the 7 `<Voices>` blocks. For each claim in a `<Layman>` or `<Bangla>` panel, I found the `<Technical>` sentence of the same `##` section that it restates. A claim that is not in the Technical panel, or that changes a number, a version, a flag, a command, a path, a product name, a scope, or a condition, is a FAIL. An omission is not a FAIL. For each `<Cite n>` in a voice panel, I checked that the same section's Technical panel cites the same `n` and that the source supports the same claim. Only the section "What is recorded and what is not" has cites in the voice panels (7 and 6); both match the Technical panel. The intro and the "Where these facts come from" callout, which are outside the voices, were not checked. I read the Bangla text for meaning, for polite address (আপনি), for English technical terms, and for the hyphen between an English word and a Bangla suffix.

Notes from the reader:

- Layman "can sign in first" (What is recorded): a softer wording of "describe a setup project that signs in first". The scope and the cite do not change. PASS.
- Layman and Bangla "What is recorded": the Layman text joins the "replies are condensed" (10-03) and "outputs are condensed" (10-04) facts in one bullet. The facts stay true for both logs. PASS.
- Layman "The workspace": the Layman text omits "a SQL dump and notes" and "The dates are the dates of the commits that added each file". These are omissions. PASS.
