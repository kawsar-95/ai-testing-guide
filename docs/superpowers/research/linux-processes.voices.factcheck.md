# Voice fact-check: Processes (Linux stage, round 1, 2026-10-20)

Page: `content/linux/processes.mdx`. I did not write this page.

Method: I read the 8 `<Voices>` blocks. For each claim in a `<Layman>` or `<Bangla>` panel, I found the `<Technical>` sentence of the same `##` section that it restates. A claim that is not in the Technical panel, or that changes a number, a flag, a command, a path, a scope, or a condition, is a FAIL. An omission is not a FAIL. A Bangla language problem is a FAIL only if it changes or hides the meaning. I also ran a script that lists, for each section, the `<Cite n>` values of each voice panel and of the Technical panel. No voice panel cites a source that its Technical panel does not cite. Each cite in a voice panel follows the same claim as the same cite in the Technical panel, so it supports the claim in the same way. The Technical panels cite the Linux sources of `page.sources`, and the Linux module accepts them (see CLAUDE.md, "Linux Module"). I did not re-check the Technical text against its sources. That is the job of the separate stage report. The page has no "Key words" section.

Notes on the table:

- Some Layman and Bangla panels leave out a Technical sentence (for example the tool groups, the tester advice, or a "may differ" clause). An omission does not add or change a fact, so it is a PASS.
- The Layman panels of sections 3, 5, 6, and 7 keep the `<Callout type="danger">` content only in part. That is an omission.
- Every Bangla row keeps commands, flags, paths, signal names, and technical terms in English. English words with a Bangla suffix use a hyphen, and the text uses "আপনি" forms.
