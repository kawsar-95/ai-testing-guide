# Voice fact-check: Defects and the 7 Principles (round 1, 2026-10-20)

Page: `content/fundamentals/defects-principles.mdx`. I did not write the voices.

Method: I read the 7 `<Voices>` blocks. Each block has a `<Technical>`, a `<Layman>`, and a `<Bangla>` panel, and each panel has one `notes` and one `istqb` block. A script confirmed this for all 7 sections (21 panels, 42 version blocks). For each claim in a voice panel, I found the sentence of the Technical panel that it restates, in the version block of the same kind (notes with notes, istqb with istqb). A claim that is not in that Technical block, or that changes a number, a term, a definition, a list, a step order, a scope, or a condition, is a FAIL. An omission is not a FAIL. A mix of notes and istqb content is a FAIL.

Cites: no `<Cite>` is in any `notes` block (Technical, Layman, or Bangla). In each `istqb` block, the set of cite numbers of the Layman and Bangla panels equals the set of the Technical panel: section 1 uses 1 to 5, section 2 uses 1, section 3 uses 1, section 4 uses 1 and 6, section 5 uses 1, section 6 uses 1 and 7, section 7 uses 1, section 8 uses 1, 8, and 9. Each cite sits after the claim that the same cite follows in the Technical panel. I did not re-check the sources. `fundamentals-defects-principles.factcheck.md` does that.

Language: I read the Bangla for meaning, politeness (আপনি), English testing terms, and the hyphen between an English word and a Bangla suffix. The Bangla uses the polite imperative (দেখুন, শুরু করুন, যান, করুন). The "Key words" rule does not apply: this page has no such section.

Row notes: "Principle 1:" and "1." are the same label. The Technical notes heading has a bold number. I treat both as the same.

## Items I looked at with extra care

- Section 1, Layman notes, Failure: "The system does not do what it should" has no "may". The Technical text says "the system may fail to do what it should do". The sentence defines what a failure is, so the meaning is the same. The Bangla keeps "না-ও করতে পারে". PASS, row 5.
- Section 1, Layman notes, last line: "ISTQB defines failure and bug differently." The Technical callouts say that the ISTQB definitions differ from the notes. The Layman line does not say "from the notes". It is short, and it points to the ISTQB version. PASS, row 10. See the language notes.
- Section 1, Layman istqb: "In the environment, radiation or electromagnetic fields can also cause defects in firmware". It drops "The environment can also cause [failures]". The example is the same as in the Technical text. PASS, row 17.
- Section 4, Layman istqb: "does not cause more defects" for the Technical "does not cause later defects". The scope is the same: the work products that come from the removed defect. PASS, row 62.
- Section 8, Layman istqb: "makes a system succeed" for "ensures the success of a system". PASS, row 115.
- Section 8, Layman istqb, last paragraph: it says "the syllabus name" and does not repeat "Absence-of-defects fallacy". The `##` heading of the section shows the name. PASS, row 119.
