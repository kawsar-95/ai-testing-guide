## Points the writer flagged (checked first)

- **zip / unzip.** The page says only two things about ZIP: "ZIP is another format: it packs and compresses in one step" [27], and "Use `unzip` for a ZIP file with many members" [26]. I searched the whole MDX (prose, callouts, code blocks) for `zip`: no other statement and no zip/unzip command. S27 says "Zip puts one or more compressed files into a single ZIP archive" and "An entire directory structure can be packed into a ZIP archive with a single command". S26 says "To extract zip files with several members, use unzip instead of gunzip." Local run: `gzip -dc < t.zip` on a ZIP with 2 members printed "gzip: stdin has more than one entry--rest ignored"; `unzip -q t.zip -d x` extracted both. Verdict PASS (rows 110, 111). Advice, not a FAIL: the official UnZip page `https://infozip.sourceforge.net/UnZip.html` can be fetched ("UnZip will list, test, or extract files from a .zip archive") and is a better source for `unzip`.
- **Tutorial-only facts** (editor list, nano is the Ubuntu default, Vim over SSH, no recycle bin, glob in `mv`, `cat >` with Ctrl+D, `rmdir`, Red Hat on hard links): each sentence matches the tutorial text (rows 6, 13, 15, 38, 39, 48, 49, 50, 59, 93). Extra local checks: `readlink -f /etc/alternatives/editor` gives `/usr/bin/nano` (Ubuntu default confirmed); `mv *.log logs/` moved 4 files; `cat > draft.txt` read stdin until end of input; `ln` + `ls -li` showed the same inode and `%h` = 2. All PASS. The tutorial "C to cancel saving" is wrong: see row 65 (FAIL).
- **"cp replaces without a prompt by default"** (row 25). S11 `--update=all`: "This is the default operation when an --update option is not specified, and results in all existing files in the destination being replaced." `-i`: "prompt whether to overwrite an existing destination file". The two together support the sentence, and the sentence does not claim more. Local run (GNU cp 9.7): `cp report.txt archive/` over an existing file printed no prompt, rc=0, and the content changed. `echo n | cp -i ...` printed "overwrite '...'?" and rc=1, content kept. PASS. Note (not a FAIL): on RHEL, the root user's `~/.bashrc` sets `alias cp='cp -i'` (from memory, not fetched), so a root shell there prompts. The sentence names no case; consider "in a plain shell".
- **`vimtutor`** (row 84). S18: "The vimtutor is also a nice way to learn by doing." The page says it is a lesson that teaches by doing, so PASS. S18 does not say that it is a command; S21 does ("Run vimtutor until you are familiar with most basic commands"). Suggest adding `<Cite n={21} />` to that sentence.
- **`--update=none` "in newer versions"** (row 33). coreutils NEWS, release 9.3 (2023-04-18): "cp and mv now support --update=none to always skip existing files in the destination, while not affecting the exit status." So 9.3 is the first version. "In newer versions" is true and hedged, so PASS. It is vague: say "coreutils 9.3 or newer". Local: `cp --update=none` kept the old file, rc=0. In GNU cp 9.7 `cp -n` prints "warning: behavior of -n is non-portable and may change in future; use --update=none instead".
- **Shortened titles.** Source 5 "Linux Basics, Part 4 (create, move, delete)" for "Linux Basics – Part 4: Creating, Moving, and Deleting Files and Folders" and source 15 "Text Editing with Nano and Vim" for "The Complete Guide to Text Editing in Linux with Nano and Vim": both true.
