# Voice fact-check: What to Fix in the Setup (round 1, 2026-10-20)

Page: `content/case-study/lessons.mdx`. I did not write this page.

Method: I read the 8 `<Voices>` blocks. For each claim in a `<Layman>` or `<Bangla>` panel, I found the `<Technical>` sentence of the same `##` section that it restates. A claim that is not in the Technical panel, or that changes a number, a version, a command, a path, a product name, a scope, or a condition, is a FAIL. An omission is not a FAIL. For each `<Cite n>` in a voice panel, I checked that the Technical panel of the same section cites the same `n`, and that source `n` supports the claim that the cite follows (the claim is the same as the Technical claim that carries the cite). I read the Bangla text for meaning and for natural use: polite form (আপনি), technical terms in English, and a hyphen between an English word and a Bangla suffix. A language problem is a FAIL only if it changes or hides the meaning. The page has no "Key words" table.

Flagged items from my read:

The Technical text says the README names a user-level server "Read-only" and that it "does not describe this project server". The Technical danger callout itself says "the skills and the README describe read-only use". PASS, but the voices drop the "user-level server" scope. See the language notes.
- "The agent also had Read and Bash ... [2]" (Subagents, rows 16 and 28): the Technical panel puts cite 2 on the "refuses to launch" sentence, and the next sentence ("This agent also had ...") has no cite. The voices move cite 2 to the second sentence. Source 2 supports the rule that makes this result possible. PASS.
- "The workspace" (row 1): the Technical sentence of the glance section says "the two sub-projects". The voices add "of the workspace". The page intro and the first callout name the workspace. PASS.
