# Voice fact-check: Design, Execute, Fix, Retest (round 1 and recheck 1, 2026-10-20)

Page: `content/case-study/test-and-retest.mdx`. I did not write this page.

Method: I read the 8 `<Voices>` blocks. For each claim in a `<Layman>` or `<Bangla>` panel, I found the `<Technical>` sentence of the same `##` section that it restates. A claim that is not in the Technical panel, or that changes a number, a condition, or a scope, is a FAIL. A plain omission is not a FAIL. For each `<Cite n>` in a voice panel, I checked that the same section's Technical panel cites the same `n` for the same claim (source 1 = ISTQB CTFL v4.0, source 2 = Claude Code subagents docs, source 3 = skills docs). Facts about the private workspace have no cite, as the Case Study rule says. I read the Bangla text for meaning and for natural use, and I checked that commands, file names, and common technical terms stay in English, with a hyphen before a Bangla suffix.

Findings of round 1:

- 3 FAILs (all fixed, see "Recheck 1"), all in "Step 4: The test-executor subagent". Two panels drop the condition "unless the user asks for the major cases only" (rows 87 and 104). One panel widens "No passwords, tokens, or OTP codes in the Test Data column" to the whole report (row 90).
- The Layman "Step 3" panel starts with "So a second, adversarial agent ...". The Technical panel gives no causal link between independence and the second agent. The link is mild and the facts are the same, so this is a language note, not a FAIL (row 61).
- The Layman "Step 5" panel says "look-alike numbers" for the zero-width-space and full-width numbers of TC-007 and TC-008. The Technical text of that section does not use "look-alike", but the Technical text of Step 1 does (CH-3, "look-alike phone numbers"). The meaning is the same. PASS, row 115.
- The Layman "Step 5" panel gives the reason for 16 fixture customers as a plain fact. The Technical text gives it as "The README gives the reason". PASS, rows 119 and 129 (the Bangla keeps "README-এর কারণ").
