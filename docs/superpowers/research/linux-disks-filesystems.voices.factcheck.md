# Voice fact-check: Disks and Filesystems (round 1, 2026-10-20)

Page: `content/linux/disks-filesystems.mdx`. I did not write this page.

Method: I read the 7 `<Voices>` blocks (Disks and Filesystems, Filesystems, Inodes, Mounts, Adding Disks, Swap, LVM). For each claim in a `<Layman>` or `<Bangla>` panel, I found the `<Technical>` sentence of the same `##` section that it restates. A claim that is not in the Technical panel, or that changes a number, a version, a flag, a command, a path, a product name, a scope, or a condition, is a FAIL. An omission is not a FAIL. For each `<Cite n>` in a voice panel, I checked that the same section cites the same `n` in the Technical panel and that the cite follows the claim that it supports there. I read the Bangla text for meaning and for natural use: polite form (আপনি), common technical terms in English, and a hyphen between an English word and a Bangla suffix. A language problem is a FAIL only if it changes or hides the meaning.

Flagged items:

- Mounts, "Find that process with `fuser -m` first": the Technical callout says "Find the user with `fuser -m` first". "User" here means the user of the mount. The Technical sentence before it says "when a process uses the filesystem", and `fuser` reports processes. PASS.
- LVM, Layman, "It has three layers": the Technical panel lists 3 terms (PV, VG, LV) and says that `pvs`, `vgs`, and `lvs` "report on each layer". The number 3 is a count of that list, not a new fact. PASS.
- Swap, voices, `vm.swappiness`: the Layman panel drops "(older kernels: less)" but keeps "In the latest kernel docs", so the scope stays. PASS. The Bangla panel keeps both.
- Technical-only items (not an error): vfat (Layman), `/proc/swaps`, `oom_score`, `swapoff`, and the Mounts and Adding Disks callouts are shorter or absent in the Layman panel.
