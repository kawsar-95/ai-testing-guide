# Voice fact-check: Users and Permissions (round 1, 2026-10-20)

Page: `content/linux/users-permissions.mdx`. I did not write this page.

Method: I read the 6 `<Voices>` blocks (User Management, Users and Groups, Create Update and Delete Users, Super User, File Permissions, Managing Permissions). The "Permissions Cheat Sheet" section has no voices. For each claim in a `<Layman>` or `<Bangla>` panel, I found the `<Technical>` sentence of the same `##` section that it restates, including its callouts. A claim that is not in the Technical panel, or that changes a number, a flag, a command, a path, a product name, a scope, or a condition, is a FAIL. An omission is not a FAIL. For each `<Cite n>` in a voice panel, I checked that the same `n` is cited by the Technical panel of the same section, that it sits on the same claim, and that the source title in `page.sources` fits the claim. I read the Bangla text for meaning, for the polite form (আপনি), for technical terms in English, and for the hyphen between an English word and a Bangla suffix. A language problem is a FAIL only if it changes or hides the meaning.

Result: no claim in a voice panel goes beyond its Technical panel. Every voice `<Cite n>` is cited by its own Technical panel. The language notes below do not change a meaning.

Language notes:

- Create, Update, and Delete Users, Bangla: "পুরোপুরি আটকাতে" (to block completely) adds "completely". The Technical text says "To block the account". Remove "পুরোপুরি".
- Create, Update, and Delete Users, Bangla: "পুরো জীবনচক্র" (the whole life cycle) adds "whole". The Technical text says "the life of an account". Remove "পুরো".
- User Management, Bangla: "পড়তে পারা উচিত নয়" (should not be able to read) is softer than "must not read". A closer text is "পড়তে দেওয়া যাবে না" or "পড়া নিষেধ".
- File Permissions, Layman: "the user ID of the file owner for permission checks" drops the word "effective". The sense stays, so this is a note only.
- The `<Cite>` marks come before the full stop in the Bangla and Layman panels (for example "... logs in <Cite n={2} />."). This matches the pilot pages. No change needed.
