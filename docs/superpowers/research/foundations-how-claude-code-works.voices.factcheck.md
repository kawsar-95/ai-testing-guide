# Voice fact-check: How Claude Code Works (round 1 and recheck 1, 2026-10-20)

Page: `content/foundations/how-claude-code-works.mdx`. I did not write this page.

Method: I read the 10 `<Voices>` blocks. For each claim in a `<Layman>` or `<Bangla>` panel, I found the `<Technical>` sentence of the same `##` section that it restates. A claim that is not in the Technical panel, or that changes a number, a version, a flag, a command, a path, a product name, a scope, or a condition, is a FAIL. An omission is not a FAIL. For each `<Cite n>` in a voice panel, I checked that the Technical panel of the same section cites the same `n` and that the cite sits on the claim it supports there. I read the Bangla text for meaning and for natural use: polite আপনি, technical terms kept in English, a hyphen between an English word and a Bangla suffix. A claim that appears in both voices has one row for each voice. The Technical panels were not changed or re-checked against the sources here (see `foundations-how-claude-code-works.factcheck.md`).

Notes from the check:

- No Layman or Bangla panel uses a `<Cite n>` that its Technical panel does not use. No panel has a heading.
- All numbers match the Technical text: 100 checkpoints, 200 lines or 25KB, five files, `500k`, five categories, four parts.

- The Technical Callouts about Grep and the database rewind, the Fable model line, the hook output rules, and the override rules have no voice text. These are omissions, not FAILs.
