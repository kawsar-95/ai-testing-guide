# Voice fact-check: Hooks (round 1 and recheck 1, 2026-10-20)

Page: `content/extend/hooks.mdx`. I did not write this page.

Method: I read the 9 `<Voices>` blocks. For each claim in a `<Layman>` or `<Bangla>` panel, I found the `<Technical>` sentence of the same `##` section that it restates. A claim that is not in the Technical panel, or that changes a number, a version, a flag, a command, a path, a scope, or a condition, is a FAIL. An omission is not a FAIL. For each `<Cite n>` in a voice panel, I checked that the Technical panel of the same section cites the same `n` for the same claim. I did not re-check the Technical text against the sources; `extend-hooks.factcheck.md` does that. I read the Bangla text for meaning and for natural use: polite form (আপনি), common technical terms kept in English, and a hyphen between an English word and a Bangla suffix. A language problem is a FAIL only if it changes or hides the meaning.

Flagged items (round 1):

- Section "QA examples", Layman row 115 and Bangla row 129: the deny-rule sentence dropped the scope "`Read` and `Edit` deny rules" and the limit "They do not cover any script". FAIL in round 1. Fixed, see Recheck 1.
- Section "What your hook can answer", Bangla row 76: "tool আগেই চলে গেছে" was a language note. Fixed, see Recheck 1.
- Section "Hook types", Layman and Bangla: "five types" is not a sentence of the Technical panel, but the Technical table has 5 rows and the Technical bullet says "all five types". PASS, rows 94 and 102.
- Section "How a hook is built": the Layman and Bangla matcher text says "which tool calls" and drops "(or other event sources)". An omission. PASS.
