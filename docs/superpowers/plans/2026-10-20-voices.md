# Voices and Install Button (Phase 1) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add the per-section voice switch (`বাংলা` · `Technical` · `সহজ English` · `সবগুলো`), the site-wide `বাংলা` default button, and the install button, with 2 pilot pages.

**Architecture:** `lib/voice.ts` holds the pure logic and a head script that sets `<html data-voice-default>` before the first paint. A client `Voices` MDX component wraps the panels of one `##` section and shows the switcher. CSS picks the visible panel from `data-voice` on the wrapper, or from the `<html>` attribute before hydration. `lib/voice-source.ts` checks the MDX authoring rules in `npm test`.

**Tech Stack:** Next.js 16 App Router (static export), React 19, TypeScript, Tailwind CSS 4, `@next/mdx`, `node --test`.

**Spec:** `docs/superpowers/specs/2026-10-20-voices-design.md`

### Task 2: MDX authoring checker

**Files:**
- Create: `lib/voice-source.ts`
- Test: `tests/voice-source.test.ts`

**Interfaces:**
- Consumes: `sourceLines` and `SourceLine` from `lib/headings.ts` (skip lines with `kind` `"fence"` or `"code"`).
- Produces:
  - `type VoiceBlock = { heading: string; line: number; technical: string; layman: string; bangla: string }` (`line` is 1-based, the line of `<Voices>`; the three strings are the raw panel bodies)
  - `function voiceBlocks(source: string): VoiceBlock[]`
  - `function voiceErrors(source: string): string[]` (each message starts with `line N:`)

Rules for `voiceErrors` (spec §3):

| Rule | Message contains |
|---|---|
| `<Voices>` is the first non-blank line after a `##` heading | `first after ##` |
| `</Voices>` comes before the next `##` heading or the end of the file | `not closed` |
| Inside: `<Technical>`, `</Technical>`, `<Layman>`, `</Layman>`, `<Bangla>`, `</Bangla>`, in that order, one time each | `order` |
| Every one of the 8 tags is alone on its line at column 0 | `column 0` |
| A blank line follows each opening panel tag and comes before each closing panel tag | `blank line` |
| No Markdown heading (`#`…`######`) in `<Layman>` or `<Bangla>` | `heading` |
| Each `<Cite n={k} />` in `<Layman>` or `<Bangla>` has a `k` that `<Technical>` of the same block cites | `cite k` |

- [ ] **Step 1: Write the failing tests.** Use fixture strings. One test for each rule above: the bad fixture gives exactly one error that contains the message text. Also:
