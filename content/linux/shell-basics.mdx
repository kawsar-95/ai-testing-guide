# Shell Basics

This stage covers the shell, the first commands you type in it, and the layout of the system around you. A tester needs it because each CI log, test runner, and server check starts at a shell prompt. Many failures come from a wrong directory, a missing command, or a wrong variable.

<PageMeta />

## Shell Basics

<Voices>
<Technical>

**Goal:** Tell the terminal from the shell, and see if a shell is interactive.

The shell is a program that passes your typed commands to the operating system. <Cite n={11} /> The terminal is the program that opens the window. <Cite n={11} /> The shell is the program inside it that reads your commands. <Cite n={12} /> On most Linux systems the shell is bash. <Cite n={11} /> `SHELL` holds the absolute path of the login shell of the user. <Cite n={7} />

```bash
echo "$SHELL"
```

**Try it:** start one interactive bash (`-i`, with no `~/.bashrc`: `--norc`) and one non-interactive bash, and print `$-` in each. Bash puts `i` in `$-` when the shell is interactive. <Cite n={1} />

```bash
bash --norc -ic 'echo "$-"'   # himBHc  (has i)
bash -c 'echo "$-"'           # hBc     (no i)
# The other letters can differ on your machine.
```

<Callout type="tip" title="Why it matters for testing">

Tutorial's own advice: a CI job often runs a non-interactive shell. It does not read `~/.bashrc`, except over ssh. <Cite n={1} />

</Callout>

<details>
<summary>Go deeper</summary>

Bash is a newer shell that builds on the old Bourne shell. <Cite n={1} /> <Cite n={11} /> Other shells exist, for example ksh, tcsh, and zsh. <Cite n={11} />

Bash reads different startup files in different modes. <Cite n={1} />

- A login shell (the shell that starts when you log in) reads `/etc/profile`. Then it reads only the first file that exists of `~/.bash_profile`, `~/.bash_login`, and `~/.profile`.
- A `bash` that you start by hand at the prompt reads `~/.bashrc`, if it is interactive and was not started as a login shell.
- A script that you run with `bash script.sh` does not read `~/.bashrc`. A non-interactive shell reads the file that `BASH_ENV` names instead.

```bash
bash --version
```

The `#!` line of a script names the program that runs it. <Cite n={1} />

Tutorial's own advice: a minimal container may have no bash at all, so check the `#!` line and the shell of the runner. Compare `$-` and `$PATH` in the job with your terminal.

</details>

</Technical>

## Basic Commands

<Voices>
<Technical>

**Goal:** List the files of a directory, the hidden ones too.

`pwd` prints the absolute path of the current directory. <Cite n={1} /> `cd` changes the current directory. <Cite n={1} /> `ls` lists the entries of a directory. If you give no path, it lists the current directory. <Cite n={2} /> `ls` hides the names that start with a dot. Add `-a` to show them. <Cite n={2} />

```bash
ls -l
```

**Try it:** in a throw-away directory, make one normal file and one dot file. List them without and with `-a`. The parentheses run the block in a subshell, so your shell does not change. <Cite n={1} />

```bash
(
  cd "$(mktemp -d)" || exit 1   # make and enter a new, empty directory
  touch .hidden notes.txt
  ls       # notes.txt
  ls -a    # .  ..  .hidden  notes.txt
)
```

<Callout type="tip" title="Why it matters for testing">

Tutorial's own advice: print `pwd` and `ls -la` before a failing pipeline step. A flaky test often depends on the working directory or a file not there yet.

</Callout>

<details>
<summary>Go deeper</summary>

These options of `ls` are the most useful:

| Option | Effect |
|---|---|
| `-l` | Long format. <Cite n={2} /> |
| `-a` | Do not ignore entries that start with a dot. <Cite n={2} /> |
| `-h` | With `-l`, print sizes such as 1K, 234M, 2G. <Cite n={2} /> |
| `-t` | Sort by time, newest first. <Cite n={2} /> |
| `-r` | Reverse the sort order. <Cite n={2} /> |

```bash
pwd
ls -lah /var/log
ls -ltr          # oldest first, newest last
```

Without an argument, `cd` goes to the directory in `HOME`. <Cite n={1} />

Tutorial's own advice: `ls -ltr` puts the newest report or log at the end of the list, so you find it fast.

</details>

</Technical>

## Navigation Basics

<Voices>
<Technical>

**Goal:** Move with absolute and relative paths, and jump back to the last directory.

An absolute path starts with `/`, the root of the file tree. A relative path starts from the current directory. <Cite n={13} /> In a path, `.` is the current directory and `..` is the parent directory. <Cite n={13} /> `cd -` goes back to the directory in `OLDPWD`, the previous working directory. <Cite n={1} />

```bash
cd /usr/local/bin
```

**Try it:** in a throw-away directory, go down two levels, up one with `..`, and back with `cd -`. `cd -` prints the directory that it goes to. <Cite n={1} /> The parentheses keep your shell unchanged. <Cite n={1} />

```bash
(
  cd "$(mktemp -d)" || exit 1   # make and enter a new, empty directory
  mkdir -p a/b && cd a/b
  cd ..
  pwd     # /tmp/tmp.XXXXXXXXXX/a
  cd -    # /tmp/tmp.XXXXXXXXXX/a/b
)
# Your directory name differs from tmp.XXXXXXXXXX.
```

<Callout type="tip" title="Why it matters for testing">

Tutorial's own advice: use absolute paths in test scripts. A relative path works only from the start directory, and a CI runner often starts in another one.

</Callout>

<details>
<summary>Go deeper</summary>

Two more shortcuts:

- `~` expands to the value of `HOME`. <Cite n={1} />
- `cd` with no argument goes to your home directory. <Cite n={14} />

```bash
cd /usr/local/bin
cd ..          # now in /usr/local
cd ~           # your home directory
cd -           # back in /usr/local
pwd -P         # print the path without symbolic links
```

By default, `cd` follows symbolic links (files that point to another path) in the logical way (`-L`). The option `-P` makes `cd` use the physical directory structure. <Cite n={1} /> The option `-P` of `pwd` prints a path with no symbolic links. <Cite n={1} />

Tutorial's own advice: you can also set the directory at the top of a script with `cd "$(dirname "$0")" || exit 1`. Run the script. Do not `source` it, because then `$0` is not the path of the script.

</details>

</Technical>

<details>
<summary>আরও জানুন</summary>

`~` হয়ে যায় `HOME`-এর value। <Cite n={1} /> কোনো argument ছাড়া `cd` আপনার home directory-তে যায়। <Cite n={14} />

Symbolic link হলো এমন file, যা অন্য একটি path-এর দিকে নির্দেশ করে। Default হিসেবে `cd` symbolic link-কে logical-ভাবে (`-L`) follow করে। `-P` option দিলে `cd` physical directory structure ব্যবহার করে। <Cite n={1} /> `pwd`-এর `-P` option symbolic link ছাড়া path print করে। <Cite n={1} />

Tutorial-এর নিজস্ব পরামর্শ: Relative path শুধু সেই directory থেকে কাজ করে, যেখান থেকে আপনি test শুরু করেছেন। Script-এর শুরুতে `cd "$(dirname "$0")" || exit 1` দিয়েও directory ঠিক করে নিতে পারেন। Script-টি চালান, `source` করবেন না, কারণ তখন `$0` script-এর path থাকে না।

## Command Path

<Voices>
<Technical>

**Goal:** Find out which program runs when you type a command name.

When a command name has no slash, bash looks in a fixed order. It tries a shell function, then a builtin, then the directories of `PATH`. <Cite n={1} /> `PATH` is a list of directories with a colon between them. The shell searches the list from the first to the last. <Cite n={7} /> If bash finds no command, it prints an error and returns exit status 127. <Cite n={1} />

```bash
echo "$PATH" | tr ':' '\n'   # one directory per line
```

**Try it:** run a name that does not exist in a child shell, then print the exit status. `$?` holds the exit status of the last command. <Cite n={1} />

```bash
bash -c 'no-such-tool'   # bash: line 1: no-such-tool: command not found
echo "$?"                # 127
```

<Callout type="tip" title="Why it matters for testing">

Tutorial's own advice: on "command not found" (status 127) in CI, check `PATH` first. The first match wins, so an old copy of a tool can hide the new one.

</Callout>

<details>
<summary>Go deeper</summary>

Bash remembers the full path of a command it found. `hash -r` clears this memory. <Cite n={1} /> `whereis` shows where the program, the source, and the manual page of a command are. <Cite n={5} /> To keep a `PATH` change for new terminals, put the `export` line in `~/.bashrc`. <Cite n={18} /> The section on environment variables says which file to use for logins.

```bash
type -a ls                   # all places where ls is found
command -v python3           # the one that would run
whereis ls                   # binary, source, and manual files
export PATH="$HOME/bin:$PATH"
hash -r
```

<Callout type="warning" title="Common mistake: an empty entry in PATH">

A zero-length entry in `PATH` means the current directory. You get it from two colons in a row, or from a colon at the start or the end. <Cite n={1} /> POSIX says that an application must use an explicit `.` for this, and the legacy form is deprecated. <Cite n={7} /> Do not write `PATH="$PATH:"`.

</Callout>

Tutorial's own advice: print `$PATH` and run `command -v tool` at the start of a CI job. A missing directory for the tool is a common cause of status 127.

</details>

</Technical>
<Layman>

## Directory Hierarchy

<Voices>
<Technical>

**Goal:** Know where Linux keeps configuration, logs, and temporary files.

All files sit under one root, `/`. The absolute path of each file goes through the root. <Cite n={19} /> The Filesystem Hierarchy Standard (FHS) defines the directory structure and the purpose of each directory. <Cite n={19} /> <Cite n={10} /> `/etc` holds configuration files. `/var` holds data that changes while the system runs, for example logs. `/tmp` holds temporary files that the system may delete without notice. <Cite n={6} />

```bash
ls /
```

**Try it:** check that the directories for configuration, logs, and temporary files exist. `ls -d` lists a directory itself, not its contents. <Cite n={2} />

```bash
ls -d /etc /var/log /tmp   # /etc  /tmp  /var/log
```

<Callout type="tip" title="Why it matters for testing">

Tutorial's own advice: do not keep test evidence in `/tmp`. The system may delete it, so copy reports and logs to a folder that your CI job saves.

</Callout>

<details>
<summary>Go deeper</summary>

The root filesystem must be enough to boot, restore, recover, and repair the system. <Cite n={10} />

`ls` returns 2 when it cannot access a path that you name. <Cite n={2} /> `$?` holds the exit status of the last command. <Cite n={1} />

```bash
ls -d /etc /no-such-dir
echo "$?"
# ls: cannot access '/no-such-dir': No such file or directory
# /etc
# 2
```

| Path | What it holds |
|---|---|
| `/etc` | Configuration files for this machine. <Cite n={6} /> |
| `/home` | The home directories of users. <Cite n={6} /> |
| `/root` | The home directory of the root user. <Cite n={6} /> |
| `/usr/bin` | The main directory for executable programs. <Cite n={6} /> |
| `/usr/local` | Programs that are local to the site. <Cite n={6} /> |
| `/var` | Data that changes while the system runs, for example logs and caches. <Cite n={6} /> |
| `/tmp` | Temporary files. The system may delete them without notice. <Cite n={6} /> |
| `/dev` | Special files that refer to devices. <Cite n={6} /> |
| `/proc` | Information about running processes and the kernel. <Cite n={6} /> |
| `/opt` | Add-on application packages. <Cite n={6} /> |

```bash
ls -ld /tmp /var /etc
man 7 hier        # the full list
```

Tutorial's own advice: when a service under test fails, look in `/var/log` for its log files <Cite n={6} /> and in `/etc` for its configuration. A service can also write to the systemd journal. Read it with `journalctl -u name`. <Cite n={22} />

</details>

</Technical>

## Environment Variables

<Voices>
<Technical>

**Goal:** Pass a variable to a child process, such as a test runner.

The environment is a list of strings in the form `name=value`. A child process (a program that another program starts) gets a copy of the environment of its parent. <Cite n={7} /> A normal assignment makes a shell variable. A child process does not see it. The `export` command marks the name for the environment of later commands. <Cite n={1} /> <Cite n={21} />

```bash
printenv HOME
```

**Try it:** set a variable, and read it from a child shell before and after `export`. The parentheses run the block in a subshell, so your shell does not change. <Cite n={1} />

```bash
(
  API_URL=http://localhost:8080
```

**Goal:** Pass a variable to a child process, such as a test runner.

The environment is a list of strings in the form `name=value`. A child process is a program that another program starts. It gets a copy of the environment of its parent. <Cite n={7} /> A normal assignment makes a shell variable. A child process does not see it. `export` puts the name in the environment of later commands. <Cite n={1} /> <Cite n={21} />

**Try it:** set a variable, and read it from a child shell before and after `export`. The parentheses run the block in a subshell, so your shell does not change. <Cite n={1} />
