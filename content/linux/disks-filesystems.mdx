# Disks and Filesystems

A disk is useless until you partition it, put a filesystem on it, and mount it. This stage covers that path, plus inodes, swap, and LVM. A tester needs it to find out why a CI runner is full, slow, or unable to boot. <Cite n={1} /> <Cite n={2} />

<PageMeta />

## Disks and Filesystems

<Voices>
<Technical>

**Goal:** List the disks, and compare the space that `df` and `du` report.

A block device is a device that the kernel reads and writes in fixed-size blocks, such as a disk. A whole disk has a name like `/dev/sda`. A partition adds a number, as in `/dev/sda1`. <Cite n={15} /> A disk becomes usable in three steps: partition, make a filesystem, mount. <Cite n={8} /> `df` reports the space of a whole filesystem. <Cite n={17} /> `du` adds up the files that it can see below a path. <Cite n={18} />

```bash
lsblk -f
```

**Try it:** list the disks, then make a 1 MiB file and compare `du` with `df`. `-e7` hides the loop devices (major number 7). <Cite n={14} /> <Cite n={52} /> `status=none` stops the statistics of `dd`. <Cite n={56} />

```bash
(
  tmp=$(mktemp -d) && cd "$tmp" || exit 1   # make and enter a new, empty directory
  lsblk -e7 -o NAME,TYPE,SIZE,MOUNTPOINTS
  # NAME   TYPE  SIZE MOUNTPOINTS
  # sda    disk  100G
  # ├─sda1 part    1G /boot/efi
  # └─sda2 part   99G /
  dd if=/dev/zero of=big.bin bs=1M count=1 status=none   # a 1 MiB file of zeros
  du -sh .              # 1.0M  .   (only the files below this path)
  df -h .               # the whole filesystem that holds this path:
  # Filesystem  Size  Used Avail Use% Mounted on
  # tmpfs       7.3G   64M  7.2G   1% /tmp
  rm -r -- "${tmp:?}"   # delete the throw-away directory
)
# Your device names and sizes differ. The names above are stand-ins.
```

<Callout type="tip" title="Why it matters for testing">

Tutorial's own advice: print `lsblk -f` and `df -hT` at the start of each CI job. Then the log of a full-disk failure already has the facts.

</Callout>

<details>
<summary>Go deeper</summary>

| Term | Meaning |
|---|---|
| Partition | A slice of a disk. The partition table records where each slice starts and ends. <Cite n={15} /> |
| Sector | The unit in which a disk addresses its data. <Cite n={15} /> |
| MBR | Master Boot Record. The table sits in sector 0 and holds 4 primary partitions. It stores sector numbers in 32 bits, which allows about 2 TiB with 512-byte sectors. <Cite n={15} /> |
| GPT | GUID Partition Table, the modern standard, with checksums and UUIDs (unique IDs). A GPT disk keeps a protective MBR in sector 0. <Cite n={15} /> |

Why `df` and `du` can differ:

- `du` counts only the files that it can see. A mount can hide files below it. <Cite n={20} />
- On ext4, reserved blocks, which only root may use, lower the free space that `df` shows. <Cite n={33} /> <Cite n={6} />
- `df -T` prints the filesystem type. It is a GNU option. <Cite n={17} /> `du -x` stays on one filesystem. <Cite n={18} />

```bash
df -hT /                  # type and free space of the filesystem that holds /
du -xsh /var/log          # space of the files below one path (-x: one filesystem)
```

Tutorial's own advice: if `df` shows a full disk and `du` does not, a deleted file that a process still holds open may be the cause. `lsof +L1` lists such files. <Cite n={54} />

</details>

Block device হলো এমন একটি device, যেমন disk, যা kernel নির্দিষ্ট আকারের block-এ পড়ে ও লেখে। একটি পুরো disk-এর নাম হয় `/dev/sda`-এর মতো। Partition-এর নামে একটি সংখ্যা যোগ হয়, যেমন `/dev/sda1`। <Cite n={15} /> একটি disk তিন ধাপে ব্যবহারযোগ্য হয়: partition, filesystem তৈরি, আর mount। <Cite n={8} /> `df` পুরো filesystem-এর জায়গার হিসাব দেয়। <Cite n={17} /> `du` একটি path-এর নিচে যে file-গুলো দেখতে পায়, শুধু সেগুলোর জায়গা যোগ করে। <Cite n={18} />

## Filesystems

<Voices>
<Technical>

**Goal:** Find the filesystem type of a path, and build a filesystem in a file.

A filesystem is the structure that stores file names, data, and metadata on a device. <Cite n={4} /> `ext4` and `xfs` are journaling filesystems. `tmpfs` keeps its files in memory. <Cite n={23} /> <Cite n={36} /> <Cite n={37} /> `mkfs.<type>` builds a filesystem. <Cite n={32} /> It erases the start of the device, so the old filesystem is lost. <Cite n={30} /> Run `lsblk -f` first and check the device name.

```bash
findmnt -no FSTYPE /
```

**Try it:** build an ext4 filesystem in an 8 MiB file, not on a device. `-F` lets `mkfs.ext4` use a regular file, and `-q` makes it quiet. <Cite n={33} /> `-o value -s TYPE` prints only the type. <Cite n={16} /> Nothing is mounted.

```bash
(
  tmp=$(mktemp -d) && cd "$tmp" || exit 1   # make and enter a new, empty directory
  findmnt -no FSTYPE --target .     # tmpfs   (the type that holds this directory)
  dd if=/dev/zero of=disk.img bs=1M count=8 status=none   # an 8 MiB file
  mkfs.ext4 -q -F disk.img          # a filesystem inside the file
  blkid -o value -s TYPE disk.img   # ext4
  rm -r -- "${tmp:?}"   # delete the throw-away directory
)
# Your first line can be ext4 or another type.
```

<Callout type="tip" title="Why it matters for testing">

Tutorial's own advice: test the full-disk case. Writes to `/dev/full` always fail with `ENOSPC`. <Cite n={52} /> Try `echo x > /dev/full`.

</Callout>

<details>
<summary>Go deeper</summary>

- The kernel's virtual filesystem (VFS) layer sits above all types. <Cite n={4} />
- `btrfs` is copy-on-write (changes go to new blocks), with snapshots and checksums. `vfat` is the FAT type. <Cite n={23} /> <Cite n={37} />
- A journal is a log of metadata changes. After a crash, the kernel replays it to restore a consistent state. <Cite n={35} />
- `/proc/filesystems` lists the types that the kernel supports. A `nodev` mark means that the type needs no block device. <Cite n={46} />

## Inodes

<Voices>
<Technical>

**Goal:** Show that a hard link is a second name for the same inode.

An inode is a record that holds the metadata of one file. <Cite n={24} /> It does not store the file name. A directory entry links a name to an inode number. <Cite n={5} /> <Cite n={3} /> A hard link is a second name for the same inode. `ln` makes a hard link by default. <Cite n={28} />

```bash
ls -i
```

**Try it:** make a file and a hard link to it, and compare the inode numbers. `ls -i` prints the inode number. <Cite n={27} /> In GNU `stat -c`, `%i` is the inode number and `%h` is the link count. <Cite n={25} />

```bash
(
  tmp=$(mktemp -d) && cd "$tmp" || exit 1   # make and enter a new, empty directory
  echo data > a.txt
  ln a.txt b.txt                       # a second name for the same inode
  ls -i a.txt b.txt                    # 2166 a.txt
                                       # 2166 b.txt
  stat -c '%i inode, %h links' a.txt   # 2166 inode, 2 links
  rm -r -- "${tmp:?}"   # delete the throw-away directory
)
# Your inode number differs from 2166.
```

<Callout type="tip" title="Why it matters for testing">

Tutorial's own advice: a test that makes thousands of tiny files can use up the inodes and not the bytes. Add `df -i` to the failure report.

</Callout>

<details>
<summary>Go deeper</summary>

- A filesystem can run out of inodes while it still has free space. This happens with very many small files. `df -i` shows the inode use. <Cite n={17} /> <Cite n={6} />
- On `ext4`, the number of inodes is set when the filesystem is made. `mke2fs -i` sets the bytes per inode, and `-N` sets the count. <Cite n={33} />
- A `tmpfs` has its own limit, `nr_inodes`. <Cite n={38} />

## Mounts

<Voices>
<Technical>

**Goal:** Find the filesystem that holds a path, and its mount options.

A mount point is a directory where a filesystem is attached to the tree. A new mount hides the old contents of that directory. <Cite n={20} /> <Cite n={7} /> Before you mount over a directory, run `ls -A /path` to see its files. <Cite n={27} /> `findmnt` prints the mounts as a tree. `findmnt --target /path` shows the filesystem that holds a path. <Cite n={19} />

```bash
findmnt
```

**Try it:** ask `findmnt` which filesystems hold `/tmp` and `/`. `-o` picks the columns. <Cite n={19} /> The commands only read.

```bash
(
  findmnt --target /tmp -o TARGET,SOURCE,FSTYPE,OPTIONS
  # TARGET SOURCE FSTYPE OPTIONS
  # /tmp   tmpfs  tmpfs  rw,nosuid,nodev,nr_inodes=1048576,inode64,usrquota
  findmnt --target / -o TARGET,SOURCE,FSTYPE,OPTIONS
  # TARGET SOURCE    FSTYPE OPTIONS
  # /      /dev/sda2 ext4   rw,relatime
)
# Your sources and options differ. /dev/sda2 is a stand-in.
```

<Callout type="tip" title="Why it matters for testing">

| 3 | Type |
| 4 | Options, such as `ro`, `noexec`, `nofail` |

## Adding Disks

<Voices>
<Technical>

**Goal:** Rehearse the disk steps on a file, and check an `fstab` line before a reboot.

Add a disk in a fixed order: find it, partition it, make a filesystem, mount it, add a `UUID=` line to `/etc/fstab`, and check that file. <Cite n={8} /> <Cite n={22} /> `fdisk` rewrites the partition table, and `mkfs` erases the start of the partition. <Cite n={15} /> <Cite n={30} /> Both act on the device that you name, so a wrong name destroys data. Check the name with `lsblk -f` and keep a backup.

```bash
findmnt --verify
```

**Try it:** build a filesystem in a file, read its UUID, and check a test `fstab` line. `--tab-file` checks the test file, not `/etc/fstab`. <Cite n={19} /> The UUID belongs to a file, not to a device, so the check finds an error.

```bash
(
  tmp=$(mktemp -d) && cd "$tmp" || exit 1   # make and enter a new, empty directory

  mkdir mnt

  findmnt --verify --tab-file fstab.test
  # /tmp/tmp.XXXXXXXXXX/mnt
  #    [E] unreachable on boot required source: UUID=1b2c3d4e-...
  #
  # 0 parse errors, 1 error, 0 warnings
  rm -r -- "${tmp:?}"   # delete the throw-away directory
)
# Your directory name and UUID differ. util-linux 2.41 output.
```

<details>
<summary>Go deeper</summary>

The six steps on a real disk. Each step needs the result of the step before it.

1. Identify the new disk with `lsblk -f`. It shows no filesystem and no mount point. <Cite n={14} />
2. Partition it with `fdisk`. It edits the table in memory, `w` writes it, and `q` quits without saving. <Cite n={15} /> <Cite n={9} />
3. Make a filesystem with `mkfs.ext4` or another `mkfs.<type>`. <Cite n={32} />
4. Create a mount point and mount the partition. <Cite n={20} />
5. Read the UUID with `blkid` or `lsblk -f`. Device names follow the order of detection and can change, so use `UUID=` in `/etc/fstab`. <Cite n={16} /> <Cite n={22} />
6. Check `/etc/fstab` before a reboot. `findmnt --verify` is the recommended check. The manual calls `mount -a` a bad way to check. <Cite n={19} /> <Cite n={20} />

- `defaults` means the usual options. Add `nofail` for a disk that the boot does not need. <Cite n={22} />

# blkid /dev/sdX1         # 5. read the UUID

## Swap

<Voices>
<Technical>

**Goal:** Check the memory and swap use, and prepare a swap area in a file.

Swap is disk space that the kernel uses when memory is short. It can be a partition or a file. <Cite n={10} /> `swapon --show` lists the active swap areas. `free -h` shows memory and swap use. <Cite n={29} /> <Cite n={31} /> A new swap area needs two steps: `mkswap` prepares it, and `swapon` starts it. <Cite n={30} /> `mkswap` erases the start of its target, so check the target first. <Cite n={30} />

```bash
swapon --show
```

**Try it:** show memory and swap, then prepare a 1 MiB swap file and do not start it. `dd` from `/dev/zero` writes every block, so the file has no holes (unwritten gaps). <Cite n={29} />

```bash
(
  free -h
  #                total        used        free      shared  buff/cache   available
  # Mem:            14Gi        11Gi       1.0Gi       396Mi       2.5Gi       2.8Gi
  # Swap:          8.0Gi       1.8Gi       6.2Gi
  tmp=$(mktemp -d) && cd "$tmp" || exit 1   # make and enter a new, empty directory
  dd if=/dev/zero of=swap.img bs=1M count=1 status=none
  chmod 600 swap.img                 # only the owner can read and write it
  mkswap swap.img                    # prepare only: no swapon
  # Setting up swapspace version 1, size = 1020 KiB (1044480 bytes)
  # no label, UUID=2c3d4e5f-...
  blkid -o value -s TYPE swap.img    # swap
  rm -r -- "${tmp:?}"   # delete the throw-away directory
)
# Your memory numbers and UUID differ.
```

<Callout type="tip" title="Why it matters for testing">

Tutorial's own advice: record `free -h` in the test logs. Without swap, memory pressure may kill a test. With swap, it may only run slowly.

</Callout>

<details>
<summary>Go deeper</summary>

- `/proc/swaps` has the same list as `swapon --show`. <Cite n={48} />
- `cp` and `truncate` make files with holes, and `swapon` rejects them. The portable way to make the file is `dd` with `/dev/zero`. <Cite n={29} /> <Cite n={11} />
- To keep swap after a reboot, add an entry of type `swap` to `/etc/fstab`. <Cite n={29} />
- In the latest kernel docs, `vm.swappiness` takes 0 to 200 (older kernels: less), and the default is 60. A low value tells the kernel that swap IO is costly. <Cite n={40} />
- When the kernel runs out of memory, the OOM killer ends a process. <Cite n={40} /> A higher `oom_score` means a more likely victim. <Cite n={49} />
- `dd of=` writes into its target file or device. <Cite n={56} /> Check the target first.
- `swapoff` fails with an out-of-memory status when free memory cannot take the swapped pages back. <Cite n={29} /> Tutorial's own advice: it may also slow the host or start the OOM killer.

```bash
cat /proc/swaps                # the active swap areas, from the kernel
cat /proc/sys/vm/swappiness    # the current swappiness
cat /proc/$$/oom_score         # the OOM score of this shell ($$ is its process ID)
```

## LVM

<Voices>
<Technical>

**Goal:** Name the three LVM layers, and find an LV in the device tree.

LVM (Logical Volume Manager) builds virtual block devices from physical devices. A physical volume (PV) is a disk or partition given to LVM. A volume group (VG) is a pool of PVs. A logical volume (LV) is a part of a VG that acts like a partition: you format it and mount it. <Cite n={41} /> <Cite n={13} /> `pvs`, `vgs`, and `lvs` report on each layer. <Cite n={41} /> `lvreduce` destroys the data in the removed area, so back up first. <Cite n={44} />

```bash
lvs        # needs root and the lvm2 tools
```

**Try it:** `lsblk` lists every block device, except RAM disks, in a tree. <Cite n={14} /> An LV is a virtual block device, so it shows there too. <Cite n={41} />

```bash
(
  lsblk -e7 -o NAME,TYPE,SIZE      # -e7: hide the loop devices
  # NAME   TYPE  SIZE
  # sda    disk  100G
  # ├─sda1 part    1G
  # └─sda2 part   99G
)
# This machine has no LVM. With LVM, each LV is one more row of this tree.
# The names are stand-ins.
```

<Callout type="tip" title="Why it matters for testing">

Tutorial's own advice: take a snapshot before a destructive test run, to keep the data from before it. Remove it afterwards: it holds space.

</Callout>

<details>

**Goal:** Name the three LVM layers, and find an LV in the device tree.

LVM (Logical Volume Manager) makes virtual block devices from physical devices. A physical volume (PV) is a disk or partition that you give to LVM. A volume group (VG) is a pool of PVs. A logical volume (LV) is a part of a VG. It acts like a partition: you format it and mount it. <Cite n={41} /> <Cite n={13} /> `pvs`, `vgs`, and `lvs` show each layer. <Cite n={41} /> `lvreduce` destroys the data in the removed area, so make a backup first. <Cite n={44} />

**Try it:** `lsblk` lists every block device, except RAM disks, in a tree. <Cite n={14} /> An LV is a virtual block device, so it shows there too. <Cite n={41} />

```bash
(
  lsblk -e7 -o NAME,TYPE,SIZE      # -e7: hide the loop devices
  # NAME   TYPE  SIZE
  # sda    disk  100G
  # ├─sda1 part    1G
  # └─sda2 part   99G
)
# This machine has no LVM. With LVM, each LV is one more row of this tree.
```
