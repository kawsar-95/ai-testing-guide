# Working with Files

This stage covers the commands that create, copy, move, edit, link, and archive files. A tester needs them because every test run makes files: logs, reports, screenshots, and fixtures (fixed test data). One wrong command can destroy that data, so each section names the risk.

<PageMeta />

## Working with Files

<Voices>
<Technical>

**Goal:** Read the size and the link count of a file with `stat`.

Every file on a Linux filesystem (the structure that stores files on a disk) has an inode. An inode is a record of the metadata of the file, such as its owner, size, and timestamps. <Cite n={1} /> The name of a file is a hard link: a reference to that inode number. <Cite n={2} /> `stat` prints this data, and `-c` chooses the fields. <Cite n={4} /> `rm` has no recycle bin, so treat each removal as final. <Cite n={5} />

```bash
stat report.txt
```

**Try it:** print the size and the link count of a small file and an empty file. `%n` is the name, `%s` is the size in bytes, and `%h` is the number of hard links. <Cite n={4} />

```bash
(
  cd "$(mktemp -d)" || exit   # make and enter a new, empty directory
  echo "pass" > report.txt
  touch empty.txt
  stat -c '%n: %s bytes, %h hard links' report.txt empty.txt
  # report.txt: 5 bytes, 1 hard links
  # empty.txt: 0 bytes, 1 hard links
  rm -r "$PWD"                # delete the throw-away directory
)
```

<Callout type="tip" title="Why it matters for testing">

Tutorial's own advice: check the size of each test output file. A 0-byte report often means that the step crashed before it wrote data.

</Callout>

<details>
<summary>Go deeper</summary>

- `ls -l` lists files in the long format. <Cite n={3} /> `ls -li` adds the inode number. <Cite n={3} />
- In a `stat -c` format, `%i` is the inode number. <Cite n={4} />
- Tutorial's own advice: also check the modification time of each output file. In a CI log (the log of an automated test job), one `ls -l` of the artifact folder is a cheap check.

```bash
ls -li report.txt
stat -c '%n: %s bytes, %h hard links, inode %i' report.txt
```

</details>

## Creating Files and Directories

<Voices>
<Technical>

**Goal:** Make files and directories in a setup step that you can run two times.

`touch` creates an empty file when the name does not exist. If the file exists, `touch` only updates its times. <Cite n={6} /> `mkdir` reports an error if the directory exists, unless you add `-p`. With `-p`, it also makes the missing parent directories. <Cite n={7} /> A redirection with `>` also makes a file. <Cite n={8} />

Deletion and redirection lose data. `rm -r` deletes a directory and all of its contents, and `-f` never prompts. <Cite n={10} /> `>` cuts an existing file to zero size. <Cite n={8} /> Run `ls` on the path first.

```bash
mkdir -p results/2026/run1
```

**Try it:** run `mkdir -p` two times, overwrite a file with `>`, and delete a directory.

```bash
(
  cd "$(mktemp -d)" || exit   # make and enter a new, empty directory
  mkdir -p results/run1
  mkdir -p results/run1 && echo "second run: OK"   # second run: OK
  echo "first line" > hello.txt
  echo "new" > hello.txt
  cat hello.txt               # new  (> replaced the old text)
  rm -r results
  ls                          # hello.txt
  rm -r "$PWD"                # delete the throw-away directory
)
```

<Callout type="tip" title="Why it matters for testing">

Tutorial's own advice: start each test setup with `mkdir -p`. It succeeds when the folder exists, so a second run of the job does not fail.

</Callout>

<details>
<summary>Go deeper</summary>

| Command | Effect |
|---|---|
| `touch -c FILE` | Does not create a file. <Cite n={6} /> |
| `touch -d TIME FILE` | Sets a chosen time. <Cite n={6} /> |
| `cat > FILE` | Reads your text until you press Ctrl+D. <Cite n={9} /> |
| `rmdir DIR` | Removes only an empty directory. <Cite n={9} /> |
| `rm -I` | Asks one time before a recursive removal. <Cite n={10} /> |

`rm` deletes files, and it needs `-r` for a directory. <Cite n={10} />

```bash
touch -d '2026-01-15T10:00:00' old.log   # set a chosen time
cat > draft.txt                          # type text, then press Ctrl+D
```

Tutorial's own advice: use `touch -d` to build files with an old time when you test code that depends on the age of a file.

</details>

</Technical>

## Copying and Renaming

<Voices>
<Technical>

**Goal:** Copy and rename a file, and see that `cp` overwrites with no prompt.

`cp` makes a copy that is independent of the original. <Cite n={11} /> If the last argument is a directory, `cp` puts each source inside it. <Cite n={11} /> To rename a file, use `mv` with a new name. <Cite n={12} />

By default, `cp` replaces an existing destination file without a prompt. <Cite n={11} /> `mv` does the same. <Cite n={13} /> The old content is lost at once. Run `ls` on the destination first, or add `-i` to get a prompt. <Cite n={11} />

```bash
cp config.yml config.yml.bak
```

**Try it:** back up a file, change the file, copy it onto the backup again, and rename it. `-p` keeps the mode, owner, and times. <Cite n={11} />

```bash
(
  cd "$(mktemp -d)" || exit   # make and enter a new, empty directory
  echo "v1" > config.yml
  cp -p config.yml config.yml.bak
  echo "v2" > config.yml
  cp config.yml config.yml.bak   # no prompt
  cat config.yml.bak             # v2  (the v1 backup is gone)
  mv config.yml app.yml          # rename
  ls                             # app.yml  config.yml.bak
  rm -r "$PWD"                   # delete the throw-away directory
)
```

<Callout type="tip" title="Why it matters for testing">

Tutorial's own advice: copy a fixture before a test changes it, and compare the two files afterwards. Use `cp -p` or `cp -a`.

</Callout>

<details>
<summary>Go deeper</summary>

`cp` copies a directory only with `-r`, `-R`, or `-a`. <Cite n={11} />

| Option | Effect |
|---|---|
| `-i` | Ask before each overwrite. <Cite n={11} /> |
| `-n` | Skip a file that exists. <Cite n={11} /> |
| `-p` | Keep the mode (permission bits), owner, and times. <Cite n={11} /> |
| `-a` | Archive mode: copy a tree and keep as much as possible. <Cite n={11} /> |
| `-v` | Print what happens. <Cite n={11} /> |

The manual marks `-n` as deprecated, because its exit status (the number that a command returns to the shell) differs from other platforms. In newer versions, `--update=none` also skips existing files. <Cite n={11} />

```bash
mkdir -p /tmp/archive
cp -i report.txt /tmp/archive/
cp -a fixtures /tmp/fixtures-copy   # copy a tree, keep modes and times
```

</details>

</Technical>

`cp` এমন একটি copy তৈরি করে, যা original-এর উপর নির্ভর করে না। শেষ argument যদি একটি directory হয়, তাহলে `cp` প্রতিটি source সেই directory-র ভেতরে রাখে। <Cite n={11} /> File-এর নাম বদলাতে নতুন নাম দিয়ে `mv` ব্যবহার করুন। <Cite n={12} />

Default হিসেবে `cp` কোনো prompt ছাড়াই existing destination file replace করে। <Cite n={11} /> `mv`-ও একই কাজ করে। <Cite n={13} /> পুরোনো content সাথে সাথে হারিয়ে যায়। আগে destination-এর উপর `ls` চালান, অথবা prompt পেতে `-i` যোগ করুন। <Cite n={11} />

**চেষ্টা করুন:** একটি file-এর backup নিন, file-টি বদলান, আবার backup-এর উপর copy করুন, আর নাম বদলান। `-p` mode, owner, আর time রেখে দেয়। <Cite n={11} />

```bash
(
  cd "$(mktemp -d)" || exit   # make and enter a new, empty directory
  echo "v1" > config.yml
  cp -p config.yml config.yml.bak
  echo "v2" > config.yml
  cp config.yml config.yml.bak   # no prompt
  cat config.yml.bak             # v2  (the v1 backup is gone)
  mv config.yml app.yml          # rename
  ls                             # app.yml  config.yml.bak
  rm -r "$PWD"                   # delete the throw-away directory
)
```

<Callout type="tip" title="টেস্টিং-এ কেন দরকার">

Tutorial-এর নিজস্ব পরামর্শ: test একটি fixture বদলানোর আগে সেটির copy রাখুন, পরে দুটি file তুলনা করুন। `cp -p` বা `cp -a` ব্যবহার করুন।

</Callout>

<details>
<summary>আরও জানুন</summary>

Directory copy করতে `-r`, `-R`, অথবা `-a` লাগে। এই option-গুলোও কাজে আসে <Cite n={11} />:

- `-i`: প্রতিটি overwrite-এর আগে জিজ্ঞেস করে।
- `-n`: existing file বাদ দেয়। Manual `-n`-কে deprecated বলে, কারণ এর exit status অন্য platform থেকে আলাদা। নতুন version-এ `--update=none`-ও existing file বাদ দেয়।
- `-p`: mode (permission bit), owner, আর time রেখে দেয়।
- `-a`: archive mode; একটি পুরো tree copy করে এবং যতটা সম্ভব রেখে দেয়।
- `-v`: কী হচ্ছে তা দেখায়।

## Moving Files and Directories

<Voices>
<Technical>

**Goal:** Move many files into a directory with one command.

`mv` moves a file or directory. If the last argument is a directory, `mv` moves each source into it. <Cite n={12} /> A shell pattern such as `*.log` moves many files in one command. <Cite n={13} /> Without `-i` or `-n`, `mv` replaces a writable destination file and gives no warning. <Cite n={13} /> The old content is lost, so check the destination with `ls` first.

```bash
mv build/app.log logs/
```

**Try it:** make two logs and a note, and move only the logs. The shell expands `*.log` to the matching names.

```bash
(
  cd "$(mktemp -d)" || exit   # make and enter a new, empty directory
  mkdir logs
  touch run1.log run2.log notes.txt
  mv *.log logs/
  ls        # logs  notes.txt
  ls logs   # run1.log  run2.log
  rm -r "$PWD"                # delete the throw-away directory
)
```

<Callout type="tip" title="Why it matters for testing">

Tutorial's own advice: build your output on the same filesystem as its final place. Then `mv` is a fast rename, not a slow copy that can stop halfway.

</Callout>

<details>
<summary>Go deeper</summary>

- To rename a directory, use a new name. If that name exists, the directory moves inside it. <Cite n={13} />
- On one filesystem, `mv` usually only renames the entry. <Cite n={12} />
- Between two filesystems (separate storage areas that are mounted at different paths), `mv` copies like `cp -a` and then removes the original. <Cite n={12} />
- If a copy fails, `mv` removes the partial copy. A move of many directories can stop halfway. <Cite n={12} />
- Tutorial's own advice: a CI workspace and `/tmp` can be on different filesystems.

```bash
mv -t archive/ run1.log run2.log     # target directory first
mv -i old-name.txt new-name.txt      # ask before an overwrite
```

</details>

## Editing Files

<Voices>
<Technical>

**Goal:** Add lines to a file without an editor, with `>>` and a here document.

You edit a text file in a terminal with a text editor. Vi, Vim, Nano, and Emacs are the common ones. <Cite n={14} /> For a small change, you may need no editor. The `>>` operator adds text to the end of a file. <Cite n={8} /> The `>` operator replaces the whole content. <Cite n={8} /> A typo of `>` for `>>` erases your config, so make a backup with `cp -p` first.

```bash
echo "retries=3" >> app.conf
```

**Try it:** back up a file, append a line, and write two lines with a here document: the text up to the `EOF` line goes to the command. <Cite n={8} />

```bash
(
  cd "$(mktemp -d)" || exit   # make and enter a new, empty directory
  echo "retries=3" > app.conf
  cp -p app.conf app.conf.bak   # back up first
  echo "timeout=30" >> app.conf
  cat app.conf                  # retries=3
                                # timeout=30
  cat > extra.conf <<'EOF'
debug=false
port=8080
EOF
  cat extra.conf                # debug=false
                                # port=8080
  rm -r "$PWD"                  # delete the throw-away directory
)
```

- `>>` makes the file if it does not exist. <Cite n={8} />

<Voices>
<Technical>

**Goal:** Save a change in Vim with `:wq`, or drop it with `:q!`.

Vim is a modal editor: the same key does a different job in each mode. <Cite n={18} /> Vim starts in Normal mode, where keys are commands. Press `i` for Insert mode, where keys are text, and `Esc` to return. <Cite n={18} /> A `:` key opens Command-line mode. <Cite n={19} /> Vim changes a buffer, the copy of the file in memory, and writes it back. <Cite n={20} /> The file changes only when you write. `:q!` drops all changes, and Vim makes no backup file unless you set it up. <Cite n={18} />

```bash

# i     start Insert mode, then type your text
# Esc   go back to Normal mode
# :wq   write the file and quit (type it, then press Enter)
# :q!   quit and drop all changes
```

**Try it:** delete line 1 with no screen, then quit with `:q!` and with `:wq`. Your `vi` must be Vim.

```bash

  vi -es -c '1d' -c 'q!' notes.txt

                              # two  (q! dropped the change)
  vi -es -c '1d' -c 'wq' notes.txt

)
```

## Soft and Hard Links

<Voices>
<Technical>

**Goal:** Make a hard link and a symlink, and see which one still works after you delete the original.

A hard link is another name for a file. The link and the original share one inode, so they are the same file. <Cite n={23} /> The data stays while at least one name remains. <Cite n={24} /> A symbolic link (symlink) is a special file that holds the path of another file. <Cite n={2} /> If its target is missing, the link is dangling. <Cite n={2} /> `ln -f` removes an existing destination file first, so a wrong link name can destroy a real file. <Cite n={23} />

```bash
ln -s releases/v2 current
```

**Try it:** make both links, compare the inode numbers, delete the original, and read both links. `%i` is the inode number, and `%h` is the link count. <Cite n={4} />

```bash
(
  cd "$(mktemp -d)" || exit   # make and enter a new, empty directory
  echo "data" > data.txt
  ln data.txt hard.txt        # hard link
  ln -s data.txt soft.txt     # symlink
  stat -c '%i %h %n' data.txt hard.txt
  # 2230 2 data.txt
  # 2230 2 hard.txt           (your inode number differs)
  rm data.txt
  cat hard.txt                # data
  cat soft.txt                # cat: soft.txt: No such file or directory
  rm -r "$PWD"                # delete the throw-away directory
)
```

<Callout type="tip" title="Why it matters for testing">

Tutorial's own advice: if a test reports a missing file, run `ls -l` and look for a link whose target is gone.

</Callout>

<details>
<summary>Go deeper</summary>

- A hard link cannot point to a directory. It cannot cross a filesystem either, because inode numbers are unique only inside one filesystem. <Cite n={2} />
- The inode keeps a link count. <Cite n={1} />
- A symlink can point to a directory and cross filesystems. <Cite n={2} />
- A relative symlink resolves from the directory that holds the link, not from your current directory. <Cite n={23} />
- `-s` makes a symlink, and `-r` with `-s` makes the path relative to the link. <Cite n={23} />
- `ls -i` prints the inode number, and two names with one number are hard links. <Cite n={3} /> <Cite n={24} />
- Tutorial's own advice: use a symlink such as `current` to switch builds without changing test paths. Without `-n`, `ln` makes the new link inside the old target directory. <Cite n={23} />

```bash
ln data.txt data-hard.txt            # hard link: ln TARGET LINK_NAME
mkdir -p releases/v3
ln -sfn releases/v3 current          # switch current to v3; -n replaces the link itself
```

</details>

</Technical>

## Archiving and Compressing

<Voices>
<Technical>

**Goal:** Pack a directory into a `.tar.gz` file, list it, and extract it into a new directory.

An archive is one file that holds many files. Compression makes data smaller. `tar` makes archives, and `gzip` compresses. <Cite n={25} /> <Cite n={26} /> With `-z`, `tar` passes the archive through `gzip`. <Cite n={25} /> `-c` creates an archive, `-t` lists it, `-x` extracts it, and `-f` names it. <Cite n={25} /> Extraction can overwrite files that exist, so extract an unknown archive into a new empty directory. <Cite n={28} />

```bash
tar -czf results.tar.gz results/
```

**Try it:** pack a directory, list the archive, and extract it into a new directory. `-C DIR` changes to `DIR` before the work. <Cite n={25} />

```bash
(
  cd "$(mktemp -d)" || exit   # make and enter a new, empty directory
  mkdir results && echo "ok" > results/run.log
  tar -czf results.tar.gz results/
  tar -tzf results.tar.gz     # results/
                              # results/run.log
  mkdir unpack
  tar -xzf results.tar.gz -C unpack
  ls unpack/results           # run.log
  rm -r "$PWD"                # delete the throw-away directory
)
```

<Callout type="tip" title="Why it matters for testing">

Tutorial's own advice: pack the logs of a CI run into one `.tar.gz` for upload. In a later step, run `tar -tzf` on it to check its files.

</Callout>

<details>
<summary>Go deeper</summary>

- `gzip` replaces each file with a `.gz` file, and `-k` keeps the original. <Cite n={26} />
- ZIP is another format: it packs and compresses in one step. <Cite n={27} /> Use `unzip` for a ZIP file with many members. <Cite n={26} />
- It is often unsafe to extract names that are absolute or start with `../`. List with `-t` first. <Cite n={28} />
- `tar -c` erases an existing archive of the same name. <Cite n={28} />

```bash
gzip -k app.log                          # compress; without -k, gzip deletes app.log
gzip -d old-run.log.gz                   # decompress; deletes the .gz file (-k keeps it)
```

</details>

Archive হলো এমন একটি file, যা অনেক file ধরে রাখে। Compression data-কে ছোট করে। `tar` archive তৈরি করে, আর `gzip` compress করে। <Cite n={25} /> <Cite n={26} /> `-z` দিলে `tar` archive-টি `gzip`-এর মধ্য দিয়ে পাঠায়। `tar`-এ `-c` archive তৈরি করে, `-t` তালিকা দেখায়, `-x` extract করে, আর `-f` archive-এর নাম দেয়। <Cite n={25} /> Extraction existing file overwrite করতে পারে, তাই অচেনা archive একটি নতুন খালি directory-তে extract করুন। <Cite n={28} />

**চেষ্টা করুন:** একটি directory pack করুন, archive-এর তালিকা দেখুন, আর একটি নতুন directory-তে extract করুন। `-C DIR` কাজের আগে `DIR`-এ যায়। <Cite n={25} />

```bash
(
  cd "$(mktemp -d)" || exit   # make and enter a new, empty directory
  mkdir results && echo "ok" > results/run.log
  tar -czf results.tar.gz results/
  tar -tzf results.tar.gz     # results/
                              # results/run.log
  mkdir unpack
  tar -xzf results.tar.gz -C unpack
  ls unpack/results           # run.log
  rm -r "$PWD"                # delete the throw-away directory
)
```

<Callout type="tip" title="টেস্টিং-এ কেন দরকার">

Tutorial-এর নিজস্ব পরামর্শ: CI run-এর log একটি `.tar.gz`-এ pack করুন। পরের step-এ `tar -tzf` দিয়ে এর file-গুলো check করুন।

</Callout>

<summary>আরও জানুন</summary>

- `gzip` প্রতিটি file-কে একটি `.gz` file দিয়ে replace করে, আর `-k` original রেখে দেয়। <Cite n={26} />
- ZIP আরেকটি format, যা এক ধাপে pack আর compress করে। <Cite n={27} /> অনেক member-ওয়ালা ZIP file-এর জন্য `unzip` ব্যবহার করুন। <Cite n={26} />
- Absolute নাম বা `../` দিয়ে শুরু হওয়া নাম extract করা প্রায়ই unsafe। `tar -c` একই নামের existing archive-ও মুছে দেয়। আগে `-t` দিয়ে তালিকা দেখুন। <Cite n={28} />
