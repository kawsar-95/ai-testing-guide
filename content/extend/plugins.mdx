# Plugins & Marketplaces

A plugin packs skills, subagents, hooks, and MCP servers into one install. This page shows how to find, install, and review plugins, what the Superpowers plugin really is, and how a QA team can share its own setup through a small marketplace.

<PageMeta />

## What a plugin bundles

<Voices>
<Technical>

A Claude Code plugin is a directory of skills, agents, hooks, MCP servers, or other components that Claude Code installs and loads as one unit. <Cite n={1} /> It can contain: <Cite n={1} />

- Skills
- Agents (subagents)
- Hooks
- A hooks module (a "mod")
- MCP servers

The manifest, `.claude-plugin/plugin.json`, gives the plugin its name. <Cite n={1} /> A plugin skill runs with the plugin name in front, for example `/my-plugin:review`. <Cite n={1} />

Example: a QA team plugin.

```text
qa-toolkit/
├── .claude-plugin/
│   └── plugin.json          ← name: "qa-toolkit"
├── skills/
│   ├── find-bug/SKILL.md     ← /qa-toolkit:find-bug
│   └── test-design/SKILL.md
├── agents/
│   ├── qa-agent.md
│   └── sdet-agent.md
├── hooks/
│   └── hooks.json           ← protect .env and migrations
└── .mcp.json                ← Jira and test database servers
```

Plugin subagents ignore the `hooks`, `mcpServers`, and `permissionMode` frontmatter fields. <Cite n={2} /> So in a plugin, put the hooks in `hooks/hooks.json` and the servers in `.mcp.json`.

<Callout type="warning" title="Common mistake: short MCP names in plugin agents">

A server in a plugin's `.mcp.json` registers as `plugin:<plugin>:<server>`. <Cite n={3} /> Its tools are named `mcp__plugin_<plugin>_<server>__<tool>`. Use this full name in a subagent's `tools` field. <Cite n={3} />

- So the plugin copies of `qa-agent` and `sdet-agent` need the full tool names, for example `mcp__plugin_qa-toolkit_atlassian__<tool>` and `mcp__plugin_qa-toolkit_db__<tool>`, not `mcp__atlassian` or `mcp__db`.
- Or omit `tools`, and the agent inherits all tools. <Cite n={2} />
- Or keep the servers in the project `.mcp.json`, not in the plugin, and keep the short names.

Plugin skills are namespaced, for example `/qa-toolkit:find-bug`. <Cite n={1} /> The docs do not show how a plugin agent's `skills:` field names a skill from the same plugin. Test the plugin copies of the agents before you share the plugin.

</Callout>

### Plugin or loose files?

- Use a plugin when you want several skills, subagents, hooks, or MCP servers packaged as one unit, when you share a setup with a team, or when you publish versioned releases. <Cite n={1} />
- Skills, subagents, hooks, and MCP servers also work without a plugin. <Cite n={1} /> For one project, files in `.claude/` are enough. See [Settings & the .claude Folder](/configure/settings/).
- An enabled plugin is part of every session, not only the sessions where you use it. The names and descriptions of its skills and agents are in context on each turn. <Cite n={1} />
- `claude plugin details <name>` shows a plugin's components and its projected token cost. <Cite n={4} /> Plugins in Anthropic's official marketplace show a **Context cost** estimate in `/plugin`. <Cite n={1} />

</Technical>

## Marketplaces

<Voices>
<Technical>

A marketplace is a repository or directory with a `.claude-plugin/marketplace.json` file. The file lists plugins and where to get each one. It is a catalog, not a hosted store. <Cite n={1} />

Anthropic runs three general marketplaces: <Cite n={5} />

| Marketplace | Name | Repository |
|---|---|---|
| Official | `claude-plugins-official` | `anthropics/claude-plugins-official` <Cite n={5} /> |
| Community | `claude-community` | `anthropics/claude-plugins-community` <Cite n={5} /> |
| Demo | `claude-code-plugins` | `anthropics/claude-code` <Cite n={5} /> |

- Claude Code adds the official marketplace the first time you start an interactive terminal session, unless a managed policy or `CLAUDE_CODE_DISABLE_OFFICIAL_MARKETPLACE_AUTOINSTALL` blocks it. <Cite n={5} />
- Most plugins in the official marketplace come from partners and other authors, not from Anthropic. <Cite n={5} />
- Anthropic does not review third-party marketplaces. <Cite n={5} /> Claude Code accepts the official and community names only for marketplaces from `github.com/anthropics/` repositories, so a third-party marketplace cannot present itself as an Anthropic one. <Cite n={6} />
- A plugin marketplace is not Claude Marketplace (claude.com/marketplace). You cannot add that website with `/plugin marketplace add`. <Cite n={1} />

<Callout type="warning" title="Community directory sites">

Websites that list thousands of plugins, skills, and MCP servers are community projects. They have no official standing, and a high install count is not a review. Read the plugin before you install it. See [Review before you install](#review-before-you-install).

</Callout>

</Technical>

## Install and manage

<Voices>
<Technical>

### In a session

Run `/plugin` to open the plugin menu. The **Discover** tab lists the plugins that you can install. <Cite n={7} /> You can also pass a subcommand such as `list`, `install`, `enable`, or `disable`. <Cite n={8} />

```text
/plugin install commit-commands@claude-plugins-official
```

In a session, this command does not install at once. It opens the plugin's details in the `/plugin` panel, so that you can review it and choose a scope first. <Cite n={7} />

To add a marketplace, run `/plugin marketplace add <source>`. <Cite n={7} /> The source can be: <Cite n={7} />

- A GitHub repository, `owner/repo`. Add `#ref` to pin a branch or tag.
- A git URL.
- A local path that starts with `./`.
- The `https://` URL of a hosted `marketplace.json`.

`/plugin market` is a shorter form of `/plugin marketplace`. <Cite n={7} /> Run `/reload-plugins` to apply plugin changes in a running session. <Cite n={7} />

### From the shell

| Command | What it does |
|---|---|
| `claude plugin install <plugin>@<marketplace>` | Installs a plugin. `--scope` takes `user`, `project`, or `local`. The default is `user`. <Cite n={4} /> |
| `claude plugin uninstall <plugin>` | Removes a plugin. Use the `--scope` that you installed it at. <Cite n={6} /> |
| `claude plugin list` | Lists installed plugins. `--json` gives machine-readable output. <Cite n={4} /> |
| `claude plugin details <name>` | Shows the components and the projected token cost. <Cite n={4} /> |
| `claude plugin validate <path>` | Checks a plugin or marketplace manifest. `--strict` treats warnings as errors, for CI. <Cite n={4} /> |
| `claude plugin update <plugin>@<marketplace>` | Updates one plugin. No command updates every plugin at once. <Cite n={7} /> |
| `claude plugin marketplace list` | Lists marketplaces. `update <name>` and `remove <name>` also work. <Cite n={7} /> |

- Removing a marketplace uninstalls its plugins. <Cite n={7} />
- In a `claude -p` run, `/plugin` does not run. Use the `claude plugin` commands instead. Plugins that you already installed still load. <Cite n={7} />
- `--plugin-dir <path>` loads a plugin from a folder for one session only, without installing it. <Cite n={4} />

### Scopes

| Scope | Who gets it | Stored in |
|---|---|---|
| User | You, in all your projects | `~/.claude/settings.json` <Cite n={7} /> |
| Project | Everyone on the repository | `.claude/settings.json` <Cite n={7} /> |
| Local | You, in this repository | `.claude/settings.local.json` <Cite n={7} /> |

If a plugin is set at more than one scope, local overrides project, and project overrides user. <Cite n={7} />

A committed project-scope entry turns the plugin on for your teammates, but it does not download it to their machines. <Cite n={7} /> Each tester runs this one time: <Cite n={7} />

```bash
claude plugin install qa-toolkit@qa-team-plugins --scope project
```

### Updates

Auto-update is on by default for `claude-plugins-official`, for the other official marketplace names except `knowledge-work-plugins` and `first-party-plugins`, and for marketplaces added from claude.ai. It is off by default for every other marketplace, including the community marketplace, third-party marketplaces, and local development marketplaces. <Cite n={7} /> An update can change files that you already reviewed. <Cite n={6} /> Review the plugin again after an update.

</Technical>

## Review before you install

<Voices>
<Technical>

<Callout type="danger" title="A plugin runs code as you">

A plugin that you install can run any code on your machine with your user privileges. <Cite n={6} /> Permission rules and the sandbox cover Claude's tool calls, not the code that a plugin runs by itself. Claude Code runs hooks, monitors, MCP servers, and LSP servers outside the sandbox. <Cite n={6} />

</Callout>

A plugin can run hooks (shell commands), monitors, mods (JavaScript), MCP and LSP servers, and the files in its `bin/` folder. Claude Code adds that folder to the `PATH` of the Bash tool's shell. Its skills, commands, and agents enter Claude's context as instructions. <Cite n={6} />

The docs give these review steps: <Cite n={6} />

1. Run `claude plugin marketplace list` to see where the marketplace comes from.
2. Read the **Will install** pane in `/plugin`.
3. Read `hooks/hooks.json`, `.mcp.json`, and every file in `bin/`. The **Will install** pane shows that a hook exists, but not what it runs. <Cite n={6} />
4. Run `claude --plugin-dir <dir> plugin details <name>`.

A marketplace's name tells you who publishes the catalog, not what each plugin in it does. Review a third-party plugin from any marketplace. <Cite n={6} /> If you no longer trust a plugin, uninstall it with the scope that you installed it at. If you do not trust the owner, remove the marketplace too. <Cite n={6} />

</Technical>

আপনি যে plugin install করেন, তা আপনার user privilege নিয়ে আপনার machine-এ যেকোনো code চালাতে পারে। <Cite n={6} /> Permission rule ও sandbox শুধু Claude-এর tool call নিয়ন্ত্রণ করে, plugin নিজে যে code চালায় তা নয়। Claude Code hooks, monitors, MCP servers ও LSP servers sandbox-এর বাইরে চালায়। <Cite n={6} />

একটি plugin hooks (shell command), monitors, mods (JavaScript), MCP ও LSP server, এবং তার `bin/` folder-এর file চালাতে পারে। Claude Code ওই folder-টি Bash tool-এর shell-এর `PATH`-এ যোগ করে। Plugin-এর skills, commands ও agents instruction হিসেবে Claude-এর context-এ ঢোকে। <Cite n={6} />

Docs-এ review-এর এই ধাপগুলো আছে: <Cite n={6} />

1. Marketplace কোথা থেকে এসেছে দেখতে `claude plugin marketplace list` চালান।
2. `/plugin`-এ **Will install** pane পড়ুন।
3. `hooks/hooks.json`, `.mcp.json` এবং `bin/`-এর প্রতিটি file পড়ুন। **Will install** pane শুধু দেখায় যে একটি hook আছে, সেটি কী চালায় তা দেখায় না।
4. `claude --plugin-dir <dir> plugin details <name>` চালান।

Marketplace-এর নাম বলে catalog-টি কে publish করে, প্রতিটি plugin কী করে তা বলে না। যেকোনো marketplace-এর third-party plugin review করুন। কোনো plugin-কে আর বিশ্বাস না করলে, যে scope-এ install করেছিলেন সেই scope দিয়ে uninstall করুন। Owner-কে বিশ্বাস না করলে marketplace-টিও remove করুন। <Cite n={6} />

</Bangla>
</Voices>

## Build a team marketplace

<Voices>
<Technical>

A marketplace file lives at `.claude-plugin/marketplace.json`. Its required top-level fields are `name`, `owner`, and `plugins`. <Cite n={11} /> Each plugin entry needs a `name` and a `source`. The `description` is the line shown in `/plugin`. <Cite n={12} />

Example: a QA team marketplace, in the format of the docs example. <Cite n={12} />

```json
{
  "name": "qa-team-plugins",
  "description": "Plugins for the QA team",
  "owner": { "name": "QA Team" },
  "plugins": [
    {
      "name": "qa-toolkit",
      "source": "./plugins/qa-toolkit",
      "description": "QA skills, qa-agent and sdet-agent, and file-protection hooks"
    }
  ]
}
```

- A relative `source` path resolves from the marketplace root, the folder that holds `.claude-plugin/`. <Cite n={11} />
- The entry `name` must be the same as the `name` in the plugin's `plugin.json`. <Cite n={12} />
- Other source types are `github`, `git-subdir`, `url`, `archive`, `npm`, and `command`. <Cite n={12} />
- Official and community names such as `claude-plugins-official` are reserved, and so are names that imitate them. <Cite n={11} />

Test it locally before you share it: <Cite n={12} />

```bash
claude plugin validate ./qa-team-plugins
claude plugin marketplace add ./qa-team-plugins
claude plugin install qa-toolkit@qa-team-plugins
claude plugin list
```

</Technical>

A relative `source` path starts from the marketplace root. This is the folder that holds `.claude-plugin/`. <Cite n={11} /> The entry `name` must be the same as the `name` in the `plugin.json` file of the plugin. <Cite n={12} /> You cannot use the official and community names, such as `claude-plugins-official`, or names that imitate them. <Cite n={11} />
