# Parametric Memory

Parametric memory is what a model "just knows". The knowledge sits in the model weights, not in a file or a database. You cannot open it like a file, and you cannot easily edit one fact in it.

<PageMeta />

## In plain words

<Voices>
<Technical>

A large pre-trained language model stores factual knowledge in its parameters <Cite n={1} />. The parameters are the weights of the model. This store is parametric memory.

The model uses this memory without a lookup. The knowledge is encoded in the weights and comes out during the normal computation of an answer <Cite n={3} />. The model does not go to an external store to recall it <Cite n={3} />.

Compare this with [retrieval memory](/agent-memory/retrieval-memory/). There, the agent fetches text from a store and puts it in the prompt. Parametric memory has no such step. The knowledge is already "inside" the model.

</Technical>
<Layman>

A big language model learns facts during training and keeps them in its numbers, the weights <Cite n={1} />. We call this parametric memory.

The model does not look anything up to use it. The facts are part of the weights and come out while the model makes its answer <Cite n={3} />. No outside store is needed <Cite n={3} />.

[Retrieval memory](/agent-memory/retrieval-memory/) is different. There, the agent first fetches text and adds it to the prompt. With parametric memory, the knowledge is already inside the model.

</Layman>
<Bangla>

বড় pre-trained language model তার parameter-এর মধ্যে factual knowledge রাখে <Cite n={1} />। parameter মানে model-এর weights। এই জায়গাটাই parametric memory।

model এই memory ব্যবহার করতে কিছু খোঁজে না। knowledge weights-এর মধ্যে encode করা থাকে, আর উত্তর তৈরির সাধারণ হিসাবের সময়ই বের হয়ে আসে <Cite n={3} />। মনে করতে model-কে বাইরের কোনো store-এ যেতে হয় না <Cite n={3} />।

[retrieval memory](/agent-memory/retrieval-memory/)-এর সাথে তুলনা করুন। সেখানে agent একটা store থেকে text এনে prompt-এ বসায়। parametric memory-তে এই ধাপ নেই। knowledge আগে থেকেই model-এর "ভেতরে" থাকে।

</Bangla>
</Voices>

## Where it comes from

<Voices>
<Technical>

The 7 memory names of this module follow the infographic "7 Types of Agent Memory". Research papers group memory in other ways. CoALA has a working memory and three long-term memories: episodic, semantic, and procedural <Cite n={2} />.

"Parametric memory" is a term from machine learning research, not from human psychology. The RAG paper by Lewis et al. uses it. In that paper, the parametric memory is the pre-trained sequence-to-sequence model itself <Cite n={1} />. A 2025 survey of agent memory also uses the term. It defines it as memory stored in the model parameters and accessed implicitly <Cite n={3} />.

CoALA does not have a "parametric memory" type. It says that the LLM weights hold implicit procedural knowledge <Cite n={2} />. So CoALA puts the weights under [procedural memory](/agent-memory/procedural-memory/). The infographic keeps parametric memory as a separate type, as the RAG paper and the survey do.

</Technical>
<Layman>

The 7 names in this module come from the infographic "7 Types of Agent Memory". Research papers sort memory in other ways. CoALA has a working memory and three long-term memories: episodic, semantic, and procedural <Cite n={2} />.

"Parametric memory" comes from AI research, not from the study of the human mind. The RAG paper by Lewis et al. uses the name for the trained model itself <Cite n={1} />. A 2025 survey uses it too: memory that lives in the model's numbers and that the model uses without a lookup <Cite n={3} />.

CoALA has no type with this name. It says the model weights hold how-to knowledge <Cite n={2} />, so it counts them as [procedural memory](/agent-memory/procedural-memory/). The infographic keeps parametric memory apart, like the RAG paper and the survey.

</Layman>
<Bangla>

এই module-এর ৭টা memory-র নাম infographic "7 Types of Agent Memory" থেকে নেওয়া। research paper-গুলো memory-কে অন্যভাবে ভাগ করে। CoALA-তে একটা working memory আর তিনটা long-term memory আছে: episodic, semantic, আর procedural <Cite n={2} />।

"Parametric memory" নামটা মানুষের মনোবিজ্ঞান থেকে আসেনি, এসেছে machine learning research থেকে। Lewis et al.-এর RAG paper এই নাম ব্যবহার করে। সেখানে parametric memory মানে pre-trained sequence-to-sequence model নিজেই <Cite n={1} />। ২০২৫ সালের একটা agent memory survey-ও এই নাম ব্যবহার করে। সেখানে এটা হলো model parameter-এ রাখা memory, যা model সরাসরি না খুঁজেই ব্যবহার করে <Cite n={3} />।

CoALA-তে "parametric memory" নামে কোনো type নেই। CoALA বলে, LLM weights-এ implicit procedural knowledge থাকে <Cite n={2} />। তাই CoALA weights-কে [procedural memory](/agent-memory/procedural-memory/)-এর মধ্যে রাখে। infographic, RAG paper আর survey-এর মতো, parametric memory-কে আলাদা type হিসেবে রাখে।

</Bangla>
</Voices>

## How an agent gets it

<Voices>
<Technical>

An agent does not write to parametric memory while it works. The memory comes from training.

```text
training data ──► pre-training ──► weights (parametric memory)
                                        │
                     fine-tuning ───────┤  (changes the weights)
                                        ▼
prompt ──────────► model computes an answer with the weights ──► answer
                   (no lookup in an external store)
```

**Pre-training.** A large language model gets its factual knowledge in pre-training, and stores it in its parameters <Cite n={1} />.

**Fine-tuning.** CoALA says that fine-tuning can adapt the weights to the domain of an agent during its lifetime <Cite n={2} />.

**Added parameter modules.** The 2025 survey also describes "external" parametric memory: extra parameter modules that are added to a model <Cite n={3} />. The survey says that this way can avoid the catastrophic forgetting that full fine-tuning can cause <Cite n={3} />.

Each change of parametric memory is a training step. CoALA notes that to store text in a memory is cheaper and quicker than to update the parameters <Cite n={2} />. Tutorial's own view: for this reason, most agents keep new facts in [semantic memory](/agent-memory/semantic-memory/) or [retrieval memory](/agent-memory/retrieval-memory/), not in the weights.

Each model has a knowledge cutoff. Anthropic calls the "reliable knowledge cutoff" the date through which the knowledge of a model is most extensive and reliable <Cite n={4} />. The training data cutoff is a broader range <Cite n={4} />. The dates change with each model, so look them up in the [models overview](https://platform.claude.com/docs/en/models/overview).

</Technical>
<Layman>

An agent does not add to its parametric memory while it works. This memory comes from training.

**Pre-training.** The model learns its facts in pre-training and keeps them in its weights <Cite n={1} />.

**Fine-tuning.** CoALA says that more training (fine-tuning) can adjust the weights to the agent's field of work <Cite n={2} />.

**Added modules.** The 2025 survey also describes extra parameter parts that are added to a model <Cite n={3} />. The survey says this can avoid the "catastrophic forgetting" that full fine-tuning can cause <Cite n={3} />.

So every change to this memory is training. CoALA says that to save text in a memory is cheaper and faster than to change the weights <Cite n={2} />. Tutorial's own view: that is why most agents keep new facts in [semantic memory](/agent-memory/semantic-memory/) or [retrieval memory](/agent-memory/retrieval-memory/), not in the weights.

Every model has a knowledge cutoff. Anthropic's "reliable knowledge cutoff" is the date up to which the model's knowledge is widest and most reliable <Cite n={4} />. The training data cutoff covers a broader range <Cite n={4} />. The dates are different for each model, so check the [models overview](https://platform.claude.com/docs/en/models/overview).

</Layman>
<Bangla>

agent কাজ করার সময় parametric memory-তে কিছু লেখে না। এই memory আসে training থেকে।

**Pre-training।** বড় language model pre-training-এর সময় factual knowledge শেখে আর parameter-এ রাখে <Cite n={1} />।

**Fine-tuning।** CoALA বলে, agent-এর জীবদ্দশায় fine-tuning দিয়ে weights-কে agent-এর domain অনুযায়ী মানিয়ে নেওয়া যায় <Cite n={2} />।

**যোগ করা parameter module।** ২০২৫ সালের survey "external" parametric memory-র কথাও বলে: model-এর সাথে যোগ করা বাড়তি parameter module <Cite n={3} />। survey বলে, এভাবে full fine-tuning-এর catastrophic forgetting এড়ানো যায় <Cite n={3} />।

তাই parametric memory-র প্রতিটা পরিবর্তন মানে training। CoALA বলে, weights বদলানোর চেয়ে memory-তে text রাখা সস্তা আর দ্রুত <Cite n={2} />। Tutorial-এর নিজের মত: এই কারণে বেশিরভাগ agent নতুন fact weights-এ না রেখে [semantic memory](/agent-memory/semantic-memory/) বা [retrieval memory](/agent-memory/retrieval-memory/)-তে রাখে।

প্রতিটা model-এর একটা knowledge cutoff আছে। Anthropic-এর "reliable knowledge cutoff" হলো সেই তারিখ, যে পর্যন্ত model-এর knowledge সবচেয়ে বিস্তৃত আর নির্ভরযোগ্য <Cite n={4} />। training data cutoff আরও বড় একটা সময়সীমা <Cite n={4} />। তারিখগুলো প্রতিটা model-এ আলাদা, তাই আপনি [models overview](https://platform.claude.com/docs/en/models/overview) দেখে নিন।

</Bangla>
</Voices>

## A real-life example

<Voices>
<Technical>

This example is the tutorial's own illustration. It is not from a source.

A tester asks a coding assistant, such as Claude Code, to write a test with a test library. The tester gives no docs and no file of the library. The assistant writes the code from its weights only.

The code uses an option that was removed in a new release of the library. The new release came after the knowledge cutoff of the model. The assistant did not see it in training. The weights still hold the old API.

The parametric memory gave a confident answer, but the answer is out of date. Parametric-only models need more training to update their behavior as the world changes <Cite n={1} />. The assistant also cannot show where its answer came from. The RAG paper calls this provenance an open research problem <Cite n={1} />.

The fix is not in the weights. The tester gives the assistant the current docs, or lets it read the installed package. Then the answer comes from text in the [working memory](/agent-memory/working-memory/), and the tester can check that text.

</Technical>
<Layman>

This example is the tutorial's own. It is not from a source.

A tester asks a coding assistant, such as Claude Code, to write a test with a test library. The tester gives no docs. The assistant writes the code only from what it learned in training.

The code uses an option that a newer version of the library removed. That version came out after the model's knowledge cutoff, so the model never saw it. Its weights still hold the old way.

The answer sounds sure, but it is old. A model that has only parametric memory needs more training to keep up with the world <Cite n={1} />. It also cannot show where its answer came from. The RAG paper says this is still an open research problem <Cite n={1} />.

The fix is not to change the weights. The tester gives the assistant the current docs, or lets it read the installed package. Then the answer comes from text in the [working memory](/agent-memory/working-memory/), and the tester can check that text.

</Layman>

একজন টেস্টার Claude Code-এর মতো একটা coding assistant-কে একটা test library দিয়ে test লিখতে বলেন। তিনি library-র কোনো docs বা file দেন না। assistant শুধু তার weights থেকে code লেখে।

code-এ এমন একটা option আছে, যা library-র নতুন release-এ বাদ দেওয়া হয়েছে। নতুন release model-এর knowledge cutoff-এর পরে এসেছে। training-এ model এটা দেখেনি। weights-এ এখনও পুরোনো API আছে।

parametric memory আত্মবিশ্বাসের সাথে উত্তর দিয়েছে, কিন্তু উত্তরটা পুরোনো। শুধু parametric memory-ওয়ালা model-কে দুনিয়ার পরিবর্তনের সাথে তাল মেলাতে আবার training দিতে হয় <Cite n={1} />। assistant দেখাতেও পারে না উত্তরটা কোথা থেকে এসেছে। RAG paper বলে, এই provenance এখনও একটা open research problem <Cite n={1} />।

সমাধান weights-এ নেই। টেস্টার assistant-কে বর্তমান docs দেন, অথবা installed package পড়তে দেন। তখন উত্তর আসে [working memory](/agent-memory/working-memory/)-র text থেকে, আর আপনি সেই text যাচাই করতে পারেন।

## Common mistakes

<Voices>
<Technical>

**To trust the weights for new facts.** A parametric-only model needs more training to update its behavior as the world changes <Cite n={1} />. The knowledge of a model is most reliable only up to its reliable knowledge cutoff <Cite n={4} />. Tutorial's own view: do not trust the weights for anything after that date.

**To expect an easy edit.** Models of this kind cannot easily expand or revise their memory <Cite n={1} />. You cannot "correct one fact" in the weights the way you edit a file.

**To ask the model why it knows something.** These models cannot easily give insight into their predictions <Cite n={1} />. LLM parameters are hard to interpret <Cite n={2} />. An answer from the weights has no source that you can check.

**To ignore hallucinations.** Parametric memory can produce hallucinations <Cite n={1} />. A fluent answer is not a correct answer.

**To fine-tune without a regression check.** Full fine-tuning can cause catastrophic forgetting <Cite n={3} />. The model can lose skills that it had before.

**To mix up the two cutoffs.** The reliable knowledge cutoff and the training data cutoff are different dates <Cite n={4} />. Use the reliable one when you decide which facts to trust.

</Technical>
<Layman>

**Trusting the model for new facts.** A model with only parametric memory needs more training to keep up with the world <Cite n={1} />. Its knowledge is most reliable only up to its reliable knowledge cutoff <Cite n={4} />. Tutorial's own view: do not trust it for anything after that date.

**Expecting an easy fix.** This kind of memory is hard to grow or correct <Cite n={1} />. You cannot fix one fact in the weights the way you fix a line in a file.

**Asking the model how it knows.** The model cannot easily explain its answers <Cite n={1} />. Its numbers are hard to read <Cite n={2} />. So there is no source you can check.

**Ignoring made-up answers.** Parametric memory can produce hallucinations <Cite n={1} />. An answer that sounds good is not always right.

**Fine-tuning without re-testing old tasks.** Full fine-tuning can cause catastrophic forgetting <Cite n={3} />. The model can lose old skills.

**Mixing up the two cutoffs.** The reliable knowledge cutoff and the training data cutoff are not the same <Cite n={4} />. Use the reliable one to decide which facts to trust.

</Layman>
<Bangla>

**নতুন fact-এর জন্য weights-এর ওপর ভরসা করা।** শুধু parametric memory-ওয়ালা model-কে দুনিয়ার পরিবর্তনের সাথে তাল মেলাতে আবার training দিতে হয় <Cite n={1} />। model-এর knowledge শুধু তার reliable knowledge cutoff পর্যন্ত সবচেয়ে নির্ভরযোগ্য <Cite n={4} />। Tutorial-এর নিজের মত: ওই তারিখের পরের কোনো বিষয়ে weights-এর ওপর ভরসা করবেন না।

**সহজে বদলানো যাবে ভাবা।** এই ধরনের model সহজে তার memory বাড়াতে বা সংশোধন করতে পারে না <Cite n={1} />। file-এর একটা লাইনের মতো করে weights-এর একটা fact ঠিক করা যায় না।

**model-কে জিজ্ঞেস করা সে কীভাবে জানে।** এই model সহজে তার prediction-এর ব্যাখ্যা দিতে পারে না <Cite n={1} />। LLM parameter বোঝা কঠিন <Cite n={2} />। তাই weights থেকে আসা উত্তরের এমন কোনো source নেই, যা আপনি যাচাই করতে পারেন।

**hallucination উপেক্ষা করা।** parametric memory hallucination তৈরি করতে পারে <Cite n={1} />। সাবলীল উত্তর মানেই সঠিক উত্তর নয়।

**regression check ছাড়া fine-tuning করা।** full fine-tuning-এ catastrophic forgetting হতে পারে <Cite n={3} />। model আগের দক্ষতা হারাতে পারে।

**দুই cutoff গুলিয়ে ফেলা।** reliable knowledge cutoff আর training data cutoff আলাদা তারিখ <Cite n={4} />। কোন fact-এ ভরসা করবেন, তা ঠিক করতে reliable cutoff ব্যবহার করুন।

</Bangla>
</Voices>

## What a tester can check

<Voices>
<Technical>

You cannot open the weights, so you test parametric memory from the outside, with questions and their answers.

<Callout type="tip" title="Tutorial advice">

- Ask about an event after the knowledge cutoff. Check that the agent says it does not know, or uses a tool to look it up.
- Ask the same fact question many times. Compare the answers. Different answers show weak knowledge.
- After a model upgrade, run the old fact questions again as a regression suite.
- After fine-tuning, run the old tasks again. Check that the model did not forget them.
- For each important fact, check that the agent gives a source from a document or a tool, not from the weights only.

</Callout>

</Technical>
<Layman>

You cannot look inside the weights. So you test this memory from the outside, with questions.

<Callout type="tip" title="Tutorial advice">

- Ask about something after the knowledge cutoff. The agent should say it does not know, or look it up with a tool.
- Ask the same fact question many times and compare the answers. If they differ, the knowledge is weak.
- After a model upgrade, ask the old fact questions again.
- After fine-tuning, run the old tasks again. Check that the model still does them.
- For important facts, check that the agent shows a source, not only its own memory.

</Callout>

</Layman>
<Bangla>

আপনি weights খুলে দেখতে পারেন না। তাই parametric memory বাইরে থেকে, প্রশ্ন আর উত্তর দিয়ে টেস্ট করুন।

<Callout type="tip" title="Tutorial advice">

- knowledge cutoff-এর পরের কোনো ঘটনা নিয়ে প্রশ্ন করুন। দেখুন agent বলে কিনা যে সে জানে না, অথবা tool দিয়ে খুঁজে নেয় কিনা।
- একই fact-এর প্রশ্ন অনেকবার করুন। উত্তরগুলো মিলিয়ে দেখুন। উত্তর আলাদা হলে knowledge দুর্বল।
- model upgrade-এর পরে পুরোনো fact-এর প্রশ্নগুলো regression suite হিসেবে আবার চালান।
- fine-tuning-এর পরে পুরোনো task আবার চালান। দেখুন model সেগুলো ভুলে যায়নি।
- গুরুত্বপূর্ণ fact-এর জন্য দেখুন agent কোনো document বা tool থেকে source দেয় কিনা, শুধু weights থেকে নয়।

</Callout>

</Bangla>
</Voices>

## Key words

| Term | Meaning |
|---|---|
| Parametric memory | Knowledge stored in the model parameters and used without a lookup in an external store <Cite n={3} /> |
| Parameters (weights) | The numbers of a trained model. A pre-trained model stores factual knowledge in them <Cite n={1} /> |
| Non-parametric memory | Memory outside the weights, for example a document index that the agent searches <Cite n={1} />. See [retrieval memory](/agent-memory/retrieval-memory/) |
| Fine-tuning | More training that adapts the weights to a domain <Cite n={2} /> |
| Catastrophic forgetting | A risk of full fine-tuning: the model loses what it knew before <Cite n={3} /> |
| Reliable knowledge cutoff | The date through which a model's knowledge is most extensive and reliable <Cite n={4} /> |
| Training data cutoff | The broader range of the data used in training <Cite n={4} /> |
| Hallucination | A confident answer that is not true. Parametric memory can produce one <Cite n={1} /> |
