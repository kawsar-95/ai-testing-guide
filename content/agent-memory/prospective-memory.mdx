# Prospective Memory

The other six types of memory look back: at the context, at facts, at past events, at skills. Prospective memory looks forward. It is the memory of a task that the agent must do later, at the right time or after the right event, while it does other work.

<PageMeta />

## In plain words

<Voices>
<Technical>

Prospective memory is memory for a future action. In people, it means to remember to do something later, for example to take a medicine <Cite n={1} />. Its opposite is retrospective memory: the memory of past events <Cite n={1} />.

For an agent, prospective memory is the ability to do a planned action at a specific future cue or state. The agent must do this while other work continues <Cite n={2} />.

An intention has two parts: what to do, and when to do it. A failure in either part is a failure of prospective memory. The task "remind me at 3 pm to check the deploy" has a "what" (check the deploy) and a "when" (3 pm).

The name "prospective memory" follows the infographic "7 Types of Agent Memory". Research papers group agent memory differently. For example, CoALA has working memory and three long-term memories: episodic, semantic, and procedural <Cite n={5} />. CoALA has no prospective memory <Cite n={5} />. This topic comes from psychology <Cite n={1} />, and one benchmark applies it to LLM agents <Cite n={2} />.

</Technical>
<Layman>

Prospective memory means you remember to do something later. A person uses it to remember to take a medicine later <Cite n={1} />. The opposite is to remember what happened before <Cite n={1} />.

An agent uses it to do a planned job at the right moment. It must do this while it works on other things <Cite n={2} />.

Each planned job has two parts: what to do, and when. If the agent forgets either part, the job fails. In "remind me at 3 pm to check the deploy", the "what" is the deploy check and the "when" is 3 pm.

The name comes from the infographic "7 Types of Agent Memory". Research papers sort memory in other ways. CoALA, for example, has working memory plus episodic, semantic, and procedural memory, and no prospective memory <Cite n={5} />. The idea comes from psychology <Cite n={1} />. One benchmark uses it for LLM agents <Cite n={2} />.

</Layman>
<Bangla>

Prospective memory হলো ভবিষ্যতের কোনো কাজের memory। মানুষের ক্ষেত্রে এর মানে পরে কোনো কাজ করার কথা মনে রাখা, যেমন পরে ওষুধ খাওয়া <Cite n={1} />। এর বিপরীত হলো retrospective memory, অর্থাৎ অতীতের ঘটনা মনে রাখা <Cite n={1} />।

Agent-এর ক্ষেত্রে prospective memory হলো ভবিষ্যতের নির্দিষ্ট কোনো cue বা অবস্থায় পরিকল্পিত কাজটি করার ক্ষমতা। অন্য কাজ চলতে থাকার সময়েই agent-কে এটা করতে হয় <Cite n={2} />।

প্রতিটি intention-এর দুটি অংশ আছে: কী করতে হবে, আর কখন করতে হবে। যেকোনো একটি অংশে ভুল হলে সেটা prospective memory-র ব্যর্থতা। "বিকেল ৩টায় deploy চেক করার কথা মনে করিয়ে দাও" কাজে "কী" হলো deploy চেক, আর "কখন" হলো ৩টা।

"Prospective memory" নামটি infographic "7 Types of Agent Memory" থেকে নেওয়া। Research paper-গুলো memory-কে অন্যভাবে ভাগ করে। যেমন CoALA-তে আছে working memory এবং তিনটি long-term memory: episodic, semantic, procedural <Cite n={5} />। CoALA-তে prospective memory নেই <Cite n={5} />। ধারণাটি psychology থেকে এসেছে <Cite n={1} />, আর একটি benchmark এটিকে LLM agent-এ প্রয়োগ করে <Cite n={2} />।

## Where it comes from

<Voices>
<Technical>

**In psychology.** The APA Dictionary of Psychology defines prospective memory as remembering to do something in the future <Cite n={1} />. It contrasts this with retrospective memory, which is remembering past events <Cite n={1} />.

**In AI agents.** In the tutorial's own research, CoALA, the RAG paper, and the LangChain memory overview do not use this term. PM-Bench, a 2026 benchmark, applies it to LLM agents <Cite n={2} />. PM-Bench is a preprint on arXiv. It is not peer reviewed yet.

PM-Bench uses the classic split into two kinds <Cite n={2} />:

| Kind | The cue | Example |
|---|---|---|
| Time-based | A clock time or a time window | "At 9 am, run the smoke tests." |
| Event-based | An event or a state | "When the build fails, tell me." |

The examples in the table are the tutorial's own.

PM-Bench also separates two questions: what the agent remembers, and when it acts <Cite n={2} />. An agent can remember the task and still act at the wrong moment.

**Plans are a related idea.** In the Generative Agents paper, a plan is a future sequence of actions. Plans help keep the agent's behavior consistent over time <Cite n={4} />. Each plan has a location, a start time, and a duration <Cite n={4} />. That paper does not call plans "prospective memory". Tutorial's own view: a plan is one way to store future intentions.

</Technical>

## How an agent gets it

<Voices>
<Technical>

A language model does not watch the clock. It acts only when it gets a prompt. So prospective memory needs a part outside the model that stores the intention and wakes the agent.

Claude Code has scheduled tasks. For a one-time reminder, you describe it in plain words. Claude then schedules a task that fires one time and deletes itself after it runs <Cite n={3} />. Claude Code stores the task and sends the prompt when it is due <Cite n={3} />. The model does not remember the time.

```text
You:          "In 30 minutes, check if the nightly test run finished."
                  |
                  v
Claude Code:  stores a one-shot task (prompt + due time)
                  |
   ... the session continues with other work ...
                  |
                  v
Due time:     Claude Code sends the stored prompt to Claude
                  |
                  v
Claude:       checks the test run, then the task deletes itself
```

The diagram is the tutorial's own summary of the flow.

These rules apply to tasks in a session <Cite n={3} />:

- A task fires only while Claude Code runs and is idle. If you close the terminal or the session exits, the tasks stop firing <Cite n={3} />.
- If a due time passes while Claude is busy, the task fires one time when Claude becomes idle. It does not fire one time for each missed interval <Cite n={3} />.
- A recurring task expires 7 days after you create it <Cite n={3} />.
- Times use your local timezone <Cite n={3} />.
- A task can run at a time that is a little different from its schedule <Cite n={3} />.

Session tasks are not durable. For durable schedules, the same page points to cloud and Desktop scheduled tasks <Cite n={3} />.

Other agent setups store intentions in other ways. Generative Agents keep plans with a start time <Cite n={4} />. PM-Bench compares setups, for example a "todo-ledger" and a "heartbeat" that wakes the agent at intervals <Cite n={2} />. These are the paper's own names.

</Technical>

## A real-life example

<Voices>
<Technical>

This example is the tutorial's own illustration. The details are invented.

A tester works with Claude Code on a flaky checkout test. At 2 pm, the tester writes: "At 4 pm, remind me to rerun the checkout suite against staging." Claude schedules a one-shot task <Cite n={3} />.

At 3:55 pm, the tester starts a long refactor in the same session. Claude is still busy at 4 pm. The task fires one time when Claude becomes idle, not at 4 pm exactly <Cite n={3} />. The reminder arrives a few minutes late, but it arrives.

On another day, the tester closes the terminal at 3:30 pm. The task does not fire, because session tasks fire only while Claude Code runs <Cite n={3} />. Nothing warns the tester at 4 pm. Tutorial's own view: for a reminder that must not be lost, use a durable schedule, not a session task.

The same tester also writes: "When the build turns red, tell me which test broke." This intention is event-based, not time-based <Cite n={2} />. The agent must notice the event while it does other work <Cite n={2} />. The intention is clear, but the cue can come at any moment.

</Technical>

## Common mistakes

<Voices>
<Technical>

**To assume the model keeps time.** In Claude Code, the scheduler stores the task and sends the prompt <Cite n={3} />. If the scheduler stops, the reminder does not come. Session tasks stop when the session exits <Cite n={3} />.

**To expect exact timing.** A scheduled task can run at a time that differs from its schedule <Cite n={3} />. A busy agent also delays the task until it is idle <Cite n={3} />. A test that expects the exact second will fail.

**To expect one run for each missed interval.** After a busy period, a missed task fires one time, not once per missed interval <Cite n={3} />.

**To forget the expiry.** A recurring session task expires 7 days after its creation <Cite n={3} />. A "daily" check does not run for ever.

**To ignore the timezone.** Claude Code reads times in your local timezone <Cite n={3} />. A team in several timezones can read "9 am" in different ways.

**To test only the "what".** An agent can remember the task and still act at the wrong time. PM-Bench separates these two parts for this reason <Cite n={2} />.

**To trust that agents are good at this.** In PM-Bench, the best method reached only a 65.1% F1 score <Cite n={2} />. No single strategy was best for all models <Cite n={2} />. These numbers are for one 2026 benchmark and its own setup. They are not a general error rate.

</Technical>
<Layman>

**Thinking the model keeps time.** In Claude Code, the scheduler keeps the task and sends the prompt <Cite n={3} />. If the scheduler stops, the reminder does not come. Session tasks stop when the session ends <Cite n={3} />.

**Expecting the exact time.** A task can run at a time a little different from its schedule <Cite n={3} />. A busy agent also waits until it is free <Cite n={3} />. A test that wants the exact second will fail.

**Expecting one run for each missed time.** After a busy period, a missed task runs one time only <Cite n={3} />.

**Forgetting that tasks end.** A repeating session task ends 7 days after you make it <Cite n={3} />. A "daily" check does not go on for ever.

**Ignoring the timezone.** Claude Code reads times in your local timezone <Cite n={3} />. People in other timezones can understand "9 am" in other ways.

**Testing only the "what".** An agent can remember the job and still do it at the wrong time. PM-Bench looks at these two parts apart for this reason <Cite n={2} />.

**Thinking agents are good at this.** In PM-Bench, the best method got only a 65.1% F1 score <Cite n={2} />. No one method was best for all models <Cite n={2} />. These numbers come from one 2026 benchmark and its own setup. They are not a general error rate.

</Layman>
<Bangla>

**Model সময় রাখে, এমন ধরে নেওয়া।** Claude Code-এ scheduler task রাখে এবং prompt পাঠায় <Cite n={3} />। Scheduler থেমে গেলে reminder আসে না। Session শেষ হলে session task-ও থেমে যায় <Cite n={3} />।

**একদম সঠিক সময় আশা করা।** একটি scheduled task তার schedule থেকে আলাদা সময়ে চলতে পারে <Cite n={3} />। ব্যস্ত agent idle না হওয়া পর্যন্ত task পিছিয়ে দেয় <Cite n={3} />। যে test ঠিক সেকেন্ড আশা করে, সেটা fail করবে।

**প্রতিটি মিস হওয়া interval-এর জন্য একবার করে চলা আশা করা।** ব্যস্ত সময়ের পরে মিস হওয়া task মাত্র একবার চলে <Cite n={3} />।

**মেয়াদ শেষ হওয়ার কথা ভুলে যাওয়া।** Recurring session task তৈরির ৭ দিন পরে শেষ হয়ে যায় <Cite n={3} />। একটি "daily" check চিরকাল চলে না।

**Timezone উপেক্ষা করা।** Claude Code সময় আপনার local timezone অনুযায়ী পড়ে <Cite n={3} />। বিভিন্ন timezone-এর একটি টিম "সকাল ৯টা" ভিন্নভাবে বুঝতে পারে।

**শুধু "কী" test করা।** Agent কাজটা মনে রাখলেও ভুল সময়ে করতে পারে। এই কারণেই PM-Bench এই দুটি অংশ আলাদা করে দেখে <Cite n={2} />।

**Agent এ কাজে ভালো, এমন বিশ্বাস করা।** PM-Bench-এ সেরা পদ্ধতিও মাত্র 65.1% F1 score পেয়েছে <Cite n={2} />। কোনো একটি strategy সব model-এর জন্য সেরা ছিল না <Cite n={2} />। এই সংখ্যাগুলো ২০২৬ সালের একটি benchmark এবং তার নিজের setup-এর। এগুলো কোনো সাধারণ error rate নয়।

</Bangla>
</Voices>

## What a tester can check

<Voices>
<Technical>

Test the "what" and the "when" apart, and test both time-based and event-based intentions.

<Callout type="tip" title="Tutorial advice">

- Ask for a reminder at a set time. Check that it fires one time, near that time, in the right timezone.
- Cancel or move a reminder. Check that the old one does not fire.
- Keep the agent busy at the due time. Check that the reminder fires one time after the work ends.
- Close the session before the due time. Check what happens, and check that the docs match it.
- Give an event-based intention, for example "when the build fails, tell me". Make the event happen while the agent does other work.
- Check the content of the action, not only the timing: the agent must do the right task.

</Callout>

</Technical>
<Layman>

Test the "what" and the "when" one at a time. Test jobs that start at a time and jobs that start with an event.

<Callout type="tip" title="Tutorial advice">

- Ask for a reminder at a set time. Check that it comes one time, close to that time, in the right timezone.
- Cancel or move a reminder. Check that the old one does not come.
- Keep the agent busy at the set time. Check that the reminder comes one time after the work ends.
- Close the session before the set time. See what happens, and check that the docs say the same.
- Give a job that starts with an event, like "when the build fails, tell me". Make the event happen while the agent does other work.
- Check what the agent does, not only when: it must do the right job.

</Callout>

</Layman>
<Bangla>

"কী" এবং "কখন" আলাদা করে test করুন। Time-based এবং event-based দুই ধরনের intention-ই test করুন।

<Callout type="tip" title="Tutorial advice">

- নির্দিষ্ট সময়ের জন্য একটি reminder চান। দেখুন সেটা একবার, ওই সময়ের কাছাকাছি, সঠিক timezone-এ আসে কিনা।
- একটি reminder cancel বা সরিয়ে দিন। দেখুন পুরনোটা আর আসে না কিনা।
- নির্ধারিত সময়ে agent-কে ব্যস্ত রাখুন। দেখুন কাজ শেষে reminder একবার আসে কিনা।
- নির্ধারিত সময়ের আগে session বন্ধ করুন। কী হয় দেখুন, এবং docs-এর সাথে মেলে কিনা যাচাই করুন।
- একটি event-based intention দিন, যেমন "build fail করলে আমাকে জানাও"। Agent অন্য কাজ করার সময় ঘটনাটি ঘটান।
- শুধু সময় নয়, কাজের বিষয়বস্তুও দেখুন: agent-কে সঠিক কাজটাই করতে হবে।

</Callout>

</Bangla>
</Voices>

## Key words

| Term | Meaning |
|---|---|
| Prospective memory | Memory for an action to do in the future |
| Retrospective memory | Memory of past events |
| Intention | A planned action: what to do and when |
| Time-based cue | A clock time or interval that starts the action |
| Event-based cue | An event or state that starts the action |
| One-shot task | A Claude Code scheduled task that fires one time and deletes itself |
| Recurring task | A scheduled task that repeats; in a Claude Code session it expires after 7 days |
| Plan | In Generative Agents, a future sequence of actions with a location, a start time, and a duration |
| PM-Bench | A 2026 benchmark (preprint) that tests prospective memory in LLM agents |
