# Working Memory

Working memory is what an agent has "in mind" right now: the task, the last messages, and the tool results of the current step. It has a limited size, and a new session starts without it. This is topic 1 of 7. The 7 names follow the infographic "7 Types of Agent Memory". Research papers group memory in other ways.

<PageMeta />

## In plain words

<Voices>
<Technical>

Working memory holds the information that the agent uses for the current step <Cite n={1} />. It is short-term <Cite n={1} />. The agent does not keep it for the next session <Cite n={3} />.

For a large language model (LLM), Anthropic calls the context window the model's "working memory" <Cite n={3} />. The context window is different from the training data of the model <Cite n={3} />. The system prompt, the messages, the tool results, and the tool definitions all use space in it <Cite n={3} />.

The 7 names of this module follow the infographic. Research papers group memory differently. For example, the CoALA paper has working memory and three types of long-term memory: episodic, semantic, and procedural <Cite n={1} />. The other topics of this module, such as [semantic memory](/agent-memory/semantic-memory/) and [episodic memory](/agent-memory/episodic-memory/), describe the long-term side.

</Technical>
<Layman>

Working memory is what the agent uses for the step it is doing now <Cite n={1} />. It is short-term <Cite n={1} />. The agent does not keep it for the next session <Cite n={3} />.

For a large language model (LLM), Anthropic calls the context window the model's "working memory" <Cite n={3} />. This is not the data that the model learned in training <Cite n={3} />. The system prompt, the messages, the tool results, and the tool definitions all take space in it <Cite n={3} />.

The 7 names of this module come from the infographic. Research papers sort memory in other ways. The CoALA paper, for example, has working memory and three long-term types: episodic, semantic, and procedural <Cite n={1} />. The other topics of this module, such as [semantic memory](/agent-memory/semantic-memory/) and [episodic memory](/agent-memory/episodic-memory/), explain the long-term side.

</Layman>

Working memory হলো সেই তথ্য, যা agent এখনকার step-এর জন্য ব্যবহার করে <Cite n={1} />। এটা short-term <Cite n={1} />। পরের session-এর জন্য agent এটা রাখে না <Cite n={3} />।

## Where it comes from

<Voices>
<Technical>

**In psychology.** The term comes from the study of human memory. Working memory keeps information for a short time, in a state that is easy to use <Cite n={2} />. The common model is from Baddeley and Hitch (1974). In that model, working memory stores and changes information for tasks such as learning, reasoning, and comprehension <Cite n={2} />. Its central executive has a limited capacity <Cite n={2} />.

**In AI agents.** The CoALA paper uses the same name for a module of a language agent. Working memory keeps the active information for the current decision cycle <Cite n={1} />. It holds the inputs, knowledge from reasoning or from long-term memory, and data from the previous cycle <Cite n={1} />. CoALA calls it the central hub that connects the other parts of the agent <Cite n={1} />. The idea is older than LLMs. In the Soar architecture, working memory holds the recent input, the goals, and the results of internal reasoning <Cite n={1} />.

**Two views.** CoALA defines working memory as a module of the agent. It does not say that it is the context window. The Anthropic docs give the second view: the context window is the model's working memory <Cite n={3} />. Tutorial's own view: in a simple chat agent, the two views are close, because the agent puts its active information into the prompt.

</Technical>
<Layman>

**In psychology.** The name comes from research on human memory. Working memory keeps information for a short time, ready to use <Cite n={2} />. The best-known model is from Baddeley and Hitch (1974). In it, working memory holds and changes information for tasks such as learning, reasoning, and understanding <Cite n={2} />. The part that controls it can handle only a limited amount <Cite n={2} />.

**In AI agents.** The CoALA paper uses the same name for one part of a language agent. It keeps the active information for the current decision cycle <Cite n={1} />. That is the inputs, knowledge from reasoning or from long-term memory, and data from the last cycle <Cite n={1} />. CoALA calls it the central hub that links the other parts <Cite n={1} />. The idea is older than LLMs. In the Soar architecture, working memory holds the recent input, the goals, and the results of the agent's own reasoning <Cite n={1} />.

**Two views.** For CoALA, working memory is a part of the agent, not the context window. The Anthropic docs give the other view: the context window is the model's working memory <Cite n={3} />. Tutorial's own view: in a simple chat agent, the two are close, because the agent puts its active information into the prompt.

</Layman>
<Bangla>

**Psychology-তে।** নামটা এসেছে মানুষের memory নিয়ে গবেষণা থেকে। Working memory অল্প সময়ের জন্য তথ্য রাখে, এমনভাবে যে তা সহজে ব্যবহার করা যায় <Cite n={2} />। সবচেয়ে প্রচলিত model-টা Baddeley আর Hitch-এর (1974)। এই model-এ working memory learning, reasoning আর comprehension-এর মতো কাজের জন্য তথ্য রাখে আর বদলায় <Cite n={2} />। এর central executive-এর capacity সীমিত <Cite n={2} />।

**AI agent-এ।** CoALA paper একই নাম language agent-এর একটা module-এর জন্য ব্যবহার করে। এটা এখনকার decision cycle-এর active তথ্য রাখে <Cite n={1} />। এর মধ্যে আছে input, reasoning বা long-term memory থেকে পাওয়া knowledge, আর আগের cycle-এর data <Cite n={1} />। CoALA এটাকে central hub বলে, যা agent-এর অন্য অংশগুলো জোড়ে <Cite n={1} />। ধারণাটা LLM-এর চেয়ে পুরোনো। Soar architecture-এ working memory রাখে সাম্প্রতিক input, goal আর internal reasoning-এর ফলাফল <Cite n={1} />।

**দুটো দৃষ্টিভঙ্গি।** CoALA working memory-কে agent-এর একটা module হিসেবে define করে। এটা context window-এর সমান বলে না। Anthropic docs দ্বিতীয় দৃষ্টিভঙ্গি দেয়: context window হলো model-এর working memory <Cite n={3} />। Tutorial-এর নিজের মত: সাধারণ chat agent-এ দুটো প্রায় একই, কারণ agent তার active তথ্য prompt-এ রাখে।

</Bangla>
</Voices>

## How an agent gets it

<Voices>
<Technical>

An LLM agent fills its working memory each time that it sends a request to the model. All parts of the request use space in the context window: the system prompt, each message, the tool results, images, documents, and the tool definitions <Cite n={3} />.

```text
one request = the working memory of one step

+--------------------------------------------+
| system prompt                              |
| tool definitions                           |
| message 1 (user)                           |
| message 2 (assistant, tool call)           |
| message 3 (tool result)                    |
| ...                                        |
| message N (the newest user message)        |
+--------------------------------------------+
         |
         v
   model response  ->  usage (tokens used)
```

The agent adds the new answer and the next tool result, then sends a new request. So the working memory grows with each step <Cite n={3} />. The space is limited. When the output reaches the context window limit, Claude 4.5 models and newer stop with `stop_reason: "model_context_window_exceeded"` <Cite n={3} />. Earlier models return a validation error <Cite n={3} />.

Two facts help you to measure it. Each response reports the tokens of the request in its `usage` field <Cite n={3} />. You can also estimate a request before you send it with the token counting API <Cite n={3} />.

Tutorial's own view: what is not in the request, the model cannot use in that step. Facts from earlier sessions must come back in through a long-term store, for example [retrieval memory](/agent-memory/retrieval-memory/).

</Technical>

Tutorial-এর নিজের মত: যা request-এ নেই, model সেই step-এ তা ব্যবহার করতে পারে না। আগের session-এর তথ্য long-term store থেকে ফিরিয়ে আনতে হয়, যেমন [retrieval memory](/agent-memory/retrieval-memory/)।

## A real-life example

<Voices>
<Technical>

This example is the tutorial's own illustration. It shows no measured result.

A tester asks a coding assistant, such as Claude Code, to fix a flaky login test. The working memory of the first step has the system prompt, the tool definitions, and the request. The assistant reads the test file and the log of the failed run. Both tool results go into the next request.

The tester adds a rule early in the session: "Do not change the test data file." Then the session runs for a long time. The assistant reads many files and long logs. The rule is now far from the end of the context.

The rule is still in the context window. But more context is not always better: accuracy and recall go down as the token count grows <Cite n={3} />. Anthropic calls this "context rot" <Cite n={3} />. So the tester checks the final diff for the test data file, and does not trust that the assistant remembered the rule.

The next day, the tester opens a new session. The rule is not in the new context. Tutorial's own view: a rule that must last belongs in a long-term store, for example a project file that the tool loads at the start (see [procedural memory](/agent-memory/procedural-memory/)).

</Technical>

## Common mistakes

<Voices>
<Technical>

**"A bigger context window solves everything."** It does not. Accuracy and recall go down as the token count grows <Cite n={3} />. A long, noisy context can make the answer worse.

**"The model reads every part of a long input equally well."** Studies found that models use information at the start or the end of a long input best. They found a large drop when the key information is in the middle <Cite n={4} />. That study tested the models of 2023, so test your own model.

**"Working memory is the training data."** It is not. The context window is different from the large set of data that the model was trained on <Cite n={3} />. A fact in the training data is a different type of memory: see [parametric memory](/agent-memory/parametric-memory/).

**"Only the chat messages count."** The system prompt, the tool results, images, documents, and the tool definitions also use space <Cite n={3} />. An agent with many tools has less space for the conversation.

**"The app will never hit the limit."** It can. Then Claude 4.5 models and newer stop with `model_context_window_exceeded`, and earlier models return a validation error <Cite n={3} />. An app that does not handle this can show a cut answer or crash.

**"CoALA says working memory is the context window."** It does not. CoALA describes a module that holds variables for the current decision cycle <Cite n={1} />. The "context window as working memory" view is from the Anthropic docs <Cite n={3} />.

</Technical>
<Layman>

**"A bigger context window fixes everything."** No. Accuracy and recall drop as the number of tokens grows <Cite n={3} />. A long, messy context can make the answer worse.

**"The model reads all of a long input equally well."** Studies found that models use information at the start or the end best. They found a big drop when the key information is in the middle <Cite n={4} />. That study tested the models of 2023, so test your own model.

**"Working memory is what the model learned in training."** No. The context window is different from the training data <Cite n={3} />. Knowledge from training is a different type: see [parametric memory](/agent-memory/parametric-memory/).

**"Only the chat messages take space."** The system prompt, tool results, images, documents, and tool definitions take space too <Cite n={3} />. An agent with many tools has less room for the conversation.

**"The app will never reach the limit."** It can. Then Claude 4.5 models and newer stop with `model_context_window_exceeded`, and older models give a validation error <Cite n={3} />. An app that does not handle this can show a cut-off answer or crash.

**"CoALA says working memory is the context window."** No. CoALA describes a part of the agent that holds data for the current decision cycle <Cite n={1} />. The "context window as working memory" view comes from the Anthropic docs <Cite n={3} />.

</Layman>
<Bangla>

**"বড় context window সব সমস্যার সমাধান।"** না। token বাড়লে accuracy আর recall কমে <Cite n={3} />। লম্বা, এলোমেলো context উত্তর খারাপ করতে পারে।

**"লম্বা input-এর সব অংশ model সমানভাবে পড়ে।"** গবেষণায় দেখা গেছে, input-এর শুরু বা শেষের তথ্য model সবচেয়ে ভালো ব্যবহার করে। দরকারি তথ্য মাঝখানে থাকলে ফলাফল অনেক খারাপ হয় <Cite n={4} />। ওই গবেষণা 2023-এর model পরীক্ষা করেছিল, তাই আপনার নিজের model টেস্ট করুন।

**"Working memory মানে training data।"** না। context window, model যে বড় data-তে train হয়েছে, তা থেকে আলাদা <Cite n={3} />। training থেকে পাওয়া জ্ঞান আলাদা ধরনের memory: [parametric memory](/agent-memory/parametric-memory/) দেখুন।

**"শুধু chat message জায়গা নেয়।"** system prompt, tool result, image, document আর tool definition-ও জায়গা নেয় <Cite n={3} />। অনেক tool থাকলে conversation-এর জন্য জায়গা কম থাকে।

**"App কখনো limit-এ পৌঁছাবে না।"** পৌঁছাতে পারে। তখন Claude 4.5 আর নতুন model `model_context_window_exceeded` দিয়ে থামে, আর পুরোনো model validation error দেয় <Cite n={3} />। App এটা handle না করলে কাটা উত্তর দেখাতে পারে বা crash করতে পারে।

**"CoALA বলে working memory মানে context window।"** না। CoALA এমন একটা module-এর কথা বলে, যা এখনকার decision cycle-এর variable রাখে <Cite n={1} />। "context window হলো working memory" দৃষ্টিভঙ্গিটা Anthropic docs-এর <Cite n={3} />।

</Bangla>
</Voices>

## What a tester can check

<Voices>
<Technical>

These test ideas come from the facts above. They are the tutorial's own advice.

<Callout type="tip" title="Tutorial advice">
- Give a rule early in a long conversation. Check that the agent still follows it after many turns and long tool results.

## Key words

| Term | Meaning |
|---|---|
| Working memory | The information that an agent keeps active for the current step or decision cycle. |
| Context window | All the tokens that an LLM can use for one response: the request and the response itself. Anthropic calls it the model's "working memory". |
| Token | A small piece of text. The context window and the `usage` field count tokens. |
| Decision cycle | In CoALA, one step of the agent's loop. Working memory holds the active data of the current cycle. |
| Context rot | The drop in accuracy and recall as the token count of the context grows. |
| Lost in the middle | The finding that models use information at the middle of a long input worse than at its start or end. |
| `usage` | The field of an API response that reports the tokens that the request used. |
| `model_context_window_exceeded` | The stop reason of Claude 4.5 models and newer when the output reaches the context window limit. |
