# Procedural Memory

Semantic memory holds what an agent knows. Procedural memory holds how the agent does things: the steps, the rules, and the habits that decide its behavior. For a tester, this is the memory that you change when you edit a system prompt, a CLAUDE.md file, or a skill.

<PageMeta />

## In plain words

<Voices>
<Technical>

Procedural memory is long-term memory for the skills of tasks <Cite n={2} />. In the tutorial's words, it holds the "how", not the "what". A person often shows a skill by doing it and cannot easily put it into words <Cite n={2} />.

In an AI agent, procedural memory has two forms. One form is implicit: it is in the weights of the language model. The other form is explicit: it is in the code of the agent <Cite n={1} />. Together, they decide how the agent acts.

The name "procedural memory" in this module follows the infographic "7 Types of Agent Memory". Research papers group memory in a different way. The CoALA paper has a working memory and three long-term memories: episodic, semantic, and procedural <Cite n={1} />. Compare this page with [semantic memory](/agent-memory/semantic-memory/) (facts) and [episodic memory](/agent-memory/episodic-memory/) (past events).

</Technical>
<Layman>

Procedural memory is long-term memory for the skills of a task <Cite n={2} />. In the tutorial's words, it is about "how to do it", not "what is true". People often show a skill by doing it. They cannot always explain it in words <Cite n={2} />.

An AI agent has this memory in two places. Some of it is hidden inside the model weights. Some of it is written in the agent's code <Cite n={1} />. Both decide what the agent does.

This module uses the names from the infographic "7 Types of Agent Memory". Research papers sort memory in other ways. The CoALA paper has a working memory and three long-term memories: episodic, semantic, and procedural <Cite n={1} />. See also [semantic memory](/agent-memory/semantic-memory/) (facts) and [episodic memory](/agent-memory/episodic-memory/) (past events).

</Layman>
<Bangla>

Procedural memory হলো কাজের দক্ষতার long-term memory <Cite n={2} />। Tutorial-এর ভাষায়, এটা "কীভাবে করতে হয়" ধরে রাখে, "কী সত্য" নয়। মানুষ অনেক সময় কাজটা করে দেখিয়ে দক্ষতা প্রমাণ করে, কিন্তু মুখে সহজে বোঝাতে পারে না <Cite n={2} />।

AI agent-এ procedural memory দুই রকম। একটা implicit: language model-এর weights-এর ভেতরে থাকে। অন্যটা explicit: agent-এর code-এ লেখা থাকে <Cite n={1} />। দুটো মিলে agent কীভাবে কাজ করবে তা ঠিক করে।

## Where it comes from

<Voices>
<Technical>

**In psychology.** The APA dictionary defines procedural memory as long-term memory for the skills of particular tasks <Cite n={2} />. Skilled performance shows this memory. It is often separate from the ability to describe the skill in words <Cite n={2} />.

**In cognitive architectures.** Cognitive architectures such as Soar also use the term. In Soar, procedural memory stores the production system: the set of rules that act on working memory and decide the agent's behavior <Cite n={1} />.

**In language agents.** The CoALA paper takes this idea to agents built on large language models. It names two forms. The first form is implicit knowledge in the LLM weights. The second form is explicit knowledge in the agent's code <Cite n={1} />. The designer must write the first procedural memory, so that the agent can start <Cite n={1} />.

**Two models, one overlap.** CoALA puts the model weights under procedural memory <Cite n={1} />. The infographic has a separate type for the weights: [parametric memory](/agent-memory/parametric-memory/). So the two models split the same thing in different ways. On this page, the focus is the explicit part: code, prompts, and instruction files.

</Technical>
<Layman>

**In psychology.** The APA dictionary says procedural memory is long-term memory for the skills of a task <Cite n={2} />. You show this memory when you do the task well. Often you cannot explain the skill in words <Cite n={2} />.

**In cognitive architectures.** Soar is a cognitive architecture, a design for AI systems. In Soar, procedural memory is a set of rules. The rules look at working memory and decide what the agent does <Cite n={1} />.

**In language agents.** The CoALA paper uses the same idea for agents built on large language models. It names two forms. One form is hidden in the model weights. The other form is written in the agent's code <Cite n={1} />. The designer must write the first version, so the agent can start at all <Cite n={1} />.

**Two models, one overlap.** CoALA counts the model weights as procedural memory <Cite n={1} />. The infographic gives the weights their own type: [parametric memory](/agent-memory/parametric-memory/). So the two models cut the same thing differently. This page looks mostly at the written part: code, prompts, and instruction files.

</Layman>
<Bangla>

**মনোবিজ্ঞানে।** APA dictionary অনুযায়ী procedural memory হলো নির্দিষ্ট কাজের দক্ষতার long-term memory <Cite n={2} />। কাজটা দক্ষতার সঙ্গে করলেই এই memory দেখা যায়। অনেক সময় দক্ষতাটা কথায় বোঝানোর ক্ষমতা এর থেকে আলাদা থাকে <Cite n={2} />।

**Cognitive architecture-এ।** Soar-এর মতো cognitive architecture-ও এই শব্দ ব্যবহার করে। Soar-এ procedural memory হলো production system: কিছু rule, যেগুলো working memory-র ওপর কাজ করে agent-এর আচরণ ঠিক করে <Cite n={1} />।

**Language agent-এ।** CoALA paper এই ধারণা LLM-ভিত্তিক agent-এ নিয়ে আসে। এখানে দুই রকম আছে। প্রথমটা LLM weights-এর ভেতরের implicit জ্ঞান। দ্বিতীয়টা agent-এর code-এ লেখা explicit জ্ঞান <Cite n={1} />। Agent চালু করতে designer-কেই প্রথম procedural memory লিখে দিতে হয় <Cite n={1} />।

**দুই model, একই জিনিস।** CoALA model weights-কে procedural memory-তে রাখে <Cite n={1} />। Infographic-এ weights-এর জন্য আলাদা type আছে: [parametric memory](/agent-memory/parametric-memory/)। তাই দুই model একই জিনিস ভিন্নভাবে ভাগ করে। এই পাতায় মূলত লেখা অংশটা দেখা হবে: code, prompt, আর instruction file।

## How an agent gets it

<Voices>
<Technical>

An agent gets explicit procedural memory from text and code that a person writes. Tutorial's own view: in Claude Code, three places act as procedural memory. The Anthropic docs do not use the term "procedural memory" for them.

**CLAUDE.md files.** These are Markdown files. They give Claude persistent instructions for a project, a personal workflow, or a whole organization <Cite n={3} />. Claude reads them as context. They are not enforced configuration <Cite n={3} />. To block an action whatever Claude decides, use a `PreToolUse` hook <Cite n={3} />.

**Skills.** A skill holds a procedure. The docs advise a skill when you paste the same checklist or multi-step procedure again and again. They also advise one when a section of CLAUDE.md has become a procedure and not a fact <Cite n={4} />. A skill's body loads only when Claude uses the skill <Cite n={4} />. CLAUDE.md content does not work this way <Cite n={4} />.

**Agent code.** The CoALA paper counts the agent's own code as explicit procedural memory <Cite n={1} />. The designer writes it before the first run <Cite n={1} />.

```text
             written by a person                    loaded
CLAUDE.md  ─────────────────────────────►  every session (as context)
skill      ─────────────────────────────►  only when the skill is used
agent code ─────────────────────────────►  runs as the agent's control flow
```

## A real-life example

<Voices>
<Technical>

This example is the tutorial's own illustration. It is not from a source.

A QA team uses Claude Code in a test automation repository. The team writes three rules in the project CLAUDE.md:

```markdown
- Run the unit tests with `npm test` before you say a task is done.
- Put new Playwright tests in `tests/e2e/`.
- Never change a snapshot file to make a test pass.
```

These rules are procedural memory in the tutorial's sense: they tell the agent how to work, not what is true. Claude gets them as context in each session <Cite n={3} />. The third rule is important, but CLAUDE.md does not enforce it <Cite n={3} />. If the team must block snapshot edits in every case, a `PreToolUse` hook is the right tool <Cite n={3} />.

Later, the team has a long release checklist. They move it from CLAUDE.md into a skill. Now the checklist loads only when someone asks for a release, and it costs almost nothing in other sessions <Cite n={4} />.

To confirm that the CLAUDE.md file loaded, a tester runs `/context` in a session and looks at the list of memory files <Cite n={3} />.

</Technical>

## Common mistakes

<Voices>
<Technical>

**Treating instructions as hard rules.** CLAUDE.md content is context, not enforced configuration <Cite n={3} />. A rule in it can still be broken. Use a hook when an action must never happen <Cite n={3} />.

**Writing very long instruction files.** The docs give a target of under 200 lines for each CLAUDE.md file. Longer files use more context and Claude follows them less well <Cite n={3} />. Move long procedures into a skill, so that they load only when needed <Cite n={4} />.

**Leaving conflicting rules.** If two instructions contradict each other, Claude may pick one of them arbitrarily <Cite n={3} />. A tester may then see behavior that changes from run to run.

**Expecting code to cover every case.** Agent code is easy to read and extend. But it is often brittle with random inputs, and it handles only the situations that the designer expected <Cite n={1} />.

**Letting the agent rewrite its own procedures without checks.** An agent can change its own procedural memory. This is much riskier than a write to episodic or semantic memory. It can add bugs, or it can let the agent work against the designer's intent <Cite n={1} />.

</Technical>
<Layman>

**Thinking instructions are hard rules.** CLAUDE.md is context, not a rule that is forced <Cite n={3} />. Claude can still break a rule in it. Use a hook when something must never happen <Cite n={3} />.

**Very long instruction files.** The docs say to aim for less than 200 lines in each CLAUDE.md file. Longer files use more context, and Claude follows them less well <Cite n={3} />. Move long step lists into a skill, so they load only when needed <Cite n={4} />.

**Rules that fight each other.** If two instructions say opposite things, Claude may pick either one <Cite n={3} />. Then the behavior may change from one run to the next.

**Expecting code to handle everything.** Agent code is easy to read and to add to. But it often breaks with random inputs, and it only covers the cases the designer thought of <Cite n={1} />.

**Letting the agent rewrite its own steps with no checks.** An agent can change its own procedural memory. This is much riskier than changing its episodic or semantic memory. It can add bugs, or the agent can go against what the designer wanted <Cite n={1} />.

</Layman>
<Bangla>

**Instruction-কে কঠিন rule ভাবা।** CLAUDE.md-এর লেখা context, enforced configuration নয় <Cite n={3} />। তাই এর rule-ও ভাঙতে পারে। কোনো action কখনোই না হতে দিতে চাইলে hook ব্যবহার করুন <Cite n={3} />।

**খুব লম্বা instruction file লেখা।** Docs প্রতিটা CLAUDE.md file 200 লাইনের নিচে রাখার লক্ষ্য দেয়। লম্বা file বেশি context খরচ করে, আর Claude সেগুলো কম মেনে চলে <Cite n={3} />। লম্বা procedure skill-এ সরিয়ে নিন, যাতে দরকার হলেই শুধু load হয় <Cite n={4} />।

**পরস্পরবিরোধী rule রেখে দেওয়া।** দুটো instruction একে অপরের উল্টো হলে Claude যেকোনো একটা বেছে নিতে পারে <Cite n={3} />। তখন আপনি হয়তো প্রতি run-এ ভিন্ন আচরণ দেখবেন।

**ভাবা যে code সব case সামলাবে।** Agent code পড়া আর বাড়ানো সহজ। কিন্তু random input-এ এটা প্রায়ই ভেঙে যায়, আর designer যেসব অবস্থা আগে ভেবেছিলেন শুধু সেগুলোই সামলায় <Cite n={1} />।

**যাচাই ছাড়া agent-কে নিজের procedure বদলাতে দেওয়া।** Agent নিজের procedural memory বদলাতে পারে। এটা episodic বা semantic memory-তে লেখার চেয়ে অনেক বেশি ঝুঁকির। এতে bug ঢুকতে পারে, বা agent designer-এর উদ্দেশ্যের বিরুদ্ধে কাজ করতে পারে <Cite n={1} />।

## What a tester can check

<Voices>
<Technical>

Procedural memory is text and code that a person can read, so a tester can test it like any other configuration.

<Callout type="tip" title="Tutorial advice">
These test ideas are the tutorial's own advice.

- **Repeat the run.** Give one rule in the system prompt or CLAUDE.md. Run the same task many times and count how often the agent follows the rule. A rule that is only context can fail sometimes.
- **Plant a conflict.** Add two rules that contradict each other. Record which one the agent follows in each run, then remove the conflict.
- **Check that the file loaded.** Before you report a broken rule, confirm that the instruction file is in the session.
- **Trigger a skill, then avoid it.** Send a request that matches a skill and check that it loads. Send an unrelated request and check that it does not load.
- **Rerun the old prompts.** After the agent or a person edits the instructions, run the old regression prompts again and compare the results.
</Callout>

</Technical>
<Layman>

Procedural memory is text and code that people can read. So a tester can test it like any other settings file.

<Callout type="tip" title="Tutorial advice">
These test ideas are the tutorial's own advice.

- **Run it many times.** Put one rule in the system prompt or CLAUDE.md. Run the same task again and again. Count how often the agent obeys. A rule that is only context can fail now and then.
- **Add a conflict on purpose.** Write two rules that say opposite things. Note which one wins in each run. Then remove the conflict.
- **Make sure the file loaded.** Before you report a broken rule, check that the instruction file is in the session.
- **Call a skill, then don't.** Ask for something that matches a skill and check that it loads. Ask for something else and check that it stays unloaded.
- **Run the old prompts again.** After anyone changes the instructions, run the old test prompts again and compare.
</Callout>

</Layman>

Procedural memory হলো মানুষের পড়ার মতো text আর code। তাই একজন tester এটাকে অন্য যেকোনো configuration-এর মতোই test করতে পারেন।

<Callout type="tip" title="Tutorial advice">
এই test idea-গুলো tutorial-এর নিজের পরামর্শ।

- **বারবার চালান।** System prompt বা CLAUDE.md-এ একটা rule দিন। একই কাজ অনেকবার চালান আর গুনুন agent কতবার rule মানে। শুধু context হিসেবে থাকা rule মাঝে মাঝে ভাঙতে পারে।
- **ইচ্ছা করে conflict রাখুন।** পরস্পরবিরোধী দুটো rule লিখুন। প্রতি run-এ কোনটা মানা হলো লিখে রাখুন, তারপর conflict সরিয়ে দিন।
- **File load হয়েছে কি না দেখুন।** Rule ভাঙার report দেওয়ার আগে নিশ্চিত হোন যে instruction file-টা session-এ আছে।
- **Skill চালু করুন, তারপর এড়িয়ে যান।** Skill-এর সঙ্গে মেলে এমন request দিন আর দেখুন skill load হয় কি না। অন্য request দিন আর দেখুন সেটা load হয় না।
- **পুরোনো prompt আবার চালান।** Agent বা কেউ instruction বদলালে পুরোনো regression prompt-গুলো আবার চালিয়ে ফল মিলিয়ে দেখুন।
</Callout>

## Key words

| Term | Meaning |
|---|---|
| Procedural memory | Long-term memory for skills: how to do a task, not what is true. |
| Implicit procedural memory | Skills stored in the LLM weights (CoALA). The infographic calls the weights parametric memory. |
| Explicit procedural memory | Skills written in the agent's code (CoALA). In the tutorial's view, also prompts and instruction files. |
| Production system | In Soar, the set of rules that act on working memory and decide behavior. |
| CLAUDE.md | A Markdown file with persistent instructions for Claude Code. Claude reads it as context. |
| Skill | A Claude Code extension that holds a procedure. Its body loads only when it is used. |
| `PreToolUse` hook | A hook that can block a tool action whatever Claude decides. |
