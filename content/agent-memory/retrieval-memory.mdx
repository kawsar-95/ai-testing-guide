# Retrieval Memory

Retrieval memory is a store outside the model that an agent searches when it needs a fact. The agent copies the search results into its context, and then it answers. For a tester, this memory is a search system with its own bugs: wrong results, old results, or results from the wrong user.

<PageMeta />

## In plain words

<Voices>
<Technical>

A language model has knowledge in its weights. It can also use a second memory: a store of documents that a retriever searches <Cite n={1} />. Lewis et al. call the weights "parametric memory" and the searched store "non-parametric memory" <Cite n={1} />. This page calls the searched store retrieval memory.

You can change the knowledge in the store directly. You can also see which items the model used <Cite n={1} />. Thus you can update the knowledge without a new training run <Cite n={1} />. See [parametric memory](/agent-memory/parametric-memory/).

The 7 memory names of this module follow the infographic "7 Types of Agent Memory". Research papers group memory differently. CoALA has working memory and three long-term memories: episodic, semantic, and procedural <Cite n={2} />. Retrieval is not one of them. It is an action that reads from them <Cite n={2} />.

</Technical>
<Layman>

A language model keeps some knowledge inside the model itself. It can also look things up in a separate store of documents <Cite n={1} />. One research paper calls the first kind "parametric memory" and the store "non-parametric memory" <Cite n={1} />. On this page, the store is called retrieval memory.

You can edit the store directly. You can also see which documents the model used <Cite n={1} />. So you can update what the model knows without training it again <Cite n={1} />.

The 7 names in this module come from the infographic "7 Types of Agent Memory". Research papers use other groups. CoALA has working memory and three long-term memories: episodic, semantic, and procedural <Cite n={2} />. In CoALA, retrieval is an action that reads from these memories, not a memory of its own <Cite n={2} />.

</Layman>
<Bangla>

একটা language model-এর কিছু জ্ঞান তার weights-এর ভেতরে থাকে। এর পাশাপাশি সে আলাদা একটা document store-ও ব্যবহার করতে পারে, যেটা একটা retriever খোঁজে <Cite n={1} />। Lewis et al. weights-কে বলেন "parametric memory", আর খোঁজার store-কে বলেন "non-parametric memory" <Cite n={1} />। এই পেজে ওই store-কে retrieval memory বলা হয়েছে।

আপনি store-এর জ্ঞান সরাসরি বদলাতে পারেন। model কোন item ব্যবহার করল, সেটাও আপনি দেখতে পারেন <Cite n={1} />। তাই নতুন training ছাড়াই জ্ঞান update করা যায় <Cite n={1} />।

এই module-এর ৭টা memory-র নাম infographic "7 Types of Agent Memory" থেকে নেওয়া। research paper-গুলো memory-কে অন্যভাবে ভাগ করে। CoALA-তে আছে working memory আর তিনটা long-term memory: episodic, semantic, আর procedural <Cite n={2} />। CoALA-তে retrieval আলাদা কোনো memory নয়। এটা একটা action, যেটা ওই memory-গুলো থেকে পড়ে <Cite n={2} />।

## Where it comes from

<Voices>
<Technical>

"Retrieval memory" is the infographic's own name. The sources of this page do not define a psychology memory type or an agent memory type with that name. Tutorial's own view: the infographic uses the name for the external store that the agent searches.

In AI, the idea comes from retrieval-augmented generation (RAG). Lewis et al. describe hybrid models that combine parametric memory with retrieval-based memory <Cite n={1} />. In their RAG models, the store is a dense vector index of Wikipedia, and a pre-trained neural retriever reads it <Cite n={1} />.

CoALA uses different words. A retrieval action reads information from long-term memory into working memory <Cite n={2} />. CoALA counts a RAG document collection as semantic memory, as a store of unstructured text <Cite n={2} />. So a reader of CoALA finds the same mechanism under the names "retrieval action" and "semantic memory". See [semantic memory](/agent-memory/semantic-memory/) and [working memory](/agent-memory/working-memory/).

MemGPT gives an operating-system view. It moves data between a fast memory and a slow memory, like a computer with paging <Cite n={3} />. The fast memory is the context. The slow memory is "archival storage", a read/write database of text <Cite n={3} />.

</Technical>
<Layman>

"Retrieval memory" is a name from the infographic. The sources of this page do not use this name for a type of human memory or of agent memory. Tutorial's own view: the infographic uses the name for the store that the agent searches.

In AI, the idea comes from retrieval-augmented generation (RAG). Lewis et al. mix the memory inside the model with a memory that the model searches <Cite n={1} />. In their system, the store is a vector index of Wikipedia, and a trained retriever searches it <Cite n={1} />.

CoALA uses other words. A retrieval action copies information from long-term memory into working memory <Cite n={2} />. CoALA calls a RAG document collection semantic memory <Cite n={2} />. So it is the same idea with other names.

MemGPT compares the agent to an operating system. It moves data between a small fast memory and a large slow memory <Cite n={3} />. The fast memory is the context. The slow memory is "archival storage", a database of text that the agent can read and write <Cite n={3} />.

</Layman>
<Bangla>

"Retrieval memory" নামটা infographic-এর নিজের। এই পেজের source-গুলো এই নামে মানুষের বা agent-এর কোনো memory type সংজ্ঞায়িত করে না। Tutorial-এর নিজের মত: agent যে বাইরের store খোঁজে, infographic সেটাকেই এই নাম দিয়েছে।

AI-তে ধারণাটা এসেছে retrieval-augmented generation (RAG) থেকে। Lewis et al. model-এর ভেতরের memory আর খোঁজার memory একসাথে ব্যবহার করেন <Cite n={1} />। তাঁদের RAG model-এ store হলো Wikipedia-র একটা dense vector index, আর একটা pre-trained neural retriever সেটা পড়ে <Cite n={1} />।

CoALA অন্য শব্দ ব্যবহার করে। একটা retrieval action long-term memory থেকে তথ্য working memory-তে আনে <Cite n={2} />। CoALA একটা RAG document collection-কে semantic memory ধরে <Cite n={2} />। মানে একই কৌশল, শুধু নাম আলাদা।

MemGPT agent-কে একটা operating system-এর মতো দেখে। এটা একটা fast memory আর একটা slow memory-র মধ্যে data সরায় <Cite n={3} />। fast memory হলো context। slow memory হলো "archival storage", text-এর একটা read/write database <Cite n={3} />।

</Bangla>

## How an agent gets it

<Voices>
<Technical>

The agent does not get this memory from training. It gets it from a search at run time. The loop has four steps:

```text
question ──► retriever ──► store (index of documents or facts)
                │
                ▼
        top results (ranked)
                │
                ▼
   context = question + results ──► model ──► answer
```

The search can use rules, keyword (sparse) search, or vector (dense) search <Cite n={2} />. The choice depends on the information and the memory type <Cite n={2} />.

In MemGPT, the model itself starts the search. It calls a function on archival storage, and the search results come into the main context page by page <Cite n={3} />. Thus the model decides when to look something up.

The agent can also write to the store. Memory-augmented agents can read and write their own content, not only text that people wrote <Cite n={2} />. MemGPT's archival storage is also read/write <Cite n={3} />.

A product API can wrap the same loop. For example, the Telnyx Agent Memory API has a "recall" endpoint that returns ranked facts for a question <Cite n={4} />. It also has namespaces: a separate store for each application or environment <Cite n={4} />.

</Technical>
<Layman>

The agent does not learn this memory in training. It looks things up while it runs. The loop is: the question goes to a retriever, the retriever searches the store, the best results come back, and the model reads the question and the results together.

The search can follow fixed rules, match keywords, or compare vectors <Cite n={2} />. Which one you use depends on the data and the memory type <Cite n={2} />.

In MemGPT, the model decides to search. It calls a function, and the results come into its context one page at a time <Cite n={3} />.

The agent can also save new items in the store, not only read text that people wrote <Cite n={2} />. MemGPT's archival storage can also be read and written <Cite n={3} />.

Products can offer the same loop as an API. One example is Telnyx Agent Memory: it has a "recall" call that returns ranked facts for a question <Cite n={4} />. It keeps a separate store for each application or environment <Cite n={4} />.

</Layman>
<Bangla>

agent এই memory training থেকে পায় না। চলার সময় search করে পায়। loop-টা এরকম: প্রশ্ন যায় retriever-এর কাছে, retriever store খোঁজে, সেরা result-গুলো ফেরত আসে, তারপর model প্রশ্ন আর result একসাথে পড়ে উত্তর দেয়।

search হতে পারে rule-based, keyword (sparse) search, অথবা vector (dense) search <Cite n={2} />। কোনটা ব্যবহার হবে, সেটা তথ্য আর memory type-এর ওপর নির্ভর করে <Cite n={2} />।

MemGPT-তে model নিজেই search শুরু করে। সে archival storage-এ একটা function call করে, আর result-গুলো পাতা ধরে ধরে main context-এ আসে <Cite n={3} />।

agent store-এ লিখতেও পারে। মানুষের লেখা text ছাড়াও সে নিজের তৈরি content পড়তে ও লিখতে পারে <Cite n={2} />। MemGPT-র archival storage-ও read/write <Cite n={3} />।

একটা product API-ও এই loop দিতে পারে। যেমন Telnyx Agent Memory-র একটা "recall" endpoint আছে, যেটা একটা প্রশ্নের জন্য ranked fact ফেরত দেয় <Cite n={4} />। প্রতিটা application বা environment-এর জন্য আলাদা store (namespace) থাকে <Cite n={4} />।

</Bangla>
</Voices>

## A real-life example

<Voices>
<Technical>

This example is the tutorial's own illustration. It is not from a source.

A team has a support chatbot for its test management tool. The help articles are in a vector store. A user asks: "How do I export a test run as CSV?" The retriever finds the two closest articles. The bot puts them into the context and writes the answer. The answer names the article that it used.

Next week, the export menu moves. A writer changes one help article. The bot gives the new steps at once, with no new training. This is the update property of non-parametric memory <Cite n={1} />.

Then the team adds a "remember this" feature. The bot saves a note per customer, for example "uses the Jira plugin". Now the bot writes to the store as well as reads from it <Cite n={2} />. Each customer's notes must stay in that customer's store. A namespace per application or environment is one way to keep stores apart <Cite n={4} />.

</Technical>
<Layman>

This example is the tutorial's own. It is not from a source.

A team has a support chatbot for its test management tool. The help articles are in a vector store. A user asks how to export a test run as CSV. The search finds the two best articles. The bot reads them and answers, and it says which article it used.

Next week, the export menu moves. A writer edits one article. The bot gives the new steps right away, with no new training <Cite n={1} />.

Then the team lets the bot save notes about each customer. Now the bot writes to the store too <Cite n={2} />. Each customer's notes must stay apart from other customers' notes. A separate store per application or environment is one way to do this <Cite n={4} />.

</Layman>
<Bangla>

এই উদাহরণটা tutorial-এর নিজের। এটা কোনো source থেকে নেওয়া নয়।

একটা টিমের test management tool-এর জন্য একটা support chatbot আছে। help article-গুলো একটা vector store-এ রাখা। একজন user জিজ্ঞেস করলেন, একটা test run কীভাবে CSV হিসেবে export করবেন। retriever সবচেয়ে কাছের দুটো article খুঁজে পায়। bot সেগুলো context-এ নিয়ে উত্তর লেখে, আর কোন article ব্যবহার করল তা জানায়।

পরের সপ্তাহে export menu অন্য জায়গায় সরে যায়। একজন writer একটা article বদলান। নতুন training ছাড়াই bot সঙ্গে সঙ্গে নতুন ধাপগুলো বলে <Cite n={1} />।

এরপর টিম bot-কে প্রতিটা customer-এর জন্য note রাখার সুযোগ দেয়। এখন bot store-এ লেখেও <Cite n={2} />। এক customer-এর note অন্য customer-এর note থেকে আলাদা থাকতে হবে। প্রতিটা application বা environment-এর জন্য আলাদা store রাখা এর একটা উপায় <Cite n={4} />।

</Bangla>

## Common mistakes

<Voices>
<Technical>

**Retrieval is a cure for hallucination.** It helps, but it is not a guarantee. In the RAG study, RAG models hallucinated less than the baseline model without retrieval <Cite n={1} />. "Less" is not "never".

**The right item is always found.** In the Generative Agents study, a common error was that the agent did not retrieve the relevant memories <Cite n={5} />. The agents also sometimes added false details to their memories <Cite n={5} />.

**More results give a better answer.** Models use information at the start or end of a long input best. Performance drops when the relevant item is in the middle <Cite n={6} />. A long list of retrieved items can hide the one that matters.

**A write is visible at once.** It may not be. In the Telnyx API, a memory cannot be recalled until its write operation completes. A read just after the write does not see it yet <Cite n={4} />. Telnyx Agent Memory is one product, so check this behavior in the system that you test.

**One store for everyone.** Without a boundary, one user's data can come back in another user's answer. Separate stores per application or environment keep memories apart <Cite n={4} />.

</Technical>
<Layman>

**"Search stops all made-up answers."** It helps, but it does not stop them all. In the RAG study, models with search made up fewer facts than the model without search <Cite n={1} />. Fewer is not zero.

**"The right item is always found."** In the Generative Agents study, a common error was that the agent did not find the memory that it needed <Cite n={5} />. It also sometimes added false details <Cite n={5} />.

**"More results are better."** Models use the start and the end of a long input best. They do worse when the important part is in the middle <Cite n={6} />. Many results can hide the one that counts.

**"A save shows up at once."** In the Telnyx API, you cannot recall a memory until the save is complete. If you save and read right away, you do not see it yet <Cite n={4} />. Check this in your own system.

**"One store for all users."** Then one user's data can show up for another user. A separate store per application or environment keeps memories apart <Cite n={4} />.

</Layman>
<Bangla>

**"Retrieval থাকলে hallucination হয় না।"** এটা সাহায্য করে, কিন্তু নিশ্চয়তা দেয় না। RAG study-তে RAG model-গুলো retrieval ছাড়া baseline model-এর চেয়ে কম hallucinate করেছে <Cite n={1} />। কম মানে শূন্য নয়।

**"সঠিক item সবসময় পাওয়া যায়।"** Generative Agents study-তে একটা সাধারণ ভুল ছিল, agent দরকারি memory খুঁজে পায়নি <Cite n={5} />। কখনো কখনো agent memory-তে মিথ্যা detail-ও যোগ করেছে <Cite n={5} />।

**"বেশি result মানে ভালো উত্তর।"** লম্বা input-এর শুরু বা শেষের তথ্য model সবচেয়ে ভালো ব্যবহার করে। দরকারি তথ্য মাঝখানে থাকলে performance কমে যায় <Cite n={6} />। অনেক result-এর ভিড়ে আসল result-টা হারিয়ে যেতে পারে।

**"লেখার সঙ্গে সঙ্গে দেখা যায়।"** Telnyx API-তে write operation শেষ না হওয়া পর্যন্ত memory recall করা যায় না। লিখেই সঙ্গে সঙ্গে পড়লে আপনি সেটা এখনো দেখবেন না <Cite n={4} />। আপনি যে system test করছেন, সেখানে এটা যাচাই করুন।

**"সবার জন্য একটা store।"** boundary না থাকলে এক user-এর data অন্য user-এর উত্তরে চলে আসতে পারে। প্রতিটা application বা environment-এর জন্য আলাদা store memory-গুলোকে আলাদা রাখে <Cite n={4} />।

</Bangla>
</Voices>

## What a tester can check

<Voices>
<Technical>

Treat the retriever and the store as a system under test, apart from the model.

<Callout type="tip" title="Tutorial advice">
- Ask a question whose answer is only in the store. Check that the answer names the right document.
- Change one document. Ask again, and check that the answer uses the new text.
- Ask a question with no answer in the store. Check that the agent says so and does not invent an answer.
- Write a memory and read it at once. Then read it again after the write completes. Record when it becomes visible.
- Sign in as two tenants. Check that one tenant cannot retrieve the data of the other.
- Put the key document among many similar ones. Check that the answer still uses it.
</Callout>

</Technical>
<Layman>

Test the search and the store on their own, not only the final answer.

<Callout type="tip" title="Tutorial advice">
- Ask something that only the store knows. Check that the answer points to the right document.
- Edit one document. Ask again and check for the new text.
- Ask something that the store does not know. Check that the agent says it does not know.
- Save a memory and read it at once, then read it again later. Note when it shows up.
- Use two customer accounts. Check that one cannot see the other's data.
- Hide the key document among many similar ones. Check that the answer still uses it.
</Callout>

</Layman>
<Bangla>

শুধু শেষ উত্তর নয়, retriever আর store-কেও আলাদা একটা system হিসেবে test করুন।

<Callout type="tip" title="Tutorial advice">
- এমন প্রশ্ন করুন যার উত্তর শুধু store-এ আছে। উত্তরে সঠিক document-এর নাম আছে কি না দেখুন।
- একটা document বদলান। আবার প্রশ্ন করুন, উত্তরে নতুন text এসেছে কি না দেখুন।
- এমন প্রশ্ন করুন যার উত্তর store-এ নেই। agent সেটা স্বীকার করে কি না, নাকি উত্তর বানায়, দেখুন।
- একটা memory লিখে সঙ্গে সঙ্গে পড়ুন, তারপর write শেষ হওয়ার পর আবার পড়ুন। কখন দেখা যায়, লিখে রাখুন।
- দুটো tenant হিসেবে sign in করুন। এক tenant অন্যের data retrieve করতে পারে না, তা যাচাই করুন।

## Key words

| Term | Meaning |
|---|---|
| Retrieval memory | The infographic's name for an external store that an agent searches at run time |
| Non-parametric memory | The term of Lewis et al. for a retrieval-based memory outside the model weights |
| Parametric memory | Knowledge that is stored in the model weights |
| RAG | Retrieval-augmented generation: the model answers with the help of retrieved documents |
| Retriever | The part that searches the store and returns the best matches |
| Vector index | A store that finds items by the closeness of their vectors (dense retrieval) |
| Retrieval action | CoALA's term for reading from long-term memory into working memory |
| Archival storage | MemGPT's read/write database of text outside the main context |
| Namespace | In the Telnyx API, a separate memory store per application or environment |
