# Open Models

An open-weight model is a model whose weights you can download and run on your own hardware. It is a specialist skill. Learn it when data rules say that some data must stay inside your company, and a hosted model is not allowed for that data.

<PageMeta />

## In plain words

<Voices>
<Technical>

A hosted model runs on the servers of a vendor, and your prompts go to those servers. An **open-weight model** publishes its weights (its parameters), so you can download it and run it on a laptop, a server, or a private cloud. Well-known families are Llama, Mistral, Qwen, and Gemma.

"Open weights" is not always "open source". The Open Source Initiative defines open source AI with four freedoms: use, study, modify, and share <Cite n={1} />. For that, it asks for more than the weights: also detailed information about the training data and the complete code to train and run the system <Cite n={1} />. Many models publish the weights under their own license, with their own rules. So always read the license.

**The trigger for this skill:** a data rule (a contract, a policy, or a law) says that some data must stay in-house. Examples are customer records, health data, or the source code of a client. Then a model that runs on your own machines can be the only allowed choice. For the general model choice, see [Claude Models](/getting-started/models/).

</Technical>

## How it works

<Voices>
<Technical>

You need three things: the weights, a program that runs them (a runtime), and an API that your tools can call.

- **Ollama** is a runtime for a laptop or a server. It runs open models such as Qwen, Gemma, and gpt-oss <Cite n={2} />. `ollama pull <model>` downloads a model <Cite n={10} />, and `ollama run <model>` runs a model and opens a chat with it <Cite n={2} />. It also has a REST API to run and manage models <Cite n={2} />.
- **vLLM** is a serving engine for bigger loads. `vllm serve <model>` starts an HTTP server that supports OpenAI APIs <Cite n={4} />.

On a local Ollama install, the API is at `http://localhost:11434/api`, and an OpenAI-compatible API is at `http://localhost:11434/v1` <Cite n={3} />. Local requests need no API key <Cite n={3} />. Because the API looks like the OpenAI API, many test tools and scripts only need a new base URL.

```bash
# Ask a local model a question. Replace <model> with a model that you pulled.
curl http://localhost:11434/api/chat -d '{
  "model": "<model>",
  "messages": [{"role": "user", "content": "Give 3 fake customer names for a test."}],
  "stream": false
}'
```

```text
test script --> http://localhost:11434 --> Ollama --> model weights on disk
                     (your machine)          |
                                             +--> cloud model (only after sign-in)
```

Watch the last line of the diagram. After you sign in to Ollama, the local server can also send requests to cloud models <Cite n={3} />. Then the data leaves the machine.

Each model on Hugging Face has a **model card**: the `README.md` of the model repo, with metadata at the top <Cite n={5} />. It should describe the intended uses, the limits, the training data, and the eval results <Cite n={5} />, and the page shows the license from the metadata <Cite n={5} />.

</Technical>

আপনার তিনটা জিনিস লাগবে: weight, সেটা চালানোর একটা প্রোগ্রাম (runtime), আর একটা API যেটা আপনার টুলগুলো কল করতে পারে।

এখানে সাবধান থাকুন। Ollama-তে সাইন ইন করার পর লোকাল সার্ভার ক্লাউড মডেলেও রিকুয়েস্ট পাঠাতে পারে <Cite n={3} />। তখন ডেটা মেশিনের বাইরে চলে যায়।

## How a tester uses it

<Voices>
<Technical>

1. **Make test data from sensitive data.** You need realistic test data, but the source rows hold personal data that must not leave the company. A local model can write fake records in the same shape, and the real rows stay on your machine. First check that the model really runs locally: a local request needs no API key <Cite n={3} />, and a model that the server reaches through a sign-in is a cloud model <Cite n={3} />.
2. **Run AI checks with no network.** Point a test script or an eval at the OpenAI-compatible endpoint of Ollama or vLLM <Cite n={3} /> <Cite n={4} />. The same suite can run on a laptop, in a closed CI runner, or on a plane. See [Headless & CI](/automate/headless/) for the CI side, and [Checking AI Quality (Evals)](/ai-skills/ai-evals/) for the suite.
3. **Check the license before the product uses the model.** Read the model card and the license <Cite n={5} />. Licenses differ a lot (see the next section). Some products must show a notice, and some uses are not allowed.
4. **Test safety yourself.** Some open models have no built-in safety layer. The card of Mistral-7B-Instruct-v0.3 says that it has no moderation mechanisms <Cite n={9} />. If the product shows the model output to users, test harmful and off-topic prompts.

<Callout type="tip" title="Tutorial advice">
This is the tutorial's own advice. Pin the exact model name and version in your test config, as you pin a library version. A new download under the same name can change the answers, and then your old test results do not compare.
</Callout>

</Technical>

<Bangla>

1. **সংবেদনশীল ডেটা থেকে টেস্ট ডেটা বানান।** আপনার বাস্তবসম্মত টেস্ট ডেটা দরকার। কিন্তু সোর্স রো-গুলোতে ব্যক্তিগত তথ্য আছে, যা কোম্পানির বাইরে যাওয়া চলবে না। একটা লোকাল মডেল একই আকারের নকল রেকর্ড লিখে দিতে পারে। আসল রো আপনার মেশিনেই থাকে। আগে চেক করুন মডেলটা সত্যিই লোকালে চলছে কিনা। লোকাল রিকুয়েস্টে API key লাগে না <Cite n={3} />। সাইন ইনের মাধ্যমে সার্ভার যে মডেলে পৌঁছায়, সেটা ক্লাউড মডেল <Cite n={3} />।
2. **নেটওয়ার্ক ছাড়াই AI চেক চালান।** একটা টেস্ট স্ক্রিপ্ট বা eval-কে Ollama বা vLLM-এর OpenAI-এর মতো endpoint-এর দিকে তাক করুন <Cite n={3} /> <Cite n={4} />। একই suite ল্যাপটপে, বন্ধ একটা CI runner-এ, এমনকি প্লেনেও চলতে পারে। CI দিকের জন্য [Headless & CI](/automate/headless/) আর suite-এর জন্য [Checking AI Quality (Evals)](/ai-skills/ai-evals/) দেখুন।
3. **প্রোডাক্টে মডেল ব্যবহারের আগে লাইসেন্স চেক করুন।** Model card আর লাইসেন্স পড়ুন <Cite n={5} />। লাইসেন্সগুলো একে অপরের থেকে অনেক আলাদা (পরের অংশ দেখুন)। কিছু প্রোডাক্টে একটা নোটিশ দেখাতে হয়। কিছু ব্যবহার অনুমোদিত নয়।
4. **Safety নিজে টেস্ট করুন।** কিছু ওপেন মডেলের নিজস্ব কোনো safety স্তর নেই। Mistral-7B-Instruct-v0.3-এর card বলে, এর কোনো moderation ব্যবস্থা নেই <Cite n={9} />। প্রোডাক্ট যদি মডেলের আউটপুট ইউজারকে দেখায়, তাহলে ক্ষতিকর প্রম্পট আর বিষয়ের বাইরের প্রম্পট টেস্ট করুন।

এটা টিউটোরিয়ালের নিজের পরামর্শ। লাইব্রেরির ভার্সন যেমন পিন করেন, তেমনি টেস্ট config-এ মডেলের সঠিক নাম আর ভার্সন পিন করুন। একই নামে নতুন ডাউনলোড উত্তর বদলে দিতে পারে। তখন আপনার পুরনো টেস্টের ফলাফলের সাথে তুলনা চলে না।

## Common mistakes

<Voices>
<Technical>

- **"Open" means "no rules".** The team ships a model without reading its license. Fix: read the license on the model card <Cite n={5} /> and note the duties, such as a notice <Cite n={6} /> or use limits that you must pass on <Cite n={7} />. Ask your legal or governance team (see [AI Governance](/ai-skills/ai-governance/)).
- **"Local" that is not local.** A test sends sensitive data to a model that the local server reaches through a cloud sign-in <Cite n={3} />. Fix: use a model whose weights are on your disk, and check the network traffic in a test run.
- **No safety tests.** The team expects the same filters as a hosted product. Some open models have none <Cite n={9} />. Fix: add safety cases to your eval set.
- **One model for every job.** A small local model is good at simple tasks and weak at hard ones. Fix (the tutorial's advice): score each task on the local model before you replace a hosted model.

</Technical>

<Bangla>

- **"Open" মানে "কোনো নিয়ম নেই"।** লাইসেন্স না পড়েই টিম মডেল শিপ করে। সমাধান: model card-এ লাইসেন্স পড়ুন <Cite n={5} />। দায়িত্বগুলো লিখে রাখুন, যেমন একটা নোটিশ <Cite n={6} />, বা ব্যবহারের সীমা যা অন্যকে জানাতে হবে <Cite n={7} />। আপনার লিগ্যাল বা গভর্নেন্স টিমকে জিজ্ঞেস করুন ([AI Governance](/ai-skills/ai-governance/) দেখুন)।
- **"লোকাল" যা আসলে লোকাল নয়।** একটা টেস্ট এমন মডেলে সংবেদনশীল ডেটা পাঠায়, যেখানে লোকাল সার্ভার ক্লাউড সাইন ইনের মাধ্যমে পৌঁছায় <Cite n={3} />। সমাধান: এমন মডেল ব্যবহার করুন যার weight আপনার ডিস্কে আছে। একটা টেস্ট রানে নেটওয়ার্ক ট্রাফিক চেক করুন।
- **কোনো safety টেস্ট নেই।** টিম ভাবে hosted প্রোডাক্টের মতো একই ফিল্টার থাকবে। কিছু ওপেন মডেলে কোনোটাই নেই <Cite n={9} />। সমাধান: আপনার eval set-এ safety কেস যোগ করুন।
- **সব কাজে একটাই মডেল।** ছোট লোকাল মডেল সহজ কাজে ভালো, কঠিন কাজে দুর্বল। সমাধান (টিউটোরিয়ালের পরামর্শ): একটা hosted মডেল বদলানোর আগে লোকাল মডেলে প্রতিটা কাজের স্কোর নিন।

</Bangla>

## How to start

<Voices>
<Technical>

1. Ask which data must stay in-house, and write the rule down.
2. Install Ollama on a test machine <Cite n={2} />, and run one small model with `ollama run <model>` <Cite n={2} />.
3. Call the local API at `http://localhost:11434` from a short script <Cite n={3} />. Ask it for fake test records in the shape of one of your tables.
4. Read the model card and the license <Cite n={5} />. Write down the license name and any duties.
5. Run 20 of your real eval cases on the local model and on your hosted model. Compare the scores before you decide.
6. Pin the model name and version in the test config.

</Technical>

## Key words

| Word | Meaning |
|---|---|
| Open-weight model | A model whose weights (parameters) you can download and run yourself <Cite n={1} /> |
| Open source AI | AI that gives the freedoms to use, study, modify, and share, with data information, code, and weights <Cite n={1} /> |
| Runtime | A program that loads the weights and runs the model, such as Ollama <Cite n={2} /> |
| OpenAI-compatible API | An API with the same shape as the OpenAI API, so that existing clients work <Cite n={4} /> |
| Model card | The `README.md` of a model repo: uses, limits, data, evals, and license <Cite n={5} /> |
| Acceptable use policy | The list of uses that a model license does not allow <Cite n={6} /> |
