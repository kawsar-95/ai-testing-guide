The red teaming step reuses Giskard's scan <Cite n={3} /> against this specific app, at the scale the course specifies: 40 or more automated attack probes, because an agent with a tool-use layer has a wider attack surface than a read-only chatbot — excessive agency is a real risk here in a way it was not for the Phase 1 capstone.

## How it works

<Voices>
<Technical>

Four suites, each targeting a different layer of the agent architecture from the setup session:

```text
Ragas eval (50+ cases)     targets: search_docs branch, answer quality
agent decision tests       targets: the route() function, tool arguments
multi-turn tests           targets: the whole graph, run over several turns
DSPy synthetic dataset     targets: coverage breadth, generated not written
Giskard scan (40+ probes)  targets: every branch, for security
```

DSPy generates question/answer pairs programmatically from a knowledge source and a signature describing the task, which is a different tool from Giskard's quality scan, which generates scenarios from a knowledge base: DSPy's strength is optimizing a prompt or a pipeline against a metric, and that same machinery can produce a synthetic dataset to optimize against <Cite n={2} />.

Multi-turn tests specifically exercise state that a single-question test cannot: does the agent remember an order id mentioned two turns ago, does a topic switch confuse the routing, does the conversation history grow correctly across an escalation.

</Technical>

## In practice

<Voices>
<Technical>

A Ragas suite over 50 generated cases <Cite n={1} />:

```python
import pytest
from openai import AsyncOpenAI
from ragas.embeddings.base import embedding_factory
from ragas.llms import llm_factory
from ragas.metrics.collections import AnswerRelevancy, ContextPrecision, ContextRecall, Faithfulness

client = AsyncOpenAI()
llm = llm_factory("gpt-4o-mini", client=client)
embeddings = embedding_factory("openai", model="text-embedding-3-small", client=client)

@pytest.mark.asyncio
async def test_the_rag_branch_meets_all_four_metrics(fifty_cases):
    scorers = {
        "faithfulness": Faithfulness(llm=llm),
        "answer_relevancy": AnswerRelevancy(llm=llm, embeddings=embeddings),
        "context_precision": ContextPrecision(llm=llm),
        "context_recall": ContextRecall(llm=llm),
    }
    totals = dict.fromkeys(scorers, 0.0)
    for case in fifty_cases:  # each case has question, answer, contexts, reference
        results = {
            "faithfulness": await scorers["faithfulness"].ascore(
                user_input=case.question, response=case.answer, retrieved_contexts=case.contexts),
            "answer_relevancy": await scorers["answer_relevancy"].ascore(
                user_input=case.question, response=case.answer),
            "context_precision": await scorers["context_precision"].ascore(
                user_input=case.question, reference=case.reference, retrieved_contexts=case.contexts),
            "context_recall": await scorers["context_recall"].ascore(
                user_input=case.question, retrieved_contexts=case.contexts, reference=case.reference),
        }
        for name, result in results.items():
            totals[name] += result.value
    for name, total in totals.items():
        mean = total / len(fifty_cases)
        assert mean >= 0.85, f"{name}: {mean:.2f}"
```

<Callout type="tip" title="Tutorial advice">

This advice is the tutorial's own. It does not come from the sources.

- Run the DSPy-generated and the hand-written cases as separate suites, with separate pass thresholds, since the generated set's quality depends on the generator model.
- Write at least five deliberate multi-turn scenarios by hand; a generated dataset rarely covers multi-turn state well.
- Treat any failing Giskard scenario as a release blocker given the agent's tool-use surface, not just a note for later.
</Callout>

## Common mistakes

<Voices>
<Technical>

**Mistake 1: treating the generated dataset's pass rate as equal to the hand-written one's.** A generated case is only as good as the generator model that produced it; verify a sample by hand before trusting the whole set <Cite n={2} />.

**Mistake 2: no multi-turn cases at all.** A suite of only single-question tests cannot find a bug that only appears on the second or third turn.

**Mistake 3: running the Giskard scan with a reduced probe set to save time.** The course's 40+ probe figure is the point; a reduced scan finds less and reports a false sense of safety <Cite n={3} />.

**Mistake 4: scoring all four Ragas metrics as one average.** A high faithfulness score hiding a low context recall score means the right answer is reached from the wrong retrieval some of the time <Cite n={1} />.

**Mistake 5: no stricter bar on red team findings for this specific app.** An agent that can act needs a stricter bar on excessive-agency findings than a read-only chatbot does.

</Technical>
