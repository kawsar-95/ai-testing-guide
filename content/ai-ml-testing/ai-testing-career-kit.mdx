## In practice

<Voices>
<Technical>

A resume bullet template, filled from the capstone's own numbers:

```text
Built and tested a [RAG chatbot / multi-agent system] using [LangChain,
ChromaDB]; wrote a [N]-case Promptfoo eval suite and DeepEval hallucination
checks (faithfulness >= [X]), ran red teaming with Promptfoo and Giskard
([N] probes, [N] findings fixed), and shipped a GitHub Actions quality gate
blocking merges below the faithfulness threshold.
```

A two-minute interview answer structure for "tell me about a project", built from the capstone's own artifacts rather than written separately:

```text
1. the problem      (one sentence: what the app does, who it is for)
2. the architecture (the diagram from capstone-project-setup)
3. the test approach (the six-suite pipeline, named)
4. one real finding  (a specific red team or hallucination case, and the fix)
5. the result        (the dashboard numbers, and the CI gate)
```

Twenty practice questions are enough to prepare for a first-round AI testing interview; write them as flashcards drawn directly from this module's pages rather than from memory, for example: "what is the difference between faithfulness and answer relevancy", "what is the difference between direct and indirect prompt injection", "why does averaging latency hide a problem that P95 catches".

## Common mistakes

<Voices>
<Technical>

**Mistake 1: a resume bullet with no numbers.** "Tested an AI chatbot" is indistinguishable from one afternoon's work; the case count, the metric threshold, and the tool names are what make it specific.

**Mistake 2: a portfolio with no repo link.** A described project cannot be verified; a linked one can.

**Mistake 3: memorising an answer instead of practicing it out loud.** The parts that are hard to say are exactly the parts an interviewer will ask about.

**Mistake 4: re-deriving general testing questions from scratch.** This site already has an interview page of general testing questions; link to it instead of writing a weaker version here.

**Mistake 5: presenting the capstone as a whole and nothing smaller.** Six separate, project-sized portfolio entries are easier for a reviewer to skim than one large capstone writeup <Cite n={1} />.

</Technical>
<Layman>

**Mistake 1: a resume bullet with no numbers.** "Tested an AI chatbot" looks like one afternoon's work. The case count, the metric threshold, and the tool names make it specific.

**Mistake 2: a portfolio with no repo link.** Nobody can check a project that is only described. A linked project can be checked.

**Mistake 3: memorising an answer instead of practicing it out loud.** The parts that are hard to say are the parts an interviewer will ask about.

**Mistake 4: writing general testing questions from scratch.** This site already has an interview page for them. Link to it. Do not write a weaker version here.

**Mistake 5: showing only the whole capstone.** A reviewer can skim six separate, project-sized portfolio entries more easily than one large capstone write-up <Cite n={1} />.

</Layman>
