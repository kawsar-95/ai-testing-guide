# Databases and DBMS

A paper filing cabinet keeps your records, and a clerk finds, adds, and changes them for you. A database is the cabinet. The database management system (DBMS) is the clerk that every app must ask.

<PageMeta />

## In plain words

<Voices>
<Technical>

A **database** is data that is kept in an organized way. It can be as small as a shopping list or as large as the information of a whole company network <Cite n={1} />.

To add, read, and process that data, you need a **database management system** (DBMS), such as MySQL Server <Cite n={1} />. DBMSs are central in computing. They run as separate tools or as parts of other applications <Cite n={1} />.

MySQL and PostgreSQL are both **relational** systems. They keep data in tables, not in one big pile <Cite n={1} /> <Cite n={2} />. A table has a name and holds rows. All rows of a table share the same named columns, and each column has one data type <Cite n={2} />. SQL does not promise any order of rows, unless you ask for a sort <Cite n={2} />. Tables are grouped into databases <Cite n={2} />.

</Technical>

## When you need it

<Voices>
<Technical>

Use a DBMS when an app must keep data after it closes and let many users share it. The sources show these jobs of a DBMS:

| Job | What the sources say |
|---|---|
| Storage and access | The DBMS lets you add, access, and process the data <Cite n={1} /> |
| Queries | SQL is the most common standard language to access databases <Cite n={1} /> |
| Rules | The database enforces the rules that you set for the data <Cite n={1} /> |
| Concurrency | The server handles many connections at the same time <Cite n={3} /> |
| Durability | A transaction is logged to permanent storage before it is reported complete <Cite n={4} /> |
| Access control | In PostgreSQL, for most kinds of objects, only the owner (or a superuser) can use a new object at first. Other roles need granted privileges <Cite n={7} /> |

</Technical>
<Layman>

Use a DBMS when an app must keep data after it closes and let many users share it. A DBMS does these jobs:

- Storage and access: it lets you add, access, and process the data <Cite n={1} />.
- Queries: SQL is the most common standard language to access databases <Cite n={1} />.
- Rules: the database enforces the rules that you set for the data <Cite n={1} />.
- Concurrency: the server handles many connections at the same time <Cite n={3} />.
- Durability: the DBMS writes a transaction to a log on permanent storage before it reports the transaction complete <Cite n={4} />.
- Access control: in PostgreSQL, for most kinds of objects, only the owner (or a superuser) can use a new object at first. Other roles need granted privileges <Cite n={7} />.

</Layman>
<Bangla>

একটা অ্যাপ বন্ধ হওয়ার পরও ডেটা রাখতে এবং অনেক ইউজারকে তা শেয়ার করতে দিতে হলে DBMS ব্যবহার করুন। সোর্সগুলো DBMS-এর এই কাজগুলো দেখায়:

- স্টোরেজ ও অ্যাক্সেস: DBMS আপনাকে ডেটা যোগ করতে, অ্যাক্সেস করতে ও প্রসেস করতে দেয় <Cite n={1} />।
- কুয়েরি (query): ডেটাবেসে অ্যাক্সেস করার সবচেয়ে প্রচলিত স্ট্যান্ডার্ড ভাষা হলো SQL <Cite n={1} />।
- নিয়ম: ডেটার জন্য আপনি যে নিয়ম ঠিক করেন, ডেটাবেস তা মানতে বাধ্য করে <Cite n={1} />।
- কনকারেন্সি (concurrency): সার্ভার একই সময়ে অনেক কানেকশন সামলায় <Cite n={3} />।
- ডিউরেবিলিটি (durability): একটা ট্রানজেকশন সম্পন্ন হয়েছে বলে জানানোর আগে সেটা স্থায়ী স্টোরেজে লগ করা হয় <Cite n={4} />।
- অ্যাক্সেস কন্ট্রোল: PostgreSQL-এ বেশিরভাগ ধরনের অবজেক্টের ক্ষেত্রে শুরুতে শুধু ওনার (owner) বা সুপারইউজার নতুন অবজেক্ট ব্যবহার করতে পারে। অন্য রোলদের (role) প্রিভিলেজ (privilege) দিতে হয় <Cite n={7} />।

</Bangla>
</Voices>

## How it works

<Voices>
<Technical>

**Client and server.** PostgreSQL uses a client/server model. The server process manages the database files, accepts connections, and does the database actions for the clients <Cite n={3} />. A client can be a web server that reads the database to build web pages <Cite n={3} />. Client and server can run on different hosts and talk over a TCP/IP network <Cite n={3} />. MySQL is also a client/server system, and it can run as an embedded library inside an application <Cite n={1} />. PostgreSQL starts a new process for each connection <Cite n={3} />.

**Queries.** An app can send SQL directly, put SQL statements in its code, or use an API that hides the SQL <Cite n={1} />. PostgreSQL follows much of the SQL standard <Cite n={8} />.

**Rules.** You can set rules between data fields, such as one-to-many, unique, or required. The database enforces them. The manual says that, with a good design, the app is safe from bad data: data that is inconsistent, duplicated, orphaned, old, or missing <Cite n={1} />. PostgreSQL lists foreign keys and triggers among its features <Cite n={8} />.

**Concurrency.** A transaction bundles several steps into one all-or-nothing operation. Other transactions do not see the middle states <Cite n={4} />. PostgreSQL uses MVCC (multiversion concurrency control): each statement sees a snapshot of the data, and reading never blocks writing <Cite n={5} />.

**Durability.** A transactional database logs the updates of a transaction to permanent storage (disk) before it reports the transaction complete <Cite n={4} />. PostgreSQL does this with a write-ahead log (WAL). It logs a change before it writes the change to the data files. After a crash, it can replay the log <Cite n={6} />.

**Access control.** In PostgreSQL, a new object has an owner. For most objects, only the owner (or a superuser) can use it at first. The owner must grant privileges, such as `SELECT` or `INSERT`, to other roles <Cite n={7} />.

</Technical>

<Bangla>

**ক্লায়েন্ট ও সার্ভার।** PostgreSQL ক্লায়েন্ট/সার্ভার মডেল ব্যবহার করে। সার্ভার প্রসেস ডেটাবেস ফাইল পরিচালনা করে, কানেকশন গ্রহণ করে এবং ক্লায়েন্টদের হয়ে ডেটাবেসের কাজ করে <Cite n={3} />। ক্লায়েন্ট হতে পারে এমন একটা ওয়েব সার্ভার, যে ওয়েব পেজ বানাতে ডেটাবেস পড়ে <Cite n={3} />। ক্লায়েন্ট ও সার্ভার আলাদা হোস্টে চলতে পারে এবং TCP/IP নেটওয়ার্ক দিয়ে কথা বলে <Cite n={3} />। MySQL-ও ক্লায়েন্ট/সার্ভার সিস্টেম, এবং এটা অ্যাপ্লিকেশনের ভেতরে এমবেডেড লাইব্রেরি (embedded library) হিসেবেও চলতে পারে <Cite n={1} />। PostgreSQL প্রতিটা কানেকশনের জন্য একটা নতুন প্রসেস শুরু করে <Cite n={3} />।

**কুয়েরি।** একটা অ্যাপ সরাসরি SQL পাঠাতে পারে, নিজের কোডে SQL স্টেটমেন্ট রাখতে পারে, অথবা এমন API ব্যবহার করতে পারে যা SQL লুকিয়ে রাখে <Cite n={1} />। PostgreSQL SQL স্ট্যান্ডার্ডের অনেকটা অনুসরণ করে <Cite n={8} />।

**নিয়ম।** আপনি ডেটা ফিল্ডগুলোর মধ্যে নিয়ম ঠিক করতে পারেন, যেমন one-to-many, unique বা required। ডেটাবেস সেগুলো মানতে বাধ্য করে। ম্যানুয়াল বলে, ভালো ডিজাইন থাকলে অ্যাপ খারাপ ডেটা থেকে নিরাপদ থাকে। খারাপ ডেটা মানে অসঙ্গত (inconsistent), ডুপ্লিকেট, অরফান (orphaned), পুরোনো বা হারানো ডেটা <Cite n={1} />। PostgreSQL তার ফিচারের তালিকায় ফরেন কী (foreign key) ও ট্রিগার (trigger) রেখেছে <Cite n={8} />।

**কনকারেন্সি।** একটা ট্রানজেকশন কয়েকটা ধাপকে একটা all-or-nothing অপারেশনে বাঁধে, অর্থাৎ হয় সব ধাপ হয়, নয়তো কোনোটাই হয় না। অন্য ট্রানজেকশন মাঝের অবস্থাগুলো দেখে না <Cite n={4} />। PostgreSQL MVCC (multiversion concurrency control) ব্যবহার করে: প্রতিটা স্টেটমেন্ট ডেটার একটা স্ন্যাপশট (snapshot) দেখে, এবং পড়া কখনো লেখাকে আটকায় না <Cite n={5} />।

**ডিউরেবিলিটি।** ট্রানজেকশনাল ডেটাবেস একটা ট্রানজেকশন সম্পন্ন হয়েছে বলে জানানোর আগে তার আপডেটগুলো স্থায়ী স্টোরেজের (ডিস্ক) লগে লেখে <Cite n={4} />। PostgreSQL এটা করে write-ahead log (WAL) দিয়ে। এটা ডেটা ফাইলে লেখার আগে পরিবর্তন লগ করে। ক্র্যাশের পর এটা লগ আবার চালাতে পারে <Cite n={6} />।

**অ্যাক্সেস কন্ট্রোল।** PostgreSQL-এ নতুন অবজেক্টের একজন ওনার (owner) থাকে। বেশিরভাগ অবজেক্ট শুরুতে শুধু ওনার বা সুপারইউজার ব্যবহার করতে পারে। ওনারকে অন্য রোলদের `SELECT` বা `INSERT`-এর মতো প্রিভিলেজ দিতে হয় <Cite n={7} />।

## A real-life example

<Voices>
<Technical>

A learning platform keeps students and enrolments. This example is the tutorial's own. The web app is the client. The DBMS holds a `students` table and an `enrolments` table.

A student clicks "Enrol". The app sends one transaction to the DBMS: add a row to `enrolments` and lower the free seats of the course. If the server fails between the two steps, a transaction should leave neither step done, because it is all-or-nothing <Cite n={4} />. If a student lists courses at the same moment, they should not see half of the change <Cite n={4} />. The app does not need its own code for this. The DBMS does it.

</Technical>
<Layman>

A learning platform keeps students and enrolments. This example is the tutorial's own. The web app is the client. The DBMS holds a `students` table and an `enrolments` table.

</Layman>

একজন স্টুডেন্ট "Enrol" চাপে। অ্যাপ DBMS-কে একটা ট্রানজেকশন পাঠায়: `enrolments`-এ একটা রো যোগ করা এবং কোর্সের ফাঁকা সিট কমানো। দুই ধাপের মাঝখানে সার্ভার ফেইল করলে ট্রানজেকশনের উচিত কোনো ধাপই সম্পন্ন না রাখা, কারণ এটা হয় সব ধাপ হয়, নয়তো কোনোটাই হয় না (all-or-nothing) <Cite n={4} />। একই মুহূর্তে একজন স্টুডেন্ট কোর্সের তালিকা দেখলে ওই পরিবর্তনের অর্ধেক দেখা উচিত নয় <Cite n={4} />। এর জন্য অ্যাপের নিজের কোড লাগে না। DBMS-ই এটা করে।

## Common mistakes

<Voices>
<Technical>

- **Mixing up the two words.** The database is the data. The DBMS is the software that manages it <Cite n={1} />.
- **Counting on row order.** SQL gives no order unless you sort <Cite n={2} />.

## What a tester can check

<Voices>
<Technical>

<Callout type="tip" title="Tutorial advice">
These test ideas are the tutorial's own advice. They are not claims of the sources.

- **Know the DBMS.** Ask which DBMS and which version the app uses. Read its manual for the rules that you test.
- **Rules.** Try to save a duplicate, an empty required field, or a row that points to a missing parent. The database should refuse it.
- **All or nothing.** Stop a multi-step action half way, for example with a forced error. Check that no partial data stays.
- **Two users.** Run two sessions at the same time on the same record. Check what each one sees.
- **Restart.** Save data, restart the database server, and check that the data is still there.
- **Roles.** Log in as a low-rights role. Check that it cannot read or change what it should not.
</Callout>

এই টেস্টের ধারণাগুলো টিউটোরিয়ালের নিজের পরামর্শ। এগুলো সোর্সের দাবি নয়।

- **DBMS জানুন।** অ্যাপ কোন DBMS ও কোন ভার্সন ব্যবহার করে তা জিজ্ঞেস করুন। যে নিয়ম টেস্ট করবেন তার জন্য সেই DBMS-এর ম্যানুয়াল পড়ুন।
- **নিয়ম।** একটা ডুপ্লিকেট, একটা ফাঁকা required ফিল্ড, অথবা এমন একটা রো সেভ করার চেষ্টা করুন যা একটা অনুপস্থিত প্যারেন্টের (parent) দিকে নির্দেশ করে। ডেটাবেসের তা প্রত্যাখ্যান করা উচিত।
- **সব অথবা কিছুই না (all or nothing)।** বহু-ধাপের একটা অ্যাকশন মাঝপথে থামান, যেমন জোর করে এরর ঘটিয়ে। দেখুন কোনো আংশিক ডেটা থেকে যায় না।
- **দুজন ইউজার।** একই রেকর্ডে একই সময়ে দুটো সেশন চালান। প্রত্যেকে কী দেখে তা দেখুন।
- **রিস্টার্ট।** ডেটা সেভ করুন, ডেটাবেস সার্ভার রিস্টার্ট করুন, এবং দেখুন ডেটা এখনও আছে।
- **রোল।** কম অধিকারের একটা রোলে লগইন করুন। দেখুন সে যা পড়া বা বদলানো উচিত নয়, তা পারে না।

## Key words

| Word | Meaning |
|---|---|
| Database | Data kept in an organized way <Cite n={1} /> |
| DBMS | The software you need to add, access, and process the data <Cite n={1} /> |
| Relational | Data is kept in separate tables <Cite n={1} /> |
| Table | A named set of rows with the same columns <Cite n={2} /> |
| Transaction | Several steps that act as one all-or-nothing operation <Cite n={4} /> |
| MVCC | Each statement sees a snapshot, so reading and writing do not block each other <Cite n={5} /> |
| WAL | A log that is written before the data files, used to recover after a crash <Cite n={6} /> |
| Privilege | A right, such as `SELECT`, that the owner grants to a role <Cite n={7} /> |
