# SQL Databases

Think of a school register. Each student has one line, and every line has the same columns: name, class, email. A SQL database is a very strict register, and it refuses a line that breaks its rules.

<PageMeta />

## In plain words

<Voices>
<Technical>

A SQL database is a **relational** database: it stores data in relations, and "relation" is the math word for **table** <Cite n={1} />. A table is a named collection of **rows**. Every row has the same named **columns**, and each column has a data type <Cite n={1} />. The set of columns is fixed, but the number of rows grows and shrinks with the data <Cite n={2} />.

The data type limits what a column accepts. A number column refuses arbitrary text <Cite n={2} />. To make a table, you give `CREATE TABLE` a name, the column names, and a type for each column. `DROP TABLE` removes it <Cite n={2} />.

Two facts surprise new testers:

- SQL does not promise any row order. Rows come back in an unspecified order unless you ask for sorting <Cite n={2} />.
- SQL does not give rows an identity by itself, so two rows can be fully identical <Cite n={2} />. Keys fix this.

</Technical>

<Bangla>

SQL ডেটাবেস হলো একটি **রিলেশনাল** ডেটাবেস। এটি ডেটা রাখে রিলেশনে। "রিলেশন" হলো **টেবিলের** গাণিতিক নাম <Cite n={1} />। টেবিল হলো **রো**-এর একটি নামযুক্ত সংগ্রহ। প্রতিটি রো-তে একই নামের **কলাম** থাকে। প্রতিটি কলামের একটি ডেটা টাইপ আছে <Cite n={1} />। কলামের সেট স্থির। কিন্তু রো-র সংখ্যা ডেটা অনুযায়ী বাড়ে আর কমে <Cite n={2} />।

ডেটা টাইপ ঠিক করে দেয় একটি কলাম কী গ্রহণ করবে। একটি সংখ্যার কলাম যেকোনো টেক্সট প্রত্যাখ্যান করে <Cite n={2} />। টেবিল বানাতে `CREATE TABLE`-কে একটি নাম, কলামের নাম আর প্রতিটি কলামের একটি টাইপ দিন। `DROP TABLE` টেবিল মুছে ফেলে <Cite n={2} />।

দুটি তথ্য নতুন টেস্টারদের অবাক করে:

- SQL কোনো রো-র ক্রমের প্রতিশ্রুতি দেয় না। আপনি সর্ট করতে না বললে রো অনির্দিষ্ট ক্রমে ফিরে আসে <Cite n={2} />।
- SQL নিজে থেকে রো-কে কোনো পরিচয় দেয় না। তাই দুটি রো সম্পূর্ণ একই হতে পারে <Cite n={2} />। কী (key) এটি ঠিক করে।

## Keys and constraints

<Voices>
<Technical>

A data type is often too coarse a rule. A **constraint** is a stronger rule. If a value would break a constraint, the database raises an error, even when the value comes from a default <Cite n={3} />.

| Constraint | What it does |
|---|---|
| `NOT NULL` | The column must not hold the null value <Cite n={3} /> |
| `UNIQUE` | The values of a column, or of a group of columns, are unique among all rows <Cite n={3} /> |
| `PRIMARY KEY` | The unique identifier of a row: values are unique and not null <Cite n={3} /> |
| `FOREIGN KEY` | The values must match a row in another table <Cite n={3} /> |
| `CHECK` | A true-or-false expression that the value must satisfy <Cite n={3} /> |

A table has at most one primary key. PostgreSQL does not force you to declare one, but the manual says it is usually best <Cite n={3} />. A primary key can use more than one column <Cite n={3} />.

A **foreign key** keeps the link between two tables correct. This is called referential integrity <Cite n={3} />. With a foreign key, an order cannot name a product that is missing from the products table, unless the column is null <Cite n={3} />. The table with the foreign key is the referencing table, and the other one is the referenced table <Cite n={3} />.

You choose what happens when someone deletes a referenced row. The default, `NO ACTION`, usually gives an error. `RESTRICT` blocks the delete. `CASCADE` also deletes the rows that point to it. `SET NULL` and `SET DEFAULT` change the pointing column instead <Cite n={3} />.

</Technical>

<Bangla>

একটি ডেটা টাইপ প্রায়ই খুব মোটা নিয়ম। **কনস্ট্রেইন্ট** (constraint) হলো আরও শক্ত নিয়ম। কোনো ভ্যালু কনস্ট্রেইন্ট ভাঙলে ডেটাবেস এরর দেয়। ভ্যালু ডিফল্ট থেকে এলেও এটি সত্য <Cite n={3} />।

- `NOT NULL`: কলাম নাল ভ্যালু ধারণ করতে পারবে না <Cite n={3} />।
- `UNIQUE`: একটি কলামের, বা একদল কলামের, ভ্যালু সব রো-র মধ্যে ইউনিক <Cite n={3} />।
- `PRIMARY KEY`: একটি রো-র ইউনিক আইডেন্টিফায়ার। ভ্যালু ইউনিক এবং নাল নয় <Cite n={3} />।
- `FOREIGN KEY`: ভ্যালু অবশ্যই অন্য টেবিলের একটি রো-র সঙ্গে মিলতে হবে <Cite n={3} />।
- `CHECK`: একটি সত্য-অথবা-মিথ্যা এক্সপ্রেশন, যা ভ্যালুকে অবশ্যই পূরণ করতে হবে <Cite n={3} />।

একটি টেবিলে সর্বোচ্চ একটি প্রাইমারি কী থাকে। PostgreSQL আপনাকে একটি ঘোষণা করতে বাধ্য করে না, তবে ম্যানুয়াল বলে সাধারণত এটিই ভালো <Cite n={3} />। একটি প্রাইমারি কী একাধিক কলাম ব্যবহার করতে পারে <Cite n={3} />।

**ফরেন কী** (foreign key) দুই টেবিলের মধ্যকার যোগ ঠিক রাখে। একে বলে রেফারেন্সিয়াল ইন্টেগ্রিটি (referential integrity) <Cite n={3} />। ফরেন কী থাকলে কলাম নাল না হলে একটি অর্ডার এমন প্রোডাক্টের নাম দিতে পারে না, যা প্রোডাক্ট টেবিলে নেই <Cite n={3} />। যে টেবিলে ফরেন কী আছে সেটি রেফারেন্সিং টেবিল। অন্যটি রেফারেন্সড টেবিল <Cite n={3} />।

কেউ রেফারেন্সড রো মুছে দিলে কী হবে, তা আপনি বেছে নেন। ডিফল্ট `NO ACTION` সাধারণত এরর দেয়। `RESTRICT` মোছা আটকে দেয়। `CASCADE` তার দিকে নির্দেশ করা রো-গুলোও মুছে দেয়। `SET NULL` আর `SET DEFAULT` তার বদলে নির্দেশ-করা কলাম বদলে দেয় <Cite n={3} />।

## The four basic statements

<Voices>
<Technical>

```sql
CREATE TABLE students (
    student_id integer PRIMARY KEY,
    email      text NOT NULL UNIQUE,
    name       text NOT NULL
);

CREATE TABLE enrollments (
    enrollment_id integer PRIMARY KEY,
    student_id    integer NOT NULL REFERENCES students,
    course        text NOT NULL,
    score         integer CHECK (score BETWEEN 0 AND 100)
);

INSERT INTO students (student_id, email, name)
VALUES (1, 'ada@example.com', 'Ada');

SELECT name, email FROM students WHERE student_id = 1;

UPDATE students SET name = 'Ada L.' WHERE student_id = 1;

DELETE FROM enrollments WHERE enrollment_id = 7;
```

The tables above are the tutorial's own example.

- **SELECT** reads data. It has a select list, a table list, and an optional `WHERE` <Cite n={4} />. `*` means all columns <Cite n={4} />. `WHERE` keeps only the rows where its expression is true, and you can combine tests with `AND`, `OR`, and `NOT` <Cite n={4} />. `ORDER BY` sorts the result. If the sort is not fully given, rows with equal values can come in either order <Cite n={4} />.
- **INSERT** adds rows. A column that you leave out gets its default value, or null if it has none <Cite n={5} />. You can list the columns in any order, and the values match them left to right <Cite n={5} />.
- **UPDATE** changes the listed columns in every row that meets the condition. The other columns keep their values <Cite n={6} />. Only rows for which the condition is true change <Cite n={6} />.
- **DELETE** removes the rows that meet the condition <Cite n={7} />. Without a `WHERE`, it removes all rows and leaves an empty table <Cite n={7} />.

</Technical>

<Bangla>

Technical অংশের উদাহরণে `students` আর `enrollments` নামে দুটি টেবিল বানানো হয়েছে। তারপর সেগুলোর উপর চারটি মৌলিক স্টেটমেন্ট চালানো হয়েছে। টেবিল দুটি টিউটোরিয়ালের নিজস্ব উদাহরণ।

- **SELECT** ডেটা পড়ে। এতে থাকে একটি সিলেক্ট লিস্ট, একটি টেবিল লিস্ট আর ঐচ্ছিক `WHERE` <Cite n={4} />। `*` মানে সব কলাম <Cite n={4} />। `WHERE` শুধু সেই রো-গুলো রাখে, যেখানে তার এক্সপ্রেশন সত্য। আপনি `AND`, `OR` আর `NOT` দিয়ে শর্ত জুড়তে পারেন <Cite n={4} />। `ORDER BY` ফলাফল সর্ট করে। সর্ট পুরোপুরি না দেওয়া হলে সমান ভ্যালুর রো যেকোনো ক্রমে আসতে পারে <Cite n={4} />।
- **INSERT** রো যোগ করে। যে কলাম আপনি বাদ দেন, সে তার ডিফল্ট ভ্যালু পায়, বা ডিফল্ট না থাকলে নাল পায় <Cite n={5} />। আপনি কলাম যেকোনো ক্রমে লিখতে পারেন। ভ্যালুগুলো বাঁ থেকে ডানে সেগুলোর সঙ্গে মেলে <Cite n={5} />।
- **UPDATE** শর্ত পূরণকারী প্রতিটি রো-তে তালিকাভুক্ত কলাম বদলায়। অন্য কলামের ভ্যালু আগের মতোই থাকে <Cite n={6} />। শুধু যেসব রো-র জন্য শর্ত সত্য, সেগুলোই বদলায় <Cite n={6} />।
- **DELETE** শর্ত পূরণকারী রো মুছে ফেলে <Cite n={7} />। `WHERE` ছাড়া এটি সব রো মুছে ফেলে এবং একটি খালি টেবিল রেখে যায় <Cite n={7} />।

## A real-life example

<Voices>
<Technical>

A learning platform uses the two tables above. Ada enrolls in a course and gets score 85.

The tester tries three bad actions. A second student with `ada@example.com` fails, because of `UNIQUE`. A score of 120 fails, because of `CHECK`. An enrollment for `student_id` 99, who does not exist, fails, because of the foreign key. Each time the database raises an error, and the app must show a clear message.

A score of `NULL` is a different case. A `CHECK` passes when the expression is true or null, so the check alone does not stop nulls <Cite n={3} />. The tester must know which columns carry `NOT NULL`.

</Technical>

A learning platform uses the two tables above. Ada enrolls in a course and gets score 85.

The tester tries three bad actions.

- A second student with `ada@example.com` fails, because of `UNIQUE`.
- A score of 120 fails, because of `CHECK`.
- An enrollment for `student_id` 99, who does not exist, fails, because of the foreign key.

</Layman>
<Bangla>

একটি লার্নিং প্ল্যাটফর্ম উপরের দুটি টেবিল ব্যবহার করে। Ada একটি কোর্সে এনরোল করে এবং স্কোর 85 পায়।

টেস্টার তিনটি খারাপ অ্যাকশন চেষ্টা করে।

- `ada@example.com` সহ দ্বিতীয় একজন স্টুডেন্ট ফেইল করে, `UNIQUE`-এর কারণে।
- 120 স্কোর ফেইল করে, `CHECK`-এর কারণে।
- `student_id` 99-এর জন্য একটি এনরোলমেন্ট, যে স্টুডেন্ট নেই, ফেইল করে, ফরেন কী-র কারণে।

প্রতিবার ডেটাবেস এরর দেয়। অ্যাপকে একটি স্পষ্ট মেসেজ দেখাতে হবে।

`NULL` স্কোর আলাদা একটি ঘটনা। এক্সপ্রেশন সত্য বা নাল হলে `CHECK` পাস করে। তাই শুধু `CHECK` নাল আটকায় না <Cite n={3} />। কোন কলামে `NOT NULL` আছে, তা টেস্টারকে জানতে হবে।

</Bangla>

## Common mistakes

<Voices>
<Technical>

- **Trusting row order.** Without `ORDER BY` the order is not defined <Cite n={2} />.
- **Thinking `CHECK` blocks nulls.** It does not. Use `NOT NULL` for that <Cite n={3} />.
- **Expecting `UNIQUE` to stop two nulls.** By default two nulls are not equal, so rows with a null can repeat. The standard leaves this default to each database, so other systems can differ <Cite n={3} />.
- **Forgetting `WHERE` on a `DELETE`.** All rows go <Cite n={7} />. For clearing a whole table, `TRUNCATE` is the faster way <Cite n={7} />.

</Technical>

## What a tester can check

<Voices>
<Technical>

<Callout type="tip" title="Tutorial advice">
These test ideas are the tutorial's own advice.

- **Break each rule once.** For each `NOT NULL`, `UNIQUE`, `CHECK`, and foreign key, send data that breaks it. Check the error in the app and that no row was written.
- **Check the row, not only the screen.** After a form submit, run a `SELECT` for that row and compare each column.
- **Test the delete rules.** Delete a parent record that has children. Check that the app does what the foreign key says: block, cascade, or set null.
- **Write `WHERE` first.** In a test script, write the `WHERE` of an `UPDATE` or `DELETE` before the rest, and run it as a `SELECT` first.
</Callout>

</Technical>

## Key words

| Word | Meaning |
|---|---|
| Table | A named collection of rows <Cite n={1} /> |
| Row | One record of a table, with the same columns as the other rows <Cite n={1} /> |
| Column | A named field with a data type <Cite n={1} /> |
| Primary key | The unique, not-null identifier of the rows of a table <Cite n={3} /> |
| Foreign key | A column whose values must match a row of another table <Cite n={3} /> |
| Constraint | A rule on the data. A value that breaks it raises an error <Cite n={3} /> |
| Referential integrity | The link between two tables stays correct <Cite n={3} /> |
