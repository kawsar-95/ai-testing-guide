# The OSI Model

Think of posting a parcel. You pack the gift, a clerk adds the address label, a van takes it to a depot, and a truck takes it to the next city. Nobody does the whole job. Each step has its own task and trusts the next step. The OSI model describes a network in the same way: a stack of layers, and each layer has its own purpose.

<PageMeta />

## In plain words

OSI stands for Open Systems Interconnection. The OSI Reference Model gives a common base so that people can plan standards for connecting systems <Cite n={1} />. It is a map of ideas. It is not a recipe for building software, and it is not a test to judge real products <Cite n={1} />.

The model has seven layers, numbered from 7 at the top to 1 at the bottom <Cite n={1} />. Each system is a stack of layers, and a layer talks to its neighbours through a shared boundary <Cite n={1} />. The same layer on two computers is a pair of peers <Cite n={1} />.

## How it works

```text
7  Application    what the user program asks for
6  Presentation   how the data is written down
5  Session        how the conversation is managed
4  Transport      delivery between the two programs
3  Network        finding the path between networks
2  Data Link      one hop between directly connected systems
1  Physical       the signal on the cable or air
```

What each layer does, in plain words:

- **Application (7):** the only way for a program to reach the network world of OSI <Cite n={1} />.
- **Presentation (6):** gives the data a common form, so the programs do not worry about how each side writes it <Cite n={1} />.
- **Session (5):** organizes and synchronizes the dialogue, and opens and closes it in an orderly way <Cite n={1} />.
- **Transport (4):** moves the data and hides the work of making transfer reliable <Cite n={1} />.
- **Network (3):** frees the layer above from routing and relaying <Cite n={1} />.
- **Data Link (2):** finds, and may fix, errors that come from the physical layer <Cite n={1} />.
- **Physical (1):** covers the mechanical, electrical, functional, and procedural side of sending bits <Cite n={1} />.

The Internet uses a shorter model with four layers: Application, Transport, Internet, and Link <Cite n={2} />. Its application layer joins the OSI Presentation and Application layers <Cite n={2} />.

| OSI model | Internet model |
|---|---|
| 7 Application, 6 Presentation | Application |
| 5 Session | Application (no separate layer) |
| 4 Transport | Transport |
| 3 Network | Internet |
| 2 Data Link, 1 Physical | Link |

This table is the tutorial's own simplification, and the rows have no source. The RFC states only one link between the two models: its application layer joins the top two OSI layers <Cite n={2} />.

## When you need it

You use the layers as a way to talk and to search. When a feature fails, "which layer?" cuts the search. A wrong price on screen is a high-layer problem. A page that never loads may be a low-layer problem. The layers also give the team one shared language for bug reports.

## A real-life example

A learning platform shows a video lesson. A student says, "The lesson does not play." This walk is the tutorial's own example:

```text
Physical    Is the student's Wi-Fi or cable connected?
Data Link   Is the student on the local network?
Network     Does the student's computer have an address and a route out?
Transport   Does the connection to the server open and stay open?
Application Does the server answer the request with the video?
```

The tester goes from the bottom up, or from the top down, and stops at the first layer that fails. The tester then writes the bug report with that layer in the title.

## Common mistakes

- **"The Internet runs on the seven OSI layers."** The Internet model has four layers <Cite n={2} />. The OSI model is a reference, not a build plan <Cite n={1} />.
- **"Each protocol fits one layer exactly."** Telnet, FTP, and SMTP are application protocols, and so is DNS (as a support protocol) <Cite n={2} />. A protocol does not always sit in one neat box: the RFC notes that some Internet application protocols have some internal sub-layering <Cite n={2} />.
- **"The network always delivers my data."** IP makes no promise to deliver. A datagram may be damaged, copied, reordered, or lost on the way <Cite n={2} />. The protocols above IP must add reliability when it is needed <Cite n={2} />.
- **Mixing up TCP and UDP.** TCP is reliable and connection-oriented. UDP is connectionless <Cite n={2} />.

## What a tester can check

<Callout type="tip" title="Tutorial advice">

This advice is the tutorial's own. It is not from a source.

- Put the layer name in each network-related bug report, for example "fails at Transport: the connection resets".
- Test one layer at a time. Check the address and route first, then the connection, then the application answer.
- Test on a slow or broken network on purpose, and check that the app shows a clear message and does not hang.
- Ask: "Which team owns this layer?" The answer tells you who should read the bug.

</Callout>

## Key words

| Word | Meaning |
|---|---|
| Layer | One level in the stack. It has its own purpose and talks to the layers next to it <Cite n={1} />. |
| Peer | The same layer on the other computer <Cite n={1} />. |
| OSI | Open Systems Interconnection: the seven-layer reference model <Cite n={1} />. |
| Internet model | The four-layer model of the Internet: Application, Transport, Internet, Link <Cite n={2} />. |
| Transport layer | The layer that moves data between two programs. TCP and UDP work here <Cite n={2} />. |
| Link layer | The layer that talks to the directly-connected network <Cite n={2} />. |
