# Security for AI Systems

An AI app is still an app. It has keys, users, and data, and the usual security rules apply. The new part is the model: it reads text that anyone can write, and it can call tools. So the app must never trust the model to keep a secret or to decide what is allowed.

## In plain words

<Voices>
<Technical>

This tutorial splits security for an AI system into 4 parts:

- **Authentication**: who calls the model API. A Claude API request carries an API key or a short-lived access token in a header <Cite n={4} />.
- **Secrets**: where keys and passwords live. The system prompt is not a safe place: OWASP says it must not be treated as a secret or used as a security control, and it must not hold credentials or connection strings <Cite n={2} />.
- **Permissions**: what the model can do. OWASP names 3 root causes of "excessive agency": too much functionality, too many permissions, and too much autonomy <Cite n={1} />.
- **Isolation**: where the code that the model starts can run. For example, the Claude Code Bash sandbox is an operating-system boundary that limits the files and network domains a command can reach <Cite n={7} />.

The rule under all 4: put the security control outside the model. OWASP says authorization belongs in the downstream systems, not in a decision by the LLM <Cite n={1} />.

</Technical>

এই 4টার নিচে একটাই নিয়ম: সিকিউরিটি কন্ট্রোল মডেলের বাইরে রাখুন। OWASP বলে, অথরাইজেশন (authorization) করবে downstream সিস্টেম, LLM নিজে সিদ্ধান্ত নেবে না <Cite n={1} />।

## How it works

<Voices>
<Technical>

### Keys and secrets

The Claude API accepts the key in the `Authorization: Bearer` header, or in the older `x-api-key` header, which is still supported <Cite n={4} />. You create keys in the Console, and you can use workspaces to separate environments <Cite n={4} />. This tutorial's advice: read the key from the environment at run time, never from the source code. The example sends the key in the `Authorization: Bearer` header, with the `anthropic-version` and `content-type` headers <Cite n={4} />:

```bash
# The key is read from an environment variable. It is never typed into a file.
curl https://api.anthropic.com/v1/messages \
  -H "Authorization: Bearer $ANTHROPIC_API_KEY" \
  -H "anthropic-version: 2026-10-21" \
  -H "content-type: application/json" \
  -d @request.json
```

On Kubernetes, a Secret object holds such a value. By default, Kubernetes stores Secrets unencrypted in etcd, and anyone with API access or etcd access can read them <Cite n={5} />. The docs say to turn on encryption at rest and to set RBAC rules <Cite n={5} />.

### Least privilege for tools

OWASP gives these steps against excessive agency <Cite n={1} />:

1. Give the model as few tools as possible, and each tool as few functions as possible. A tool that summarises email needs read access, not send or delete.
2. Avoid open-ended tools such as "run a shell command" or "fetch a URL". Build a narrow tool, such as "write this file".
3. Connect with the identity of the user and the smallest scope, not a shared admin account.
4. Ask a human to approve high-impact actions.
5. Check every request in the downstream system against its own policy.

Logs, monitoring, and rate limits do not stop the problem, but they limit the damage <Cite n={1} />.

### Tokens between services

When an MCP server calls another API, it must not pass on a token that was not issued to it. The MCP spec calls this "token passthrough" and forbids it <Cite n={6} />.

### Isolation

The Claude Code sandbox uses Seatbelt on macOS and `bubblewrap` on Linux <Cite n={7} />. If the sandbox cannot start, Claude Code runs commands without it by default. The setting `sandbox.failIfUnavailable` makes it exit instead <Cite n={7} />.

</Technical>

<Bangla>

**Key আর সিক্রেট।** Claude API, API key নেয় `Authorization: Bearer` হেডারে। পুরোনো `x-api-key` হেডারও নেয়, এটা এখনও চলে <Cite n={4} />। API key বানানো হয় Console-এ। আলাদা এনভায়রনমেন্ট আলাদা রাখতে আপনি workspace ব্যবহার করতে পারেন <Cite n={4} />। এই টিউটোরিয়ালের পরামর্শ: অ্যাপ চলার সময় API key পড়ে একটা environment variable থেকে। API key কখনও সোর্স কোডে রাখবেন না।

Kubernetes-এ এমন মান রাখে একটা Secret অবজেক্ট। ডিফল্টভাবে Kubernetes এই Secret etcd-তে এনক্রিপশন ছাড়া রাখে। যার API বা etcd অ্যাক্সেস আছে, সে-ই এগুলো পড়তে পারে <Cite n={5} />। ডকুমেন্টেশন বলে: encryption at rest চালু করুন, আর RBAC নিয়ম সেট করুন <Cite n={5} />।

**টুলের জন্য সবচেয়ে কম পারমিশন (least privilege)।** Excessive agency ঠেকাতে OWASP এই ধাপগুলো দেয় <Cite n={1} />:

1. মডেলকে কম টুল দিন, আর প্রতিটা টুলকে কম ফাংশন দিন। ইমেইলের সারাংশ বানানোর টুলের পড়ার অনুমতি লাগে, পাঠানো বা মুছে ফেলার নয়।
2. "শেল কমান্ড চালাও" বা "একটা URL আনো"-এর মতো খোলা টুল এড়িয়ে চলুন। "এই ফাইলটা লেখো"-এর মতো সরু টুল বানান।
3. ইউজারের পরিচয় আর সবচেয়ে ছোট scope দিয়ে কানেক্ট করুন, শেয়ার্ড অ্যাডমিন অ্যাকাউন্ট দিয়ে নয়।
4. বড় প্রভাবের কাজের আগে একজন মানুষের অনুমোদন নিন।
5. Downstream সিস্টেম প্রতিটা রিকুয়েস্ট নিজের পলিসি দিয়ে যাচাই করবে।

লগ, মনিটরিং আর রেট লিমিট সমস্যাটা থামায় না, তবে ক্ষতি কমায় <Cite n={1} />।

**সার্ভিসের মধ্যে টোকেন।** একটা MCP সার্ভার অন্য API কল করতে পারে। যে টোকেন তাকে দেওয়া হয়নি, সেটা সে সামনে পাঠাতে পারবে না। MCP স্পেক একে "token passthrough" বলে এবং নিষিদ্ধ করে <Cite n={6} />।

**আইসোলেশন।** Claude Code sandbox macOS-এ Seatbelt আর Linux-এ `bubblewrap` ব্যবহার করে <Cite n={7} />। Sandbox চালু না হতে পারলে Claude Code ডিফল্টভাবে sandbox ছাড়াই কমান্ড চালায়। `sandbox.failIfUnavailable` সেটিং দিলে সে বরং থেমে যায় <Cite n={7} />।

## A real-life example

<Voices>
<Technical>

A team builds an email assistant. It reads the inbox of a user and writes a summary. OWASP describes this exact case <Cite n={1} />: the developer picks a mail plugin that can also send mail. An attacker sends an email with hidden instructions, and the model forwards private mail to the attacker. That is an indirect prompt injection.

OWASP lists 3 fixes, and any one of them breaks the attack <Cite n={1} />:

| Fix | Change |
|---|---|
| Less functionality | Use a plugin that can only read mail. |
| Fewer permissions | Log in through OAuth with a read-only scope. |
| Less autonomy | The user reviews each draft and presses Send. |

A rate limit on the send function would also reduce the damage <Cite n={1} />.

</Technical>

OWASP 3টা সমাধান দেয়। যেকোনো একটাই আক্রমণটা ভেঙে দেয় <Cite n={1} />:

- কম ফাংশনালিটি: এমন প্লাগইন ব্যবহার করুন, যেটা শুধু মেইল পড়তে পারে।
- কম পারমিশন: read-only scope দিয়ে OAuth-এ লগইন করুন।
- কম স্বাধীনতা: ইউজার প্রতিটা ড্রাফট দেখে নিজে Send চাপবেন।

Send ফাংশনে একটা রেট লিমিট দিলেও ক্ষতি কমত <Cite n={1} />।

## Common mistakes

<Voices>
<Technical>

- **A key in the system prompt.** If the prompt leaks, the key leaks. OWASP says to keep keys, database names, and roles out of the prompt and in systems the model cannot reach <Cite n={2} />.
- **"Do not reveal this" as the only guard.** Training or instructions can help, but the model may not always follow them. An independent check of the output is better <Cite n={2} />.
- **The model decides who may do what.** The app skips its own session and authorization checks. The real risk is this design, not the leak of the prompt <Cite n={2} />.
- **A shared admin identity for a tool.** A tool that reads the documents of one user connects with an account that sees the files of all users <Cite n={1} />.
- **Trust in the prompt to stop data leaks.** A rule in the system prompt about what data to return can be bypassed through prompt injection <Cite n={3} />.
- **Default Kubernetes Secrets.** They are not encrypted at rest until you turn it on <Cite n={5} />.

</Technical>
<Layman>

- **A key in the system prompt.** If the prompt leaks, the key leaks. OWASP says: keep keys, database names, and roles out of the prompt. Keep them in systems that the model cannot reach <Cite n={2} />.
- **"Do not reveal this" as the only guard.** Training or instructions can help. But the model may not always follow them. An independent check of the output is better <Cite n={2} />.
- **The model decides who may do what.** The app skips its own session and authorization checks. This design is the real risk, not the leak of the prompt <Cite n={2} />.
- **A shared admin identity for a tool.** A tool must read the documents of one user. But it connects with an account that sees the files of all users <Cite n={1} />.
- **Trust in the prompt to stop data leaks.** A rule in the system prompt about what data to return can be bypassed with prompt injection <Cite n={3} />.

<Bangla>

- **সিস্টেম প্রম্পটে key রাখা।** প্রম্পট ফাঁস হলে key-ও ফাঁস হয়। OWASP বলে: key, ডেটাবেসের নাম আর রোল প্রম্পটের বাইরে রাখুন, এমন সিস্টেমে রাখুন যেখানে মডেল পৌঁছায় না <Cite n={2} />।
- **একমাত্র পাহারা "এটা প্রকাশ কোরো না"।** ট্রেনিং বা নির্দেশ সাহায্য করতে পারে, কিন্তু মডেল সবসময় তা মানবে না। আউটপুটের একটা স্বাধীন চেক এর চেয়ে ভালো <Cite n={2} />।
- **কে কী করতে পারবে, তা মডেল ঠিক করে।** অ্যাপ নিজের সেশন আর অথরাইজেশন চেক বাদ দেয়। আসল ঝুঁকি এই ডিজাইন, প্রম্পট ফাঁস হওয়া নয় <Cite n={2} />।
- **টুলের জন্য শেয়ার্ড অ্যাডমিন পরিচয়।** একজন ইউজারের ডকুমেন্ট পড়ার টুল এমন অ্যাকাউন্টে কানেক্ট করে, যেটা সব ইউজারের ফাইল দেখে <Cite n={1} />।
- **ডেটা ফাঁস ঠেকাতে প্রম্পটের ওপর ভরসা।** কোন ডেটা ফেরত দেবে, সে বিষয়ে সিস্টেম প্রম্পটের নিয়ম prompt injection দিয়ে এড়ানো যায় <Cite n={3} />।
- **ডিফল্ট Kubernetes Secret।** আপনি চালু না করা পর্যন্ত এগুলো at rest এনক্রিপ্টেড থাকে না <Cite n={5} />।

## What a tester can check

<Voices>
<Technical>

<Callout type="tip" title="Tutorial advice">
These test ideas are the tutorial's own advice.

- **Search for keys.** Grep the repo, the build output, the logs, and the system prompt for strings that look like API keys.
- **Ask for the prompt.** Ask the bot to print its instructions. If the answer shows a key, a password, or a role list, file a bug.
