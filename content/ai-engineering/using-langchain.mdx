# Using LangChain

You can call a model API directly with a few lines of code. When an app needs several models, tools, and data sources, many teams use a framework that gives all of them one shape. LangChain is one of the best-known of these frameworks.

<PageMeta />

## In plain words

<Voices>
<Technical>

**LangChain** is a framework for apps that use language models. It gives one standard interface to the models of many providers, so you can try and switch models with little code change <Cite n={3} />. It supports OpenAI, Anthropic, Google, and more <Cite n={1} />.

Its main building block today is `create_agent`. LangChain describes an agent as a model plus a **harness**: the prompt, the tools, and the **middleware** around the model loop <Cite n={1} />. The same model interface also works alone, outside an agent, for tasks such as text generation, classification, or extraction <Cite n={3} />.

The LangChain team also makes LangGraph, a lower-level framework for flows that mix fixed steps with agent steps, and LangSmith, a tool to trace, debug, and evaluate agents <Cite n={1} />.

</Technical>

## How it works

<Voices>
<Technical>

### Install

You install the `langchain` package, and then one package for each provider, for example `langchain-anthropic` or `langchain-openai`. LangChain needs Python 3.10 or later <Cite n={2} />.

```bash
pip install -U langchain langchain-anthropic
```

### A model

`init_chat_model` creates a chat model from a model name. A model can also be written as `provider:model`, for example `openai:o1` <Cite n={3} />. The API key usually comes from an environment variable <Cite n={3} />. The model has 3 key methods: `invoke` (one full answer), `stream` (the answer in parts), and `batch` (many requests at once) <Cite n={3} />.

```python
from langchain.chat_models import init_chat_model

model = init_chat_model("claude-sonnet-4-6", temperature=0, timeout=30, max_retries=6)
answer = model.invoke("List 3 boundary values for an age field that accepts 18 to 65.")
print(answer.content)
```

Chat models retry failed calls with exponential backoff, up to 6 times by default. They retry network errors, 429, and 5xx errors, but not 401 or 404 <Cite n={3} />.

### A tool

The `@tool` decorator turns a Python function into a tool. The docstring becomes the description that tells the model when to use it, and the type hints are required, because they define the input schema <Cite n={4} />.

```python
from langchain.tools import tool

@tool
def find_ticket(ticket_id: str) -> str:
    """Return the status of a bug ticket by its ID, for example BUG-123."""
    return lookup_ticket_status(ticket_id)  # your own code
```

### An agent

An agent is a model that calls tools in a loop until the task is done <Cite n={5} />. `create_agent` takes the model, the tools, and a system prompt <Cite n={1} />:

```python
from langchain.agents import create_agent

agent = create_agent(
    model="claude-sonnet-4-6",
    tools=[find_ticket],
    system_prompt="You help testers check the status of bug tickets.",
)
result = agent.invoke({"messages": [{"role": "user", "content": "Is BUG-123 fixed?"}]})
print(result["messages"][-1].content_blocks)
```

</Technical>

আপনি `langchain` প্যাকেজ ইনস্টল করেন। তারপর প্রতিটা প্রোভাইডারের জন্য একটা প্যাকেজ ইনস্টল করেন, যেমন `langchain-anthropic` বা `langchain-openai`। LangChain-এর জন্য Python 3.10 বা নতুন লাগে <Cite n={2} />।

`init_chat_model` একটা মডেলের নাম থেকে একটা চ্যাট মডেল তৈরি করে। মডেলকে `provider:model` আকারেও লেখা যায়, যেমন `openai:o1` <Cite n={3} />। API key সাধারণত একটা এনভায়রনমেন্ট ভেরিয়েবল থেকে আসে <Cite n={3} />। মডেলের ৩টা মূল মেথড আছে <Cite n={3} />:

- `invoke` একটা পুরো উত্তর দেয়।
- `stream` উত্তরটা অংশে অংশে দেয়।
- `batch` একসাথে অনেক রিকুয়েস্ট পাঠায়।

চ্যাট মডেল ফেল করা কল আবার চেষ্টা করে, প্রতিবার অপেক্ষা বাড়িয়ে। ডিফল্টভাবে এটা ৬ বার পর্যন্ত করে। এটা নেটওয়ার্ক এরর, 429, আর 5xx এরর রিট্রাই করে। 401 বা 404 রিট্রাই করে না <Cite n={3} />।

`@tool` ডেকোরেটর একটা Python ফাংশনকে টুলে পরিণত করে। Docstring হয়ে যায় টুলের বর্ণনা। এটা মডেলকে বলে কখন টুলটা ব্যবহার করতে হবে। টাইপ হিন্ট বাধ্যতামূলক, কারণ এগুলোই টুলের ইনপুট ঠিক করে <Cite n={4} />।

এজেন্ট হলো এমন একটা মডেল, যা কাজ শেষ না হওয়া পর্যন্ত একটা লুপে টুল কল করে <Cite n={5} />। `create_agent` নেয় মডেল, টুল, আর একটা সিস্টেম প্রম্পট <Cite n={1} />। Technical লেখায় মডেল, টুল আর এজেন্টের ছোট উদাহরণ আছে।

## A real-life example

<Voices>
<Technical>

A QA team builds a "release helper" for its testers. A tester asks: "Which bugs in release 4.2 are still open?" The agent has 2 tools: one reads the bug tracker, and one reads the release notes. The model decides which tool to call and when to stop <Cite n={3} />.

At first the team uses an OpenAI model. Later they try an Anthropic model. Because LangChain gives one interface for both, they change only the model name and install the provider package <Cite n={3} /> <Cite n={2} />.

For the unit tests, the team does not call a real model. They use `GenericFakeChatModel`, which returns scripted answers, including tool calls, one per call <Cite n={7} />:

```python
from langchain.agents import create_agent
from langchain.messages import AIMessage, HumanMessage, ToolCall
from langchain_core.language_models.fake_chat_models import GenericFakeChatModel

class FakeToolCallingModel(GenericFakeChatModel):
    def bind_tools(self, tools, **kwargs):  # create_agent calls bind_tools
        return self

model = FakeToolCallingModel(messages=iter([
    AIMessage(content="", tool_calls=[ToolCall(name="find_ticket", args={"ticket_id": "BUG-123"}, id="call_1")]),
    AIMessage(content="BUG-123 is fixed in build 4.2.1."),
]))
agent = create_agent(model, tools=[find_ticket])
result = agent.invoke({"messages": [HumanMessage(content="Is BUG-123 fixed?")]})
assert "BUG-123" in result["messages"][-1].text
```

`GenericFakeChatModel` has no `bind_tools` method, and `create_agent` calls it when you pass tools. So the test uses a small subclass, as the LangChain docs show <Cite n={7} />.

The tests are now fast, free, and repeatable, and they need no API key <Cite n={7} />. The team adds integration tests with the real model too, because those find problems with keys, schemas, and latency <Cite n={6} />.

</Technical>

## Common mistakes

<Voices>
<Technical>

- **Old tutorials.** LangChain changes fast. The current docs build agents with `create_agent` <Cite n={1} />. Check the version of an example before you copy it.
- **A weak docstring.** The model chooses a tool from its description, which comes from the docstring <Cite n={4} />. A vague docstring leads to wrong tool calls.
- **Missing type hints.** Type hints define the tool's input schema, and they are required <Cite n={4} />.
- **Only real-model tests.** LLM output is not deterministic, so tests that always call a real model can be flaky <Cite n={6} />. Use fake models for logic, and real models for integration <Cite n={6} /> <Cite n={7} />.
- **Fake model limits.** `FakeListChatModel` starts again at the first answer when it runs out <Cite n={7} />. A test that calls it too many times can pass by accident.
- **Hidden retries.** 6 retries by default can hide a real outage and make a request slow <Cite n={3} />. Set `max_retries` and `timeout` for your case.

</Technical>

## What a tester can check

<Voices>
<Technical>

<Callout type="tip" title="Tutorial advice">
These test ideas are the tutorial's own advice.

- **Unit tests with fakes.** Script a tool call and a final answer. Check that the right tool runs with the right arguments.
- **Tool errors.** Make a tool raise an error or return empty data. The agent must answer clearly, not invent a result.
- **Tool choice.** Ask 20 questions that need a known tool. Count how often the agent picks it.
- **Model swap.** When the team changes the model name, run the same eval set on the old and the new model.
- **Retries and timeouts.** Mock a 429 and a slow answer. Check the total time and the message to the user.
