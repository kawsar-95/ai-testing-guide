# Data Governance

An AI app moves data in new ways. A user types a question with a customer name in it. The app adds 5 internal documents and sends all of it to a model provider. The answer goes into a log. Data governance is the set of rules that says what may go where, who can see it, and how long it stays.

## In plain words

<Voices>
<Technical>

Tutorial's own view: data governance for an AI app covers 4 questions.

| Question | Topic |
|---|---|
| What data may enter the system, and the model? | Privacy |
| How long is each copy kept, and where? | Retention |
| Who and what can read it? | Access |
| Can we show later what happened? | Audit trail |

OWASP lists the data at risk in an LLM app: personal data, financial and health data, confidential business data, credentials, and legal papers <Cite n={2} />. NIST names governance outcomes that fit here: the legal and regulatory requirements for AI are understood, managed, and documented <Cite n={1} />; there is an inventory of AI systems <Cite n={1} />; and the privacy risk of each system is examined and documented <Cite n={1} />.

## How it works

<Voices>
<Technical>

### Map the copies

Tutorial's own view: start with a map of every place the data lands. A typical chat app:

```text
user question --> app server logs
              --> vector store (documents, chunks)
              --> model provider (prompt + response)
              --> trace / observability tool
              --> chat history database
              --> eval set (sampled questions)
```

Each box needs an owner, a retention period, and an access rule.

### Privacy: send less

OWASP advises data sanitization, such as scrubbing or masking sensitive content, so that user data does not enter training <Cite n={2} />. It also suggests pattern matching to detect and redact confidential content before processing <Cite n={2} />. OWASP warns that a rule in the system prompt about what data to return can be bypassed through prompt injection <Cite n={2} />.

### Retention at the model provider

Each provider documents what it keeps. Read the page of your provider:

- **Anthropic**: conversation content is not retained by default, except for some models that need 30-day retention <Cite n={3} />. Under a zero data retention (ZDR) arrangement, prompts and responses are not stored at rest after the response returns <Cite n={3} />. ZDR is enabled per organization, and it does not cover features such as code execution, which the eligibility table marks "No" <Cite n={3} />.
- **OpenAI**: since March 1, 2023, API data is not used to train its models unless the customer opts in <Cite n={4} />. Abuse monitoring logs are kept for up to 30 days, unless the law needs longer, or a longer period is reasonably needed to protect its services or others <Cite n={4} />.

### Access

OWASP says: limit access to sensitive data by the principle of least privilege, and grant only the data that a user or process needs <Cite n={2} />. Tutorial's own view: in a retrieval app, that means the search step filters by the permissions of the user before the model sees any document.

### Audit trail

An audit trail is a time-ordered record of actions. Kubernetes auditing is one model: it records who did what, when, on what, and from where <Cite n={5} />. Tutorial's own view: for an AI app, log the user, the documents retrieved, the tools called, and the model ID, and protect that log like the data itself.

</Technical>

<Bangla>

**কপিগুলোর মানচিত্র বানান।** টিউটোরিয়ালের নিজের মত: ডেটা যেখানে যেখানে যায়, তার একটা মানচিত্র দিয়ে শুরু করুন। একটা সাধারণ চ্যাট অ্যাপে ইউজারের প্রশ্ন যায় অ্যাপ সার্ভারের লগে, ভেক্টর স্টোরে, মডেল প্রোভাইডারের কাছে, একটা trace টুলে, চ্যাট হিস্ট্রির ডেটাবেসে আর eval-সেটে। প্রতিটা জায়গার একজন মালিক, একটা রিটেনশন সময় আর একটা অ্যাক্সেসের নিয়ম লাগবে।

**প্রাইভেসি: কম পাঠান।** OWASP data sanitization-এর পরামর্শ দেয়, যেমন সংবেদনশীল লেখা মুছে ফেলা বা ঢেকে দেওয়া, যাতে ইউজারের ডেটা ট্রেনিংয়ে না ঢোকে <Cite n={2} />। প্রসেস করার আগে গোপন লেখা খুঁজে সরিয়ে দিতে pattern matching-এর কথাও বলে <Cite n={2} />। OWASP সতর্ক করে: কোন ডেটা ফেরত দেবে, সে বিষয়ে সিস্টেম প্রম্পটের নিয়ম prompt injection দিয়ে এড়ানো যায় <Cite n={2} />।

**মডেল প্রোভাইডারের কাছে রিটেনশন।** প্রতিটা প্রোভাইডার লিখে রাখে সে কী রাখে। আপনার প্রোভাইডারের পেজটা পড়ুন।

- **Anthropic**: কথোপকথনের লেখা ডিফল্টভাবে রাখা হয় না, তবে কিছু মডেল ব্যতিক্রম, সেগুলোর 30 দিনের রিটেনশন লাগে <Cite n={3} />। Zero data retention (ZDR) ব্যবস্থায় রেসপন্স ফেরত যাওয়ার পর প্রম্পট আর রেসপন্স at rest রাখা হয় না <Cite n={3} />। ZDR প্রতিটা অর্গানাইজেশনের জন্য আলাদা চালু হয়, আর টেবিলে "No" লেখা ফিচার, যেমন code execution, এর আওতায় পড়ে না <Cite n={3} />।
- **OpenAI**: March 1, 2023 থেকে API-র ডেটা তাদের মডেল ট্রেনিংয়ে ব্যবহার হয় না, যদি না কাস্টমার নিজে opt in করেন <Cite n={4} />। Abuse monitoring লগ 30 দিন পর্যন্ত রাখা হয়, যদি না আইন আরও বেশি সময় চায়, বা তাদের সার্ভিস বা অন্যদের সুরক্ষার জন্য আরও বেশি সময় যুক্তিসঙ্গতভাবে দরকার হয় <Cite n={4} />।

**অ্যাক্সেস।** OWASP বলে: least privilege নীতিতে সংবেদনশীল ডেটার অ্যাক্সেস সীমিত করুন, আর একজন ইউজার বা প্রসেসকে শুধু ততটুকু ডেটা দিন, যতটুকু তার দরকার <Cite n={2} />। টিউটোরিয়ালের নিজের মত: একটা রিট্রিভাল অ্যাপে এর মানে, মডেল কোনো ডকুমেন্ট দেখার আগেই সার্চ ধাপ ইউজারের পারমিশন দিয়ে ফিল্টার করে।

**অডিট ট্রেইল।** অডিট ট্রেইল হলো সময়ের ক্রমে কাজের একটা রেকর্ড। Kubernetes auditing একটা নমুনা: এটা লিখে রাখে কে কী করেছে, কখন, কিসের ওপর আর কোথা থেকে <Cite n={5} />। টিউটোরিয়ালের নিজের মত: একটা AI অ্যাপে ইউজার, খুঁজে পাওয়া ডকুমেন্ট, কল করা টুল আর মডেল ID লগ করুন, আর সেই লগকে ডেটার মতোই সুরক্ষিত রাখুন।

## A real-life example

<Voices>
<Technical>

A hospital group builds an internal assistant that answers questions about shift rules. The data map shows a problem: nurses paste patient notes into the chat to ask about a procedure. Those notes go to the app log, the trace tool, and the model provider.

The team makes 4 changes:

1. A redaction step masks names and record numbers before the prompt leaves the app, as OWASP suggests <Cite n={2} />.
2. They check the retention terms of their provider and request ZDR for the organization <Cite n={3} />.
3. The trace tool keeps only the redacted prompt, and keeps it for 14 days. Tutorial's own view: a log often holds more personal data than the main database.
4. Each answer logs the user ID, the document IDs, and the model ID, so a later question "who saw what?" has an answer <Cite n={5} />.

NIST also asks that the privacy risk is examined and documented <Cite n={1} />, so the team writes it down in the system inventory.

</Technical>

একটা হাসপাতাল গ্রুপ শিফটের নিয়ম নিয়ে প্রশ্নের উত্তর দেওয়ার জন্য একটা অভ্যন্তরীণ অ্যাসিস্ট্যান্ট বানায়। ডেটার মানচিত্র একটা সমস্যা দেখায়: নার্সরা একটা প্রসিডিউর নিয়ে জিজ্ঞেস করতে রোগীর নোট চ্যাটে পেস্ট করেন। সেই নোট যায় অ্যাপের লগে, trace টুলে আর মডেল প্রোভাইডারের কাছে।

4. প্রতিটা উত্তর ইউজার ID, ডকুমেন্ট ID আর মডেল ID লগ করে, যাতে পরে "কে কী দেখেছে?" প্রশ্নের উত্তর থাকে <Cite n={5} />।

## Common mistakes

<Voices>
<Technical>

- **"The provider keeps nothing."** Retention depends on the provider, the feature, and the contract. For example, ZDR leaves out the features that its table marks "No" <Cite n={3} />, and OpenAI keeps abuse monitoring logs for up to 30 days by default <Cite n={4} />.
- **Forgotten copies.** The prompt is redacted, but the trace tool and the eval set keep the raw text. Tutorial's own view: this is the most common leak.
- **The model filters access.** A system prompt that says "only show HR data to HR" can be bypassed <Cite n={2} />. Filter before retrieval.
- **No inventory.** Nobody knows which teams run which AI features. NIST asks for mechanisms to inventory AI systems <Cite n={1} />.
- **Logs with no answer.** The log shows a request, but not who sent it or what data it touched. An audit record should answer who, what, when, and on what <Cite n={5} />.

</Technical>

- **"The provider keeps nothing."** Retention depends on the provider, the feature, and the contract. For example, ZDR leaves out the features that its table marks "No" <Cite n={3} />. And OpenAI keeps abuse monitoring logs for up to 30 days by default <Cite n={4} />.
- **Forgotten copies.** The prompt is redacted. But the trace tool and the eval set keep the raw text. The tutorial's own view: this is the most common leak.
- **The model filters access.** A system prompt says "only show HR data to HR". This can be bypassed <Cite n={2} />. Filter before retrieval.
- **No inventory.** Nobody knows which teams run which AI features. NIST asks for ways to keep a list of AI systems <Cite n={1} />.

- **"প্রোভাইডার কিছুই রাখে না।"** রিটেনশন নির্ভর করে প্রোভাইডার, ফিচার আর চুক্তির ওপর। যেমন, টেবিলে "No" লেখা ফিচার ZDR-এর আওতায় পড়ে না <Cite n={3} />, আর OpenAI ডিফল্টভাবে abuse monitoring লগ 30 দিন পর্যন্ত রাখে <Cite n={4} />।

- **তালিকা নেই।** কোন টিম কোন AI ফিচার চালায়, কেউ জানে না। NIST AI সিস্টেমের তালিকা রাখার ব্যবস্থা চায় <Cite n={1} />।
- **উত্তরহীন লগ।** লগে একটা রিকুয়েস্ট দেখা যায়, কিন্তু কে পাঠিয়েছে বা কোন ডেটা ছুঁয়েছে দেখা যায় না। একটা অডিট রেকর্ডের উত্তর দেওয়া উচিত কে, কী, কখন আর কিসের ওপর <Cite n={5} />।
