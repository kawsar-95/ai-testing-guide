# Frontend with React and Next.js

If you know how a React component gets its data, keeps its state, and becomes clickable, you know where its bugs hide. This page builds a tiny shop in Next.js and tests it with Playwright.

<PageMeta />

## What it is

<Voices>
<Technical>

**React** lets you combine markup, CSS, and JavaScript into components: reusable UI elements <Cite n={5} />. A component is a JavaScript function, and its name must start with a capital letter <Cite n={5} />. **Props** are the information that you pass to a JSX tag <Cite n={6} />.

**Next.js** uses file-system based routing: folders and files define the routes <Cite n={2} />. A page is the UI of one route <Cite n={2} />. A layout is UI that several pages share, and it keeps its state on navigation <Cite n={2} />.

You start a new app with `npx create-next-app@latest [project-name] [options]` <Cite n={13} />. The `--yes` flag skips the prompts and uses your saved preferences or the defaults, which include TypeScript and the App Router <Cite n={1} />. Next.js needs Node.js 20.9 or later <Cite n={1} />.

The language underneath is on [JavaScript for Testers](/sdet/javascript/) and [TypeScript for Testers](/sdet/typescript/). The test tool is on [UI Automation with Playwright](/sdet/playwright-ui/).

</Technical>

**Next.js** uses its folders and files to decide the routes of the app <Cite n={2} />. A page is the UI of one route <Cite n={2} />. A layout is the frame that many pages share, and it keeps its state when you move between them <Cite n={2} />.

You start an app with `npx create-next-app@latest` and a name <Cite n={13} />. Add `--yes` to skip the prompts and use your saved or default choices, such as TypeScript <Cite n={1} />. You need Node.js 20.9 or newer <Cite n={1} />.

## How it works

<Voices>
<Technical>

- **Server Components.** By default, layouts and pages are Server Components: they render on the server, and the result streams to the client <Cite n={3} />. They can use API keys, tokens, and other secrets without exposing them to the client <Cite n={3} />.
- **Client Components.** The `"use client"` directive at the top of a file makes a Client Component <Cite n={3} />. You need one for state, event handlers such as `onClick`, effects, and browser-only APIs <Cite n={3} />. Everything that such a file imports goes into the client bundle too <Cite n={3} />.
- **Hydration.** The first HTML is static. JavaScript then hydrates the Client Components to make them interactive <Cite n={3} />: hydration attaches the event handlers to the HTML <Cite n={3} />.
- **State.** `useState` gives a state variable that keeps its value between renders, and a setter that updates it and renders the component again <Cite n={7} />. Hooks, the functions whose names start with `use`, such as `useState`, can only be called at the top level of a component <Cite n={7} />.
- **Events and effects.** Event handlers are functions that run in response to clicks, hovers, focus, and other interactions <Cite n={11} />. Effects run code after rendering, to sync the component with a system outside React <Cite n={8} />.
- **Lists.** Keys tell React which array item each component belongs to <Cite n={9} />.
- **Routes.** A folder name in square brackets, such as `[id]`, is a dynamic segment <Cite n={2} />. The `<Link>` component links pages, and Next.js prefetches a linked route when the link enters the viewport <Cite n={4} />.

</Technical>
<Layman>

- **Server Components.** Pages are built on the server by default, and sent to the browser <Cite n={3} />. They can use secret keys without exposing them to the browser <Cite n={3} />.
- **Client Components.** Put `"use client"` at the top of a file to make a Client Component <Cite n={3} />. You need one for state, event handlers such as `onClick`, effects, and browser-only features <Cite n={3} />.
- **Hydration.** The page first arrives as plain HTML. Then JavaScript "hydrates" it to make it interactive: it attaches the event handlers to the HTML <Cite n={3} />.
- **State.** `useState` gives the component a memory, and a way to change it that redraws the component <Cite n={7} />. Hooks, the functions whose names start with `use`, go only at the top level of a component <Cite n={7} />.
- **Events and effects.** Event handlers run when the user clicks, hovers, focuses, and so on <Cite n={11} />. Effects run after drawing, to keep the component in sync with a system outside React <Cite n={8} />.
- **Lists.** A `key` tells React which item of the list each component belongs to <Cite n={9} />.
- **Routes.** A folder name in square brackets, like `[id]`, is a dynamic segment <Cite n={2} />. `<Link>` connects pages, and Next.js loads a linked page early, when the link comes into view <Cite n={4} />.

</Layman>
<Bangla>

- **Server Component।** ডিফল্টভাবে layout আর page হলো Server Component: এগুলো server-এ render হয়, আর ফলাফল stream হয়ে client-এ যায় <Cite n={3} />। এগুলো API key, token আর অন্য secret client-এর কাছে প্রকাশ না করেই ব্যবহার করতে পারে <Cite n={3} />।
- **Client Component।** File-এর শুরুতে `"use client"` directive দিলে Client Component হয় <Cite n={3} />। State, `onClick`-এর মতো event handler, effect আর শুধু browser-এর API-র জন্য এটা লাগে <Cite n={3} />। এমন file যা import করে, তার সবকিছুও client bundle-এ যায় <Cite n={3} />।
- **Hydration।** প্রথম HTML স্থির। তারপর JavaScript Client Component-গুলোকে hydrate করে interactive বানায় <Cite n={3} />: hydration HTML-এর সাথে event handler জুড়ে দেয় <Cite n={3} />।
- **State।** `useState` একটা state variable দেয়, যেটা render-এর মাঝে নিজের value ধরে রাখে, আর একটা setter দেয়, যেটা value বদলে component আবার render করায় <Cite n={7} />। Hook হলো `use` দিয়ে শুরু হওয়া function, যেমন `useState`; Hook শুধু component-এর top level-এ call করা যায় <Cite n={7} />।
- **Event আর effect।** Event handler হলো এমন function, যেটা click, hover, focus আর অন্য interaction-এর জবাবে চলে <Cite n={11} />। Effect render-এর পরে কোড চালায়, component-কে React-এর বাইরের কোনো system-এর সাথে মেলাতে <Cite n={8} />।
- **List।** Key React-কে বলে কোন array item কোন component-এর <Cite n={9} />।
- **Route।** `[id]`-এর মতো square bracket-এর ভেতরের folder নাম হলো dynamic segment <Cite n={2} />। `<Link>` component page-গুলো জোড়ে, আর link viewport-এ এলে Next.js linked route আগেভাগে prefetch করে <Cite n={4} />।

</Bangla>

## Try it

<Voices>
<Technical>

Create the app with `npx create-next-app@latest my-app --yes --no-cache-components` <Cite n={13} />. `--yes` skips the prompts and uses your saved preferences or the defaults <Cite n={1} />. `--no-*` turns a default off, here Cache Components, which is on by default for the App Router <Cite n={13} />. With it on, `npm run build` stops at the product page with `Route "/products/[id]": Next.js encountered uncached or runtime data during prerendering.` Add the data as `app/products.ts`:

```ts
export const products = [
  { id: 1, name: 'Red pen', price: 20 },
  { id: 2, name: 'Blue mug', price: 350 },
];
```

Add a Client Component as `app/counter.tsx`. It needs `"use client"` because it has state and a click handler <Cite n={3} />:

```tsx
'use client';

import { useState } from 'react';

export default function Counter() {
  const [count, setCount] = useState(0);

  return (
    <div>
      <p>In cart: {count}</p>
      <button onClick={() => setCount(count + 1)}>Add to cart</button>
    </div>
  );
}
```

Replace `app/page.tsx` with a Server Component that lists the products, each with a `key` <Cite n={9} /> and a `<Link>` <Cite n={4} />:

```tsx
import Link from 'next/link';
import Counter from './counter';
import { products } from './products';

export default function Page() {
  return (
    <main>
      <h1>Shop</h1>
      <ul>
        {products.map((product) => (
          <li key={product.id}>
            <Link href={`/products/${product.id}`}>{product.name}</Link>
          </li>
        ))}
      </ul>
      <Counter />
    </main>
  );
}
```

Add the dynamic route `app/products/[id]/page.tsx` <Cite n={2} />. An unknown id calls `notFound()`:

```tsx
import { notFound } from 'next/navigation';
import { products } from '../../products';

export default async function ProductPage({
  params,
}: {
  params: Promise<{ id: string }>;
}) {
  const { id } = await params;
  const product = products.find((p) => p.id === Number(id));
  if (!product) notFound();

  return (
    <main>
      <h1>{product.name}</h1>
      <p>Price: {product.price} taka</p>
    </main>
  );
}
```

Now test it with Playwright. Install Playwright first with `npm init playwright` (it creates `playwright.config.ts`), or start from `npx create-next-app@latest --example with-playwright with-playwright-app` <Cite n={10} />. Next.js recommends testing against the production build: run `npm run build` and `npm run start`, then `npx playwright test` <Cite n={10} />. Save this as `tests/shop.spec.ts`:

```ts
import { test, expect } from '@playwright/test';

test('the cart counts clicks', async ({ page }) => {
  await page.goto('/');
  const button = page.getByRole('button', { name: 'Add to cart' });
  await button.click();
  await button.click();
  await expect(page.getByText('In cart: 2')).toBeVisible();
});

test('a product link opens its page', async ({ page }) => {
  await page.goto('/');
  await page.getByRole('link', { name: 'Blue mug' }).click();
  await expect(page).toHaveURL('/products/2');
  await expect(page.getByRole('heading', { name: 'Blue mug' })).toBeVisible();
});

test('an unknown product answers 404', async ({ page }) => {
  const response = await page.goto('/products/999');
  expect(response?.status()).toBe(404);
});
```

With `baseURL` set to the address of `npm run start` in `playwright.config.ts`, all three tests pass.

## How a tester uses it

<Voices>
<Technical>

- **Test the production build.** Next.js recommends running the tests against production code, because it behaves more like the real app <Cite n={10} />.
- **Know what is interactive.** State and event handlers need a Client Component <Cite n={3} />. When a button does nothing, look for the component that should own its handler.
- **Mind hydration.** The first HTML is static until JavaScript hydrates it <Cite n={3} />. Until then, the HTML is a fast, non-interactive preview <Cite n={3} />. Assert on the result of a click, as the cart test does, not only on the click.
- **Read the console.** A list item without a key makes React log `Each child in a list should have a unique "key" prop.` <Cite n={9} />. Collect browser console errors in the tests of the development build.
- **Check that secrets stay on the server.** Server Components can use API keys and tokens without exposing them to the client <Cite n={3} />. Search the page source and the JavaScript that the browser loads for keys and tokens.
- **Test unknown routes.** A dynamic segment generates many pages from data <Cite n={2} />, so also test an id that does not exist. The third test expects `404`.

</Technical>
<Layman>

- **Test the real build.** Next.js recommends testing the production build, because it more closely resembles how the app will behave <Cite n={10} />.
- **Know what can be clicked.** State and event handlers, such as a click handler, need a Client Component <Cite n={3} />. If a button does nothing, find the component that should handle it.
- **Mind hydration.** The page is plain HTML until JavaScript wakes it up <Cite n={3} />. Check the result of a click, not just the click itself.
- **Read the console.** A list item without a `key` makes React log a message <Cite n={9} />. Let the tests of the development build collect console errors.
- **Check that secrets stay hidden.** Server Components can use keys without sending them to the browser <Cite n={3} />. Search what the browser gets for keys and tokens.
- **Test unknown routes.** One `[id]` folder makes many pages from data <Cite n={2} />, so also try an id that does not exist.

</Layman>
<Bangla>

- **Production build টেস্ট করুন।** Next.js production কোডের ওপর টেস্ট চালানোর পরামর্শ দেয়, কারণ app আসলে কেমন আচরণ করবে, তার সাথে এটা বেশি মেলে <Cite n={10} />।
- **কী interactive, তা জানুন।** State আর event handler-এর জন্য Client Component লাগে <Cite n={3} />। কোনো button কিছু না করলে সেই component খুঁজুন, যার কাছে এর handler থাকার কথা।
- **Hydration মাথায় রাখুন।** JavaScript hydrate না করা পর্যন্ত প্রথম HTML স্থির থাকে <Cite n={3} />। তার আগে HTML একটা দ্রুত, non-interactive preview <Cite n={3} />। শুধু click নয়, cart-এর টেস্টের মতো click-এর ফলাফলের ওপর assert করুন।
- **Console পড়ুন।** Key ছাড়া list item থাকলে React লগ করে `Each child in a list should have a unique "key" prop.` <Cite n={9} />। Development build-এর টেস্টে browser console-এর error সংগ্রহ করুন।
- **Secret server-এই থাকে কি না চেক করুন।** Server Component API key আর token client-এর কাছে প্রকাশ না করেই ব্যবহার করতে পারে <Cite n={3} />। Page source আর browser যে JavaScript নামায়, তাতে key আর token খুঁজুন।
- **অজানা route টেস্ট করুন।** Dynamic segment দিয়ে ডেটা থেকে অনেক page তৈরি হয় <Cite n={2} />, তাই এমন একটা id-ও টেস্ট করুন, যেটা নেই। তৃতীয় টেস্ট `404` আশা করে।

</Bangla>

## Common mistakes

<Voices>
<Technical>

- **State in a Server Component.** State and event handlers need a Client Component, marked with `"use client"` <Cite n={3} />.
- **`"use client"` on a large file.** Everything that the file imports goes into the client bundle <Cite n={3} />, so the browser downloads more JavaScript than it needs.
- **A Hook inside a condition.** Hooks can only be called at the top level of a component or of another Hook <Cite n={7} />.
- **The index as a key.** Using the index as a key often leads to subtle and confusing bugs, when items move, are inserted, or are deleted <Cite n={9} />.
- **An Effect for a value you can calculate.** If you can calculate something during render, you do not need an Effect <Cite n={12} />.
- **Testing only the development server.** The tests should run against the production build <Cite n={10} />.

</Technical>
<Layman>

- **State in a Server Component.** State and event handlers need `"use client"` <Cite n={3} />.
- **`"use client"` on a big file.** Everything it imports goes to the browser too <Cite n={3} />.
- **A Hook inside an `if`.** Call Hooks only at the top level of a component or of another Hook <Cite n={7} />.
- **The index as a key.** It often causes strange bugs when items move <Cite n={9} />.
- **An Effect for a value you can work out.** If you can calculate it while drawing, skip the Effect <Cite n={12} />.
- **Testing only the dev server.** Run the tests against the production build <Cite n={10} />.

</Layman>
<Bangla>

- **Server Component-এ state।** State আর event handler-এর জন্য `"use client"` চিহ্নিত Client Component লাগে <Cite n={3} />।
- **বড় file-এ `"use client"`।** File যা import করে, তার সবকিছু client bundle-এ যায় <Cite n={3} />, ফলে browser দরকারের চেয়ে বেশি JavaScript নামায়।
- **শর্তের ভেতরে Hook।** Hook শুধু component বা অন্য Hook-এর top level-এ call করা যায় <Cite n={7} />।
- **Index-কে key বানানো।** Item সরলে, ঢুকলে বা মুছলে index-কে key হিসেবে ব্যবহার করা প্রায়ই সূক্ষ্ম আর বিভ্রান্তিকর bug আনে <Cite n={9} />।
- **হিসাব করা যায় এমন value-র জন্য Effect।** Render-এর সময় কিছু হিসাব করা গেলে Effect লাগে না <Cite n={12} />।
- **শুধু development server টেস্ট করা।** টেস্ট চালানো উচিত production build-এর ওপর <Cite n={10} />।

</Bangla>
</Voices>

## What a tester can check

<Voices>
<Technical>

<Callout type="tip" title="Tutorial advice">
This list is the tutorial's own advice, not a fact from a source.

- **Roles and names.** Can every button, link, and field be found by its role and its visible name?
- **First click.** Does the first click work on a slow network, right after the page appears?
- **Console.** Is the browser console free of errors and warnings on each page?
- **Unknown URLs.** Do unknown ids and unknown paths answer `404` with a helpful page?
- **Secrets.** Is the JavaScript that the browser loads free of API keys and tokens?
- **Lists.** Do lists keep the right item in the right place after sorting, adding, and deleting?
</Callout>

</Technical>
<Layman>

<Callout type="tip" title="Tutorial advice">
This list is the tutorial's own advice, not a fact from a source.

- **Roles and names.** Can every button and link be found by its role and its text?
- **First click.** Does the first click work on a slow network?
- **Console.** Is the console free of errors?
- **Unknown URLs.** Do wrong ids get a helpful `404` page?
- **Secrets.** Is the browser's JavaScript free of keys and tokens?
- **Lists.** Do items stay right after sorting, adding, and deleting?
</Callout>

</Layman>
<Bangla>

<Callout type="tip" title="Tutorial advice">
এই তালিকা টিউটোরিয়ালের নিজের পরামর্শ, কোনো source থেকে নেওয়া তথ্য নয়।

- **Role আর নাম।** প্রতিটা button, link আর field কি তার role আর দৃশ্যমান নাম দিয়ে খুঁজে পাওয়া যায়?
- **প্রথম click।** Page দেখা দেওয়ার ঠিক পরে, ধীর network-এও কি প্রথম click কাজ করে?

- **Secret।** Browser যে JavaScript নামায়, তাতে কি কোনো API key বা token নেই?
- **List।** Sort, যোগ আর মোছার পরে list কি ঠিক item ঠিক জায়গায় রাখে?

## Key words

| Term | Meaning |
|---|---|
| Component | A JavaScript function whose name must start with a capital letter. |
| Props | The information that you pass to a JSX tag. |
| State | A component's memory; `useState` keeps it and re-renders on change. |
| Hook | A function whose name starts with `use`, called at the top level of a component. |
| Effect | Code that runs after rendering, to sync with something outside React. |
| Key | A value that tells React which list item is which. |
| Server Component | The default in Next.js; renders on the server and can use secrets safely. |
| Client Component | A component in a `"use client"` file; it can have state and event handlers. |
| Hydration | Attaching event handlers to the server HTML, to make it interactive. |
| Dynamic segment | A route folder in square brackets, such as `[id]`. |
| Prefetching | Next.js loads a linked route early, when the link enters the viewport. |
