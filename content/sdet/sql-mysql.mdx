# SQL with MySQL

A screen can say "Order placed" while the database holds a different total, a missing row, or a duplicate. SQL lets a tester look behind the app. This page teaches the queries a tester runs on MySQL, the traps of `NULL` and counting, and how to change test data safely.

<PageMeta />

## What it is

<Voices>
<Technical>

**MySQL** is a database management system, and its databases are relational <Cite n={16} />. A relational database stores data in separate tables <Cite n={16} />. **SQL** is the most common standardized language used to access databases <Cite n={16} />.

`SELECT` retrieves rows from one or more tables <Cite n={1} />. `INSERT` adds new rows to a table <Cite n={5} />. `UPDATE` modifies rows <Cite n={6} />, and `DELETE` removes them <Cite n={7} />.

The command-line client is `mysql`, a simple SQL shell that you can use interactively or from a script <Cite n={15} />. You connect with `mysql --user=user_name --password db_name`, and it asks for the password <Cite n={15} />.

[Databases and DBMS](/course/database/) explains what a database server does for an app, and [Indexes](/course/indexes/) explains why some queries are fast. This page is about writing the queries.

## How it works

<Voices>
<Technical>

- **Filtering and limits.** `WHERE` gives the conditions that a row must satisfy to be selected <Cite n={1} />. `LIMIT` constrains the number of rows that come back <Cite n={1} />.
- **Joins.** `ON` says how to join two tables, and `WHERE` says which rows to keep <Cite n={2} />. In a `LEFT JOIN`, a left row with no match gets a right-side row with every column set to `NULL` <Cite n={2} />. That is how you find rows with no counterpart in another table <Cite n={2} />.
- **`NULL`.** `NULL` means a missing, unknown value <Cite n={3} />, and it is not an empty string <Cite n={10} />. Test for it with `IS NULL` and `IS NOT NULL` <Cite n={3} />. You cannot test for it with `=`, `<`, or `<>` <Cite n={3} />: a comparison with `NULL` gives `NULL` <Cite n={3} />.
- **Counting.** `COUNT(expr)` counts the non-`NULL` values of the expression <Cite n={4} />. `COUNT(*)` counts the rows, whether they contain `NULL` values or not <Cite n={4} />. `GROUP BY` groups the rows for each value, so a count per customer is one query <Cite n={12} />.
- **Patterns.** In a `LIKE` pattern, `_` matches one character and `%` matches any number of characters <Cite n={14} />. Patterns are case-insensitive by default <Cite n={14} />.
- **Keys.** A primary key is the column or columns of your most vital queries, and it cannot include `NULL` <Cite n={13} />. A foreign key links a child table to the values of a parent table <Cite n={9} />. By default, MySQL rejects a delete of a parent row that a child row still references <Cite n={9} />.
- **Transactions.** `START TRANSACTION` starts a transaction. `COMMIT` makes its changes permanent, and `ROLLBACK` cancels them <Cite n={8} />. Autocommit is on by default, so outside a transaction each statement is committed at once and you cannot roll it back <Cite n={8} />.

</Technical>
<Layman>

- **Picking rows.** `WHERE` says which rows you want <Cite n={1} />. `LIMIT` says how many to show <Cite n={1} />.
- **Joining tables.** `ON` says how two tables match <Cite n={2} />. In a `LEFT JOIN`, a left row with no match gets a right side filled with `NULL` <Cite n={2} />. That is how you find rows that have no partner <Cite n={2} />.
- **`NULL`.** `NULL` means "unknown" <Cite n={3} />, and it is not the same as empty text <Cite n={10} />. Check it with `IS NULL` <Cite n={3} />. `= NULL` never works, because any comparison with `NULL` is `NULL` <Cite n={3} />.
- **Counting.** `COUNT(column)` skips `NULL` values <Cite n={4} />. `COUNT(*)` counts every row <Cite n={4} />. `GROUP BY` groups the rows, so one query can give a count for each group <Cite n={12} />.
- **Patterns.** In `LIKE`, `%` is any text and `_` is one character <Cite n={14} />. Capital letters do not matter by default <Cite n={14} />.
- **Keys.** A primary key is the column or columns of your most vital queries, and it can never hold `NULL` <Cite n={13} />. A foreign key links a child table to the values of a parent table <Cite n={9} />. By default, MySQL stops you from deleting a parent that still has children <Cite n={9} />.
- **Transactions.** Start with `START TRANSACTION`. `COMMIT` keeps the changes, and `ROLLBACK` throws them away <Cite n={8} />. Autocommit is on by default, so without a transaction each statement is saved at once and cannot be undone <Cite n={8} />.

</Layman>
<Bangla>

- **Filter আর limit।** একটা row বাছাই হতে হলে কোন শর্ত মানতে হবে, তা বলে `WHERE` <Cite n={1} />। কতগুলো row ফেরত আসবে, তা সীমিত করে `LIMIT` <Cite n={1} />।
- **Join।** দুটো table কীভাবে join হবে তা বলে `ON`, আর কোন row রাখা হবে তা বলে `WHERE` <Cite n={2} />। `LEFT JOIN`-এ বাঁ দিকের কোনো row-এর মিল না থাকলে ডান দিকে এমন একটা row বসে, যার সব column `NULL` <Cite n={2} />। এভাবেই খুঁজে পাওয়া যায় কোন row-এর অন্য table-এ কোনো জোড়া নেই <Cite n={2} />।
- **`NULL`।** `NULL` মানে হারানো, অজানা একটা value <Cite n={3} />, আর এটা empty string নয় <Cite n={10} />। এটা চেক করুন `IS NULL` আর `IS NOT NULL` দিয়ে <Cite n={3} />। `=`, `<` বা `<>` দিয়ে এটা চেক করা যায় না <Cite n={3} />: `NULL`-এর সাথে যেকোনো তুলনার ফল `NULL` <Cite n={3} />।
- **গণনা।** `COUNT(expr)` expression-এর non-`NULL` value গোনে <Cite n={4} />। `COUNT(*)` row গোনে, তাতে `NULL` থাকুক বা না থাকুক <Cite n={4} />। `GROUP BY` প্রতিটা value-এর জন্য row-গুলোকে group করে, তাই প্রতি customer-এর গণনা একটা query-তেই হয় <Cite n={12} />।
- **Pattern।** `LIKE` pattern-এ `_` একটা character-এর সাথে মেলে, আর `%` যেকোনো সংখ্যক character-এর সাথে <Cite n={14} />। ডিফল্টভাবে pattern case-insensitive <Cite n={14} />।
- **Key।** Primary key হলো সবচেয়ে জরুরি query-গুলোর column বা column-গুলো, আর এতে `NULL` থাকতে পারে না <Cite n={13} />। Foreign key একটা child table-কে parent table-এর value-র সাথে যুক্ত করে <Cite n={9} />। ডিফল্টভাবে, কোনো child row এখনো যে parent row-কে refer করে, MySQL সেটা মুছতে দেয় না <Cite n={9} />।
- **Transaction।** `START TRANSACTION` একটা transaction শুরু করে। `COMMIT` তার পরিবর্তন স্থায়ী করে, আর `ROLLBACK` বাতিল করে <Cite n={8} />। Autocommit ডিফল্টভাবে চালু, তাই transaction-এর বাইরে প্রতিটা statement সঙ্গে সঙ্গে commit হয়, আর সেটা rollback করা যায় না <Cite n={8} />।

</Bangla>
</Voices>

## Try it

<Voices>
<Technical>

You need a MySQL 8.4 server on which you may create a database: a local install or a throwaway container. Connect with the `mysql` client and create two tables:

```sql
CREATE TABLE customers (
  id INT PRIMARY KEY,
  name VARCHAR(50) NOT NULL,
  phone VARCHAR(20)
);

CREATE TABLE orders (
  id INT PRIMARY KEY,
  customer_id INT NOT NULL,
  total DECIMAL(8,2) NOT NULL,
  status VARCHAR(20) NOT NULL,
  FOREIGN KEY (customer_id) REFERENCES customers (id)
);

INSERT INTO customers (id, name, phone) VALUES
  (1, 'Asha', '01711000000'),
  (2, 'Rafi', NULL),
  (3, 'Mina', '');

INSERT INTO orders (id, customer_id, total, status) VALUES
  (10, 1, 1200.00, 'paid'),
  (11, 1, 450.50, 'pending'),
  (12, 2, 999.00, 'paid');
```

Now count the orders of each customer:

```sql
SELECT customers.name, COUNT(orders.id) AS order_count
FROM customers
LEFT JOIN orders ON orders.customer_id = customers.id
GROUP BY customers.id, customers.name
ORDER BY customers.id;
```

In interactive use, `mysql` shows the result as a table <Cite n={15} />: Asha 2, Rafi 1, Mina 0. Then try these, and predict each answer first:

1. Change `COUNT(orders.id)` to `COUNT(*)`. Mina now has 1: the `LEFT JOIN` made a row for her with `NULL` on the right side <Cite n={2} />, and `COUNT(*)` counts rows whether or not they contain `NULL` values <Cite n={4} />.
2. Find the customers with no orders. Keep the `LEFT JOIN`, select only the name, and keep the rows where the right side is `NULL` <Cite n={2} />: `SELECT customers.name FROM customers LEFT JOIN orders ON orders.customer_id = customers.id WHERE orders.id IS NULL;` Only Mina comes back.
3. Run `WHERE phone IS NULL`, then `WHERE phone = ''`, then `WHERE phone = NULL`. You get Rafi, then Mina, then no rows <Cite n={3} />.
4. Run `START TRANSACTION;`, then `DELETE FROM orders WHERE status = 'pending';`. `SELECT COUNT(*) FROM orders;` gives 2. Run `ROLLBACK;` and count again: 3 <Cite n={8} />.
5. Run `DELETE FROM customers WHERE id = 1;`. MySQL answers `ERROR 1451 (23000): Cannot delete or update a parent row: a foreign key constraint fails (...)`, where the server fills in the table and constraint names. It refuses because orders still reference Asha and, with no `ON DELETE` clause, the default is RESTRICT, which rejects the parent delete <Cite n={9} />.

</Technical>

## How a tester uses it

<Voices>
<Technical>

- **Check what the app saved.** After a test places an order through the UI or the API, retrieve its row with a `SELECT` and a `WHERE` on the order's id <Cite n={1} />. Compare the stored total and status with what the screen said.
- **Find orphans.** A `LEFT JOIN` with `WHERE ... IS NULL` finds rows with no counterpart, such as orders whose customer is missing <Cite n={2} />.
- **Count by group.** `COUNT()` with `GROUP BY` counts the rows of each group in one query, like the count per customer in Try it <Cite n={12} />.
- **Set up and clean up data.** `INSERT` builds the rows a test needs <Cite n={5} />. Inside a transaction, `ROLLBACK` cancels the changes when the check is done <Cite n={8} />.
- **Test the rules of the data.** Try to insert a row that breaks a key, or delete a parent that has children. A foreign key constraint rejects the parent delete <Cite n={9} />, and the app must show a clear message, not a crash.
- **Test for SQL injection.** When an app builds a query by joining strings, an attacker can put SQL into the input, and the database runs it <Cite n={11} />. The fix is to define the SQL structure apart from its data values, then bind the values through the database API: a parameterized query, with `?` as the placeholder for each value <Cite n={11} />. [Web Application Security](/security/web-application-security/) shows how to test for it.

</Technical>
<Layman>

- **Check what was saved.** After a test places an order, get its row with a `SELECT` and a `WHERE` on its id <Cite n={1} />. Does it match the screen?
- **Find orphans.** A `LEFT JOIN` with `IS NULL` finds rows with no partner, like orders whose customer is gone <Cite n={2} />.
- **Count by group.** `COUNT()` with `GROUP BY` gives a count for each group in one query <Cite n={12} />.
- **Make and clean test data.** `INSERT` adds the rows you need <Cite n={5} />. In a transaction, `ROLLBACK` removes the changes afterwards <Cite n={8} />.
- **Test the data rules.** Try to delete a parent that still has children. The foreign key refuses <Cite n={9} />, and the app must show a clear message.
- **Test for SQL injection.** If an app glues your input into a query, an attacker can sneak SQL in and the database runs it <Cite n={11} />. The fix is a parameterized query: the SQL structure is kept apart from the values, with `?` where each value goes, and the values are bound in separately <Cite n={11} />. See [Web Application Security](/security/web-application-security/).

</Layman>
<Bangla>

- **App কী সেভ করেছে, তা চেক করুন।** UI বা API দিয়ে টেস্ট একটা order দেওয়ার পর order-এর id-এর ওপর `WHERE`-সহ একটা `SELECT` দিয়ে তার row আনুন <Cite n={1} />। জমা হওয়া total আর status স্ক্রিনের কথার সাথে মিলিয়ে দেখুন।
- **অনাথ row খুঁজুন।** `WHERE ... IS NULL`-সহ `LEFT JOIN` এমন row খুঁজে দেয়, যার কোনো জোড়া নেই, যেমন এমন order, যার customer নেই <Cite n={2} />।
- **Group ধরে গুনুন।** `GROUP BY`-সহ `COUNT()` একটা query-তেই প্রতিটা group-এর row গোনে, যেমন Try it-এ প্রতি customer-এর গণনা <Cite n={12} />।
- **ডেটা তৈরি আর পরিষ্কার।** টেস্টের দরকারি row `INSERT` দিয়ে বানানো যায় <Cite n={5} />। Transaction-এর ভেতরে থাকলে চেক শেষে `ROLLBACK` পরিবর্তনগুলো বাতিল করে <Cite n={8} />।
- **ডেটার নিয়ম টেস্ট করুন।** Key ভাঙে এমন row insert করার চেষ্টা করুন, বা child আছে এমন parent মুছুন। Foreign key constraint parent মোছা বাতিল করে <Cite n={9} />, আর app-কে crash নয়, একটা পরিষ্কার message দেখাতে হবে।
- **SQL injection টেস্ট করুন।** App যখন string জোড়া দিয়ে query বানায়, তখন attacker input-এ SQL ঢোকাতে পারে, আর database সেটা চালায় <Cite n={11} />। সমাধান হলো parameterized query: SQL-এর কাঠামো data value থেকে আলাদা করে লেখা হয়, প্রতিটা value-র জায়গায় থাকে `?`, আর value-গুলো পরে database API দিয়ে bind করা হয় <Cite n={11} />। কীভাবে টেস্ট করবেন, তা [Web Application Security](/security/web-application-security/)-এ আছে।

</Bangla>
</Voices>

## Common mistakes

<Voices>
<Technical>

- **`= NULL` in a check.** Any comparison with `NULL` gives `NULL` <Cite n={3} />, and `expr = NULL` is never true, so `WHERE phone = NULL` returns no rows <Cite n={10} />. Use `IS NULL`.
- **Treating `NULL` as empty.** `NULL` is not the same thing as an empty string `''` <Cite n={10} />. A test for "no phone" must say which of the two it means.
- **`COUNT(*)` after a `LEFT JOIN`.** `COUNT(*)` counts rows whether or not they contain `NULL` values <Cite n={4} />, so it also counts the `NULL` row of an unmatched `LEFT JOIN` <Cite n={2} />. Count a column of the right table instead.
- **`UPDATE` or `DELETE` with no `WHERE`.** Without `WHERE`, `UPDATE` changes all the rows <Cite n={6} />, and `DELETE` removes all the rows <Cite n={7} />. Run the same `WHERE` in a `SELECT` first.
- **Expecting `ROLLBACK` to undo anything.** With autocommit on, a statement outside a transaction is committed at once, and `ROLLBACK` cannot undo it <Cite n={8} />.
- **`=` with a pattern.** Do not use `=` or `<>` with SQL patterns; use `LIKE` or `NOT LIKE` <Cite n={14} />.

</Technical>
<Layman>

- **`= NULL` in a check.** Comparing with `NULL` gives `NULL` <Cite n={3} />, and `= NULL` is never true, so it matches no rows <Cite n={10} />. Use `IS NULL`.

- **Thinking `ROLLBACK` always works.** With autocommit on, a statement outside a transaction is saved at once and cannot be undone <Cite n={8} />.
- **`=` with a pattern.** Do not use `=` with a pattern; use `LIKE` or `NOT LIKE` <Cite n={14} />.

</Layman>
<Bangla>

- **চেকে `= NULL`।** `NULL`-এর সাথে যেকোনো তুলনার ফল `NULL` <Cite n={3} />, আর `expr = NULL` কখনো সত্য হয় না, তাই `WHERE phone = NULL` কোনো row দেয় না <Cite n={10} />। `IS NULL` ব্যবহার করুন।
- **`NULL`-কে খালি ধরা।** `NULL` আর empty string `''` এক জিনিস নয় <Cite n={10} />। "Phone নেই"-এর টেস্টকে বলতে হবে, দুটোর কোনটা বোঝানো হচ্ছে।
- **`LEFT JOIN`-এর পরে `COUNT(*)`।** `COUNT(*)` row গোনে, তাতে `NULL` থাকুক বা না থাকুক <Cite n={4} />, তাই মিল না পাওয়া `LEFT JOIN`-এর `NULL` row-ও গোনে <Cite n={2} />। তার বদলে ডান দিকের table-এর একটা column গুনুন।
- **`WHERE` ছাড়া `UPDATE` বা `DELETE`।** `WHERE` ছাড়া `UPDATE` সব row বদলে দেয় <Cite n={6} />, আর `DELETE` সব row মুছে দেয় <Cite n={7} />। আগে একই `WHERE` দিয়ে একটা `SELECT` চালান।
- **ভাবা যে `ROLLBACK` সবকিছু ফেরাতে পারে।** Autocommit চালু থাকলে transaction-এর বাইরের statement সঙ্গে সঙ্গে commit হয়, আর `ROLLBACK` সেটা ফেরাতে পারে না <Cite n={8} />।
- **Pattern-এর সাথে `=`।** SQL pattern-এর সাথে `=` বা `<>` ব্যবহার করবেন না; `LIKE` বা `NOT LIKE` ব্যবহার করুন <Cite n={14} />।

## What a tester can check

<Voices>
<Technical>

<Callout type="tip" title="Tutorial advice">
This list is the tutorial's own advice, not a fact from a source.

- **Saved values.** After each important action, does the stored row match what the screen and the API said?
- **Orphans and duplicates.** Are there child rows with no parent, or two rows where there should be one?
- **`NULL` and empty.** Does the app store "unknown" and "none" the way the requirement says?
- **Counts.** Do the totals per group in the database match the totals in the reports?
- **Safe access.** Do the tests use a database account with only the rights they need, never production data?
- **Clean-up.** Does every test remove or roll back the data that it made?
</Callout>

</Technical>

## Key words

| Term | Meaning |
|---|---|
| SQL | The most common standardized language used to access databases. |
| `SELECT` | Reads rows; `WHERE` filters them and `LIMIT` caps how many come back. |
| `LEFT JOIN` | A join in which a left row with no match gets a right-side row of `NULL`s. |
| `NULL` | A missing, unknown value; not an empty string. Test it with `IS NULL`. |
| `COUNT(expr)` / `COUNT(*)` | Counts non-`NULL` values / counts every row. |
| `GROUP BY` | Groups the rows for each value, for one count per group. |
| Primary key | The column or columns of the most vital queries; it cannot include `NULL`. |
| Foreign key | Links a child table to the values of a parent table. |
| Transaction | Statements that `COMMIT` makes permanent or `ROLLBACK` cancels. |
| Autocommit | The default mode: each statement outside a transaction is committed at once. |
| `LIKE` | Pattern matching: `%` is any text, `_` is one character. |
| Parameterized query | A query whose SQL is defined apart from its values, with `?` placeholders that the values are bound to; the fix for SQL injection. |
