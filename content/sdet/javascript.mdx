# JavaScript for Testers

This page covers the part of JavaScript that a tester uses every day: values, functions, arrays, JSON, async code, and errors. It ends with a small script that you run with Node.js and change yourself.

**Node.js** is an open-source, cross-platform JavaScript runtime. It runs V8, the JavaScript engine of Google Chrome, outside the browser <Cite n={2} />. Its standard library has asynchronous input and output, so code does not block while it waits <Cite n={2} />.

## How it works

<Voices>
<Technical>

- **Variables.** `let` declares a block-scoped variable <Cite n={3} />. `const` declares a block-scoped variable that cannot be re-assigned and must get its value at once <Cite n={3} />.
- **Types.** The standard defines eight data types: seven primitives, such as strings, numbers, booleans, `null`, and `undefined`, and objects <Cite n={3} />.
- **Functions.** JavaScript has first-class functions <Cite n={1} />. An arrow function, such as `(user) => user.name`, is a shorter way to write a function <Cite n={5} />.
- **Arrays.** `filter()` returns a new array with the items for which the callback returned true <Cite n={6} />. `map()` returns a new array of the callback's results <Cite n={6} />. `find()` returns the first item for which the callback returned true <Cite n={6} />.
- **JSON.** `JSON.stringify()` turns a JavaScript value into a JSON string <Cite n={14} />. `JSON.parse()` turns a JSON string back into a value <Cite n={7} />.
- **Async code.** An `async` function always returns a promise <Cite n={8} />. `await` suspends the function until the promise is fulfilled or rejected <Cite n={8} />. You can use `await` only inside an `async` function or at the top level of a module <Cite n={9} />.
- **Errors.** In `try...catch`, the `try` block runs first. If it throws an exception, the `catch` block runs <Cite n={10} />. A `finally` block always runs before the statement ends <Cite n={10} />.
- **Modules.** Modules share code with `import` and `export` statements <Cite n={12} />. Node.js treats a file that ends in `.mjs` as an ES module <Cite n={12} />.

</Technical>

## Try it

<Voices>
<Technical>

You need Node.js. Save this as `users.mjs` and run `node users.mjs`. The `.mjs` extension makes the file an ES module <Cite n={12} />, so `await` works at its top level <Cite n={9} />. Node.js has a browser-compatible `fetch()` <Cite n={13} />, which the script uses to call the Postman Echo service.

```js
const users = [
  { name: 'Asha', role: 'tester', active: true },
  { name: 'Rafi', role: 'developer', active: true },
  { name: 'Mina', role: 'tester', active: false },
];

const activeTesters = users
  .filter((user) => user.active && user.role === 'tester')
  .map((user) => user.name);
console.log(activeTesters); // [ 'Asha' ]

const firstDeveloper = users.find((user) => user.role === 'developer');
console.log(firstDeveloper.name); // Rafi

const text = JSON.stringify({ course: 'sdet', step: 3 });
console.log(JSON.parse(text).step === 3); // true

async function getEcho(course) {
  try {
    const response = await fetch(`https://postman-echo.com/get?course=${course}`);
    if (!response.ok) throw new Error(`HTTP ${response.status}`);
    const body = await response.json();
    return body.args.course;
  } catch (error) {
    console.error('Request failed:', error.message);
    throw error;
  }
}

console.log(await getEcho('sdet')); // sdet
```

The output:

```text
[ 'Asha' ]
Rafi
true
sdet
```

Now change Mina to `active: true` and run it again. The first line becomes `[ 'Asha', 'Mina' ]`. Predict the output before each run: it is a quick way to learn the array methods.

</Technical>

## How a tester uses it

<Voices>
<Technical>

- **Test data.** `filter()` keeps the items that pass a check, `map()` turns each item into a new value, and `find()` returns the first item that passes <Cite n={6} />. Use them to pick the records that a test needs from a larger list.
- **API responses.** `JSON.parse()` turns a JSON string into a value <Cite n={7} />. Parse the body of a response, then check its fields. `JSON.stringify()` turns a value into a JSON string <Cite n={14} />: use it to build a JSON request body.
- **Waiting for results.** `await` waits for a promise and returns its fulfilled value <Cite n={9} />. Use it before a call that returns a promise when the test needs that value.
- **Failures with context.** Catch an error to log what the test was doing, then throw it again. The `catch` block runs only when the `try` block throws <Cite n={10} />.
- **Shared helpers.** Put a helper, such as a login or a data builder, in a module, and `import` it in each test <Cite n={12} />.
- **Exact checks.** Compare with `===`, which treats values of different types as different <Cite n={11} />.

</Technical>
<Layman>

- **Test data.** `filter()` keeps what passes, `map()` changes each item, and `find()` gives the first match <Cite n={6} />. Use them to pick the records a test needs.
- **API answers.** `JSON.parse()` turns JSON text into a value <Cite n={7} />. Parse the body, then check its fields. `JSON.stringify()` turns a value into JSON text <Cite n={14} />, for a request body.
- **Waiting.** `await` waits for a promise and gives you its value <Cite n={9} />. Use it when the test needs the value of a call that returns a promise.
- **Errors that explain.** Catch an error, write down what the test was doing, then throw it again. `catch` runs only when `try` throws <Cite n={10} />.
- **Shared helpers.** Put a helper in a module and `import` it in each test <Cite n={12} />.
- **Exact checks.** Use `===`. It treats values of different types as different <Cite n={11} />.

</Layman>
<Bangla>

- **টেস্ট ডেটা।** `filter()` চেকে পাস করা item রাখে, `map()` প্রতিটা item-কে নতুন value বানায়, আর `find()` প্রথম পাস করা item ফেরত দেয় <Cite n={6} />। বড় একটা list থেকে টেস্টের দরকারি record বেছে নিতে এগুলো ব্যবহার করুন।
- **API response।** `JSON.parse()` একটা JSON string-কে value বানায় <Cite n={7} />। Response-এর body parse করে তারপর তার field চেক করুন। `JSON.stringify()` একটা value-কে JSON string বানায় <Cite n={14} />: JSON request body বানাতে এটা ব্যবহার করুন।
- **ফলাফলের জন্য অপেক্ষা।** `await` একটা promise-এর জন্য অপেক্ষা করে আর তার fulfilled value দেয় <Cite n={9} />। Promise ফেরত দেয় এমন call-এর value টেস্টের দরকার হলে তার আগে এটা দিন।
- **কারণসহ failure।** Error catch করে টেস্ট তখন কী করছিল তা লিখে রাখুন, তারপর error-টা আবার throw করুন। `try` block throw করলে তবেই `catch` block চলে <Cite n={10} />।
- **ভাগ করা helper।** Login বা data builder-এর মতো helper একটা module-এ রাখুন, আর প্রতিটা টেস্টে `import` করুন <Cite n={12} />।
- **নির্ভুল চেক।** `===` দিয়ে তুলনা করুন, এটা আলাদা type-এর value-কে আলাদা ধরে <Cite n={11} />।

## Common mistakes

<Voices>
<Technical>

- **`==` in a check.** Strict equality treats values of different types as different, so `"1" === 1` is `false` <Cite n={11} />. Use `===`.
- **A missing `await`.** An `async` function always returns a promise <Cite n={8} />. To get its fulfilled value, `await` the promise <Cite n={9} />.
- **Trusting `const` too much.** `const` makes the reference fixed, not the value, so the properties of an object in a `const` can still be added, updated, or removed <Cite n={4} />.
- **Parsing text that is not JSON.** `JSON.parse()` throws a `SyntaxError` when the text is not valid JSON <Cite n={7} />. Check the status of a response before you parse its body.
- **An empty `catch`.** When the `try` block throws, the `catch` block runs instead <Cite n={10} />. Put code there that reports the error, or throw it again.

</Technical>
<Layman>

- **`==` in a check.** `===` treats different types as different, so `"1" === 1` is `false` <Cite n={11} />. Use `===`.
- **A missing `await`.** An `async` function always gives back a promise <Cite n={8} />. To get its value, `await` it <Cite n={9} />.
- **Trusting `const` too much.** `const` fixes the reference, not the value, so an object in a `const` can still get properties added, updated, or removed <Cite n={4} />.

- **An empty `catch`.** When `try` throws, `catch` runs instead <Cite n={10} />. Put code there that reports the error, or throw it again.

</Layman>
<Bangla>

- **চেকে `==` ব্যবহার করা।** Strict equality আলাদা type-এর value-কে আলাদা ধরে, তাই `"1" === 1` হলো `false` <Cite n={11} />। `===` ব্যবহার করুন।
- **`await` বাদ পড়া।** `async` function সবসময় একটা promise ফেরত দেয় <Cite n={8} />। এর fulfilled value পেতে promise-টা `await` করুন <Cite n={9} />।
- **`const`-এর ওপর বেশি ভরসা।** `const` reference-টা স্থির করে, value-টা নয়, তাই `const`-এ রাখা object-এর property তবুও যোগ, বদল বা মুছে ফেলা যায় <Cite n={4} />।
- **JSON নয় এমন text parse করা।** Text ঠিক JSON না হলে `JSON.parse()` একটা `SyntaxError` throw করে <Cite n={7} />। Body parse করার আগে response-এর status দেখুন।
- **খালি `catch`।** `try` block throw করলে তার বদলে `catch` block চলে <Cite n={10} />। সেখানে error-এর খবর দেওয়ার কোড রাখুন, বা error-টা আবার throw করুন।

</Bangla>
</Voices>

## What a tester can check

<Voices>
<Technical>

<Callout type="tip" title="Tutorial advice">
This list is the tutorial's own advice, not a fact from a source.

- **Comparisons.** Do the checks use `===` or the assertions of the test tool, never `==`?
- **Awaits.** Is every async call awaited? Look for a call to an async helper with no `await` in front.
- **Catch blocks.** Does every `catch` log the context and throw again, or fail the test?
- **Test data.** Is the data built from one source with `filter()` and `map()`, or copied by hand into many tests?
- **Helpers.** Do the tests `import` shared helpers, or does each test paste its own copy?
- **Secrets.** Do the scripts read tokens and passwords from the environment, not from the code?
</Callout>

</Technical>

## Key words

| Term | Meaning |
|---|---|
| `let` / `const` | Block-scoped variables; a `const` cannot be re-assigned, but its object can still change. |
| Primitive | One of the seven simple data types, such as a string, a number, or a boolean. |
| Arrow function | A short way to write a function: `(user) => user.name`. |
| `filter()` / `map()` / `find()` | Array methods: keep the items that pass, transform each item, return the first item that passes. |
| JSON | Text for data. `JSON.stringify()` writes it and `JSON.parse()` reads it. |
| Promise | The value that an `async` function returns. |
| `await` | Waits for a promise and returns its fulfilled value. |
| `try...catch` | Runs the `catch` block when the `try` block throws. |
| Strict equality (`===`) | A comparison that treats values of different types as different. |
| ES module | A file that shares code with `import` and `export`, such as a `.mjs` file in Node.js. |
| Node.js | The runtime that runs JavaScript outside the browser. |
