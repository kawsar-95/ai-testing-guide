# AWS Databases and Serverless

This page covers four AWS services: AWS Lambda, Amazon DynamoDB, Amazon Athena, and AWS Step Functions. The practice run tests the example function of AWS Lambda, runs the AWS tutorial for DynamoDB on your own machine, and models two rules. It needs no AWS account. It comes after [AWS Identity and Security](/devops/aws-identity-security/) and before [Terraform and Infrastructure as Code](/devops/terraform-iac/).

## What it is

<Voices>
<Technical>

**AWS Lambda.** AWS Lambda is a serverless compute service <Cite n={1} />. With Lambda, you can run code without provisioning or managing servers <Cite n={1} />. Lambda automatically manages the underlying infrastructure, including server maintenance, capacity provisioning, scaling, and patching <Cite n={1} />. Lambda provides three compute primitives <Cite n={1} />. This page covers Event Functions, which is the name for the original Lambda function type <Cite n={1} />. An Event Function runs code in response to events or API calls without managing servers <Cite n={1} />.

**Amazon DynamoDB.** Amazon DynamoDB is a serverless, fully managed, distributed NoSQL database with single-digit millisecond performance at any scale <Cite n={9} />. A table is a collection of items, and each item is a collection of attributes <Cite n={10} />. DynamoDB uses primary keys to uniquely identify each item in a table <Cite n={10} />. DynamoDB doesn't support a JOIN operator <Cite n={9} />. AWS recommends that you denormalize your data model <Cite n={9} />.

**Amazon Athena.** Amazon Athena is an interactive query service that makes it easy to analyze data directly in Amazon S3 using standard SQL <Cite n={24} />. You can use Athena to run ad-hoc queries using ANSI SQL, without the need to aggregate or load the data into Athena <Cite n={25} />. Athena helps you analyze unstructured, semi-structured, and structured data stored in Amazon S3 <Cite n={25} />. Examples include CSV, JSON, or columnar data formats such as Apache Parquet and Apache ORC <Cite n={25} />.

**AWS Step Functions.** With AWS Step Functions, you can create workflows, also called State machines, to build distributed applications, automate processes, orchestrate microservices, and create data and machine learning pipelines <Cite n={32} />. Each step in a workflow is called a state <Cite n={32} />. Instances of running workflows performing tasks are called executions <Cite n={32} />. A Task state represents a unit of work that another AWS service performs <Cite n={32} />. The Amazon States Language is a JSON-based, structured language used to define your state machine, a collection of states <Cite n={33} />.

**What you pay for.** Lambda has pay-per-use billing, with no upfront commitments <Cite n={1} />. DynamoDB on-demand mode offers pay-per-request pricing for read and write requests <Cite n={12} />. In Athena, you pay only for the queries that you run <Cite n={24} />. Standard workflows of Step Functions are priced by state transition <Cite n={32} />. Express workflows are priced by the number and the duration of executions <Cite n={32} />.

## How it works

<Voices>
<Technical>

**Lambda: the function, the event, and the handler.** In Python, a Lambda function can contain more than one Python function, but the handler function is always the entry point to your code <Cite n={2} />. When your function is invoked, Lambda runs this method <Cite n={2} />. The handler takes two arguments, event and context <Cite n={2} />.

An event in Lambda is a JSON formatted document that contains data for your function to process <Cite n={2} />. If another AWS service invokes your function, the event object contains information about the event that caused the invocation <Cite n={2} />. Lambda passes the context object to your function automatically <Cite n={2} />. The context object contains information about the function invocation and execution environment <Cite n={2} />.

With Python, you can use either a print statement or a Python logging library to send information to your function's log <Cite n={2} />. In a production application, AWS recommends a logging library <Cite n={2} />. When you invoke your function outside of the Lambda console, you must use CloudWatch Logs to view your function's execution results <Cite n={2} />.

**Lambda: how a function is invoked.** After you deploy your function, you can invoke it in several ways <Cite n={3} />. One way is the `aws lambda invoke` AWS CLI command <Cite n={3} />. Another way is a function URL, which is a dedicated HTTP(S) endpoint <Cite n={3} />.

Some services can invoke a function with each new event, and this is called a trigger <Cite n={3} />. For stream and queue-based services, Lambda invokes the function with batches of records, which is called an event source mapping <Cite n={3} />.

With synchronous invocation, you wait for the function to process the event and return a response <Cite n={3} />. With asynchronous invocation, Lambda queues the event for processing and returns a response immediately <Cite n={3} />. The InvocationType parameter decides which one: RequestResponse means synchronous, and Event means asynchronous <Cite n={3} />.

For an error in a synchronous invocation, you view the error message in the response and retry the invocation manually <Cite n={3} />. For asynchronous invocations, Lambda handles retries automatically and can send invocation records to a destination <Cite n={3} />.

**Lambda: the execution role and the settings.** A function's execution role is an IAM role that grants the function permission to access AWS services and resources <Cite n={4} />. Lambda automatically assumes your execution role when you invoke your function <Cite n={4} />. The trust policy of the role must specify the Lambda service principal, `lambda.amazonaws.com`, as a trusted service <Cite n={4} />. In the Lambda console, Lambda creates an execution role with minimal permissions by default <Cite n={4} />. This role includes the AWSLambdaBasicExecutionRole managed policy, which gives basic permissions to log events to Amazon CloudWatch Logs <Cite n={4} />.

Timeout is the maximum amount of time in seconds that a Lambda function can run <Cite n={5} />. The default is 3 seconds, and you can adjust it in increments of 1 second up to a maximum value of 1,800 seconds (30 minutes) <Cite n={5} />. For functions using AWS Lambda Managed Instances, asynchronous invocations and event source mapping invocations (except Amazon MQ and Amazon DocumentDB) support a maximum allowed value of 5,400 seconds (90 minutes) <Cite n={5} />. The `update-function-configuration` command sets the timeout, in seconds <Cite n={5} />.

**Lambda: the execution environment, cold starts, and scaling.** Lambda invokes your function in an execution environment, which provides a secure and isolated runtime environment <Cite n={6} />. In the Init phase, Lambda performs three tasks <Cite n={6} />. It starts all extensions, bootstraps the runtime, and runs the static code of the function <Cite n={6} />. The Init phase is limited to 10 seconds <Cite n={6} />. The timeout setting of the function limits the duration of the entire Invoke phase <Cite n={6} />.

After an invocation, Lambda keeps the execution environment for some time, in anticipation of another invocation <Cite n={6} />. Objects declared outside of the handler remain initialized when the function is invoked again <Cite n={6} />. The `/tmp` directory keeps its content while the environment is frozen <Cite n={6} />. Background processes that did not complete when the function ended resume if Lambda reuses the environment <Cite n={6} />. Lambda terminates execution environments every few hours <Cite n={6} />. So you should not assume that the environment persists indefinitely <Cite n={6} />. If a function crashes or times out during the Invoke phase, Lambda resets the environment <Cite n={6} />.

When Lambda has to initialize a new environment to carry out an invocation, this is known as a cold start <Cite n={7} />. A cold start adds latency to the invocation duration, and you are charged for this time <Cite n={6} />. Cold starts typically occur in under 1% of invocations <Cite n={6} />. They are typically more common in development and test functions than in production workloads <Cite n={6} />. The reason is that development and test functions are usually invoked less frequently <Cite n={6} />.

Concurrency is the number of in-flight requests that a function is handling at the same time <Cite n={7} />. For each concurrent request, Lambda provisions a separate instance of your execution environment <Cite n={7} />. By default, an account has a total limit of 1,000 concurrent executions across all Event Functions in a Region <Cite n={7} />. If a function runs out of available concurrency, it experiences throttling, which means that it starts to drop requests <Cite n={7} />. Reserved concurrency reserves a portion of the concurrency of your account for a function <Cite n={7} />. There is no charge for configuring it <Cite n={7} />. Provisioned concurrency pre-initializes environment instances, which reduces cold start latencies <Cite n={7} />. Using provisioned concurrency incurs additional charges <Cite n={7} />.

**DynamoDB: tables, items, and keys.** When you create a table, in addition to the table name, you must specify its primary key <Cite n={10} />. The primary key uniquely identifies each item in the table, so that no two items can have the same key <Cite n={10} />. DynamoDB uses the value of the partition key as input to an internal hash function <Cite n={10} />. The output of the hash function determines the partition in which the item is stored <Cite n={10} />. In a table that has only a partition key, no two items can have the same partition key value <Cite n={10} />.

With a partition key and a sort key, all items with the same partition key value are stored together, in sorted order by sort key value <Cite n={10} />. Multiple items can have the same partition key value, but they must have different sort key values <Cite n={10} />. **Lambda: function কীভাবে চালু হয়।** আপনার function deploy করার পর আপনি তাকে কয়েকভাবে চালু করতে পারেন <Cite n={3} />। একটা উপায় হলো `aws lambda invoke` AWS CLI command <Cite n={3} />। আরেকটা উপায় হলো function URL, যা একটা নির্দিষ্ট HTTP(S) endpoint <Cite n={3} />।

synchronous invocation-এ আপনি অপেক্ষা করেন, যতক্ষণ না function event-টা প্রক্রিয়া করে response ফেরত দেয় <Cite n={3} />। asynchronous invocation-এ Lambda event-টা প্রক্রিয়ার জন্য queue-তে রাখে আর সঙ্গে সঙ্গে response ফেরত দেয় <Cite n={3} />। InvocationType parameter ঠিক করে কোনটা হবে: RequestResponse মানে synchronous, আর Event মানে asynchronous <Cite n={3} />।

synchronous invocation-এর একটা error-এ আপনি response-এ error message দেখেন আর invocation নিজে হাতে আবার চালান <Cite n={3} />। asynchronous invocation-এ Lambda নিজে থেকেই retry করে আর invocation record একটা destination-এ পাঠাতে পারে <Cite n={3} />।

**Lambda: execution role আর setting।** একটা function-এর execution role হলো একটা IAM role, যা function-কে AWS service ও resource-এ প্রবেশের permission দেয় <Cite n={4} />। আপনি function চালু করলে Lambda নিজে থেকেই আপনার execution role assume করে <Cite n={4} />। role-এর trust policy-তে Lambda service principal `lambda.amazonaws.com`-কে একটা বিশ্বস্ত service হিসেবে উল্লেখ করতে হয় <Cite n={4} />। Lambda console-এ Lambda by default ন্যূনতম permission-সহ একটা execution role বানায় <Cite n={4} />। এই role-এ AWSLambdaBasicExecutionRole managed policy থাকে, যা Amazon CloudWatch Logs-এ event log করার মৌলিক permission দেয় <Cite n={4} />।

Timeout হলো একটা Lambda function সর্বোচ্চ কত সেকেন্ড চলতে পারে <Cite n={5} />। default ৩ সেকেন্ড, আর আপনি ১ সেকেন্ড করে বাড়িয়ে সর্বোচ্চ ১,৮০০ সেকেন্ড (৩০ মিনিট) পর্যন্ত বদলাতে পারেন <Cite n={5} />। AWS Lambda Managed Instances ব্যবহার করা function-এর জন্য asynchronous invocation আর event source mapping invocation (Amazon MQ আর Amazon DocumentDB ছাড়া) সর্বোচ্চ অনুমোদিত মান হিসেবে ৫,৪০০ সেকেন্ড (৯০ মিনিট) সমর্থন করে <Cite n={5} />। `update-function-configuration` command timeout সেকেন্ডে ঠিক করে <Cite n={5} />।

**Lambda: execution environment, cold start আর scaling।** Lambda আপনার function একটা execution environment-এ চালায়, যা একটা নিরাপদ ও বিচ্ছিন্ন runtime environment দেয় <Cite n={6} />। Init phase-এ Lambda তিনটা কাজ করে <Cite n={6} />। সে সব extension চালু করে, runtime bootstrap করে আর function-এর static code চালায় <Cite n={6} />। Init phase ১০ সেকেন্ডে সীমিত <Cite n={6} />। function-এর timeout setting পুরো Invoke phase-এর সময় সীমিত করে <Cite n={6} />।

একটা invocation-এর পর Lambda আরেকটা invocation-এর প্রত্যাশায় execution environment কিছু সময় রেখে দেয় <Cite n={6} />। handler-এর বাইরে ঘোষণা করা object function আবার চালু হলে initialized-ই থাকে <Cite n={6} />। environment frozen থাকার সময় `/tmp` directory-র content থেকে যায় <Cite n={6} />। function শেষ হওয়ার সময় যে background process শেষ হয়নি, Lambda environment আবার ব্যবহার করলে সেগুলো আবার চলতে শুরু করে <Cite n={6} />। Lambda প্রতি কয়েক ঘণ্টায় execution environment বন্ধ করে দেয় <Cite n={6} />। তাই environment যে অনির্দিষ্টকাল টিকে থাকবে, তা ধরে নেওয়া উচিত নয় <Cite n={6} />। Invoke phase-এর সময় function crash করলে বা time out হলে Lambda environment reset করে <Cite n={6} />।

Lambda-কে একটা invocation চালাতে নতুন একটা environment initialize করতে হলে একে cold start বলে <Cite n={7} />। cold start invocation-এর সময়ে latency যোগ করে, আর সেই সময়ের জন্য আপনার খরচ হয় <Cite n={6} />। cold start সাধারণত ১%-এরও কম invocation-এ ঘটে <Cite n={6} />। production workload-এর চেয়ে development আর test function-এ এগুলো সাধারণত বেশি ঘটে <Cite n={6} />। কারণ development আর test function সাধারণত কম চালু হয় <Cite n={6} />।

Concurrency হলো একটা function একই সময়ে যতগুলো in-flight request সামলাচ্ছে তার সংখ্যা <Cite n={7} />। প্রতিটা concurrent request-এর জন্য Lambda আপনার execution environment-এর আলাদা একটা instance provision করে <Cite n={7} />। by default একটা account-এর একটা Region-এ সব Event Function মিলিয়ে মোট ১,০০০টা concurrent execution-এর সীমা থাকে <Cite n={7} />। একটা function-এর available concurrency ফুরিয়ে গেলে সে throttling-এর মুখে পড়ে, মানে request ফেলে দিতে শুরু করে <Cite n={7} />। Reserved concurrency আপনার account-এর concurrency-র একটা অংশ একটা function-এর জন্য রেখে দেয় <Cite n={7} />। এটা ঠিক করতে কোনো খরচ নেই <Cite n={7} />। Provisioned concurrency কিছু environment instance আগে থেকে initialize করে রাখে, যা cold start latency কমায় <Cite n={7} />। Provisioned concurrency ব্যবহারে বাড়তি খরচ হয় <Cite n={7} />।

**DynamoDB: table, item আর key।** একটা table বানানোর সময় table-এর নামের পাশাপাশি তার primary key-ও ঠিক করে দিতে হয় <Cite n={10} />। primary key table-এর প্রতিটা item-কে আলাদাভাবে চেনায়, ফলে দুটো item-এর key এক হতে পারে না <Cite n={10} />। DynamoDB partition key-র মানকে একটা internal hash function-এর input হিসেবে ব্যবহার করে <Cite n={10} />। hash function-এর output ঠিক করে item-টা কোন partition-এ রাখা হবে <Cite n={10} />। শুধু partition key আছে এমন একটা table-এ দুটো item-এর partition key-র মান এক হতে পারে না <Cite n={10} />।

partition key আর sort key থাকলে একই partition key-র মান আছে এমন সব item একসঙ্গে রাখা হয়, sort key-র মান অনুযায়ী সাজানো অবস্থায় <Cite n={10} />। একাধিক item-এর partition key-র মান এক হতে পারে, কিন্তু তাদের sort key-র মান আলাদা হতে হবে <Cite n={10} />। AWS-এর Music উদাহরণে আপনি শুধু Artist-এর মান দিলে DynamoDB সেই artist-এর সব গান নিয়ে আসে <Cite n={10} />। Music উদাহরণে প্রতিটা item-এ দুটো key attribute-ই থাকতে হয় <Cite n={10} />। primary key ছাড়া Music table schemaless <Cite n={10} />। প্রতিটা primary key attribute scalar হতে হয় <Cite n={10} />। primary key attribute-এর জন্য অনুমোদিত data type শুধু string, number বা binary <Cite n={10} />।

একটা secondary index আপনাকে primary key-র query-র পাশাপাশি একটা বিকল্প key দিয়ে table-এর data query করতে দেয় <Cite n={10} />। একটা global secondary index-এর partition key আর sort key table-এর থেকে আলাদা হতে পারে <Cite n={10} />। একটা local secondary index-এর partition key table-এর মতোই, কিন্তু sort key আলাদা <Cite n={10} />। প্রতিটা table-এ ২০টা global secondary index (default quota) আর ৫টা local secondary index-এর quota আছে <Cite n={10} />।

**DynamoDB: read, write, capacity আর মেয়াদ।** আপনার application একটা table-এ লিখে HTTP 200 response পেলে তার মানে লেখা সফলভাবে শেষ হয়েছে আর স্থায়ীভাবে জমা হয়েছে <Cite n={11} />। table আর local secondary index দুটো read consistency বিকল্প দেয়: eventually consistent, যা default, আর strongly consistent read <Cite n={11} />। global secondary index আর stream থেকে সব read eventually consistent <Cite n={11} />। একটা eventually consistent read সদ্য শেষ হওয়া লেখার ফল না-ও দেখাতে পারে <Cite n={11} />। আপনি ConsistentRead true করলে DynamoDB সবচেয়ে হালনাগাদ data ফেরত দেয়, যাতে আগের সব সফল লেখার পরিবর্তন প্রতিফলিত থাকে <Cite n={11} />। একটা global secondary index বা stream থেকে strongly consistent read সমর্থিত নয় <Cite n={11} />। eventually consistent read-এর খরচ strongly consistent read-এর অর্ধেক <Cite n={11} />।

On-demand mode বেশির ভাগ workload-এর জন্য default আর সুপারিশ করা throughput বিকল্প <Cite n={12} />। provisioned mode-এ আপনাকে ঠিক করে দিতে হয় প্রতি সেকেন্ডে কতটা read আর write আপনার লাগে <Cite n={12} />। আপনি যে capacity provision করেছেন তার জন্য আপনার খরচ হয়, যে capacity ব্যবহার করেছেন তার জন্য নয় <Cite n={12} />।

Time To Live (TTL) হলো যে item আর প্রাসঙ্গিক নয় তা মুছে ফেলার একটা পদ্ধতি <Cite n={13} />। মেয়াদ শেষের timestamp একটা Number হিসেবে সেকেন্ড granularity-তে Unix epoch time format-এ রাখতে হয় <Cite n={13} />। TTL attribute Number নয় এমন item-কে TTL process উপেক্ষা করে <Cite n={13} />। বৈধ, মেয়াদোত্তীর্ণ TTL attribute-সহ item system যেকোনো সময় মুছে ফেলতে পারে, সাধারণত মেয়াদ শেষের কয়েক দিনের মধ্যে <Cite n={13} />। মেয়াদোত্তীর্ণ item Scan আর Query-র ফল থেকে বাদ দিতে আপনি filter expression ব্যবহার করতে পারেন <Cite n={13} />।

**DynamoDB local।** DynamoDB-র downloadable version দিয়ে আপনি DynamoDB web service-এ না গিয়েই application develop ও test করতে পারেন <Cite n={20} />। এটা পাওয়া যায় এমন download হিসেবে যার জন্য JRE লাগে, Apache Maven dependency হিসেবে, বা Docker image হিসেবে <Cite n={20} />। production-এর জন্য তৈরি হলে আপনি code থেকে local endpoint সরিয়ে দেন, আর তখন সেটা DynamoDB web service-কে নির্দেশ করে <Cite n={20} />। AWS CLI একে default endpoint হিসেবে ব্যবহার করতে পারে না, তাই প্রতিটা AWS CLI command-এ `--endpoint-url` দিতে হয় <Cite n={22} />। DynamoDB local by default port 8000 ব্যবহার করে <Cite n={21} />। AWS-এর page বলে, এটা চলতে credential লাগে, আর সে বানানো মান `fakeMyKeyId`, `fakeSecretAccessKey` ও `fakeRegion` দেখায় <Cite n={21} />। page-টা Docker image-টার নাম দেয় `amazon/dynamodb-local:latest` <Cite n={21} />।

`-inMemory` option-এ DynamoDB memory-তে চলে, আর বন্ধ করলে কোনো data সংরক্ষিত থাকে না <Cite n={22} />। DynamoDB local telemetry সংগ্রহ করে, যেমন সাধারণ ব্যবহারের metric, system ও environment-এর তথ্য আর error <Cite n={23} />। telemetry চালু থাকলে সে ডেটা background-এ পাঠায় <Cite n={23} />। `-disableTelemetry` option দিলে DynamoDB local কোনো telemetry পাঠাবে না <Cite n={22} />।

downloadable version শুধু development আর testing-এর উদ্দেশ্যে <Cite n={22} />। web service-এর থেকে এর কয়েকটা পার্থক্য আছে <Cite n={22} />। provisioned throughput setting উপেক্ষা করা হয়, যদিও CreateTable সেগুলো চায় <Cite n={22} />। Scan operation পরপর চলে, আর parallel scan সমর্থিত নয় <Cite n={22} />। table-এর operation সঙ্গে সঙ্গে ঘটে, আর table state সবসময় ACTIVE <Cite n={22} />। read operation eventually consistent, কিন্তু local copy-র গতির কারণে বেশির ভাগ read strongly consistent মনে হয় <Cite n={22} />। এটা point-in-time recovery সমর্থন করে না <Cite n={22} />। এটা billingModeSummary-র জন্য সবসময় null ফেরত দেয় <Cite n={22} />। client স্তরে AWS Region আর আলাদা AWS account সমর্থিত নয় <Cite n={22} />।

**Athena: table, data catalog আর partition।** Athena-য় catalog, database আর table হলো সেই metadata সংজ্ঞার container, যা নিচের source data-র একটা schema ঠিক করে <Cite n={30} />। একটা database হলো table-এর একটা দল, আর একটা table হলো row বা column আকারে সাজানো data <Cite n={30} />। একটা table-এর metadata Athena-কে বলে data Amazon S3-এ কোথায় আছে, আর data-র কাঠামো ঠিক করে <Cite n={30} />। data query করার আগে একটা table Athena-য় register করা থাকতে হয় <Cite n={30} />। আপনি একটা AWS Glue crawler দিয়ে স্বয়ংক্রিয়ভাবে table বানাতে পারেন <Cite n={30} />। Athena AWS Glue Data Catalog-এর সঙ্গে সমন্বিত, যা একটা স্থায়ী metadata store দেয় <Cite n={25} />।

```python
DAYS = ["2014-07-05", "2014-07-06", "2014-07-07"]

        for n in range(1000 * i):  # 1000, 2000, and 3000 lines
            out.write(LINE.format(day=day, n=n))


def run(label, folders):
    rows = size = 0
    for folder in folders:
        for path in folder.glob("*.tsv"):
            data = path.read_bytes()
            size += len(data)
            rows += data.count(b"\n")
    print(f"{label:26} folders read: {len(folders)}  rows: {rows:5}  bytes read: {size}")


run("no filter on dt", sorted(root.glob("dt=*")))
```

**4. Model three rules of Step Functions.** This script is the tutorial's own, and it is not the Step Functions service. It holds three rules of the AWS pages. StartAt and States are required <Cite n={34} />. The value of StartAt must exactly match the name of one of the state objects <Cite n={34} />. A Choice state goes to its Default if no rule is true, and the state machine throws an error if there is no Default <Cite n={35} />. The Hello World definition is the example of the state machine structure page <Cite n={34} />. The Choice state is the example of the TestState page, which sends the input `{"number": 2}` to the state `Equals 2` <Cite n={37} />. Save it as `asl_model.py`:

```python
"""A model of three rules of the Step Functions pages. It is not the Step Functions service."""
import json

HELLO = json.loads("""{
  "Comment": "A Hello World example of the Amazon States Language using a Pass state",
  "StartAt": "HelloWorld",
  "States": {
    "HelloWorld": {
      "Type": "Pass",
      "Result": "Hello World!",
      "End": true
    }
  }
}""")

CHOICE = json.loads('{"Type": "Choice", "Choices": [{"Variable": "$.number", "NumericEquals": 1, "Next": "Equals 1"}, '
                    '{"Variable": "$.number", "NumericEquals": 2, "Next": "Equals 2"}], "Default": "No Match"}')


def check(definition):
    """StartAt and States are required, and StartAt must exactly match the name of a state."""
    problems = [f"{field} is required" for field in ("StartAt", "States") if field not in definition]
    if not problems and definition["StartAt"] not in definition["States"]:
        problems.append(f"StartAt {definition['StartAt']!r} does not exactly match the name of a state")
    return problems or ["ok"]


def choose(state, data):
    """The next state of a Choice state. It handles only NumericEquals rules on a top-level name such as $.number."""
    for rule in state["Choices"]:
        name = rule["Variable"].removeprefix("$.")
        if name in data and data[name] == rule["NumericEquals"]:
            return rule["Next"]
    if "Default" in state:
        return state["Default"]
    raise RuntimeError("no rule is true and there is no Default")


print("Hello World example:", check(HELLO))
print("StartAt in lower case:", check({**HELLO, "StartAt": "helloworld"}))
print("no States field:", check({"StartAt": "HelloWorld"}))
for number in (1, 2, 3):
    print(f"Choice state, input number {number}:", choose(CHOICE, {"number": number}))
no_default = {key: value for key, value in CHOICE.items() if key != "Default"}
try:
    choose(no_default, {"number": 3})
except RuntimeError as error:
    print("Choice state without Default, input number 3:", error)
```

**3. Model partition pruning for Athena.** This step models one rule of the AWS page: if you query a partitioned table and specify the partition in the WHERE clause, Athena scans the data only from that partition <Cite n={31} />. The script is the tutorial's own. It writes three days of log lines into folders named in the Hive style, such as `dt=2014-07-05`, with 1,000, 2,000, and 3,000 lines. The lines have tab-separated fields, like the sample log data of the AWS tutorial <Cite n={28} />. Save it as `partitions.py`:

```python
"""A model of one rule of the Athena page: with the partition in the WHERE clause, only that partition is read."""
from pathlib import Path

DAYS = ["2014-07-05", "2014-07-06", "2014-07-07"]
LINE = "{day}\t20:00:09\tDFW3\t4260\t10.0.0.15\tGET\teabcd12345678.cloudfront.net\t/test-image-{n}.jpeg\t200\t-\tMozilla/5.0\n"

root = Path("logs")
for i, day in enumerate(DAYS, start=1):
    folder = root / f"dt={day}"  # a Hive-style path: key=value
    folder.mkdir(parents=True)
    with open(folder / "part-0.tsv", "w", encoding="utf-8") as out:
        for n in range(1000 * i):  # 1000, 2000, and 3000 lines
            out.write(LINE.format(day=day, n=n))


def run(label, folders):
    rows = size = 0
    for folder in folders:
        for path in folder.glob("*.tsv"):
            data = path.read_bytes()
            size += len(data)
            rows += data.count(b"\n")
    print(f"{label:26} folders read: {len(folders)}  rows: {rows:5}  bytes read: {size}")


run("no filter on dt", sorted(root.glob("dt=*")))
run("WHERE dt = '2014-07-06'", [root / "dt=2014-07-06"])
```

**4. Model three rules of Step Functions.** This script is the tutorial's own, and it is not the Step Functions service. It holds three rules of the AWS pages. StartAt and States are required <Cite n={34} />. The value of StartAt must exactly match the name of one of the state objects <Cite n={34} />. A Choice state goes to its Default if no rule is true, and the state machine throws an error if there is no Default <Cite n={35} />. The Hello World definition is the example of the state machine structure page <Cite n={34} />. The Choice state is the example of the TestState page, which sends the input `{"number": 2}` to the state `Equals 2` <Cite n={37} />. Save it as `asl_model.py`:

```python
"""A model of three rules of the Step Functions pages. It is not the Step Functions service."""
import json

HELLO = json.loads("""{
  "Comment": "A Hello World example of the Amazon States Language using a Pass state",
  "StartAt": "HelloWorld",
  "States": {
    "HelloWorld": {
      "Type": "Pass",
      "Result": "Hello World!",
      "End": true
    }
  }
}""")

CHOICE = json.loads('{"Type": "Choice", "Choices": [{"Variable": "$.number", "NumericEquals": 1, "Next": "Equals 1"}, '
                    '{"Variable": "$.number", "NumericEquals": 2, "Next": "Equals 2"}], "Default": "No Match"}')


def check(definition):
    """StartAt and States are required, and StartAt must exactly match the name of a state."""
    problems = [f"{field} is required" for field in ("StartAt", "States") if field not in definition]
    if not problems and definition["StartAt"] not in definition["States"]:
        problems.append(f"StartAt {definition['StartAt']!r} does not exactly match the name of a state")
    return problems or ["ok"]


def choose(state, data):
    """The next state of a Choice state. It handles only NumericEquals rules on a top-level name such as $.number."""
    for rule in state["Choices"]:
        name = rule["Variable"].removeprefix("$.")
        if name in data and data[name] == rule["NumericEquals"]:
            return rule["Next"]
    if "Default" in state:
        return state["Default"]
    raise RuntimeError("no rule is true and there is no Default")


print("Hello World example:", check(HELLO))
print("StartAt in lower case:", check({**HELLO, "StartAt": "helloworld"}))
print("no States field:", check({"StartAt": "HelloWorld"}))
for number in (1, 2, 3):
    print(f"Choice state, input number {number}:", choose(CHOICE, {"number": number}))
no_default = {key: value for key, value in CHOICE.items() if key != "Default"}
try:
    choose(no_default, {"number": 3})
except RuntimeError as error:
    print("Choice state without Default, input number 3:", error)
```

Run it:

```bash

```

```text
StartAt in lower case: ["StartAt 'helloworld' does not exactly match the name of a state"]
no States field: ['States is required']
Choice state, input number 1: Equals 1
Choice state, input number 2: Equals 2
Choice state, input number 3: No Match
Choice state without Default, input number 3: no rule is true and there is no Default
```

- The Hello World definition passes the check.

- Without a `Default`, and with no true rule, the model raises an error. Step Functions throws an error in this case too, and the wording of the message is the tutorial's own.

The model reads only `NumericEquals` rules on a top-level name. It checks only three rules, so a definition that passes the model can still be refused by Step Functions.

এই test function-টাকে Lambda-র বাইরে সাধারণ Python হিসেবে চালিয়েছে। তাই timeout, memory setting, execution role বা log-এর permission নিয়ে এটা কিছু বলে না। AWS বলে, সব Lambda function code timeout আর memory setting-এর ওপর নির্ভর করে, আর সেই setting ঠিকমতো না দিলে function ব্যর্থ হতে পারে <Cite n={8} />।

**২. DynamoDB local-এ DynamoDB-র tutorial চালান।** DynamoDB local Docker image হিসেবে পাওয়া যায় <Cite n={21} />, আর AWS-এর page image-টার নাম দেয় `amazon/dynamodb-local:latest` <Cite n={21} />। এই ধাপে Docker লাগে। টিউটোরিয়াল run-এর আগে `docker pull amazon/dynamodb-local:latest` দিয়ে image pull করেছে, যা image পাওয়ার টিউটোরিয়ালের নিজের উপায়।

প্রথম block container চালু করে। `--cap-drop ALL`, `--security-opt no-new-privileges` আর `--memory 1g` option টিউটোরিয়ালের নিজের পছন্দ, `-p`-এর মানও তাই। `--publish` বা `-p` flag একটা port-কে host-এর বাইরে পাওয়া যাওয়ার মতো করে দেয় <Cite n={42} />। Docker-এর page `-p 192.168.1.100:8080:80` রূপটা দেখায়, যা Docker host IP 192.168.1.100-এর ৮০৮০ নম্বর port-কে container-এর TCP ৮০ নম্বর port-এর সঙ্গে জুড়ে দেয় <Cite n={42} />। টিউটোরিয়ালের মান `127.0.0.1:18000:8000` সেই রূপ মেনে চলে: host IP 127.0.0.1, host port ১৮০০০, আর container port ৮০০০। publish flag-এর সঙ্গে localhost IP address (127.0.0.1, বা ::1) দিলে শুধু Docker host publish করা container port-এ ঢুকতে পারে <Cite n={42} />। `--rm` option container বন্ধ হয়ে যাওয়ার (exit) সময় container আর তার সঙ্গে জড়িত anonymous volume আপনা থেকে মুছে দেয় <Cite n={43} />। `-inMemory` দিলে DynamoDB বন্ধ হওয়ার পর কোনো data রাখে না <Cite n={22} />। `-disableTelemetry` দিলে DynamoDB local কোনো telemetry পাঠায় না <Cite n={22} />। credential হলো AWS-এর page-এ দেখানো বানানো মান <Cite n={21} />। `AWS_CONFIG_FILE` আর `AWS_SHARED_CREDENTIALS_FILE` configuration profile আর access key রাখার file-এর নাম দেয়, আর `AWS_EC2_METADATA_DISABLED` EC2 instance metadata service-এর ব্যবহার বন্ধ করে <Cite n={40} />। এগুলো সেট করা টিউটোরিয়ালের নিজের পছন্দ। `ddb` function প্রতিটা command-এ `--endpoint-url` যোগ করে, কারণ AWS CLI-র প্রতিটা command-এ সেটা লাগে <Cite n={22} />। `j` function একটা উত্তর এক লাইনে ছাপে, যা টিউটোরিয়ালের নিজের formatting।

```bash

docker run -d --rm --name ddb-practice --cap-drop ALL --security-opt no-new-privileges --memory 1g \
  -p 127.0.0.1:18000:8000 amazon/dynamodb-local:latest -jar DynamoDBLocal.jar -inMemory -disableTelemetry

export AWS_ACCESS_KEY_ID=fakeMyKeyId AWS_SECRET_ACCESS_KEY=fakeSecretAccessKey AWS_DEFAULT_REGION=fakeRegion
export AWS_CONFIG_FILE=/dev/null AWS_SHARED_CREDENTIALS_FILE=/dev/null AWS_EC2_METADATA_DISABLED=true
```

**৩. Athena-র জন্য partition pruning-এর model বানান।** এই ধাপ AWS-এর page-এর একটা নিয়মের model বানায়: আপনি একটা partitioned table query করে WHERE clause-এ partition উল্লেখ করলে Athena শুধু সেই partition থেকে data scan করে <Cite n={31} />। script টিউটোরিয়ালের নিজের। এটা তিন দিনের log লাইন লেখে Hive style-এ নাম দেওয়া folder-এ, যেমন `dt=2014-07-05`, ১,০০০, ২,০০০ আর ৩,০০০ লাইন সহ। লাইনগুলোতে tab দিয়ে আলাদা করা field আছে, AWS-এর tutorial-এর নমুনা log data-র মতো <Cite n={28} />। এটা `partitions.py` নামে save করুন:

```python
"""A model of one rule of the Athena page: with the partition in the WHERE clause, only that partition is read."""
from pathlib import Path

DAYS = ["2014-07-05", "2014-07-06", "2014-07-07"]
LINE = "{day}\t20:00:09\tDFW3\t4260\t10.0.0.15\tGET\teabcd12345678.cloudfront.net\t/test-image-{n}.jpeg\t200\t-\tMozilla/5.0\n"

root = Path("logs")
for i, day in enumerate(DAYS, start=1):
    folder = root / f"dt={day}"  # a Hive-style path: key=value
    folder.mkdir(parents=True)
    with open(folder / "part-0.tsv", "w", encoding="utf-8") as out:
        for n in range(1000 * i):  # 1000, 2000, and 3000 lines
            out.write(LINE.format(day=day, n=n))


def run(label, folders):
    rows = size = 0
    for folder in folders:
        for path in folder.glob("*.tsv"):
            data = path.read_bytes()
            size += len(data)
            rows += data.count(b"\n")
    print(f"{label:26} folders read: {len(folders)}  rows: {rows:5}  bytes read: {size}")


run("no filter on dt", sorted(root.glob("dt=*")))
run("WHERE dt = '2014-07-06'", [root / "dt=2014-07-06"])
```

**৪. Step Functions-এর তিনটা নিয়মের model বানান।** এই script টিউটোরিয়ালের নিজের, আর এটা Step Functions service নয়। এতে AWS-এর page-এর তিনটা নিয়ম আছে। StartAt আর States আবশ্যক <Cite n={34} />। StartAt-এর মান state object-গুলোর একটার নামের সঙ্গে হুবহু মিলতে হয় <Cite n={34} />। কোনো rule true না হলে একটা Choice state তার Default-এ যায়, আর Default না থাকলে state machine একটা error ছোড়ে <Cite n={35} />। Hello World definition হলো state machine structure page-এর উদাহরণ <Cite n={34} />। Choice state হলো TestState page-এর উদাহরণ, যা `{"number": 2}` input-কে `Equals 2` state-এ পাঠায় <Cite n={37} />। এটা `asl_model.py` নামে save করুন:

```python
"""A model of three rules of the Step Functions pages. It is not the Step Functions service."""
import json

HELLO = json.loads("""{
  "Comment": "A Hello World example of the Amazon States Language using a Pass state",
  "StartAt": "HelloWorld",
  "States": {
    "HelloWorld": {
      "Type": "Pass",
      "Result": "Hello World!",
      "End": true
    }
  }
}""")

CHOICE = json.loads('{"Type": "Choice", "Choices": [{"Variable": "$.number", "NumericEquals": 1, "Next": "Equals 1"}, '
                    '{"Variable": "$.number", "NumericEquals": 2, "Next": "Equals 2"}], "Default": "No Match"}')


def check(definition):
    """StartAt and States are required, and StartAt must exactly match the name of a state."""
    problems = [f"{field} is required" for field in ("StartAt", "States") if field not in definition]
    if not problems and definition["StartAt"] not in definition["States"]:
        problems.append(f"StartAt {definition['StartAt']!r} does not exactly match the name of a state")
    return problems or ["ok"]


def choose(state, data):
    """The next state of a Choice state. It handles only NumericEquals rules on a top-level name such as $.number."""
    for rule in state["Choices"]:
        name = rule["Variable"].removeprefix("$.")
        if name in data and data[name] == rule["NumericEquals"]:
            return rule["Next"]
    if "Default" in state:
        return state["Default"]
    raise RuntimeError("no rule is true and there is no Default")


print("Hello World example:", check(HELLO))
print("StartAt in lower case:", check({**HELLO, "StartAt": "helloworld"}))
print("no States field:", check({"StartAt": "HelloWorld"}))
for number in (1, 2, 3):
    print(f"Choice state, input number {number}:", choose(CHOICE, {"number": number}))
no_default = {key: value for key, value in CHOICE.items() if key != "Default"}
try:
    choose(no_default, {"number": 3})
except RuntimeError as error:
    print("Choice state without Default, input number 3:", error)
```

## How a tester uses it

<Voices>
<Technical>

- **Test the function as code, and then in the cloud.** For serverless testing, you still write unit, integration and end-to-end tests <Cite n={8} />. Cloud-based tests provide the most accurate measure of quality of both your functions and serverless applications <Cite n={8} />. You cannot fully replicate a cloud environment locally <Cite n={8} />.
- **Keep the handler thin.** The handler should be a slim adapter that takes in event data and passes only the details that matter to your business logic <Cite n={8} />. It should extract and validate data from the incoming event and context objects <Cite n={8} />.
- **Know what mocks and emulators miss.** Tests that rely on emulators might pass locally, but fail in the cloud due to production security policies, inter-service configurations, or exceeding Lambda quotas <Cite n={8} />. Mock frameworks are limited in testing or detecting IAM policy or quota limitations <Cite n={8} />. Even a function that calls no other service depends on its timeout and memory settings <Cite n={8} />. The permission for logs cannot be accurately mocked or emulated <Cite n={8} />.
- **Give cloud tests their own resources.** Automated test processes should create uniquely named resources for each stack <Cite n={8} />. Load testing is an activity that you should isolate from your production stack <Cite n={8} />. Environments should have alerts and controls to avoid unnecessary spending <Cite n={8} />.
- **Test timeouts with realistic data.** If the timeout value is close to the average duration of a function, there is a higher risk that the function times out unexpectedly <Cite n={5} />. Tests often use small samples, but you should use datasets at the upper bounds of what is reasonably expected <Cite n={5} />.
- **Test both invocation types.** A synchronous invocation returns the error message in the response, and an asynchronous invocation is retried by Lambda automatically <Cite n={3} />.
- **Do not lean on a reused environment.** You should not assume that the execution environment will persist indefinitely <Cite n={6} />. The `/tmp` directory keeps its content while the environment is frozen <Cite n={6} />. So a test can pass on a reused environment because of state that an earlier invocation left behind.
- **Expect cold starts and throttling.** Cold starts are typically more common in development and test functions than in production workloads <Cite n={6} />. A function that runs out of available concurrency experiences throttling <Cite n={7} />.
- **Read after a write on purpose.** Eventually consistent is the default read model, and a read might not reflect a recently completed write <Cite n={11} />. Set ConsistentRead to true to get the most up-to-date data <Cite n={11} />. Reads from a global secondary index are always eventually consistent <Cite n={11} />. DynamoDB local says that most reads appear to be strongly consistent <Cite n={22} />. It also ignores provisioned throughput settings <Cite n={22} />. A local run therefore cannot show stale reads or throttling.
- **Do not wait for TTL in a test.** The system might delete expired items at any time, typically within a few days after their expiration <Cite n={13} />. Check that the TTL attribute is a Number in Unix epoch time at the seconds granularity <Cite n={13} />. Use filter expressions to remove expired items from Scan and Query results <Cite n={13} />.
- **Test the key rules.** Each item in the Music table must have both key attributes <Cite n={10} />. Each primary key attribute must be a scalar of the type string, number, or binary <Cite n={10} />. In the tutorial's run, the item without the sort key was refused.
- **Compare a sample with a real run.** In the tutorial's run, the sample result of step 3 of the DynamoDB tutorial showed a type that the real output did not show (see step 2 of Try it).
- **Check the partition filter and the registration in Athena.** If the WHERE clause names the partition, Athena scans the data only from that partition <Cite n={31} />. The MSCK REPAIR TABLE command works only with Hive-style partitions <Cite n={31} />. If the S3 path is in camel case, it does not add the partitions to the AWS Glue Data Catalog <Cite n={31} />. Before querying data, a table must be registered in Athena <Cite n={30} />.
- **Unit-test states with the TestState API.** The API enables you to write unit tests for your state machines <Cite n={37} />. You can assert which Catch or Retry applies <Cite n={37} />. You can assert the input after the InputPath filter, in `afterInputPath` <Cite n={37} />. Mocking is necessary to test Map, Parallel, Activity, `.sync`, and `waitForTaskToken` patterns <Cite n={37} />. The console TestState feature does not yet support some of the enhancements <Cite n={37} />.
- **Test an input that no Choice rule matches.** If no Choices evaluate to true and no Default is provided, the state machine throws an error <Cite n={35} />.
- **Make Express steps safe to repeat.** One or more steps in an Express workflow can potentially run more than once, while each step executes at least once <Cite n={32} />. So check that a repeated step does no harm.

- **cloud test-কে নিজস্ব resource দিন।** স্বয়ংক্রিয় test process-এর উচিত প্রতিটা stack-এর জন্য অনন্য নামের resource বানানো <Cite n={8} />। load test এমন একটা কাজ, যা আপনার production stack থেকে আলাদা রাখা উচিত <Cite n={8} />। অপ্রয়োজনীয় খরচ এড়াতে environment-এ alert আর নিয়ন্ত্রণ থাকা উচিত <Cite n={8} />।

- **দুই ধরনের invocation-ই test করুন।** synchronous invocation response-এ error message ফেরত দেয়, আর asynchronous invocation Lambda নিজে থেকেই retry করে <Cite n={3} />।

- **cold start আর throttling আশা করুন।** production workload-এর চেয়ে development আর test function-এ cold start সাধারণত বেশি ঘটে <Cite n={6} />। available concurrency ফুরিয়ে গেলে একটা function throttling-এর মুখে পড়ে <Cite n={7} />।

- **key-এর নিয়ম test করুন।** Music table-এর প্রতিটা item-এ দুটো key attribute-ই থাকতে হয় <Cite n={10} />। প্রতিটা primary key attribute string, number বা binary type-এর একটা scalar হতে হয় <Cite n={10} />। টিউটোরিয়ালের run-এ sort key ছাড়া item-টা প্রত্যাখ্যাত হয়েছে।
- **নমুনার সঙ্গে আসল run মিলিয়ে দেখুন।** টিউটোরিয়ালের run-এ DynamoDB tutorial-এর ৩ নম্বর ধাপের নমুনা ফল এমন একটা type দেখিয়েছে, যা আসল output দেখায়নি (Try it-এর ২ নম্বর ধাপ দেখুন)।
- **Athena-য় partition filter আর registration যাচাই করুন।** WHERE clause partition-এর নাম দিলে Athena শুধু সেই partition থেকে data scan করে <Cite n={31} />। MSCK REPAIR TABLE command শুধু Hive-style partition-এর সঙ্গে কাজ করে <Cite n={31} />। S3 path camel case-এ থাকলে সেটা AWS Glue Data Catalog-এ partition যোগ করে না <Cite n={31} />। data query করার আগে একটা table Athena-য় register করা থাকতে হয় <Cite n={30} />।
- **TestState API দিয়ে state-এর unit test করুন।** API আপনাকে আপনার state machine-এর জন্য unit test লিখতে সক্ষম করে <Cite n={37} />। আপনি assert করতে পারেন কোন Catch বা Retry প্রযোজ্য <Cite n={37} />। আপনি InputPath filter-এর পরের input assert করতে পারেন, `afterInputPath`-এ <Cite n={37} />। Map, Parallel, Activity, `.sync` আর `waitForTaskToken` pattern test করতে mocking লাগে <Cite n={37} />। console-এর TestState সুবিধা এখনো কিছু উন্নতি সমর্থন করে না <Cite n={37} />।

## Common mistakes

<Voices>
<Technical>

- **Renaming the handler function.** Be sure not to edit the name of the handler function, because Lambda won't be able to run your code if you do <Cite n={2} />.
- **Calling `sts:AssumeRole` in function code.** Lambda automatically assumes your execution role <Cite n={4} />. You should avoid manually calling `sts:AssumeRole` to assume the execution role in your function code <Cite n={4} />.
- **Forgetting the trust policy of the role.** For Lambda to properly assume the execution role, the trust policy must specify the Lambda service principal as a trusted service <Cite n={4} />.
- **Testing only on your own machine.** You cannot fully replicate a cloud environment locally <Cite n={8} />. Tests that rely on emulators might provide successful results locally, but fail in the cloud <Cite n={8} />.
- **Putting the logic in the handler.** The handler should be a slim adapter that passes only the details that matter to your business logic <Cite n={8} />.
- **Setting a timeout close to the usual duration.** If the timeout value is close to the average duration of a function, there is a higher risk that the function times out unexpectedly <Cite n={5} />.
- **Trusting a reused execution environment.** You should not assume that the execution environment will persist indefinitely <Cite n={6} />. Background processes that did not complete when the function ended resume if Lambda reuses the execution environment <Cite n={6} />.
- **Forgetting `--endpoint-url`.** By default, the AWS SDKs and tools use endpoints for the DynamoDB web service <Cite n={22} />. To use them with DynamoDB local, you must specify the local endpoint <Cite n={22} />.
- **Treating DynamoDB local as the real service.** The downloadable version is intended for development and testing purposes only <Cite n={22} />. With `-inMemory`, none of the data is saved when you stop DynamoDB <Cite n={22} />. If telemetry remains on, DynamoDB local sends telemetry data in the background <Cite n={23} />.
- **Expecting a JOIN in DynamoDB.** DynamoDB doesn't support a JOIN operator <Cite n={9} />.
- **Expecting a strongly consistent read by default.** Eventually consistent is the default read consistent model <Cite n={11} />. Strongly consistent reads from a global secondary index or a stream are not supported <Cite n={11} />.
- **Expecting TTL to delete items on time.** The system might delete expired items at any time, typically within a few days after their expiration <Cite n={13} />. Items with a TTL attribute that is not a Number are ignored by the TTL process <Cite n={13} />.
- **Pointing an Athena table at a file.** The LOCATION clause specifies an Amazon S3 folder, not a specific file, because Athena expects to scan all of the files in a folder <Cite n={28} />.
- **Using a camel case path with `MSCK REPAIR TABLE`.** If the S3 path is in camel case, MSCK REPAIR TABLE doesn't add the partitions to the AWS Glue Data Catalog <Cite n={31} />. The command works only with Hive-style partitions <Cite n={31} />.
- **Leaving a big S3 bucket unpartitioned.** If you issue queries against Amazon S3 buckets with a large number of objects and the data is not partitioned, such queries may affect the GET request rate limits in Amazon S3 and lead to Amazon S3 exceptions <Cite n={31} />.
- **Getting the name in `StartAt` wrong.** The value must exactly match, and is case sensitive, the name of one of the state objects <Cite n={34} />.
- **Leaving out `Default` in a Choice state.** If no Choices evaluate to true and no Default is provided, the state machine throws an error <Cite n={35} />. Choice states do not support the End field <Cite n={35} />.
- **Expecting a catcher to save a failed execution.** Catchers are not available for top-level state machine execution failures <Cite n={36} />. By default, Step Functions fails the entire state machine execution <Cite n={36} />.
- **Assuming an Express step runs once.** One or more steps in an Express workflow can potentially run more than once <Cite n={32} />.
- **Choosing the console to test Map or Parallel states.** The console TestState feature does not yet support mocking service integrations or testing Map and Parallel states <Cite n={37} />.
- **Naming a state machine in a hurry.** You cannot rename a state machine after you create it <Cite n={38} />.
- **Forgetting what costs money.** Using provisioned concurrency incurs additional charges to your account <Cite n={7} />. In provisioned mode, you are charged for the capacity that you provisioned, not for the capacity that you consumed <Cite n={12} />. In the Athena tutorial, you are charged for the queries that you run, and if you upload your own data files to Amazon S3, charges do apply <Cite n={26} />.

</Technical>

- **`MSCK REPAIR TABLE`-এ camel case path ব্যবহার করা।** S3 path camel case-এ থাকলে MSCK REPAIR TABLE AWS Glue Data Catalog-এ partition যোগ করে না <Cite n={31} />। command-টা শুধু Hive-style partition-এর সঙ্গে কাজ করে <Cite n={31} />।
- **বড় S3 bucket partition না করে রাখা।** আপনি অনেক object-সহ Amazon S3 bucket-এ এমন query চালালে, যার data partition করা নেই, সেই query Amazon S3-এর GET request rate limit-এ প্রভাব ফেলতে পারে আর Amazon S3 exception ঘটাতে পারে <Cite n={31} />।
- **`StartAt`-এ নাম ভুল দেওয়া।** মান state object-গুলোর একটার নামের সঙ্গে হুবহু মিলতে হয়, আর এটা case sensitive <Cite n={34} />।
- **Choice state-এ `Default` বাদ দেওয়া।** কোনো Choice true না হলে আর Default না থাকলে state machine একটা error ছোড়ে <Cite n={35} />। Choice state End field সমর্থন করে না <Cite n={35} />।
- **catcher ব্যর্থ execution বাঁচাবে আশা করা।** top-level state machine execution-এর ব্যর্থতার জন্য catcher পাওয়া যায় না <Cite n={36} />। by default Step Functions পুরো state machine execution ব্যর্থ করে দেয় <Cite n={36} />।
- **Express-এর একটা ধাপ একবারই চলবে ধরে নেওয়া।** একটা Express workflow-র এক বা একাধিক ধাপ সম্ভবত একাধিকবার চলতে পারে <Cite n={32} />।
- **Map বা Parallel state test করতে console বেছে নেওয়া।** console-এর TestState সুবিধা এখনো service integration mock করা বা Map ও Parallel state test করা সমর্থন করে না <Cite n={37} />।
- **তাড়াহুড়ো করে state machine-এর নাম দেওয়া।** state machine বানানোর পর তার নাম বদলানো যায় না <Cite n={38} />।
- **কিসে খরচ হয় ভুলে যাওয়া।** provisioned concurrency ব্যবহারে আপনার account-এ বাড়তি খরচ হয় <Cite n={7} />। provisioned mode-এ আপনি যে capacity provision করেছেন তার জন্য খরচ হয়, যে capacity ব্যবহার করেছেন তার জন্য নয় <Cite n={12} />। Athena-র tutorial-এ আপনি যে query চালান তার জন্য খরচ হয়, আর আপনি নিজের data file Amazon S3-এ upload করলে খরচ হয় <Cite n={26} />।

## What a tester can check

<Voices>
<Technical>

<Callout type="tip" title="Tutorial advice">
This list is the tutorial's own advice for a tester who works with Lambda, DynamoDB, Athena, and Step Functions.

- Write the expected result of an event or a request before you run it, and keep it with the test.
- Keep the handler thin, and put the logic in plain functions that a test can call.
- Test with the largest realistic input, not only with a small sample.
- Use made-up data for every practice table, secret, and bucket, and start each name with a prefix that says it is a test.
- Put the clean-up in the same script that creates the resources.
- When a sample on a docs page and a real run disagree, write down both, and tell the owner of the page.
- For DynamoDB, read right after a write twice: once with ConsistentRead and once without.
- For Athena, check what a query reads, not only what it returns.
- For Step Functions, keep one test for every branch of a Choice state, and one test for an input that matches no branch.
- Run the local tools with made-up credentials and an explicit endpoint, and check the endpoint before you run a command.
- Keep the date, the tool versions, and the exact commands with every test result.
- Use the models of this page to learn the rules, not as a test oracle for a real account.

## Key words

| Term | Meaning |
|---|---|
| Serverless | Lambda is a serverless compute service; you can run code without provisioning or managing servers |
| Event | A JSON formatted document that contains data for your function to process |
| Handler | The handler function is always the entry point to your code; when your function is invoked, Lambda runs this method |
| Context object | It contains information about the function invocation and execution environment |
| Trigger | Some services can invoke a function with each new event, and this is called a trigger |
| Event source mapping | What it is called when, for stream and queue-based services, Lambda invokes the function with batches of records |
| Synchronous invocation | You wait for the function to process the event and return a response |
| Asynchronous invocation | Lambda queues the event for processing and returns a response immediately |
| Execution role | An IAM role that grants the function permission to access AWS services and resources |
| Timeout | The maximum amount of time in seconds that a Lambda function can run; the default is 3 seconds, and you can adjust it up to a maximum value of 1,800 seconds |
| Execution environment | It provides a secure and isolated runtime environment; Lambda invokes your function in it |
| Cold start | What it is known as when Lambda has to initialize a new environment to carry out an invocation |
| Concurrency | The number of in-flight requests that a function is handling at the same time |
| Reserved concurrency | It reserves a portion of the concurrency of your account for a function; there is no charge for configuring it |
| Provisioned concurrency | It pre-initializes environment instances, which reduces cold start latencies; using it incurs additional charges |
| Throttling | What a function experiences if it runs out of available concurrency; it starts to drop requests |
| Table, item, attribute | A table is a collection of items, and each item is a collection of attributes |
| Primary key | It uniquely identifies each item in the table, so that no two items can have the same key |
| Partition key | DynamoDB uses its value as input to an internal hash function; the output determines the partition in which the item is stored |
| Sort key | All items with the same partition key value are stored together, in sorted order by sort key value |
| Global secondary index | An index with a partition key and sort key that can be different from those of the table |
| Local secondary index | An index that has the same partition key as the table, but a different sort key |
| Eventually consistent read | The default read model; a read might not reflect the results of a recently completed write |
| Strongly consistent read | If you set ConsistentRead to true, DynamoDB returns the most up-to-date data; it is not supported on a global secondary index or a stream |
| On-demand mode | The default and recommended throughput option for most workloads; it has pay-per-request pricing |
| Provisioned mode | You must specify the number of reads and writes per second that you require, and you are charged for the capacity that you provisioned |
| Time To Live (TTL) | A method for deleting items that are no longer relevant; the system might delete expired items at any time, typically within a few days after their expiration |
| DynamoDB local | The downloadable version of DynamoDB; it is intended for development and testing purposes only |
| Athena table | Its metadata tells Athena where the data is located in Amazon S3 and specifies the structure of the data; before querying data, a table must be registered in Athena |
| Partition (Athena) | If the WHERE clause names the partition, Athena scans the data only from that partition |
| Hive style partition | A partition whose data paths contain key value pairs connected by equal signs |
| MSCK REPAIR TABLE | The command that loads new Hive partitions; it works only with Hive-style partitions |
| State machine | A collection of states; the Amazon States Language, a JSON-based, structured language, defines it |
| State | Each step in a workflow is called a state |
| Execution | Instances of running workflows performing tasks are called executions |
| Standard workflow | Exactly-once workflow execution; it can run for up to one year |
| Express workflow | At-least-once workflow execution; it can run for up to five minutes, and one or more steps can potentially run more than once |
| Choice state | It adds conditional logic to a state machine; Default is the name of the state to transition to if no Choice Rule evaluates to true |
| TestState API | It accepts the definition of a state and executes it; it allows you to test a state without creating a state machine |
| Mock | It lets you test state logic without calling the actual service |
| Fake | A mock that takes shortcuts to simplify or speed up testing |
| Test case (unittest) | The individual unit of testing; it checks for a specific response to a particular set of inputs |
