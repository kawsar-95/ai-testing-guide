# Kubernetes Operations

Liveness probes, autoscaling, and resource limits. A short explanation with its sources comes first. The reels after it show the topic at work.

<PageMeta />

## What it is

<Voices>
<Technical>

Many applications running for long periods of time eventually transition to broken states, and cannot recover except by being restarted. Kubernetes provides liveness probes to detect and remedy such situations <Cite n={1} />. A HorizontalPodAutoscaler automatically updates a workload resource, such as a Deployment or StatefulSet, with the aim of automatically scaling capacity to match demand <Cite n={2} />. When you specify a resource limit for a container, the kubelet enforces it, so the running container is not allowed to use more of that resource than the limit you set <Cite n={3} />.

</Technical>
<Layman>

Many applications that run for a long time end up in a broken state. They cannot recover unless someone restarts them. Kubernetes provides liveness probes to detect and fix such cases <Cite n={1} />. A HorizontalPodAutoscaler updates a workload resource, such as a Deployment or StatefulSet, by itself. Its aim is to scale capacity to match demand <Cite n={2} />. You can set a resource limit for a container. The kubelet enforces it: a running container may not use more of that resource than the limit <Cite n={3} />.

</Layman>
<Bangla>

অনেক application দীর্ঘ সময় চলতে চলতে শেষে broken অবস্থায় চলে যায়। restart করা ছাড়া সেগুলো আর সুস্থ হতে পারে না। এমন ক্ষেত্র শনাক্ত করতে ও ঠিক করতে Kubernetes liveness probe দেয় <Cite n={1} />। HorizontalPodAutoscaler নিজে থেকেই একটা workload resource (যেমন Deployment বা StatefulSet) update করে। এর লক্ষ্য হলো চাহিদার সাথে মিলিয়ে capacity scale করা <Cite n={2} />। আপনি একটা container-এর জন্য resource limit ঠিক করে দিতে পারেন। kubelet সেটা প্রয়োগ করে: চলমান container ওই limit-এর বেশি সেই resource ব্যবহার করতে পারে না <Cite n={3} />।
