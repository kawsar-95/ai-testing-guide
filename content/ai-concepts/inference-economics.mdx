# Inference Economics

A taxi meter counts each kilometre, but you care about the price of the whole trip. A model API bills each token, but your team cares about the price of each finished task. This page shows how the bill is made, which levers cut it, and how a tester measures it.

<PageMeta />

## In plain words

<Voices>
<Technical>

**Inference** is one run of a trained model: you send a prompt, and the model sends back an answer. A model API bills inference by **tokens**, the small pieces of text that the model reads and writes. Prices are given per million tokens (MTok) <Cite n={1} />.

The bill has a few parts:

- **Input tokens**: the prompt, the system prompt, tool definitions, and the history that you send.
- **Output tokens**: the answer, the tool calls, and the thinking. Thinking tokens are billed as output tokens <Cite n={5} />.
- **Cache tokens**: input that the provider stored from an earlier request and reads again at a lower price <Cite n={1} />.

For the two list prices below, an output token costs 5 times an input token. Claude Sonnet 5.5 costs $2 per MTok for input and $10 per MTok for output <Cite n={1} />. OpenAI's gpt-6.1-sol has the same list price: $2.00 and $10.00 per 1M tokens for short prompts (272K input tokens or fewer). Above that, it is $4.00 and $15.00 <Cite n={6} />. These ratios belong to one provider, one model, and one date (2026-10-28). Check the current price page before you plan a budget.

One call is not the unit that matters. An agent can make many calls, retry, and still fail. So the useful number is the **cost per finished task**: the total spend divided by the number of tasks that really succeeded. This metric is the tutorial's own framing, not a vendor term.

</Technical>

নিচের দুটো লিস্ট প্রাইসে একটা output token-এর দাম একটা input token-এর ৫ গুণ। Claude Sonnet 5.5-এ input প্রতি MTok $2, output প্রতি MTok $10 <Cite n={1} />। OpenAI-এর gpt-6.1-sol-এর ছোট prompt-এর লিস্ট প্রাইসও একই <Cite n={6} />। এই হিসাব একটা প্রোভাইডার, একটা মডেল আর একটা তারিখের (2026-10-28)। বাজেট করার আগে আপনি বর্তমান দামের পেজ আবার দেখে নিন।

একটা call আসল হিসাব নয়। একটা agent অনেক call করতে পারে, আবার চেষ্টা করতে পারে, তবুও ফেল করতে পারে। তাই আপনি গুনুন **cost per finished task**: মোট খরচকে সত্যিই সফল task-এর সংখ্যা দিয়ে ভাগ করুন। এই ধারণাটা টিউটোরিয়ালের নিজের, কোনো vendor-এর শব্দ নয়।

## How it works

<Voices>
<Technical>

Each request goes through the same meter. The provider counts the tokens of each kind and multiplies each count by its own price.

```text
request
  |-- shared prefix (system prompt, tools, docs)
  |       cache hit?  yes -> cache read price (cheap)
  |                   no  -> cache write price (a bit more than input)
  |-- new input (this test's log)        -> input price
  '-- output (thinking + text + tool calls) -> output price (highest)
                                             |
                                    sum of all parts = cost of the call
```

**Prompt caching.** The provider stores a prompt **prefix** and reuses it when the next request starts with the same prefix <Cite n={2} />. On the Claude API, a 5-minute cache write costs 1.25x the base input price, and a 1-hour write costs 2x. A cache read costs 0.1x on most models, 0.05x on Claude Opus 5.5 and Sonnet 5.5, and 0.025x on Claude Fable 5.1 and Mythos 5.1 <Cite n={1} />. The default lifetime is 5 minutes, and each use refreshes it at no cost <Cite n={2} />. The response reports `cache_creation_input_tokens`, `cache_read_input_tokens`, and `input_tokens`. Their sum is the total input <Cite n={2} />. OpenAI turns caching on by default and gives cached input a discount of up to 95%. Its response reports `usage.input_tokens_details.cached_tokens` <Cite n={7} />.

**Batching.** A batch API runs many requests later, not now. The Claude Message Batches API gives 50% off input and output tokens <Cite n={1} />. Most batches finish within 1 hour, and a batch expires if it does not finish within 24 hours <Cite n={3} />. OpenAI's Batch API also gives a 50% discount, with a 24-hour completion window <Cite n={8} />. On the Claude API, the cache multipliers stack with the batch discount <Cite n={1} />.

**Effort.** The Claude `effort` setting changes how many tokens the model spends. It affects all output tokens: text, tool calls, and thinking <Cite n={4} />. It is a signal, not a strict budget <Cite n={4} />. Most Claude models default to `high`; Claude Opus 5.5 and Haiku 5.5 default to `medium` <Cite n={4} />. The hard limit on output is `max_tokens`, which covers thinking and text together <Cite n={5} />.

</Technical>
<Layman>

Each request goes through the same meter. The provider counts each kind of token. Then it multiplies each count by its own price and adds them up.

The parts are these. A shared start of the prompt (the system prompt, the tools, the docs) is cheap if the cache has it. The new input (for example, the log of one test) costs the input price. The output (thinking, text, and tool calls) costs the most.

**Prompt caching.** The provider keeps the start of a prompt, the **prefix**. It reuses the prefix when the next request starts the same way <Cite n={2} />. On the Claude API, writing to the 5-minute cache costs 1.25 times the normal input price. Writing to the 1-hour cache costs 2 times. Reading from the cache costs 0.1 times on most models. It costs 0.05 times on Claude Opus 5.5 and Sonnet 5.5, and 0.025 times on Claude Fable 5.1 and Mythos 5.1 <Cite n={1} />. The cache lives for 5 minutes by default. Each use starts the clock again for free <Cite n={2} />. The response tells you how many tokens were written to the cache, read from it, or not cached <Cite n={2} />. OpenAI turns caching on by default. It takes up to 95% off cached input and reports `cached_tokens` <Cite n={7} />.

**Batching.** A batch API runs many requests later, not right now. The Claude batch API takes 50% off input and output <Cite n={1} />. Most batches finish within 1 hour. A batch that does not finish in 24 hours expires <Cite n={3} />. OpenAI's batch API also takes 50% off and has a 24-hour window <Cite n={8} />. On the Claude API, you can get the cache price and the batch discount together <Cite n={1} />.

**Effort.** The Claude `effort` setting changes how many tokens the model spends. It changes all output: text, tool calls, and thinking <Cite n={4} />. It is a hint, not a strict limit <Cite n={4} />. Most Claude models start at `high`. Claude Opus 5.5 and Haiku 5.5 start at `medium` <Cite n={4} />. The real hard limit is `max_tokens`. It covers thinking and text together <Cite n={5} />.

</Layman>
<Bangla>

প্রতিটা রিকুয়েস্ট একই মিটারের মধ্য দিয়ে যায়। প্রোভাইডার প্রতিটা ধরনের token গোনে। তারপর প্রতিটা সংখ্যাকে তার নিজের দাম দিয়ে গুণ করে যোগ করে।

অংশগুলো এই রকম। Prompt-এর শেয়ার করা শুরুর অংশ (system prompt, tool, ডকুমেন্ট) cache-এ থাকলে সস্তা পড়ে। নতুন input (যেমন একটা টেস্টের log) input-এর দামে যায়। Output (thinking, লেখা, tool call)-এর দাম সবচেয়ে বেশি।

**Prompt caching.** প্রোভাইডার prompt-এর শুরুর অংশ, মানে **prefix**, রেখে দেয়। পরের রিকুয়েস্ট একইভাবে শুরু হলে সে prefix আবার ব্যবহার করে <Cite n={2} />। Claude API-তে 5 মিনিটের cache-এ লিখতে সাধারণ input দামের 1.25 গুণ লাগে। 1 ঘণ্টার cache-এ লিখতে লাগে 2 গুণ। বেশিরভাগ মডেলে cache থেকে পড়তে লাগে 0.1 গুণ। Claude Opus 5.5 আর Sonnet 5.5-এ লাগে 0.05 গুণ, আর Claude Fable 5.1 ও Mythos 5.1-এ 0.025 গুণ <Cite n={1} />। ডিফল্টভাবে cache 5 মিনিট থাকে। প্রতিবার ব্যবহারে ঘড়ি বিনা খরচে আবার শুরু হয় <Cite n={2} />। Response আপনাকে বলে কতগুলো token cache-এ লেখা হলো, cache থেকে পড়া হলো, আর কতগুলো cache হয়নি <Cite n={2} />। OpenAI ডিফল্টভাবে caching চালু রাখে। Cached input-এ সর্বোচ্চ 95% ছাড় দেয় আর `cached_tokens` রিপোর্ট করে <Cite n={7} />।

**Batching.** Batch API অনেক রিকুয়েস্ট এখনই নয়, পরে চালায়। Claude-এর batch API input আর output-এ 50% ছাড় দেয় <Cite n={1} />। বেশিরভাগ batch 1 ঘণ্টার মধ্যে শেষ হয়। 24 ঘণ্টায় শেষ না হলে batch expire হয়ে যায় <Cite n={3} />। OpenAI-এর batch API-ও 50% ছাড় দেয়, আর তার সময়সীমা 24 ঘণ্টা <Cite n={8} />। Claude API-তে cache-এর দাম আর batch-এর ছাড় একসাথে পাওয়া যায় <Cite n={1} />।

**Effort.** Claude-এর `effort` সেটিং ঠিক করে মডেল কত token খরচ করবে। এটা সব output-এ প্রভাব ফেলে: লেখা, tool call আর thinking <Cite n={4} />। এটা একটা ইঙ্গিত, কড়া সীমা নয় <Cite n={4} />। বেশিরভাগ Claude মডেল `high` দিয়ে শুরু করে। Claude Opus 5.5 আর Haiku 5.5 শুরু করে `medium` দিয়ে <Cite n={4} />। আসল কড়া সীমা হলো `max_tokens`। এটা thinking আর লেখা দুটো মিলিয়ে গোনে <Cite n={5} />।

</Bangla>
</Voices>

## Trade-offs

<Voices>
<Technical>

Each lever saves money and costs something else.

| Lever | Saves | Costs |
|---|---|---|
| Prompt cache | Cheap reads of a repeated prefix <Cite n={1} /> | A write costs more than plain input (1.25x or 2x on Claude) <Cite n={1} />. Prompts below a minimum length are not cached, and the API returns no error <Cite n={2} />. |
| Batch API | 50% on input and output <Cite n={1} /> | Results can take up to 24 hours <Cite n={3} />. Not for a user who waits. |
| Lower effort | Fewer output tokens <Cite n={4} /> | Some loss of capability <Cite n={4} />. A change of top-level effort between requests also breaks the prompt cache <Cite n={4} />. |
| Smaller model | Lower price per token (Claude Haiku 4.5 is $1 / $5 per MTok, Opus 5.5 is $4 / $20) <Cite n={1} /> | It can fail more tasks. |

The 5-minute cache pays off after one read, and the 1-hour cache after two reads <Cite n={1} />. So caching helps only when the same prefix comes back soon.

The last two rows show the main trap. A cheaper call that fails more often can make the **finished task** more expensive. You find out only when you measure success and cost together.

</Technical>
<Layman>

Each way to save money has a price of its own.

- **Prompt cache.** Reads of a repeated start are cheap <Cite n={1} />. But a write costs more than plain input: 1.25 or 2 times on Claude <Cite n={1} />. A prompt that is too short is not cached, and the API shows no error <Cite n={2} />.
- **Batch API.** You save 50% on input and output <Cite n={1} />. But results can take up to 24 hours <Cite n={3} />. It does not suit a user who waits.
- **Lower effort.** The model writes fewer output tokens <Cite n={4} />. But it can do a bit worse <Cite n={4} />. If you change the top-level effort between requests, the cache stops working <Cite n={4} />.
- **Smaller model.** Each token is cheaper. Claude Haiku 4.5 is $1 / $5 per MTok, and Opus 5.5 is $4 / $20 <Cite n={1} />. But it can fail more tasks.

The 5-minute cache pays for itself after one read. The 1-hour cache pays for itself after two reads <Cite n={1} />. So caching helps only when the same start comes back soon.

The last two points show the main trap. A cheaper call that fails more often can make each **finished task** cost more. You see this only when you measure success and cost together.

</Layman>
<Bangla>

খরচ কমানোর প্রতিটা উপায়ের নিজস্ব একটা দাম আছে।

- **Prompt cache.** বারবার আসা শুরুর অংশ পড়া সস্তা <Cite n={1} />। কিন্তু cache-এ লেখা সাধারণ input-এর চেয়ে দামি: Claude-এ 1.25 বা 2 গুণ <Cite n={1} />। খুব ছোট prompt cache হয় না, আর API কোনো error দেখায় না <Cite n={2} />।
- **Batch API.** Input আর output-এ 50% বাঁচে <Cite n={1} />। কিন্তু ফল আসতে 24 ঘণ্টা পর্যন্ত লাগতে পারে <Cite n={3} />। যে ইউজার অপেক্ষা করছেন, তাঁর জন্য এটা ঠিক নয়।
- **কম effort.** মডেল কম output token লেখে <Cite n={4} />। কিন্তু কাজের মান একটু কমতে পারে <Cite n={4} />। রিকুয়েস্টের মাঝে top-level effort বদলালে cache আর কাজ করে না <Cite n={4} />।
- **ছোট মডেল.** প্রতিটা token সস্তা। Claude Haiku 4.5 প্রতি MTok $1 / $5, আর Opus 5.5 $4 / $20 <Cite n={1} />। কিন্তু এটা বেশি task-এ ফেল করতে পারে।

5 মিনিটের cache একবার পড়লেই খরচ উঠে আসে। 1 ঘণ্টার cache-এ উঠে আসে দুবার পড়লে <Cite n={1} />। তাই একই শুরুর অংশ তাড়াতাড়ি ফিরে এলে তবেই caching কাজে লাগে।

শেষের দুটো পয়েন্টই আসল ফাঁদ দেখায়। সস্তা call যদি বেশি ফেল করে, তাহলে প্রতিটা **finished task**-এর খরচ বেড়ে যেতে পারে। সাফল্য আর খরচ একসাথে মাপলে তবেই আপনি এটা দেখতে পাবেন।

## A real-life example

<Voices>
<Technical>

This is an invented example. The prices are the Claude Sonnet 5.5 list prices on 2026-10-28: input $2, 5-minute cache write $2.50, cache read $0.10, and output $10 per MTok <Cite n={1} />. A batch would halve input and output <Cite n={1} />.

A test-triage agent reads each failing test of a nightly run and labels it "product bug", "test bug", or "flaky". One night has 200 failures. Each call sends a 20,000-token shared prefix (instructions, tool definitions, a project guide), 3,000 tokens of the failure log, and gets 1,000 output tokens back, thinking included.

```text
No cache:     per call = 23,000 x $2/M + 1,000 x $10/M
                       = $0.046 + $0.010 = $0.056
              200 calls = $11.20
Batch only:   $11.20 / 2 = $5.60

With cache (all calls inside the 5-minute lifetime):
  call 1      = 20,000 x $2.50/M + 3,000 x $2/M + 1,000 x $10/M
              = $0.050 + $0.006 + $0.010 = $0.066
  calls 2-200 = 20,000 x $0.10/M + 3,000 x $2/M + 1,000 x $10/M
              = $0.002 + $0.006 + $0.010 = $0.018 each
  total       = $0.066 + 199 x $0.018 = $3.648

Cost per finished task (160 labels were right):
  $3.648 / 160 = $0.0228

Lower effort, 600 output tokens, only 100 labels right:
  total = $0.062 + 199 x $0.014 = $2.848
  $2.848 / 100 = $0.0285   <- cheaper night, dearer task
```

The cache cut the night from $11.20 to about $3.65. The low-effort run cost less in total, but each correct label cost more. The team keeps the higher effort.

</Technical>
<Layman>

- **Cost per finished task:** 160 labels were right. $3.648 / 160 = $0.0228.
- **Lower effort:** 600 output tokens and only 100 right labels. The night costs $2.848, but each right label costs $0.0285.

## Common mistakes

<Voices>
<Technical>

- **One ratio for every provider.** "Output costs 5x input" and "a cache hit costs 5%" are not laws. On the Claude API a cache read is 0.1x on most models and 0.05x only on Opus 5.5 and Sonnet 5.5 <Cite n={1} />. OpenAI says "up to 95%" off cached input <Cite n={7} />. Read the price page of your provider and model, and write down the date.
- **Free cache writes.** On the Claude API a cache write costs 1.25x or 2x the base input price <Cite n={1} />. A cache that is never read again costs more than no cache.
- **A silent cache miss.** A prompt below the minimum length (for example 1,024 tokens on Claude Sonnet 5) is not cached, and no error comes back <Cite n={2} />. A change of top-level effort between requests also breaks the cache <Cite n={4} />.
- **Counting only the visible answer.** You pay for the full thinking, not the summary that you see <Cite n={5} />.
- **Token counts carried across models.** Claude 4.7 and later models use a tokenizer that makes about 30% more tokens for the same text <Cite n={1} />. The same prompt can cost more on a new model at the same price per token.
- **Batch for a live user.** A batch can take up to 24 hours <Cite n={3} />.
- **Price per call as the goal.** A cheaper call that fails more often can raise the cost per finished task (see the example above).

</Technical>

## What a tester can check

<Voices>
<Technical>

Claude Code shows the session cost with `/usage`. The figure is a local estimate at list price, not the bill <Cite n={9} />. The same screen shows the share of input tokens served from cache and the cache misses <Cite n={9} />. In print mode, `--output-format json` gives machine-readable output <Cite n={10} />, and `--max-budget-usd` stops a run once the estimated spend reaches a limit. The spend can pass the cap, so leave headroom <Cite n={10} />. In the API response, read `cache_read_input_tokens`, `cache_creation_input_tokens`, and `input_tokens` <Cite n={2} />, and `usage.output_tokens_details.thinking_tokens` <Cite n={5} />.

<Callout type="tip" title="Tutorial advice">
This list is the tutorial's own advice.

- Log the tokens of each kind and the cost of every test run. Store them next to the pass or fail result.
- Report the cost per finished task: total spend divided by the tasks that passed review, not by the calls.
- Check the cache hit rate: cache read tokens divided by total input tokens. Alert when it drops after a prompt or tool change.
- Check that a prompt you mark for caching is above the minimum length, and that the second request shows cache reads.
- Compare two effort levels or two models on the same task set. Compare success rate and cost together.
- Set a cost budget in CI. Fail or warn the job when one run passes it, and keep headroom under the hard cap.
- Re-read the price page when you change provider, model, or region, and record the date of the prices you used.
</Callout>

</Technical>

## Key words

| Term | Meaning |
|---|---|
| Inference | One run of a trained model on a prompt |
| Token | A small piece of text that the model reads or writes; the unit of billing |
| MTok | One million tokens; the unit of most price tables |
| Input tokens | What you send: prompt, system prompt, tools, history |
| Output tokens | What the model writes: text, tool calls, and thinking |
| Thinking tokens | Tokens of the model's reasoning, billed as output |
| Prompt caching | Storing a prompt prefix so that later requests read it at a lower price |
| Cache write / cache read | Storing the prefix (a higher price) / reusing it (a lower price) |
| Cache hit rate | Cache read tokens divided by total input tokens |
| Batch API | An API that runs many requests later at a discount |
| Effort | A Claude setting that changes how many tokens the model spends |
| `max_tokens` | The hard limit on output tokens of one request |
| Cost per finished task | Total spend divided by the tasks that really succeeded |
