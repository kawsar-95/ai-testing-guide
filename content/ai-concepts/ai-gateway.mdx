# AI Gateways

An office building has one front desk. Every visitor signs in there, gets a badge, and goes to the right floor. An AI gateway is the front desk for model calls: every app sends its requests to it, and the gateway decides who may pass, where the request goes, and what to write in the log.

<PageMeta />

## In plain words

<Voices>
<Technical>

An **AI gateway** (also called an **LLM gateway**) is a proxy that sits between your apps and the model providers. The apps do not call each provider directly. They call one gateway endpoint, and the gateway forwards the request.

The Claude Code docs say that a gateway gives an organization one place to manage credentials, usage tracking, cost controls, audit logging, and provider switching <Cite n={1} />. In detail <Cite n={1} />:

- **Credentials**: the provider key stays on the server. Developers hold gateway credentials instead.
- **Cost controls**: budgets and rate limits live in one place.
- **Audit logging**: the gateway logs every model request.
- **Provider switching**: you change the provider in the gateway configuration, not on each developer machine.

Many products do this job. Cloudflare AI Gateway gives visibility and control over AI apps <Cite n={3} />. LiteLLM is a self-hosted server with one endpoint for more than 100 LLM providers, MCP tools, and A2A agents <Cite n={5} />. Kong AI Gateway connects to major LLM providers through one consistent API <Cite n={8} />. Azure API Management has AI gateway features to govern models, agents, and tools <Cite n={7} />. This page shows no product as the best one. They share the same idea.

The upstream side can be a hosted model API, a self-hosted model, or a remote MCP server <Cite n={7} />. So a gateway can be one control point for model calls and tool calls.

</Technical>
<Layman>

An **AI gateway** (also called an **LLM gateway**) is a middle stop between your apps and the model companies. Your apps do not talk to each company. They talk to the gateway, and the gateway passes the request on.

The Claude Code docs say that a gateway gives a company one place to manage keys, usage, cost limits, logs, and the choice of provider <Cite n={1} />. The real provider key stays on the server. Each developer gets a gateway key instead. Budgets and rate limits are set in one place. The gateway logs every model request. To change the provider, you change the gateway, not every laptop <Cite n={1} />.

Many products do this job. Cloudflare AI Gateway gives you a view of your AI apps and control over them <Cite n={3} />. LiteLLM is a server that you run yourself. It gives one endpoint for more than 100 providers, MCP tools, and A2A agents <Cite n={5} />. Kong AI Gateway gives one API for the major providers <Cite n={8} />. Azure API Management can govern models, agents, and tools <Cite n={7} />. No product here is "the best". They share one idea.

Behind the gateway there can be a hosted model, a model that you run yourself, or a remote MCP server <Cite n={7} />. So one gateway can control calls to models and calls to tools.

</Layman>

## How it works

<Voices>
<Technical>

Here is the path of one request:

```text
 App A ─┐                ┌───────────────────────────┐      ┌─> OpenAI
 App B ─┼─ gateway key ─>│        AI gateway         │──────┼─> Anthropic
 App C ─┘                │ 1 auth   2 limits/budget  │ prov.├─> Gemini
                         │ 3 route  4 fallback       │ key  ├─> self-hosted model
                         │ 5 log, metrics, cost      │      └─> MCP server
                         └───────────────────────────┘
```

1. **Auth.** The app sends a gateway credential, not the provider key. LiteLLM gives each user, team, and project a **virtual key** <Cite n={5} />. Azure API Management can use managed identities, so it needs no API key to reach Azure AI services <Cite n={7} />.
2. **Limits and budgets.** Each LiteLLM key has its models, budgets, and rate limits <Cite n={5} />. Azure can set a tokens-per-minute (TPM) limit or a token quota per consumer <Cite n={7} />. Cloudflare can limit the number of requests <Cite n={3} />.
3. **Routing.** The gateway picks the upstream model. Some gateways also answer from a cache instead of the provider <Cite n={3} />.
4. **Fallback.** If the first model fails, the gateway tries the next one. In Cloudflare, an error triggers the fallback by default, and a configured timeout can too <Cite n={4} />. The response header `cf-aig-step` tells which step served the request: `0` is the first model <Cite n={4} />. LiteLLM tries fallbacks in order, with retries and cooldowns, and has special fallbacks for context-window and content-policy errors <Cite n={6} />. Azure can stop sending requests to a backend that does not respond (a circuit breaker) <Cite n={7} />.
5. **Logs and cost.** Cloudflare shows requests, tokens, and cost <Cite n={3} />. LiteLLM records the cost of each request and can send logs and metrics to OpenTelemetry, Prometheus, and other tools <Cite n={5} />. Azure can log prompts and completions <Cite n={7} />. Some gateways also clean the prompt: Kong can redact PII before it reaches the provider <Cite n={8} />.

To send Claude Code through a gateway, set `ANTHROPIC_BASE_URL` to the gateway address <Cite n={2} />. Put the gateway credential in `ANTHROPIC_AUTH_TOKEN` (sent as `Authorization: Bearer`) or `ANTHROPIC_API_KEY` (sent as `x-api-key`) <Cite n={2} />:

```bash
export ANTHROPIC_BASE_URL=https://llm-gateway.example.com
export ANTHROPIC_AUTH_TOKEN=sk-gateway-key
```

Then run `/status`. The `Anthropic base URL` line shows only when a gateway address is set <Cite n={2} />.

</Technical>

gateway-এর ভেতরে একটা রিকোয়েস্ট পাঁচটা ধাপ পার হয়:

1. **Auth।** অ্যাপ আসল provider key দেখায় না, দেখায় gateway key। LiteLLM প্রতিটা user, team আর project-কে আলাদা **virtual key** দেয় <Cite n={5} />। Azure API Management managed identity ব্যবহার করতে পারে, ফলে Azure-এর AI সার্ভিসে পৌঁছাতে তার API key লাগে না <Cite n={7} />।
2. **Limit আর বাজেট।** LiteLLM-এর প্রতিটা key-এর নিজের মডেল, বাজেট আর rate limit থাকে <Cite n={5} />। Azure প্রতিটা ব্যবহারকারীর জন্য প্রতি মিনিটে token-এর সীমা (TPM) বা একটা token quota সেট করতে পারে <Cite n={7} />। Cloudflare রিকোয়েস্টের সংখ্যা সীমিত করতে পারে <Cite n={3} />।
3. **Routing।** কোন মডেল রিকোয়েস্টটা পাবে, gateway তা ঠিক করে। কিছু gateway provider-কে কল না করে cache থেকেও উত্তর দিতে পারে <Cite n={3} />।
4. **Fallback।** প্রথম মডেল ব্যর্থ হলে gateway পরেরটা চেষ্টা করে। Cloudflare-এ একটা error হলে fallback শুরু হয়, আর সেট করা timeout-এও হতে পারে <Cite n={4} />। response header `cf-aig-step` বলে দেয় কোন ধাপ উত্তর দিল। `0` মানে প্রথম মডেল <Cite n={4} />। LiteLLM ক্রম অনুযায়ী fallback চেষ্টা করে। সে retry করে, ব্যর্থ মডেলকে কিছু সময় বিরতি দেয়, আর context-window ও content-policy error-এর জন্য আলাদা fallback রাখে <Cite n={6} />। কোনো backend সাড়া না দিলে Azure সেখানে রিকোয়েস্ট পাঠানো বন্ধ করতে পারে <Cite n={7} />।
5. **Log আর খরচ।** Cloudflare রিকোয়েস্ট, token আর খরচ দেখায় <Cite n={3} />। LiteLLM প্রতিটা রিকোয়েস্টের খরচ রেকর্ড করে, আর OpenTelemetry, Prometheus-এর মতো টুলে log ও metric পাঠাতে পারে <Cite n={5} />। Azure prompt আর উত্তর log করতে পারে <Cite n={7} />। Kong provider-এর কাছে পৌঁছানোর আগে prompt থেকে ব্যক্তিগত তথ্য (PII) মুছে দিতে পারে <Cite n={8} />।

Claude Code-কে gateway দিয়ে চালাতে `ANTHROPIC_BASE_URL`-এ gateway-এর ঠিকানা দিন। gateway key রাখুন `ANTHROPIC_AUTH_TOKEN`-এ (যায় `Authorization: Bearer` হিসেবে) বা `ANTHROPIC_API_KEY`-এ (যায় `x-api-key` হিসেবে) <Cite n={2} />। তারপর `/status` চালান। gateway-এর ঠিকানা সেট থাকলেই কেবল `Anthropic base URL` লাইনটা দেখা যায় <Cite n={2} />।

## Trade-offs

<Voices>
<Technical>

A gateway is not free. The Claude Code docs name the main cost: the gateway becomes infrastructure that your organization operates <Cite n={1} />. Claude Code adds features with each release, and a gateway that does not forward them breaks those features, so you must keep the gateway product up to date <Cite n={1} />.

The next point is the tutorial's own reasoning, not a quote from a source. A gateway also adds one hop to every call, and it is a shared point of failure. If the gateway is down, every app behind it loses its models, even when all providers are up.

A gateway does not make every model work with every client. For example, Anthropic does not support routing Claude Code to non-Claude models through any gateway <Cite n={1} />.

</Technical>
<Layman>

A gateway has a cost. The Claude Code docs say that the gateway becomes one more system that your company must run <Cite n={1} />. Claude Code gets new features with each release. If the gateway does not pass them on, those features break. So you must keep the gateway up to date <Cite n={1} />.

The next point is the tutorial's own reasoning, not a quote from a source. A gateway also adds one more stop to every call, and all apps share it. If the gateway is down, every app behind it loses its models, even when all providers work.

A gateway does not make every model work with every client. For example, Anthropic does not support sending Claude Code to non-Claude models through any gateway <Cite n={1} />.

</Layman>
<Bangla>

gateway-এর একটা খরচ আছে। Claude Code-এর ডকস বলে, gateway আপনার প্রতিষ্ঠানের চালানো আরেকটা infrastructure হয়ে যায় <Cite n={1} />। Claude Code প্রতিটা release-এ নতুন feature যোগ করে। gateway সেগুলো সামনে না পাঠালে সেই feature-গুলো ভেঙে যায়, তাই gateway প্রোডাক্টটাকে আপডেট রাখতে হয় <Cite n={1} />।

পরের কথাটা টিউটোরিয়ালের নিজের যুক্তি, কোনো সোর্সের উদ্ধৃতি নয়। gateway প্রতিটা কলে আরেকটা ধাপ যোগ করে, আর সব অ্যাপ এটা ভাগ করে ব্যবহার করে। gateway বন্ধ হলে তার পেছনের সব অ্যাপ মডেল হারায়, সব provider ঠিকঠাক চললেও।

gateway থাকলেই যেকোনো client যেকোনো মডেলের সাথে চলবে, এমন নয়। যেমন, Anthropic কোনো gateway দিয়েই Claude Code-কে non-Claude মডেলে পাঠানো সাপোর্ট করে না <Cite n={1} />।

## A real-life example

<Voices>
<Technical>

This is an invented example. A QA team runs three AI tools: a test-case generator, a bug-report summarizer, and a Claude Code agent that fixes flaky tests in CI. Before the gateway, each tool had its own provider key in its own config file. Nobody knew the total cost, and one leaked key meant a hunt through three repos.

The team puts a gateway in front of all three tools:

- Each tool gets its own gateway key, so usage is attributed to it, and a revoked key affects only one tool <Cite n={1} />.
- The provider keys stay only in the gateway <Cite n={1} />.
- The CI agent gets a small budget and a rate limit, so a loop in the agent cannot burn the month's spend <Cite n={5} />.
- The summarizer has a fallback model. When the first provider returns errors, the gateway sends the request to the second one <Cite n={4} />.
- The CI job sets `ANTHROPIC_BASE_URL` to the gateway and takes the gateway key from a CI secret <Cite n={2} />.

Now one dashboard shows the requests, tokens, and cost of all three tools <Cite n={3} />.

</Technical>
<Layman>

This is an invented example. A QA team uses three AI tools. One writes test cases. One sums up bug reports. One is a Claude Code agent that fixes flaky tests in CI. Before the gateway, each tool kept its own provider key in its own config file. Nobody knew the total cost. If one key leaked, the team had to search three repos.

The team puts a gateway in front of all three tools:

- Each tool gets its own gateway key. So the team sees the usage of each tool, and a revoked key stops only one tool <Cite n={1} />.
- The provider keys stay only in the gateway <Cite n={1} />.
- The CI agent gets a small budget and a rate limit. So an agent stuck in a loop cannot use up the money for the month <Cite n={5} />.
- The summarizer has a second model. When the first provider returns errors, the gateway sends the request to the second one <Cite n={4} />.
- The CI job sets `ANTHROPIC_BASE_URL` to the gateway and reads the gateway key from a CI secret <Cite n={2} />.

Now one dashboard shows the requests, tokens, and cost of all three tools <Cite n={3} />.

</Layman>
<Bangla>

এটা একটা বানানো উদাহরণ। একটা QA টিম তিনটা AI টুল চালায়: একটা test case লেখে, একটা bug report-এর সারাংশ বানায়, আর একটা Claude Code agent CI-তে flaky test ঠিক করে। gateway-এর আগে প্রতিটা টুলের নিজের config ফাইলে নিজের provider key ছিল। মোট খরচ কেউ জানত না, আর একটা key ফাঁস হলে তিনটা repo খুঁজতে হতো।

টিম তিনটা টুলের সামনেই একটা gateway বসায়:

- প্রতিটা টুল নিজের gateway key পায়। তাই প্রতিটা টুলের usage আলাদা দেখা যায়, আর একটা key বাতিল করলে শুধু একটা টুল থামে <Cite n={1} />।
- provider key শুধু gateway-তেই থাকে <Cite n={1} />।
- CI agent পায় একটা ছোট বাজেট আর একটা rate limit। ফলে agent একটা loop-এ আটকে গেলেও পুরো মাসের টাকা শেষ করতে পারে না <Cite n={5} />।
- summarizer-এর একটা fallback মডেল আছে। প্রথম provider error দিলে gateway রিকোয়েস্টটা দ্বিতীয়টায় পাঠায় <Cite n={4} />।
- CI job `ANTHROPIC_BASE_URL`-এ gateway সেট করে, আর gateway key নেয় একটা CI secret থেকে <Cite n={2} />।

এখন একটা dashboard-এ তিনটা টুলের রিকোয়েস্ট, token আর খরচ দেখা যায় <Cite n={3} />।

</Bangla>
</Voices>

## Common mistakes

<Voices>
<Technical>

- **The provider key is still in the app.** The point of the gateway is that the provider key stays on the server and clients hold only gateway credentials <Cite n={1} />. If an app still has the real key, it can skip the gateway.
- **A side door stays open.** A gateway controls only the traffic that goes through it. Claude Code can be locked to the gateway: with `allowedProviders` set to `["customEndpoint"]` in managed settings, it refuses a session pointed anywhere else <Cite n={1} />.
- **The gateway key is committed.** The Claude Code docs warn not to put the credential in a project's `.claude/settings.json`, because that file is committed and shared <Cite n={2} />.
- **One shared key for everyone.** Give each developer a credential, so usage is attributed and offboarding revokes one credential <Cite n={1} />.
- **The fallback is never tested.** A fallback that has never fired is a guess. LiteLLM's docs say to test it with a real provider error in a non-production environment <Cite n={6} />.
- **The logs hold secrets.** A gateway can log prompts and completions <Cite n={7} />. If a prompt has personal data, the log has it too, unless the gateway redacts it first <Cite n={8} />.
- **The gateway falls behind the client.** A gateway that does not forward new Claude Code features breaks them <Cite n={1} />.

</Technical>
<Layman>

- **The real key is still in the app.** The gateway is there so that the real key stays on the server and apps hold only gateway keys <Cite n={1} />. If an app still has the real key, it can go around the gateway.
- **A side door stays open.** A gateway controls only the calls that go through it. You can lock Claude Code to the gateway. With `allowedProviders` set to `["customEndpoint"]` in managed settings, it refuses any other address <Cite n={1} />.

- **Nobody tested the fallback.** A fallback that never ran is only a hope. The LiteLLM docs say to test it with a real provider error, outside production <Cite n={6} />.
- **The logs hold secrets.** A gateway can log the prompts and the answers <Cite n={7} />. If a prompt has personal data, the log has it too, unless the gateway removes it first <Cite n={8} />.
- **The gateway is older than the client.** If the gateway does not pass on new Claude Code features, those features break <Cite n={1} />.

</Layman>
<Bangla>

- **আসল key এখনো অ্যাপে আছে।** gateway-এর উদ্দেশ্যই হলো provider key সার্ভারে রাখা, আর client-এর হাতে শুধু gateway credential দেওয়া <Cite n={1} />। কোনো অ্যাপে আসল key থেকে গেলে সে gateway এড়িয়ে যেতে পারে।
- **পাশের দরজা খোলা থাকে।** gateway শুধু তার ভেতর দিয়ে যাওয়া traffic-ই নিয়ন্ত্রণ করে। Claude Code-কে gateway-তে আটকে রাখা যায়: managed settings-এ `allowedProviders`-কে `["customEndpoint"]` দিলে সে অন্য কোনো ঠিকানার session চালাতে রাজি হয় না <Cite n={1} />।
- **gateway key git-এ commit হয়ে যায়।** Claude Code-এর ডকস সতর্ক করে: project-এর `.claude/settings.json`-এ credential রাখবেন না, কারণ ফাইলটা commit হয় আর সবার সাথে শেয়ার হয় <Cite n={2} />।
- **সবার জন্য একটাই key।** প্রতিটা ডেভেলপারকে আলাদা credential দিন। তাহলে কে কতটা ব্যবহার করল তা বোঝা যায়, আর কেউ চলে গেলে একটা credential বাতিল করলেই হয় <Cite n={1} />।
- **fallback কখনো টেস্ট হয়নি।** যে fallback কখনো চলেনি, সেটা শুধু একটা অনুমান। LiteLLM-এর ডকস বলে, production-এর বাইরে একটা আসল provider error দিয়ে এটা টেস্ট করতে <Cite n={6} />।
- **log-এ গোপন তথ্য থাকে।** gateway prompt আর উত্তর log করতে পারে <Cite n={7} />। prompt-এ ব্যক্তিগত তথ্য থাকলে log-এও সেটা থাকে, যদি না gateway আগে তা মুছে দেয় <Cite n={8} />।
- **gateway client-এর থেকে পিছিয়ে পড়ে।** gateway নতুন Claude Code feature সামনে না পাঠালে সেগুলো ভেঙে যায় <Cite n={1} />।

</Bangla>

## What a tester can check

<Voices>
<Technical>

<Callout type="tip" title="Tutorial advice">
This list is the tutorial's own advice, not a quote from a source.

- **Fallback:** in a test environment, block or break the primary provider. Check that the call still succeeds, that the response shows which model served it, and that the app's behavior is still correct with the second model.
- **Total outage:** break all providers. Check that the app shows a clear error and does not hang or retry forever.
- **Rate limit:** send requests faster than the limit. Check the status code, the error body, and that the app backs off.
- **Budget:** give a test key a tiny budget and use it up. Check that the gateway blocks the next call and that the cost in the dashboard matches your count.
- **Keys:** search the app bundle, the repo, the CI logs, and the browser traffic for the provider key. It must not be there. Check that a revoked gateway key gets `401` at once.
- **Bypass:** from an app machine, try to call the provider directly. Check that policy or the network blocks it.
- **Log redaction:** send a prompt with fake personal data (a fake email, a fake card number). Check that the gateway log does not show it in clear text.
- **Routing rules:** for each rule (by team, by model name, by header), send one request and check that the right upstream got it.
- **Gateway down:** stop the gateway. Check what each app does.
</Callout>

</Technical>

<Bangla>

<Callout type="tip" title="Tutorial advice">
এই তালিকা টিউটোরিয়ালের নিজের পরামর্শ, কোনো সোর্সের উদ্ধৃতি নয়।

- **Fallback:** টেস্ট এনভায়রনমেন্টে প্রথম provider-কে block করুন বা ভেঙে দিন। দেখুন কলটা তবুও সফল হয় কি না, response-এ কোন মডেল উত্তর দিল তা দেখা যায় কি না, আর দ্বিতীয় মডেলেও অ্যাপ ঠিকমতো চলে কি না।
- **সব provider বন্ধ:** সব provider ভেঙে দিন। দেখুন অ্যাপ একটা পরিষ্কার error দেখায় কি না, আর আটকে থাকে বা অনন্তকাল retry করে কি না।
- **Rate limit:** limit-এর চেয়ে দ্রুত রিকোয়েস্ট পাঠান। status code আর error body দেখুন, আর দেখুন অ্যাপ আবার চেষ্টার আগে অপেক্ষা করে কি না।
- **বাজেট:** একটা test key-কে খুব ছোট বাজেট দিন আর সেটা শেষ করুন। দেখুন gateway পরের কল আটকায় কি না, আর dashboard-এর খরচ আপনার নিজের হিসাবের সাথে মেলে কি না।
- **Key:** অ্যাপের ফাইল, repo, CI log আর ব্রাউজার traffic-এ আসল provider key খুঁজুন। সেটা থাকা চলবে না। দেখুন বাতিল করা gateway key সাথে সাথে `401` পায় কি না।
- **পাশের দরজা:** অ্যাপের মেশিন থেকে সরাসরি provider-কে কল করার চেষ্টা করুন। দেখুন কোনো policy বা নেটওয়ার্ক সেটা আটকায় কি না।
- **Log redaction:** নকল ব্যক্তিগত তথ্য (নকল email, নকল card নম্বর) দিয়ে একটা prompt পাঠান। দেখুন gateway log-এ সেটা সাধারণ লেখা হিসেবে দেখা যায় কি না।
- **Routing rule:** প্রতিটা rule-এর (team, মডেলের নাম বা header অনুযায়ী) জন্য একটা রিকোয়েস্ট পাঠান, আর দেখুন সঠিক upstream সেটা পেল কি না।
- **gateway বন্ধ:** gateway থামিয়ে দিন। দেখুন প্রতিটা অ্যাপ কী করে।
</Callout>

## Key words

| Term | Meaning |
|---|---|
| AI gateway / LLM gateway | A proxy between apps and model providers that handles credentials, limits, routing, and logs in one place. |
| Upstream | The model provider, self-hosted model, or MCP server behind the gateway. |
| Gateway credential / virtual key | The key an app or person uses to call the gateway. It is not the provider key. |
| Provider key | The real key of the model provider. It stays in the gateway. |
| Fallback | A second model or provider that the gateway tries when the first one fails. |
| Circuit breaker | A rule that stops sending requests to a backend that does not respond. |
| Rate limit | A cap on requests or tokens per time unit. |
| Budget / quota | A cap on spend or tokens for a key, team, or app over a period. |
| TPM | Tokens per minute. |
| PII redaction | Removing personal data from a prompt or a log. |
| `ANTHROPIC_BASE_URL` | The variable that points Claude Code at a gateway. |
