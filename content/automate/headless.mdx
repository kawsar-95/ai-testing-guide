# Headless & CI

A CI job has no person at the keyboard to answer prompts. This page shows how to run Claude Code from a script with `claude -p`, read its answer as JSON, keep the run repeatable and locked down, cap its cost, and sign in from a pipeline, with a failing-test triage job as the running example.

<PageMeta />

## What headless mode is

<Voices>
<Technical>

Add the `-p` (or `--print`) flag to any `claude` command to run it non-interactively. <Cite n={1} /> An example from the docs: <Cite n={1} />

```bash
claude -p "Find and fix the bug in auth.py" --allowedTools "Read,Edit,Bash"
```

This example allows the bare `Bash` tool. In CI, prefer a scoped rule such as `Bash(npm test)`. See [Permissions in unattended runs](#permissions-in-unattended-runs).

- `claude -p` uses the Agent SDK through the CLI. The SDK is also available as Python and TypeScript packages for full programmatic control. <Cite n={1} />
- Claude Code exits with code 0 on success and a non-zero code when the run fails, so a CI step can branch on the exit status. <Cite n={1} />
- If you pass an invalid flag, Claude Code reports the error on stderr before the run starts. A failure inside the run, such as missing authentication, is printed as the result on stdout. <Cite n={1} />
- Not every CLI option combines with `-p`. For example, Claude Code rejects `--bg` with `-p`. <Cite n={1} />

<Callout type="note" title="--help does not list every flag">

The CLI reference says that `claude --help` does not list every flag, so a flag that is missing from `--help` can still be available. <Cite n={2} /> This page states each flag as the CLI reference documents it.

</Callout>

</Technical>
<Layman>

A headless run has no person to answer questions. To start one, add the `-p` flag (or `--print`) to a `claude` command. <Cite n={1} /> `claude -p` uses the Agent SDK through the CLI. The SDK is also available as Python and TypeScript packages. <Cite n={1} />

When the run is successful, Claude Code exits with code 0. When the run fails, the exit code is not 0. Thus, a CI step can make a decision from the exit code. <Cite n={1} />

If a flag is not valid, Claude Code shows the error on stderr before the run starts. If the run fails after it starts, for example because authentication is missing, Claude Code shows the failure as the result on stdout. <Cite n={1} />

Some options do not work with `-p`. For example, Claude Code does not accept `--bg` with `-p`. <Cite n={1} /> Also, `claude --help` does not show all flags. <Cite n={2} />

The example in the docs allows the full `Bash` tool. In CI, use a smaller rule, such as `Bash(npm test)`.

</Layman>
<Bangla>

Headless mode-এ prompt-এর উত্তর দেওয়ার জন্য কেউ থাকে না। যেকোনো `claude` command-এ `-p` (অথবা `--print`) flag যোগ করলে command-টি non-interactive mode-এ চলে। <Cite n={1} /> `claude -p` CLI-এর মাধ্যমে Agent SDK ব্যবহার করে। পুরো programmatic control-এর জন্য SDK-টি Python এবং TypeScript package হিসেবেও পাওয়া যায়। <Cite n={1} />

Run সফল হলে Claude Code exit code 0 দেয়, আর run fail করলে একটি non-zero code দেয়। তাই একটি CI step exit status দেখে সিদ্ধান্ত নিতে পারে। <Cite n={1} />

ভুল flag দিলে Claude Code run শুরু হওয়ার আগেই stderr-এ error দেখায়। Run-এর ভেতরের কোনো failure, যেমন authentication না থাকা, stdout-এ result হিসেবে দেখায়। <Cite n={1} />

সব CLI option `-p`-এর সাথে চলে না। যেমন, Claude Code `-p`-এর সাথে `--bg` গ্রহণ করে না। <Cite n={1} /> আর `claude --help` সব flag দেখায় না, তাই `--help`-এ না থাকা একটি flag-ও থাকতে পারে। <Cite n={2} />

Docs-এর উদাহরণে পুরো `Bash` tool-কে allow করা হয়েছে। CI-তে `Bash(npm test)`-এর মতো একটি scoped rule ব্যবহার করুন।

</Bangla>

## Pipe a test log into Claude

<Voices>
<Technical>

Print mode reads stdin, so you can pipe data in and redirect the answer out. The docs pipe a build log like this: <Cite n={1} />

```bash
cat build-error.txt | claude -p 'concisely explain the root cause of this build error' > output.txt
```

Piped stdin is capped at 10MB. For a larger log, write it to a file and name the file in your prompt. <Cite n={1} />

Example: explain the failures of the last test run in plain text.

```bash
npm test > test-output.txt 2>&1
cat test-output.txt | claude -p 'list each failing test, the root cause, and the file to fix' > triage.txt
```

</Technical>
<Layman>

In print mode, Claude Code reads stdin. Thus, you can send data into Claude with a pipe and send the answer to a file. The docs send a build log this way. <Cite n={1} />

The limit for piped stdin is 10MB. If your log is larger, write the log to a file. Then give the file name in your prompt. <Cite n={1} />

In the example, `npm test` writes its output to `test-output.txt`. Then a pipe sends that file to Claude. Claude writes each failing test, the root cause, and the file to fix into `triage.txt`.

</Layman>
<Bangla>

Print mode stdin থেকে পড়ে। তাই আপনি pipe দিয়ে data পাঠাতে পারেন এবং উত্তর একটি file-এ redirect করতে পারেন। Docs এভাবে একটি build log pipe করে। <Cite n={1} />

Piped stdin-এর সীমা 10MB। এর চেয়ে বড় log হলে log-টি একটি file-এ লিখুন এবং prompt-এ সেই file-এর নাম দিন। <Cite n={1} />

উদাহরণে `npm test` তার output `test-output.txt`-এ লেখে। তারপর file-টি pipe করে Claude-কে দেওয়া হয়, আর Claude প্রতিটি failing test, তার root cause এবং কোন file ঠিক করতে হবে তা `triage.txt`-এ লেখে।

</Bangla>
</Voices>

## Output formats

<Voices>
<Technical>

`--output-format` works only in print mode. <Cite n={2} /> It has three values: <Cite n={1} />

| Value | What you get |
|---|---|
| `text` (default) | Plain text output <Cite n={1} /> |
| `json` | Structured JSON with the result, the session ID, and metadata <Cite n={1} /> |
| `stream-json` | Newline-delimited JSON for real-time streaming <Cite n={1} /> |

- With `json`, the text answer is in the `result` field. `jq -r '.result'` extracts it. <Cite n={1} />
- The `json` payload also includes `total_cost_usd` and a per-model cost breakdown. These are client-side estimates and can differ from your bill. <Cite n={1} />
- The docs use `stream-json` with `--verbose` and `--include-partial-messages` to receive tokens as Claude generates them. The last line is a `result` message with the final text, cost, and session metadata. <Cite n={1} />

```bash
claude -p "Summarize this project" --output-format json | jq -r '.result'
```

### Validate the answer with a JSON Schema

Use `--output-format json` with `--json-schema` to get output that matches a schema. The validated output is in the `structured_output` field. <Cite n={1} />

- If the value is not a valid JSON Schema, `claude` exits with `Error: --json-schema is not a valid JSON Schema`. <Cite n={1} />
- Claude Code accepts the `format` keyword, such as `"format": "email"`, but treats it as an annotation and does not enforce it. <Cite n={1} />

### QA example: triage a failing test in CI

<Callout type="tip" title="Example">

This CI step sends the test log to Claude and gets back one JSON object that later steps can read. The schema and the prompt are the tutorial's example. The flags are documented. <Cite n={1} /> <Cite n={2} />

</Callout>

```bash
cat test-output.txt | claude --bare -p "Classify the first failing test in this log. Do not change any files." \
  --permission-mode dontAsk \
  --output-format json \
  --json-schema '{"type":"object","properties":{"test":{"type":"string"},"category":{"type":"string","enum":["product-bug","test-bug","flaky","environment"]},"root_cause":{"type":"string"},"suspected_file":{"type":"string"}},"required":["test","category","root_cause"]}' \
  > triage.json

jq '.structured_output' triage.json
jq -r '.structured_output.category' triage.json
```

- `--bare` needs `ANTHROPIC_API_KEY` or an `apiKeyHelper` in the job. See [Authenticate in CI](#authenticate-in-ci). <Cite n={6} />
- Save `triage.json` as a CI artifact, so a reviewer sees the same answer that the pipeline used.
- Use the `category` value to route the failure, for example to post a comment only for `product-bug`.
- Treat the classification as a first guess. A person confirms a product bug before anyone files it.

</Technical>
<Layman>

The `--output-format` flag works only in print mode. <Cite n={2} /> It has three values: `text` (the default) gives plain text, `json` gives structured JSON, and `stream-json` gives JSON line by line, in real time. <Cite n={1} />

With `json`, the answer is in the `result` field. The JSON also shows `total_cost_usd`. This cost is an estimate, and it can be different from your bill. <Cite n={1} />

To make the answer agree with a JSON Schema, add `--json-schema` with `--output-format json`. Then the validated answer is in the `structured_output` field. If the schema is not valid, `claude` exits with an error. Claude Code does not enforce the `format` keyword. <Cite n={1} />

The QA example sends a test log to Claude. Claude puts the first failing test into one category, such as `product-bug` or `flaky`. Later CI steps read this category. `--bare` needs `ANTHROPIC_API_KEY` or an `apiKeyHelper`. <Cite n={6} /> Keep `triage.json` as a CI artifact. The category is only a first guess. A person confirms a product bug before someone files it.

</Layman>
<Bangla>

`--output-format` শুধু print mode-এ কাজ করে। <Cite n={2} /> এর তিনটি value আছে: `text` (default) plain text দেয়, `json` result, session ID এবং metadata সহ structured JSON দেয়, আর `stream-json` real-time streaming-এর জন্য newline-delimited JSON দেয়। <Cite n={1} />

একটি schema মেনে output পেতে `--output-format json`-এর সাথে `--json-schema` দিন। Validated output `structured_output` field-এ থাকে। Schema valid না হলে `claude` একটি error দিয়ে exit করে। Claude Code `format` keyword গ্রহণ করে, কিন্তু enforce করে না। <Cite n={1} />

## Make CI runs repeatable with --bare

<Voices>
<Technical>

Add `--bare` to skip auto-discovery of hooks, skills, custom commands, subagents, installed plugins, MCP servers, auto memory, and CLAUDE.md. <Cite n={1} /> Without it, `claude -p` loads the same context as an interactive session. <Cite n={1} />

- Bare mode is useful for CI and scripts where you need the same result on every machine. It also starts faster. <Cite n={1} />
- In bare mode, Claude has the Bash, file read, and file edit tools. <Cite n={1} />
- Only MCP servers that you give on the command line connect, for example with `--mcp-config`. Bare mode runs no background tasks. These limits hold fully from v2.1.286. <Cite n={1} />
- The docs call `--bare` the recommended mode for scripted and SDK calls. It will become the default for `-p` in a future release. <Cite n={1} />

Pass the context that the job needs with flags: <Cite n={1} />

| To load | Use |
|---|---|
| System prompt additions | `--append-system-prompt`, `--append-system-prompt-file` |
| Settings | `--settings <file-or-json>` |
| MCP servers | `--mcp-config <file-or-json>` |
| Custom agents | `--agents <file-or-json>` |
| A plugin | `--plugin-dir <path>`, `--plugin-url <url>` |

`--append-system-prompt` adds instructions and keeps the default prompt. `--system-prompt` replaces the default prompt. <Cite n={1} /> <Cite n={2} /> Use the append form for test-review rules, so Claude keeps its default tool guidance.

<Callout type="warning" title="A repository can decide what runs">

Without `--bare`, a `-p` session runs the hooks in the project's `.claude/settings.json` and connects the servers in its `.mcp.json`, even in a folder that you never trusted. A `-p` session shows no workspace trust dialog and no per-server approval prompt. <Cite n={1} />

With `--bare`, Claude Code reads no hooks, skills, custom commands, subagents, plugins, or `.mcp.json` servers from the project. The project's `env` block and helpers such as `awsAuthRefresh` in its settings files still apply. <Cite n={3} /> So `--bare` alone does not block everything from a repository that you did not write. Another control is `--setting-sources user`, so Claude Code reads neither the project's settings files nor its `.mcp.json`. <Cite n={3} />

</Callout>

Bare mode does not use your subscription login. Set `ANTHROPIC_API_KEY`, or give an `apiKeyHelper` in the `--settings` JSON. <Cite n={1} /> See [Authenticate in CI](#authenticate-in-ci).

</Technical>

The append flag keeps the default prompt. `--system-prompt` replaces it. <Cite n={1} /> <Cite n={2} />

It shows no trust dialog and no approval prompt. <Cite n={1} /> With `--bare`, the project's `env` block still applies. Bare mode does not use your subscription login. Set `ANTHROPIC_API_KEY`, or give an `apiKeyHelper`. <Cite n={1} />

`--bare` ছাড়া `claude -p` একটি interactive session-এর মতোই একই context load করে। `--bare` দিলে Claude Code hooks, skills, custom commands, subagents, installed plugins, MCP servers, auto memory এবং CLAUDE.md auto-discover করে না। <Cite n={1} /> তাই যেখানে প্রতিটি মেশিনে একই result দরকার, সেখানে bare mode কাজে লাগে। এছাড়া run দ্রুত শুরু হয়। Docs scripted এবং SDK call-এর জন্য `--bare`-কে recommended mode বলে, এবং ভবিষ্যতের একটি release-এ এটি `-p`-এর default হবে। <Cite n={1} />

## Permissions in unattended runs

<Voices>
<Technical>

Nobody answers a permission prompt in a CI job. Decide before the run what Claude may do. The [Permission Modes](/getting-started/permission-modes/) page explains each mode.

### Allow, deny, and restrict tools

| Flag | What it does |
|---|---|
| `--allowedTools` (alias `--allowed-tools`) | Tools that run without a prompt. It uses permission rule syntax. <Cite n={2} /> |
| `--disallowedTools` (alias `--disallowed-tools`) | Deny rules. A bare tool name such as `"Edit"` removes the tool from Claude's context. A scoped rule such as `Bash(rm *)` denies only the matching calls. <Cite n={2} /> |
| `--tools` | Restricts the built-in tools: `""` disables all, `"default"` gives the default set, or list names such as `"Bash,Edit,Read"`. It does not affect MCP tools. To deny those, use `--disallowedTools "mcp__*"`. <Cite n={2} /> |

In a rule, a trailing space and star is a prefix match: `Bash(git diff *)` allows any command that starts with `git diff`. <Cite n={1} />

### Set the permission mode

`--permission-mode` accepts `default`, `acceptEdits`, `plan`, `auto`, `dontAsk`, `bypassPermissions`, or `manual` as an alias for `default`. <Cite n={2} /> For CI, the useful modes are these:

- **`dontAsk`**: Claude Code denies every call that would otherwise prompt. File reads in your working directories, the read-only command set, and calls that your `--allowedTools` entries or `permissions.allow` rules cover still run. <Cite n={1} />
- **`acceptEdits`**: Claude writes files without a prompt, and common filesystem commands such as `mkdir`, `touch`, `mv`, and `cp` are approved. Other shell commands and network requests still need an `--allowedTools` entry or a `permissions.allow` rule. <Cite n={1} />

The docs show this command to run the tests in CI with an exact allowlist: <Cite n={4} />

```bash
claude -p "run the test suite" --permission-mode dontAsk --allowedTools "Bash(npm test)" "Read"
```

<Callout type="tip" title="Always pass --permission-mode in CI">

A run where nothing sets a permission mode takes the built-in starting mode, which can be `auto`. Pass the mode you want. <Cite n={1} />

</Callout>

### When nobody can answer a prompt

`--permission-prompts none` denies prompts without asking a permission host, and tells Claude not to retry. <Cite n={1} /> The choices are `host` (the default) and `none`. The flag needs Claude Code v2.1.259 or later. <Cite n={2} />

`--dangerously-skip-permissions` is the same as `--permission-mode bypassPermissions`. <Cite n={2} /> Use it only inside a container, a VM, or a sandbox runtime. On Linux and macOS, run Claude Code as a non-root user. <Cite n={4} />

</Technical>
<Layman>

In a CI job, nobody can answer a permission prompt. Thus, decide before the run what Claude can do.

`--allowedTools` gives the tools that run without a prompt. `--disallowedTools` gives the deny rules. `--tools` limits the built-in tools, but it does not change MCP tools. <Cite n={2} /> A rule such as `Bash(git diff *)` allows each command that starts with `git diff`. <Cite n={1} />

In `dontAsk` mode, Claude Code denies each call that would show a prompt. File reads in your working directories, read-only commands, and calls that your allow rules cover still run. In `acceptEdits` mode, Claude writes files without a prompt, but other shell commands and network requests still need an allow rule. <Cite n={1} />

Always give `--permission-mode` in CI. If nothing sets a mode, the mode can be `auto`. <Cite n={1} />

`--permission-prompts none` denies prompts and tells Claude not to try again. <Cite n={1} /> It needs Claude Code v2.1.259 or later. <Cite n={2} /> `--dangerously-skip-permissions` is the same as `--permission-mode bypassPermissions`. <Cite n={2} /> Use it only in a container, a VM, or a sandbox runtime. On Linux and macOS, run Claude Code as a user that is not root. <Cite n={4} />

</Layman>
<Bangla>

CI job-এ permission prompt-এর উত্তর দেওয়ার কেউ থাকে না। তাই run-এর আগেই ঠিক করুন Claude কী কী করতে পারবে।

`--allowedTools` সেই tool-গুলো দেয় যেগুলো prompt ছাড়া চলে। `--disallowedTools` deny rule দেয়: `"Edit"`-এর মতো একটি bare tool name tool-টিকে Claude-এর context থেকে সরিয়ে দেয়, আর `Bash(rm *)`-এর মতো একটি scoped rule শুধু মিলে যাওয়া call-গুলো deny করে। `--tools` built-in tool-গুলো সীমিত করে, কিন্তু MCP tool-এ এর কোনো প্রভাব নেই। MCP tool deny করতে `--disallowedTools "mcp__*"` ব্যবহার করুন। <Cite n={2} /> `Bash(git diff *)`-এর মতো rule `git diff` দিয়ে শুরু হওয়া যেকোনো command allow করে। <Cite n={1} />

`dontAsk` mode-এ যে call-এ prompt আসত, Claude Code তা deny করে। তবে working directory-র file read, read-only command set এবং `--allowedTools` বা `permissions.allow` rule-এ থাকা call-গুলো চলে। `acceptEdits` mode-এ Claude prompt ছাড়া file লেখে, আর `mkdir`, `touch`, `mv`, `cp`-এর মতো command approved থাকে। অন্য shell command এবং network request-এর জন্য এখনও allow rule লাগে। <Cite n={1} />

CI-তে সবসময় `--permission-mode` দিন। কিছুই mode set না করলে built-in starting mode নেওয়া হয়, যা `auto` হতে পারে। <Cite n={1} />

`--permission-prompts none` permission host-কে জিজ্ঞেস না করেই prompt deny করে এবং Claude-কে retry না করতে বলে। <Cite n={1} /> এর জন্য Claude Code v2.1.259 বা তার পরের version লাগে। <Cite n={2} /> `--dangerously-skip-permissions` আর `--permission-mode bypassPermissions` একই। <Cite n={2} /> এটি শুধু container, VM অথবা sandbox runtime-এর ভেতরে ব্যবহার করুন। Linux এবং macOS-এ Claude Code একটি non-root user হিসেবে চালান। <Cite n={4} />

</Bangla>
</Voices>

## Limits and budgets

<Voices>
<Technical>

| Flag | What it does |
|---|---|
| `--max-turns <n>` | Limits the number of agentic turns, in print mode only. Claude Code exits with an error when it reaches the limit. There is no limit by default. <Cite n={2} /> |
| `--max-budget-usd <amount>` | Stops the run once the estimated spend on API calls reaches the amount, in print mode only. <Cite n={2} /> |

- `--max-budget-usd` uses the client-side cost estimate, which can differ from your bill. Spend from subagents counts. Spend can pass the cap, so leave headroom. <Cite n={2} />
- Your `claude --help` output may not show `--max-turns`. The CLI reference documents it, and `--help` does not list every flag. <Cite n={2} /> At the limit, Claude Code exits with an error. The CLI reference gives no specific exit code for this case. <Cite n={2} />
- The GitLab CI/CD docs advise appropriate `--max-turns` and job `timeout` values. <Cite n={5} />
- If you stop a `claude -p` run with SIGTERM, Claude Code exits with code 143 and leaves the current turn unfinished. To end the turn first, send SIGINT. <Cite n={1} />

Example: cap one triage run.

```bash
claude --bare -p "Explain why the checkout tests failed" --permission-mode dontAsk --max-turns 5 --max-budget-usd 1.00
```

</Technical>
<Layman>

`--max-turns` sets a limit on the number of agentic turns. When Claude Code gets to the limit, it exits with an error. By default, there is no limit. `--max-budget-usd` stops the run when the estimated spend on API calls gets to the amount. Both flags work only in print mode. <Cite n={2} />

The budget uses a cost estimate, which can be different from your bill. Spend from subagents counts. The spend can go above the limit, so leave some space. <Cite n={2} />

Your `claude --help` output may not show `--max-turns`, but the CLI reference documents it. The CLI reference gives no specific exit code for the turn limit. <Cite n={2} /> The GitLab CI/CD docs advise appropriate `--max-turns` and job `timeout` values. <Cite n={5} />

If you stop a run with SIGTERM, Claude Code exits with code 143, and the current turn does not finish. To end the turn first, send SIGINT. <Cite n={1} />

</Layman>
<Bangla>

`--max-turns <n>` agentic turn-এর সংখ্যা সীমিত করে। সীমায় পৌঁছালে Claude Code একটি error দিয়ে exit করে। Default-এ কোনো সীমা নেই। `--max-budget-usd <amount>` API call-এর estimated খরচ ওই amount-এ পৌঁছালে run থামিয়ে দেয়। দুটি flag-ই শুধু print mode-এ কাজ করে। <Cite n={2} />

`--max-budget-usd` client-side cost estimate ব্যবহার করে, যা আপনার bill-এর সাথে না-ও মিলতে পারে। Subagent-এর খরচও গোনা হয়। খরচ cap ছাড়িয়ে যেতে পারে, তাই কিছুটা headroom রাখুন। <Cite n={2} />

আপনার `claude --help` output-এ `--max-turns` না-ও থাকতে পারে, কিন্তু CLI reference এটি document করে। এই ক্ষেত্রের জন্য CLI reference কোনো নির্দিষ্ট exit code দেয় না। <Cite n={2} /> GitLab CI/CD docs উপযুক্ত `--max-turns` এবং job `timeout` value দেওয়ার পরামর্শ দেয়। <Cite n={5} />

SIGTERM দিয়ে একটি `claude -p` run থামালে Claude Code code 143 দিয়ে exit করে এবং চলতি turn অসম্পূর্ণ থাকে। আগে turn শেষ করতে চাইলে SIGINT পাঠান। <Cite n={1} />

</Bangla>
</Voices>

## Sessions in scripts

<Voices>
<Technical>

- `--continue` (`-c`) continues the most recent conversation in the current directory. With `-p`, it includes `-p` and SDK sessions. <Cite n={1} /> <Cite n={2} />
- `--resume` (`-r`) resumes a session by its ID or name. <Cite n={2} /> Since v2.1.223, Claude Code finds a session ID in any project on the machine. <Cite n={1} />
- `--fork-session`, with `--resume` or `--continue`, creates a new session ID instead of reusing the original. <Cite n={2} />
- `--no-session-persistence` does not save the session, so you cannot resume it. It works in print mode only. <Cite n={2} />

The docs capture the session ID from JSON output and resume it: <Cite n={1} />

```bash
session_id=$(claude -p "Start a review" --output-format json | jq -r '.session_id')
claude -p "Continue that review" --resume "$session_id"
```

Example for QA: the first call triages the failures, and the second call asks for a fix plan in the same session, so Claude does not read the log again.

</Technical>
<Layman>

`--continue` (`-c`) continues the most recent conversation in the current directory. With `-p`, this includes `-p` and SDK sessions. <Cite n={1} /> <Cite n={2} /> `--resume` (`-r`) resumes a session from its ID or name. <Cite n={2} /> Since v2.1.223, Claude Code finds a session ID in any project on the machine. <Cite n={1} />

With `--resume` or `--continue`, `--fork-session` makes a new session ID. It does not use the original ID again. `--no-session-persistence` does not save the session, so you cannot resume it. It works only in print mode. <Cite n={2} />

In a script, get the session ID from the JSON output. Then give the ID to `--resume`. <Cite n={1} /> For QA, the first call triages the failures. The second call asks for a fix plan in the same session, so Claude does not read the log again.

</Layman>
<Bangla>

`--continue` (`-c`) current directory-র সবচেয়ে সাম্প্রতিক conversation চালিয়ে যায়। `-p`-এর সাথে এতে `-p` এবং SDK session-ও থাকে। <Cite n={1} /> <Cite n={2} /> `--resume` (`-r`) ID অথবা নাম দিয়ে একটি session resume করে। <Cite n={2} /> v2.1.223 থেকে Claude Code মেশিনের যেকোনো project-এ একটি session ID খুঁজে পায়। <Cite n={1} />

`--resume` অথবা `--continue`-এর সাথে `--fork-session` দিলে আগের session ID আবার ব্যবহার না করে একটি নতুন session ID তৈরি হয়। `--no-session-persistence` session save করে না, তাই পরে resume করা যায় না। এটি শুধু print mode-এ কাজ করে। <Cite n={2} />

Script-এ JSON output থেকে session ID নিন, তারপর `--resume` দিয়ে সেই session resume করুন। <Cite n={1} /> QA-র জন্য প্রথম call failure-গুলো triage করে, আর দ্বিতীয় call একই session-এ একটি fix plan চায়। তাই Claude-কে log আবার পড়তে হয় না।

## Authenticate in CI

<Voices>
<Technical>

| Method | How | Notes |
|---|---|---|
| API key | Set `ANTHROPIC_API_KEY` in the job environment. | In `-p` mode, Claude Code always uses the key when it is present. <Cite n={6} /> |
| Subscription token | Run `claude setup-token` on your machine, and store the token as the `CLAUDE_CODE_OAUTH_TOKEN` secret. | The token is valid for one year. The command prints it and does not save it. <Cite n={6} /> |

- `claude setup-token` needs a Pro, Max, Team, or Enterprise plan. <Cite n={6} />
- The setup-token token can only make model requests. It cannot start Remote Control sessions or fetch claude.ai connectors. MCP servers that you configure locally still work. <Cite n={6} />
- Bare mode does not read `CLAUDE_CODE_OAUTH_TOKEN`. If your job passes `--bare`, use `ANTHROPIC_API_KEY` or an `apiKeyHelper`. <Cite n={6} />
- In the credential order, `ANTHROPIC_API_KEY` ranks above `CLAUDE_CODE_OAUTH_TOKEN`. <Cite n={6} /> Set only one of them in a job.

Store the value as a CI secret, never in the repository. To check the sign-in before the real step, run `claude auth status`. It exits with code 0 if you are signed in and 1 if not. `--text` gives readable output. <Cite n={2} />

```bash
claude auth status --text
```

The [Install Claude Code](/getting-started/setup/) page covers sign-in on your own machine.

</Technical>
<Layman>

You can sign in from CI in two ways: <Cite n={6} />

- API key: set `ANTHROPIC_API_KEY` in the job environment. In `-p` mode, Claude Code always uses this key when it is there.
- Subscription token: run `claude setup-token` on your computer. Keep the token as the `CLAUDE_CODE_OAUTH_TOKEN` secret. The token is valid for one year. The command shows the token, but it does not save it. You need a Pro, Max, Team, or Enterprise plan.

The token can only make model requests. Bare mode does not read `CLAUDE_CODE_OAUTH_TOKEN`, so with `--bare`, use `ANTHROPIC_API_KEY` or an `apiKeyHelper`. `ANTHROPIC_API_KEY` comes before `CLAUDE_CODE_OAUTH_TOKEN` in the credential order. <Cite n={6} /> Set only one of the two in a job.

Keep the value as a CI secret. Do not put it in the repository. Before the real step, run `claude auth status` to check the sign-in. It exits with code 0 if you are signed in, and 1 if you are not. <Cite n={2} />

</Layman>
<Bangla>

CI-তে sign in করার দুটি উপায় আছে: <Cite n={6} />

- API key: job environment-এ `ANTHROPIC_API_KEY` set করুন। `-p` mode-এ key থাকলে Claude Code সবসময় সেটিই ব্যবহার করে।
- Subscription token: নিজের মেশিনে `claude setup-token` চালান, আর token-টি `CLAUDE_CODE_OAUTH_TOKEN` secret হিসেবে রাখুন। Token এক বছর valid থাকে। Command-টি token print করে, কিন্তু save করে না। এর জন্য Pro, Max, Team অথবা Enterprise plan লাগে।

Setup-token-এর token শুধু model request করতে পারে। এটি Remote Control session শুরু করতে বা claude.ai connector আনতে পারে না, তবে locally configure করা MCP server কাজ করে। Bare mode `CLAUDE_CODE_OAUTH_TOKEN` পড়ে না, তাই `--bare` দিলে `ANTHROPIC_API_KEY` অথবা একটি `apiKeyHelper` ব্যবহার করুন। Credential order-এ `ANTHROPIC_API_KEY`-এর স্থান `CLAUDE_CODE_OAUTH_TOKEN`-এর উপরে। <Cite n={6} /> একটি job-এ এদের মধ্যে শুধু একটি set করুন।

Value-টি CI secret হিসেবে রাখুন, কখনো repository-তে নয়। আসল step-এর আগে sign-in check করতে `claude auth status` চালান। Sign in করা থাকলে এটি code 0 দিয়ে exit করে, না থাকলে 1 দিয়ে। `--text` পড়ার মতো output দেয়। <Cite n={2} />

</Bangla>
</Voices>
