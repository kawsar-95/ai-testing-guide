# Thresholds

A check marks one response as good or bad, but it does not decide if the test passed. A threshold does. It is a limit on a metric, and k6 fails the whole test when the limit is broken.

<PageMeta />

## What a threshold is

<Voices>
<Technical>

A threshold is a pass/fail rule for a metric. If the system under test breaks a rule, the test ends with a failed status <Cite n={1} />. Testers often use thresholds to codify their SLOs <Cite n={1} />. For example: "99% of requests finish in under 500 ms" or "less than 1% of requests fail".

You set a threshold in the `thresholds` property of `options`. The key is the name of a metric. The value is a list of expressions <Cite n={1} />. An expression gives true or false. If it is false when the test ends, k6 marks the whole test as failed <Cite n={1} />.

When all thresholds pass, k6 exits with code 0. When one fails, the exit code is not 0 <Cite n={1} />. The code is 99 <Cite n={2} />. Tutorial's own view: a CI job reads this exit code, so a failed threshold fails the job.

</Technical>

আপনি `options`-এর `thresholds`-এ threshold লেখেন। key হলো একটা metric-এর নাম। value হলো expression-এর তালিকা <Cite n={1} />। expression true অথবা false হয়। টেস্ট শেষে false হলে k6 পুরো টেস্ট fail ধরে <Cite n={1} />।

## The owner's example

<Voices>
<Technical>

This script is from the tutorial owner's practice project. It ramps the load with `stages` and sets two thresholds <Cite n={3} />. The target was a local app at `http://localhost:3000`.

```javascript
import http from 'k6/http';
import { check, sleep } from 'k6';

export const options = {
  stages: [
    { duration: '10s', target: 50 }, // ramp up from 0 to 50 VUs in 10 seconds
    { duration: '30s', target: 200 }, // ramp up from 50 to 200 VUs in 30 seconds
    { duration: '20s', target: 0 }, // ramp down to 0 VUs in 20 seconds
  ],
  thresholds: {
    // 99% of requests must finish in under 500 ms
    http_req_duration: ['p(99)<500'],
    // fewer than 1% of requests may fail
    http_req_failed: ['rate<0.01'],
  },
};

export default function () {
  const res = http.get('http://localhost:3000');

  check(res, {
    'status is 200': (r) => r.status === 200,
    'response time < 500ms': (r) => r.timings.duration < 500,
  });

  sleep(1);
}
```

The first threshold is `http_req_duration: ['p(99)<500']`. It means that 99% of requests must finish in under 500 ms. The second is `http_req_failed: ['rate<0.01']`. It means that fewer than 1% of requests may fail <Cite n={1} />.

The stages need a careful reading. The first stage ramps from 0 to 50 VUs in 10 seconds. The second stage ramps from 50 to 200 VUs in 30 seconds. It does not hold 200 VUs for 30 seconds. The third stage ramps from 200 to 0 in 20 seconds. Each stage names a VU target and a time to reach it <Cite n={3} />. The whole run is 1 minute.

The output below is one run on the owner's own machine, against a local app. Your numbers will differ.


## Threshold syntax by metric type

<Voices>
<Technical>

An expression has this format: `<aggregation_method> <operator> <value>` <Cite n={1} />. Examples are `avg < 200`, `count >= 500`, and `p(90) < 300`. The aggregation method depends on the type of the metric <Cite n={1} />:

| Metric type | Aggregation methods |
| --- | --- |
| Trend | `p(N)`, `avg`, `med`, `min`, `max` |
| Rate | `rate` |
| Gauge | `value` |
| Counter | `rate`, `count` |

In `p(N)`, N is a percentile between 0.0 and 100, for example `p(99.99)`. Trend values are in milliseconds. A percentile outside 0 to 100 fails parsing, and the test stops before it runs <Cite n={1} />.

This script has one threshold for each type. The names `errors`, `content_size`, `content_ok`, and `rtt` are custom metrics. The page on custom metrics explains how to create them.

```javascript
import http from 'k6/http';
import { Counter, Gauge, Rate, Trend } from 'k6/metrics';
import { sleep } from 'k6';

const errors = new Counter('errors');
const contentSize = new Gauge('content_size');
const contentOk = new Rate('content_ok');
const rtt = new Trend('rtt');

export const options = {
  thresholds: {
    errors: ['count<100'], // Counter
    content_size: ['value<4000'], // Gauge
    content_ok: ['rate>0.95'], // Rate
    rtt: ['p(99)<300', 'avg<200', 'med<150', 'min<100'], // Trend
  },
};

export default function () {
  const res = http.get('https://quickpizza.grafana.com/api/json?name=Bert');
  const ok = res.json('name') === 'Bert';
  rtt.add(res.timings.duration);
  contentOk.add(ok);
  contentSize.add(res.body.length);
  errors.add(!ok);
  sleep(1);
}
```

You can give one metric more than one threshold. Put all expressions in one array: `http_req_duration: ['p(50) < 300', 'p(95) < 900']` <Cite n={1} />. Do not repeat the same key in the `thresholds` object. k6 silently ignores the extra keys <Cite n={1} />.

<Callout type="warning" title="Check the key">

If you repeat a key, only one threshold counts, and k6 does not warn you. A test that looks strict can then pass with a weaker limit. Use one key and an array.

</Callout>

The long format puts a threshold in an object. It has the extra properties of the next sections <Cite n={1} />. The short format is a plain string.

</Technical>

## Fail a test with checks

<Voices>
<Technical>

A failed check never changes the exit status of k6 <Cite n={1} />. If you use only checks, a test with failed checks still exits with code 0. To fail the run, put a threshold on the built-in `checks` metric <Cite n={1} />.

```javascript
import http from 'k6/http';
import { check, sleep } from 'k6';

export const options = {
  vus: 3,
  duration: '5s',
  thresholds: {
    // the rate of passed checks must be above 90%
    checks: ['rate>0.9'],
  },
};

export default function () {
  const res = http.get('https://quickpizza.grafana.com/api/status/500');
  check(res, {
    'status is 200': (r) => r.status === 200,
  });
  sleep(1);
}
```

Here `checks: ['rate>0.9']` means that more than 90% of the checks must pass <Cite n={1} />. The endpoint returns status 500, so every check fails. The rate is 0%, the threshold fails, and k6 exits with code 99 <Cite n={2} />.

To limit one check or one group of checks, add a tag to the check and use it in the key: `'checks{myTag:hola}': ['rate>0.9']` <Cite n={1} />.

</Technical>

## Thresholds on tags and groups

<Voices>
<Technical>

A tagged request creates a sub-metric. You can set a threshold on it with the key `metric_name{tag_name:tag_value}` <Cite n={1} />. This is useful when one test calls different kinds of endpoints and each kind has its own limit. The next page, [Tags and Groups](/k6/tags-and-groups/), explains tags in detail.

```javascript
import http from 'k6/http';
import { sleep } from 'k6';

export const options = {
  vus: 2,
  duration: '5s',
  thresholds: {
    'http_req_duration{type:API}': ['p(95)<500'],
    'http_req_duration{type:static}': ['p(95)<200'],
  },
};

export default function () {
  http.get('https://quickpizza.grafana.com/api/json', { tags: { type: 'API' } });
  http.get('https://quickpizza.grafana.com/favicon.ico', { tags: { type: 'static' } });
  sleep(1);
}
```

The first threshold applies only to requests with the tag `type:API`. The second applies only to requests with the tag `type:static` <Cite n={1} />.

For a group, use the metric `group_duration` and the tag `group` with three colons: `'group_duration{group:::individualRequests}': ['avg < 400']` <Cite n={1} />.

In `dmoney-transactions.k6.js`, one loop adds a `p(95)` threshold, a failure-rate threshold, and a check-rate threshold for each API, for example `http_req_duration{api:deposit}`. This is the tutorial's own example project, not an official source.

</Callout>

## Abort a test when a threshold fails

<Voices>
<Technical>

By default, k6 judges thresholds at the end of the test. To stop the test as soon as a threshold fails, use the long format and set `abortOnFail` to `true` <Cite n={1} />.

A test can fail a threshold in the first seconds, before it has enough data. To avoid this, add `delayAbortEval`. It delays the evaluation, so k6 can collect samples first. The value is a relative time string, such as `10s` or `1m` <Cite n={1} />.

```javascript
import http from 'k6/http';
import { sleep } from 'k6';

export const options = {
  vus: 3,
  duration: '30s',
  thresholds: {
    http_req_duration: [
      {
        threshold: 'p(99)<1', // impossible on purpose
        abortOnFail: true,
        delayAbortEval: '5s', // wait 5 seconds before the first check of the limit
      },
    ],
  },
};

export default function () {
  http.get('https://quickpizza.grafana.com');
  sleep(1);
}
```

This script has an impossible limit on purpose. After 5 seconds, k6 evaluates the threshold, sees that it fails, and stops the test. The run does not last 30 seconds. k6 still exits with code 99 <Cite n={2} />.

| Property | Type | Meaning |
| --- | --- | --- |
| `threshold` | string | The expression to evaluate. |
| `abortOnFail` | boolean | Abort the test if the threshold fails before the test ends. |
| `delayAbortEval` | string | How long to wait before the first evaluation. |

<Callout type="note">

When k6 runs in the cloud, it evaluates thresholds every 60 seconds. So `abortOnFail` can be late by up to 60 seconds <Cite n={1} />.

</Callout>

Tutorial advice: use `abortOnFail` for a limit that, once broken, makes the rest of the run useless, such as a very high error rate. It saves time and load on a shared environment.

</Technical>

## Key words

| Term | Meaning |
| --- | --- |
| Threshold | A pass/fail limit on a metric. A failed threshold fails the test. |
| Expression | The limit as text, in the format `<aggregation_method> <operator> <value>`, such as `p(95)<200`. |
| Aggregation method | How k6 sums up the samples of a metric: `count`, `rate`, `value`, `avg`, `min`, `max`, `med`, or `p(N)`. |
| Percentile (`p(N)`) | The value below which N% of the samples fall. `p(99)<500` means 99% are under 500. |
| Sub-metric | A metric filtered by a tag, written `metric{tag:value}`. A threshold can use it. |
| `abortOnFail` | A long-format property that stops the test as soon as the threshold fails. |
| `delayAbortEval` | A long-format property that delays the evaluation of `abortOnFail`. |
| Exit code 99 | The code that k6 returns when one or more thresholds fail. |
| SLO | A service level objective: a target for the quality of a service, such as "99% of requests under 500 ms". |
