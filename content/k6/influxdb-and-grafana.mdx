# Live Results with InfluxDB and Grafana

The summary at the end of a k6 run shows the result only after the test stops. With InfluxDB and Grafana you watch the numbers move while the test runs.

<PageMeta />

## Why use InfluxDB and Grafana

<Voices>
<Technical>

A load test is more useful when you can see how the system behaves while the load runs. You want to see the request rate, the response time, and the error rate as lines on a graph. A graph shows when the system turns slow, and whether an error spike comes with it.

Two tools do this job together. **InfluxDB** is a time-series database: it stores values together with the time of each value. k6 writes its metrics into it. **Grafana** is a dashboard tool: it reads the data and draws the graphs. k6 has built-in support for sending metrics to InfluxDB v1 <Cite n={1} />. Grafana can query and show data from an InfluxDB instance <Cite n={1} />.

```text
k6 (runs the test)
  |  --out influxdb=http://localhost:8086/k6
  v
InfluxDB (stores the metrics, port 8086)
  ^
  |  Grafana asks InfluxDB for the data
Grafana (draws the dashboard, port 3000)
```

This page uses InfluxDB 1.x, because k6 supports it without any extra software <Cite n={1} />. The owner of this tutorial also likes this setup because it needs no plugin, unlike a JMeter setup. That is the tutorial's own view.

</Technical>

## The three InfluxDB versions

<Voices>
<Technical>

InfluxDB has three main versions. They are not the same product, and the k6 setup is different for each.

| Version | Current release | Main ideas | How k6 connects |
| --- | --- | --- | --- |
| 1.x | 1.13 (Docker tags `1.13` and `1.13.1`) <Cite n={3} /> <Cite n={5} /> | Databases, and the InfluxQL query language <Cite n={14} /> | Built into k6 <Cite n={1} /> |
| 2.x | 2.9.1 <Cite n={4} /> | Buckets, organizations, and API tokens <Cite n={1} /> <Cite n={14} /> | The xk6-output-influxdb extension <Cite n={1} /> |
| 3.x | Docker tags `3-core` and `3-enterprise`, currently 3.12.1 <Cite n={5} /> | The InfluxDB 3 Core product is the latest stable version <Cite n={3} /> | Not covered by this page |

A bucket in 2.x and 3.x is the same idea as a database in 1.x <Cite n={14} />. The version numbers change often, so read the current numbers on the release notes pages of InfluxData <Cite n={3} /> <Cite n={4} />.

For InfluxDB v2, k6 needs a custom k6 binary that you build with the **xk6** tool and the extension <Cite n={1} />. The k6 team made a separate extension, because v2 has breaking changes in its API <Cite n={2} />. This page installs only InfluxDB 1.x, because it needs no extension.

Do not use the Docker tag `latest` for InfluxDB. The InfluxData docs warn that this tag can change to a different major version, and tell you to use a specific version tag <Cite n={4} />. Use a tag such as `influxdb:1.13`.

</Technical>

## Run InfluxDB 1.x with Docker

<Voices>
<Technical>

Docker is the simplest way to run InfluxDB. Check that Docker is installed, then start the container. The InfluxData Docker guide shows a named volume and the port `8086` <Cite n={6} />:

```bash
docker --version
docker network create k6net
docker run -d --name influxdb --network k6net -p 8086:8086 -v influxdb-data:/var/lib/influxdb influxdb:1.13
```

`docker network create k6net` makes a user-defined Docker network. Grafana will join it later, so that it can reach this container by its name <Cite n={17} />. This network is the tutorial's own addition to the InfluxData command. `-p 8086:8086` makes InfluxDB reachable on port `8086` of your machine <Cite n={6} />. The named volume `influxdb-data` keeps the data when the container stops. On macOS with Docker Desktop, use a named volume or a delegated directory. A bind-mounted directory must belong to user and group ID 1500 <Cite n={6} />.

The owner of this tutorial used the tag `influxdb:1.8`. That tag still exists, but the Docker Hub list of supported tags now starts at `1.11`, and the newest is `1.13` <Cite n={5} />. Use `1.13`. The InfluxData guide pulls `influxdb:1.13.0`; a minor tag such as `1.13` follows the newest `1.13.x` patch <Cite n={5} /> <Cite n={6} />.

Check that the container runs, then open the InfluxDB shell in it <Cite n={6} />:

```bash
docker ps
docker exec -it influxdb influx
```

In the shell, you can create a database by hand. This step is not required for k6, because k6 creates a missing database on its own <Cite n={1} />. It is a good way to learn how InfluxDB works. `CREATE DATABASE` is an InfluxQL command <Cite n={8} />, and `SHOW DATABASES` lists the databases <Cite n={9} />:

```text
CREATE DATABASE k6
SHOW DATABASES
```

Then write one test point. A point is written in **line protocol**: the measurement name, then the tag set, then the field set, and an optional timestamp <Cite n={10} />. The shell command `INSERT` takes a point in this form <Cite n={10} />:

```text
INSERT response_time,api=login value=250
SELECT * FROM response_time
```

Here `response_time` is the measurement, `api=login` is a tag, and `value=250` is a field. The query returns the point with its time.

</Technical>

## Send k6 data to InfluxDB

<Voices>
<Technical>

This script runs 50 iterations with 2 VUs. After each request it sleeps for one second. It targets the public demo app QuickPizza:

```javascript
import http from 'k6/http';
import { sleep } from 'k6';

export const options = {
  vus: 2,
  iterations: 50,
};

export default function () {
  http.get('https://quickpizza.grafana.com/');
  // One second of think time keeps the load low and the graph readable.
  sleep(1);
}
```

Run it with the `--out` flag and the InfluxDB address. The last part of the URL is the database name <Cite n={1} />:

```bash
k6 run --out influxdb=http://localhost:8086/k6 first-script.js
```

k6 connects to the local InfluxDB and sends the results of the test to the database `k6`. If the database does not exist, k6 creates it <Cite n={1} />. k6 takes the last segment of the URL path as the database name. A URL that ends with a slash does not name a database, and k6 then uses the default database `k6` <Cite n={1} />.

Now look at the data. Open the InfluxDB shell on the database, and list the measurements <Cite n={7} /> <Cite n={9} />:

```bash
docker exec -it influxdb influx -database k6
```

```text
SHOW MEASUREMENTS
```

In the owner's run, the list had one measurement for each k6 metric. Part of it is shown here. This output is the owner's own result; it is not from a source:

```text
name: measurements
name
----
data_received
data_sent
http_req_duration
http_req_failed
http_reqs
iteration_duration
iterations
vus
vus_max
```

The database name is `k6` in lower case. The owner's notes wrote it in capital letters in one step. Use the same lower-case spelling in the URL, in the shell, and later in Grafana.

</Technical>
<Layman>

This script uses 2 VUs and makes 50 iterations. It waits one second after each request. It calls the public demo app QuickPizza:

## Run Grafana

<Voices>
<Technical>

Grafana runs on Linux (Debian, Ubuntu, RHEL, Fedora, and SUSE families), macOS, and Windows. It also runs in Docker <Cite n={11} />. The install steps differ for each system, and they change between releases. Follow the guide for your system on the Grafana install page, and do not copy a fixed file name from an old tutorial <Cite n={11} />.

Docker is the simplest way here, because you already use it for InfluxDB. The Grafana guide gives this command <Cite n={12} />. The tutorial adds `--network k6net`:

```bash
docker run -d -p 3000:3000 --name=grafana --network k6net grafana/grafana-enterprise
```

`-d` runs the container in the background. `-p 3000:3000` makes Grafana reachable on port `3000` of your machine <Cite n={12} />. The Enterprise image is free, and it has all the features of the open-source edition <Cite n={12} />. If you want the open-source image by name, use `grafana/grafana`. The older repository `grafana/grafana-oss` is not updated from Grafana 12.4.0 <Cite n={12} />.

Open `http://localhost:3000` in a browser. The first sign-in uses `admin` as the user name and as the password. Grafana then asks you to change the password. Grafana strongly recommends that you change it <Cite n={13} />.

A Grafana container and an InfluxDB container are separate. Inside the Grafana container, `localhost` means the Grafana container itself, not your machine. So Grafana cannot reach InfluxDB at `http://localhost:8086`. On a user-defined bridge network, containers resolve each other by name <Cite n={17} />. Both `docker run` commands above use the network `k6net`, so Grafana reaches InfluxDB at `http://influxdb:8086`. That is the container name and the port. The k6 command still runs on your machine, so it keeps `http://localhost:8086/k6`. The network is the tutorial's own setup.

On Docker Desktop, a container can also reach a service on the host with the special name `host.docker.internal` <Cite n={18} />. This name is for Docker Desktop. The owner's screenshots show Grafana that runs on the host, so they show `http://localhost:8086`.

## Key words

| Term | Meaning |
| --- | --- |
| InfluxDB | A time-series database. It stores values with their time. k6 can write its metrics to it. |
| Time series | A list of values, each with a time. A graph of response time over a test is one. |
| Database (InfluxDB 1.x) | The place where InfluxDB 1.x keeps data. In this page it is `k6`. |
| Bucket | The InfluxDB 2.x and 3.x name for a place that stores data. It matches a database in 1.x. |
| Measurement | A group of values in InfluxDB. k6 writes one measurement for each metric, such as `http_reqs`. |
| Tag and field | Parts of a point. A tag is a label such as `api=login`. A field is a value such as `value=250`. |
| InfluxQL | The SQL-like query language of InfluxDB. Grafana uses it for InfluxDB 1.x. |
| Line protocol | The text form of a point: measurement, tag set, field set, and timestamp. |
| xk6 | A tool that builds a custom k6 binary with extensions. InfluxDB v2 output needs it. |
| Grafana | A dashboard tool. It reads data from a data source and draws graphs. |
| Data source | A saved connection in Grafana to a place that holds data, such as InfluxDB. |
| Dashboard | A page of panels in Grafana. Each panel shows the result of one query. |
