# Tags and Groups

Label requests so that you can split the results.

<PageMeta />

## Calling more than one URL

<Voices>
<Technical>

A real test often calls more than one endpoint. This script calls two endpoints of `https://quickpizza.grafana.com` in each iteration and checks both.

```javascript
import http from 'k6/http';
import { check, sleep } from 'k6';

export const options = {
  vus: 10,
  duration: '5s',
  thresholds: {
    http_req_duration: ['p(95)<1000'],
  },
};

export default function () {
  // Call the first API
  const quotesRes = http.get('https://quickpizza.grafana.com/api/quotes');
  check(quotesRes, { 'quotes request successful': (r) => r.status === 200 });

  // Call the second API
  const headersRes = http.get('https://quickpizza.grafana.com/api/headers');
  check(headersRes, { 'headers request successful': (r) => r.status === 200 });

  sleep(1);
}
```

k6 shows one `http_req_duration` line for both requests. The line is a mix of the two. It cannot tell you which endpoint is slow. Tags and groups fix this.

This is the output of the owner's own run of the same kind of script. The owner called another host, `jsonplaceholder.typicode.com`, which this page no longer uses. The numbers are one run on one machine. They are not a k6 fact, and your run gives other numbers.

  █ TOTAL RESULTS

The `p(95)` of 769.76 ms covers all 72 requests together. The output does not show which of the two endpoints caused it.

<Callout type="warning" title="A common mistake: the same key twice in thresholds">

The owner's first script had the same key two times in the `thresholds` object. This is not an error, and k6 gives no warning <Cite n={3} />. In a JavaScript object, a second property with the same name replaces the first one <Cite n={6} />. So k6 sees only one threshold. If the two limits differ, only the last one counts:

```javascript
import http from 'k6/http';

export const options = {
  thresholds: {
    'http_req_duration': ['p(95)<1000'],
    'http_req_duration': ['p(95)<500'],
  },
};

export default function () {
  http.get('https://quickpizza.grafana.com/api/quotes');
}
```

`k6 inspect` on this script lists only `p(95)<500` for `http_req_duration`. The `p(95)<1000` limit is gone. To give one metric more than one limit, put all expressions in the same array, for example `['p(95)<1000', 'p(99)<1500']` <Cite n={3} />.

</Callout>

## Tags

<Voices>
<Technical>

A **tag** is a key-value pair. You use tags to label requests, checks, thresholds, and custom metrics, so that you can filter the results <Cite n={1} />. k6 has two kinds of tags <Cite n={1} />:

| Kind | Who sets it | Examples |
| --- | --- | --- |
| System tags | k6 sets them for you | `proto`, `status`, `method`, `url`, `name`, `group`, `check`, `error`, `scenario`, `expected_response` <Cite n={1} /> |
| User-defined tags | You set them in the script | `endpoint: 'quotes'` |

Some system tags are off by default and you can turn them on: `vu`, `iter`, `ip`, and `ocsp_status` <Cite n={1} />. The `systemTags` option turns off some system tags <Cite n={1} />.

You add a tag to a request with the `tags` field of the request parameters. A tag on a request becomes a filter. The key of a threshold can name a metric and a tag in braces, as in `http_req_duration{endpoint:quotes}`. k6 makes one sub-metric for each tagged value <Cite n={3} />. A threshold on a sub-metric limits only the requests with that tag <Cite n={1} />.

The same script as above, with one tag for each endpoint:

```javascript
import http from 'k6/http';
import { check, sleep } from 'k6';

export const options = {
  vus: 10,
  duration: '5s',
  thresholds: {
    'http_req_duration{endpoint:quotes}': ['p(95)<1000'],
    'http_req_duration{endpoint:headers}': ['p(95)<1000'],
  },
};

export default function () {
  const quotesRes = http.get('https://quickpizza.grafana.com/api/quotes', {
    tags: { endpoint: 'quotes' },
  });
  check(quotesRes, { 'quotes request successful': (r) => r.status === 200 });

  const headersRes = http.get('https://quickpizza.grafana.com/api/headers', {
    tags: { endpoint: 'headers' },
  });
  check(headersRes, { 'headers request successful': (r) => r.status === 200 });

  sleep(1);
}
```

You can also tag a check and a custom metric value. The third argument of `check()` takes tags, and the `add()` method of a custom metric takes tags as its second argument <Cite n={1} />.

This is the output of the owner's own run against the old host `jsonplaceholder.typicode.com`. It is one run on one machine, so the numbers are examples only. Each tagged request now has its own line:

    ✓ 'p(95)<1000' p(95)=166.59ms

    http_req_duration{endpoint:listData}
    ✓ 'p(95)<1000' p(95)=188.02ms

  █ TOTAL RESULTS

    http_req_duration..............: avg=248.87ms min=8.63ms  med=164.89ms max=8.22s    p(90)=187.18ms p(95)=187.67ms

The first line is the mix of all requests. The two lines with `endpoint` show each endpoint alone. The line `{ expected_response:true }` is a system tag that k6 added itself <Cite n={1} />.

**Test-wide tags** go on every metric of the run. You can set them with the `--tag NAME=VALUE` flag, with the `K6_TAGS` environment variable (`K6_TAGS=name:value,other:value`), in the `tags` key of `options`, or in a JSON config file <Cite n={1} />:

```javascript
export const options = {
  tags: { testid: 'tags-demo' },
};
```

These tags help you compare the results of different runs <Cite n={1} />. By default, k6 does not merge test-wide tags from more than one source. The source with the highest order of precedence replaces all the tags of the lower ones <Cite n={1} />. The `merge-run-tags` feature flag changes this <Cite n={1} />.

## The name tag for dynamic URLs

<Voices>
<Technical>

By default, the `name` tag holds the URL of the request <Cite n={2} />. This is a problem when the URL has a changing part, such as an ID. Each ID gives a different `name`, and the metrics stream gets a large number of unique URLs <Cite n={2} />. The results are then hard to read.

To collect all these requests under one name, set the `name` tag yourself <Cite n={2} />. You can also use the `http.url` template tag, which sets the `name` tag to the template with the value left out <Cite n={2} />. This is called URL grouping. The script below makes the same three calls in two ways. The first call uses `http.url`. The second call sets `tags.name`.

```javascript
import http from 'k6/http';

export const options = {
  tags: { testid: 'tags-demo' },
};

export default function () {
  for (const code of [200, 201, 202]) {
    // One sub-metric for all three URLs
    http.get(http.url`https://quickpizza.grafana.com/api/status/${code}`);
    // The same effect with an explicit name tag
    http.get(`https://quickpizza.grafana.com/api/status/${code}`, {
      tags: { name: 'StatusURL' },
    });
  }
}
```

In a local test run, the `http.url` calls got the `name` value `https://quickpizza.grafana.com/api/status/${}`, and the other calls got `StatusURL`. Each name had 3 data points, not one name for each status code. You can then use `http_req_duration{name:StatusURL}` in a threshold.

The k6 docs also say not to wrap every request in its own group. For dynamic URLs, use URL grouping. For a clear request name, set `tags.name` <Cite n={1} />.

</Technical>

## Groups

<Voices>
<Technical>

A **group** is a way to organize a script by function. You wrap a part of the script in `group(name, fn)` <Cite n={4} />. Groups can be nested <Cite n={1} />. A group does two things <Cite n={1} />:

- k6 emits the `group_duration` metric for each `group()` call. It holds the total time to run the group function.
- Each check, request, or custom metric inside the group gets the tag `group` with the group name.

The value of the `group` tag is the names of all wrapping groups, separated by `::` (two colons). The root group has an empty name. So a single group named `List quotes` has the `group` value `::List quotes` <Cite n={1} />.

This script puts each request in its own group, and adds one threshold on `group_duration`:

```javascript
import http from 'k6/http';
import { check, group, sleep } from 'k6';

export const options = {
  vus: 10,
  duration: '5s',
  thresholds: {
    'http_req_duration{endpoint:quotes}': ['p(95)<1000'],
    'http_req_duration{endpoint:headers}': ['p(95)<1000'],
    'group_duration{group:::List quotes}': ['p(95)<1500'],
  },
};

export default function () {
  group('List quotes', function () {
    const res = http.get('https://quickpizza.grafana.com/api/quotes', {
      tags: { endpoint: 'quotes' },
    });
    check(res, { 'quotes request successful': (r) => r.status === 200 });
  });

  group('Get headers', function () {
    const res = http.get('https://quickpizza.grafana.com/api/headers', {
      tags: { endpoint: 'headers' },
    });
    check(res, { 'headers request successful': (r) => r.status === 200 });
  });

  sleep(1);
}
```

The key `group_duration{group:::List quotes}` has three colons after `group`. The first colon separates the tag name from its value. The last two are the `::` prefix of the group name <Cite n={3} />.

The default summary does not print a section for each group. The `--summary-mode=full` option adds the results of each group and scenario <Cite n={5} />. A group name is just a label of the code. A request tag such as `endpoint` is a label of the request. You can use both, and you can set thresholds on both. Use a group for a user step, such as "log in" or "check out". Use `name` or another tag to tell requests apart.

**Group** হলো স্ক্রিপ্টকে function অনুযায়ী সাজানোর একটা উপায়। স্ক্রিপ্টের একটা অংশ `group(name, fn)`-এর ভেতরে রাখতে হয় <Cite n={4} />। Group nested করা যায় <Cite n={1} />। একটা group দুটো কাজ করে <Cite n={1} />:

- k6 প্রতিটা `group()` কলের জন্য `group_duration` metric পাঠায়। এতে group function চালাতে মোট যত সময় লেগেছে, তা থাকে।
- Group-এর ভেতরের প্রতিটা check, request বা custom metric `group` tag পায়, যার মান group-এর নাম।

`group` tag-এর মান হলো ঘিরে থাকা সব group-এর নাম, `::` (দুটো কোলন) দিয়ে আলাদা করা। Root group-এর নাম ফাঁকা। তাই `List quotes` নামের একটা group-এর `group` মান হয় `::List quotes` <Cite n={1} />।

একটা group-এর threshold key হলো `group_duration{group:::List quotes}`। `group`-এর পরে তিনটা কোলন আছে। প্রথম কোলন tag-এর নাম আর মানকে আলাদা করে। শেষ দুটো হলো group নামের `::` prefix <Cite n={3} />।

ডিফল্ট summary প্রতিটা group-এর জন্য আলাদা অংশ দেখায় না। `--summary-mode=full` option প্রতিটা group আর scenario-র ফলাফল যোগ করে <Cite n={5} />।

Group-এর নাম কোডের একটা লেবেল। `endpoint`-এর মতো request tag হলো request-এর লেবেল। আপনি দুটোই ব্যবহার করতে পারেন, আর দুটোর ওপরেই threshold দিতে পারেন। ব্যবহারকারীর একটা ধাপের জন্য group ব্যবহার করুন, যেমন "log in" বা "check out"। Request আলাদা করতে `name` বা অন্য tag ব্যবহার করুন।

## Key words

| Term | Meaning |
| --- | --- |
| Tag | A key-value label on a request, check, threshold, or custom metric. |
| System tag | A tag that k6 sets for you, such as `status`, `method`, `url`, `name`, and `group`. |
| User-defined tag | A tag that you set in the script, such as `endpoint: 'quotes'`. |
| Test-wide tag | A tag in `options.tags`, `--tag`, or `K6_TAGS`. It goes on every metric of the run. |
| Sub-metric | The part of a metric with one tag value. You name it in braces, as in `http_req_duration{endpoint:quotes}`. |
| `name` tag | The tag that holds the request name. By default it is the URL. |
| URL grouping | Collecting requests with a changing URL under one `name`, with `http.url` or `tags.name`. |
| Group | A named part of the script, set with `group(name, fn)`. It can be nested. |
| `group_duration` | The metric with the total time to run one group function. |
