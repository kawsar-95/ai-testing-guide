# Install k6 and Run Your First Script

Install k6, run a small script, and read the first output.

## Install k6

<Voices>
<Technical>

You can install k6 from a package on Linux, Mac, or Windows. A Docker image and a standalone binary also work <Cite n={1} />. Use the commands for your system.

**Windows.** Two package managers work. The `choco` package is unofficial. The `winget` packages are official, and the community made their manifests <Cite n={1} />.

```text
winget install k6 --source winget
choco install k6
```

You can also download and run the official MSI installer <Cite n={1} />. Use the link on the install page of the docs, so you always get the latest version.

**macOS.** Use Homebrew <Cite n={1} />:

```bash
brew install k6
```

**Linux (Debian or Ubuntu).** Add the k6 signing key and the package repository. Then install <Cite n={1} />:

```bash
curl -fsSL https://dl.k6.io/key.gpg | sudo gpg --dearmor -o /usr/share/keyrings/k6-archive-keyring.gpg
echo "deb [signed-by=/usr/share/keyrings/k6-archive-keyring.gpg] https://dl.k6.io/deb stable main" | sudo tee /etc/apt/sources.list.d/k6.list
sudo apt-get update
sudo apt-get install k6
```

**Linux (Fedora or CentOS).** Use `dnf` <Cite n={1} />:

```bash
sudo dnf install https://dl.k6.io/rpm/repo.rpm
sudo dnf install k6
```

**Docker.** Pull the image <Cite n={1} />:

```bash
docker pull grafana/k6
```

The standalone binary is on the GitHub Releases page. Put the `k6` or `k6.exe` file in your `PATH` <Cite n={1} />. The commands can change, so the install page of the docs is the place to check <Cite n={1} />.

After the install, check that k6 works. This is the tutorial's own tip. The output below is an example, and your version number will differ:

```text
$ k6 version
k6 v<version> (commit/<hash>, go<version>, <os>/<arch>)
```

</Technical>

## Write your first script

<Voices>
<Technical>

Save this script as `first-script.js`. It sends 10 GET requests to the QuickPizza demo site of Grafana. It waits 1 second after each request.

```javascript
// first-script.js
import http from 'k6/http';
import { sleep } from 'k6';

// Run the default function 10 times in total.
export const options = {
  iterations: 10,
};

// k6 calls this function again and again. Each call is one iteration.
export default function () {
  http.get('https://quickpizza.grafana.com');
  // Pause for 1 second, like a real user who reads the page.
  sleep(1);
}
```

The `default` function is the entry point of the test. k6 runs it once for each iteration <Cite n={4} />. The `iterations` option sets the total number of runs of the `default` function in the test <Cite n={5} />. The counter metric `iterations` counts these runs <Cite n={4} />.

The site `quickpizza.grafana.com` is the tutorial's own choice for this first script. The k6 docs use the same site in their examples <Cite n={2} />. Run load tests only against a system that you own or have permission to test. Keep this script small. It sends 10 requests, one at a time.

</Technical>

## Run the script

<Voices>
<Technical>

Open a terminal in the folder of the file. Run <Cite n={2} />:

```bash
k6 run first-script.js
```

With the Docker image, the script file is not inside the container. Tell k6 to read the script from `stdin`. Use `-` as the file name <Cite n={2} />:

```bash
docker run --rm -i grafana/k6 run - <first-script.js
```

When the test ends, k6 prints a summary of the results to `stdout` <Cite n={3} />.

</Technical>

The summary groups the metrics by source: HTTP (protocol) metrics, execution metrics, and network metrics <Cite n={3} />. By default, k6 prints a compact summary with the most important metrics <Cite n={3} />.

| Metric | Meaning |
|---|---|
| `http_reqs` | The total number of HTTP requests that k6 made <Cite n={4} />. |
| `http_req_failed` | The rate of failed requests <Cite n={4} />. Here it is 0 out of 10. |
| `http_req_duration` | The total time of a request: sending, waiting, and receiving. It does not include the DNS lookup and the connection time <Cite n={4} />. |
| `iterations` | How many times the VUs ran the `default` function <Cite n={4} />. Here it is 10. |
| `iteration_duration` | The time of one full iteration <Cite n={4} />. It is longer than `http_req_duration`, because the 1 second of `sleep` is part of the iteration. |
| `vus`, `vus_max` | The current number of active VUs, and the maximum number <Cite n={4} />. Here the run used 1 VU. |
| `data_sent`, `data_received` | The amount of data that k6 sent and received <Cite n={4} />. |

In this run, the average `iteration_duration` (2.35 s) is about 1.7 s more than the average `http_req_duration` (645 ms). One second of the gap is the `sleep`. This output does not show where the rest comes from. The tutorial's own view: do not read one run of 10 requests as a performance result. It only proves that the script and the tools work.

## Key words

| Term | Meaning |
| --- | --- |
| `k6 run` | The command that runs a k6 script. |
| Iteration | One run of the `default` function. |
| `iterations` | The option that sets the total number of runs. It is also a counter metric. |
| VU | A virtual user. It runs the script in a loop. |
| `sleep()` | A pause inside the script. It simulates the think time of a user. |
| End-of-test summary | The result table that k6 prints to `stdout` when the test ends. |
| `http_req_duration` | The time of an HTTP request: sending, waiting, and receiving. |
| `http_req_failed` | The rate of failed HTTP requests. |
| `stdin` | The input stream. `k6 run -` reads the script from it. |
