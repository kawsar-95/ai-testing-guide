# Custom Metrics

The built-in metrics tell you about requests. They do not know your business. A custom metric lets you count or time the thing that matters to you, such as a failed login or the time of one step.

<PageMeta />

## Why you need custom metrics

<Voices>
<Technical>

k6 has built-in metrics for HTTP, such as `http_req_duration`, which gives the time of one request <Cite n={7} />. A custom metric measures something that you define. The module `k6/metrics` creates custom metrics of several types <Cite n={6} />.

Here are two examples:

- The time of one business step, such as "log in, then open the pizza list". One step can use several requests. The built-in `group_duration` times a group <Cite n={8} /> and `iteration_duration` times a full iteration <Cite n={7} />. In the tutorial's own view, a custom `Trend` is simpler when you want one named number for one step.
- The count of failed logins. A login can return a status that the test treats as a failure, and you want a number for it.

This is the tutorial's own view: add a custom metric when you want a threshold or a chart for a number that the built-in metrics do not give.

</Technical>

## The four metric types

<Voices>
<Technical>

k6 has four custom metric types <Cite n={6} />:

| Type | What it does | Threshold variable |
| --- | --- | --- |
| `Counter` | Adds up the values <Cite n={6} />. | `count` or `rate` <Cite n={2} /> |
| `Gauge` | Keeps the latest value. The summary also shows the min and max <Cite n={3} /> <Cite n={6} />. | `value` <Cite n={3} /> |
| `Rate` | Gives the share of values that are not zero, from 0.00 to 1.00 <Cite n={4} />. | `rate` <Cite n={4} /> |
| `Trend` | Gives the min, max, average, median, and percentiles <Cite n={5} />. | `avg`, `min`, `max`, `med`, `p(N)` <Cite n={5} /> |

All four types have the method `add(value, [tags])` <Cite n={2} />. `Gauge` and `Trend` also take a second constructor argument, `isTime`. If it is `true`, k6 treats the values as time values. If it is `false` or missing, the values have no type <Cite n={3} /> <Cite n={5} />.

A `Rate` takes `true`, `false`, `1`, or `0`. Any non-zero value counts as a hit <Cite n={4} />.

</Technical>

## A script with all four

<Voices>
<Technical>

Create each metric in the init context, outside `default` <Cite n={1} />. Then call `add` in the VU code to take a measurement <Cite n={1} />. This script targets the public demo app `quickpizza.grafana.com`. It runs 2 VUs for 5 s.

```javascript
import http from 'k6/http';
import { sleep } from 'k6';
import { Counter, Gauge, Rate, Trend } from 'k6/metrics';

// Create every custom metric in the init context.
const badStatus = new Counter('bad_status_count');
const bodySize = new Gauge('home_body_bytes');
const failedRate = new Rate('failed_requests');
const waiting = new Trend('home_waiting_time', true);

export const options = {
  vus: 2,
  duration: '5s',
  thresholds: {
    bad_status_count: ['count==0'],
    home_body_bytes: ['value>0'],
    failed_requests: ['rate<0.01'],
    home_waiting_time: ['p(95)<1000'],
  },
};

export default function () {
  const res = http.get('https://quickpizza.grafana.com/');
  const failed = res.status >= 400;

  if (failed) {
    badStatus.add(1, { page: 'home' });
  }
  bodySize.add(res.body.length);
  failedRate.add(failed);
  waiting.add(res.timings.waiting);

  sleep(1);
}
```

The `{ page: 'home' }` object is a tag. You can add tags to any value. You can use them to filter results <Cite n={1} />. A tagged value also creates a sub-metric, and a threshold can name it, as in `bad_status_count{page:home}` <Cite n={2} />.

</Technical>

## Thresholds on a custom metric

<Voices>
<Technical>

A threshold on a custom metric works like any other threshold. The key is the metric name. The expression uses the variable of the metric type <Cite n={2} /> <Cite n={3} /> <Cite n={4} /> <Cite n={5} />. The script above has one threshold for each type. See [Thresholds](/k6/thresholds/) for the full syntax.

Keep these points in mind:

- Trend values are in milliseconds, so `p(95)<1000` means 1 s <Cite n={5} />. Pass `true` as the second argument when the values are times <Cite n={5} />.
- A `Rate` goes from 0.00 to 1.00, so `rate<0.01` means less than 1% <Cite n={4} />.
- Use percentiles for a `Trend`. The k6 docs do not recommend `min` and `max` in thresholds, because they show outliers <Cite n={5} />.
- k6 needs to know the metric before the test starts. This is one reason why you create metrics in the init context <Cite n={1} />.

If a threshold fails, the test fails, as with any threshold.

</Technical>

## Custom metrics in the summary

<Voices>
<Technical>

k6 prints custom metrics in the summary at the end of a test. They are also in the raw data points <Cite n={1} />. This is the output of one local run of the script above. The numbers change on each run.

```text
  █ TOTAL RESULTS 

    CUSTOM
    bad_status_count...............: 0      0/s
    failed_requests................: 0.00%  0 out of 8
    home_body_bytes................: 2847   min=2847   max=2847
    home_waiting_time..............: avg=353.85ms min=308.57ms med=322.38ms max=605.78ms p(90)=411.26ms p(95)=508.52ms
```

Each type has its own format in the summary. The `Counter` shows a total and a rate per second. The `Rate` shows a percentage and the counts. The `Gauge` shows the latest value with its min and max. The `Trend` shows its statistics, and `ms` appears because of `isTime`. All 4 thresholds passed, so k6 printed a check mark for each and exited with code 0. See [Reading Results](/k6/reading-results/) for how to read the full summary.

k6 collects custom metrics from the VUs only at the end of an iteration. In a long script, a custom metric can appear only after the test has run for a while <Cite n={1} />.

</Technical>

## Key words

| Term | Meaning |
| --- | --- |
| Custom metric | A metric that you create with `k6/metrics`. |
| `Counter` | A metric that adds up the values. |
| `Gauge` | A metric that keeps the latest value. |
| `Rate` | A metric for the share of non-zero values. |
| `Trend` | A metric for statistics such as average and percentiles. |
| `add(value, [tags])` | The method that records one value. |
| `isTime` | An option of `Gauge` and `Trend`: the values are times. |
| Init context | The code outside `default`, where you create metrics. |
| Sub-metric | A metric for one tag value, such as `bad_status_count{page:home}`. |
