# Stages and Checks

Real users do not arrive all at once. Stages let a test grow and shrink the load over time, and checks test each response while it runs.

<PageMeta />

## The e-commerce story

<Voices>
<Technical>

Think about an e-commerce site. In the first minute, 50 people visit. After that, more people arrive until 200 are on the site. They browse and buy for 3 minutes. In the last 2 minutes, everyone leaves. This is the tutorial's own example. It is a story about a real day, and you can copy its shape with the `stages` option <Cite n={2} />.

`stages` is a list of objects. Each object has a `duration` and a `target`. The `target` is the number of virtual users (VUs) that k6 ramps up or down to during that duration <Cite n={2} />. The option is a shortcut for one scenario that uses the ramping VUs executor <Cite n={2} />.

This is the script of the story. Run it against a site that you own, or against the public demo site that Grafana provides:

```javascript
import http from 'k6/http';
import { check, sleep } from 'k6';

export const options = {
  stages: [
    { duration: '1m', target: 50 }, // ramp from 1 VU up to 50 VUs over 1 minute
    { duration: '3m', target: 200 }, // ramp from 50 VUs up to 200 VUs over 3 minutes
    { duration: '2m', target: 0 }, // ramp from 200 VUs down to 0 over 2 minutes
  ],
};

export default function () {
  const res = http.get('https://quickpizza.grafana.com');

  check(res, {
    'status is 200': (r) => r.status === 200,
    'response time < 500ms': (r) => r.timings.duration < 500,
  });

  sleep(1);
}
```

Each stage has a comment that says what it really does. The next section explains why.

</Technical>

## What each stage does

<Voices>
<Technical>

A stage does not jump to its target. k6 ramps the VU count linearly from the value at the start of the stage to the target of the stage <Cite n={3} />. The first stage starts from `startVUs`. If you use the `vus` option together with `stages`, k6 uses the `vus` value as `startVUs` <Cite n={2} />. The default of `startVUs` is 1 <Cite n={3} />.

| Stage | Duration | Target | What happens |
|---|---|---|---|
| 1 | `1m` | 50 | The VU count rises from 1 to 50 over 1 minute. |
| 2 | `3m` | 200 | The VU count rises from 50 to 200 over 3 minutes. |
| 3 | `2m` | 0 | The VU count falls from 200 to 0 over 2 minutes. |

Warning about the owner's first script: the comment of stage 2 said "stay at 200 users". That is not what this stage does. The stage ramps from 50 to 200 over 3 minutes, and the test reaches 200 VUs only at the end of the stage. The script above has the corrected comments.

A ramp down can stop an iteration that is still running. The option `gracefulRampDown` sets how long k6 waits for a started iteration to finish before it stops it. Its default is `30s` <Cite n={3} />.

The tutorial's own estimate: each VU runs `sleep(1)`, so each VU finishes about one iteration each second. The average VU count of a linear ramp is the middle of its start and end. This gives about 1,500 iterations in stage 1 (average 25 VUs for 60 s), 22,500 in stage 2 (125 VUs for 180 s), and 12,000 in stage 3 (100 VUs for 120 s). The sum is about 36,000. This estimate works only because the local server of the owner answered in about 1 ms.

</Technical>

## Hold the load at a level

<Voices>
<Technical>

To hold the load steady, add a stage with the same target as the stage before it. The VU count does not change during that stage, so the load stays flat <Cite n={2} />. The k6 docs show this in their own example: a ramp to 10 VUs for 3 minutes, then a flat stage at 10 VUs for 5 minutes <Cite n={2} />.

This script now does what the first script only claimed. It ramps to 200 VUs in 1 minute, holds at 200 VUs for 3 minutes, and ramps down:

```javascript
import http from 'k6/http';
import { check, sleep } from 'k6';

export const options = {
  stages: [
    { duration: '1m', target: 50 }, // ramp up to 50 VUs
    { duration: '1m', target: 200 }, // ramp up to 200 VUs
    { duration: '3m', target: 200 }, // hold at 200 VUs: same target as before
    { duration: '2m', target: 0 }, // ramp down to 0 VUs
  ],
};

export default function () {
  const res = http.get('https://quickpizza.grafana.com');

  check(res, {
    'status is 200': (r) => r.status === 200,
    'response time < 500ms': (r) => r.timings.duration < 500,
  });

  sleep(1);
}
```

The tutorial's own advice: use a ramp, then a flat stage, then a ramp down. The ramp up gives the server time to warm up. The flat stage gives stable numbers to read. The ramp down shows how the server recovers.

</Technical>

## Checks

<Voices>
<Technical>

A check tests a true or false condition. Testers use checks to confirm that the system answers with the expected content, for example a status of 201 or a body of a given size <Cite n={1} />. A check is like an `assert` in a test framework <Cite n={1} />.

In the script above, `check(res, { ... })` tests each response. It has two checks: the status is 200, and the response time is below 500 ms. Each check is a name and a function that returns true or false.

A status of 200 can still carry an error message. In that case, add a check on the body <Cite n={1} />.

Each check creates a rate metric. The end-of-test summary shows the result as `checks_total`, `checks_succeeded`, and `checks_failed` <Cite n={1} />. In the owner's run, each iteration made 2 checks, so 36,018 iterations gave 72,036 checks.

</Technical>

## A failed check does not fail the test

<Voices>
<Technical>

When a check fails, the script keeps running, and k6 does not return a failed exit status <Cite n={1} />. Instead, k6 tracks how many checks fail during the run <Cite n={1} />. A test with many failed checks can still finish as a pass.

To fail the test, combine the check with a threshold. The `checks` metric is a rate. A threshold such as `checks: ['rate>0.99']` fails the test when fewer than 99 % of the checks pass <Cite n={1} /> <Cite n={4} />. This matters in CI, where the exit code of k6 decides if the job passes. Read [Thresholds](/k6/thresholds/) for the full rules.

This script uses short stages and the threshold. It ran against the demo site with 3 VUs:

```javascript
import http from 'k6/http';
import { check, sleep } from 'k6';

export const options = {
  stages: [
    { duration: '3s', target: 3 },
    { duration: '4s', target: 3 },
    { duration: '3s', target: 0 },
  ],
  thresholds: {
    // A failed check does not fail the test. This threshold does.
    checks: ['rate>0.99'],
  },
};

export default function () {
  const res = http.get('https://quickpizza.grafana.com');

  check(res, {
    'status is 200': (r) => r.status === 200,
    'response time < 500ms': (r) => r.timings.duration < 500,
  });

  sleep(1);
}
```

</Technical>

- `Up to 200 looping VUs for 6m0s over 3 stages`: the three stages add up to 6 minutes.
- `checks_failed: 0.00%`: every check passed.
- `iterations` and `http_reqs` are equal, because each iteration sends one request.
- `vus` shows `min=1 max=200`. This matches the ramp from 1 VU to 200 VUs.

## Key words

| Term | Meaning |
| --- | --- |
| `stages` | A list of `{ duration, target }` objects. k6 ramps the VU count linearly to each target <Cite n={2} /> <Cite n={3} />. |
| `target` | The number of VUs at the end of a stage <Cite n={2} />. |
| `startVUs` | The number of VUs at the start of the test. The default is 1 <Cite n={3} />. |
| `gracefulRampDown` | How long k6 waits for a running iteration to finish during a ramp down. The default is `30s` <Cite n={3} />. |
| Ramp up / ramp down | A stage that raises or lowers the VU count. |
| Flat stage | A stage with the same target as the stage before it. The load stays steady. |
| `check()` | Tests a true or false condition on a value, such as a response <Cite n={1} />. |
| `checks` | The rate metric of passed checks. A threshold on it can fail the test <Cite n={1} /> <Cite n={4} />. |
